#6562 · Selected Claude skill expansion depends on prompt position

Bug Priority: Medium Effort: Medium providers provider-claude-code

Issue #6562 · October 29, 2026 · trusted base 3bacfac9ed69d42392076e5b3da2815bec822cd8

REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

BB can send an explicitly selected skill to Claude as ordinary text instead of invoking it. The reproduced case is a skill mention embedded after other text, including a skill in a later input fragment. BB replaces the dollar trigger with a slash but leaves the command in that position; the installed Claude SDK expands the command only when it leads the prompt in the tested cases. A fixture with disable-model-invocation: true therefore contributes no skill instructions to the outgoing model request when its command is embedded. A leading command is a successful control and a workaround: the flag alone does not make every direct invocation fail.

5. Root cause

The shared selector validates the resource as an explicitly selected skill and checks that its offsets match the visible token: selectedSkillMentions. Selection is therefore available to the provider; it is not necessary to guess from arbitrary slash text.

Claude's normalizer changes only the trigger character and keeps its original offset:

for (const mention of selectedSkillMentions(entry)) {
  if (mention.resource.trigger === "$") replacements.add(mention.start);
}
for (const start of replacements) {
  normalized = `${normalized.slice(0, start)}/${normalized.slice(start + 1)}`;
}

The prompt builder then joins text and attachment markers with newlines. Finally, runTurnInput obtains this string and pushes it to the SDK. Thus explicit selection is reduced to a token that the tested native parser does not expand when embedded.

The real-SDK control makes the causal distinction: identical file, frontmatter, model name, and input transport; only command position changes. The skill body appears in the outgoing request only in the leading case. No body injection occurs in BB's input builder to compensate for the embedded position. This explains the missing context without needing to speculate about model compliance.

6. Proposed fix and safety gate

For exactly one validated selected skill, remove that token from its input fragment and put /skill-name before the combined remaining text and attachment markers. Preserve ordinary dollar/slash text and retain existing behavior for multiple selections. This follows the already-existing single-selection handling in the Pi provider; it requires no new wire field or API.
