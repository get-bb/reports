#8254 · Local image identity survives preview refetches

BugMedium priorityLow effortuiGitHub issue2026-11-26

Trusted base: b0ddaad731565d7e4de68d824120d802fc78f7d5

Verdict: REPRODUCED at the rendered DOM boundary. Root-cause confidence: high. Browser pixel/cache behavior and macOS-specific behavior were not verified.

1. TL;DR

The preview's Refresh action fetches the Markdown again, but does not give the embedded local images a new resource identity. A regression test renders the real project preview, clicks its real Refresh control, and observes an unchanged image source after a successful refetch. It fails on trusted main in two separate clean checkouts, including when the query returns the exact same Markdown object. The contained repair forwards the query's successful-update timestamp and versions only locally resolved image sources. This verifies the client-side cause; no screenshot or actual image-download trace is claimed because this host has no Chrome/Chromium executable.

import type { FilePreview, TextFilePreview } from "@bb/client-core";

const projectPreviewQuery = vi.hoisted(() =>
  vi.fn<
    (
      _projectId: string,
      path: string,
    ) => Pick<
      UseQueryResult<FilePreview>,
      "data" | "error" | "isFetching" | "isLoading" | "refetch"
    >
  >(),

function markdownPreview(
  path: string,
  url = `/content/${path}`,
): TextFilePreview {
  return {
    kind: "text",
    content: [
      "![absolute](/workspace/generated.png)",
      "![relative](images/chart.png)",
      "![escape](../../outside.png)",
    ].join("\n\n"),
    mimeType: "text/markdown",
    name: path.split("/").at(-1),
    path,
    url,
  };
}

function previewQuery(path: string, url?: string) {
  return {
    data: markdownPreview(path, url),
    error: null,
    isFetching: false,
    isLoading: false,
    refetch: vi.fn(),
  };
}

vi.mock("@/hooks/queries/environment-queries", () => ({

function renderImageSources(element: ReactElement): Map<string, string> {
  const sources = new Map<string, string>();
  for (const [tag] of renderToStaticMarkup(element).matchAll(
    /<img\b[^>]*>/gu,
  )) {
    const alt = /\balt="([^"]*)"/u.exec(tag)?.[1];
    const src = /\bsrc="([^"]*)"/u.exec(tag)?.[1];
    if (alt !== undefined && src !== undefined) sources.set(alt, src);
  }
  return sources;
}

5. Root cause

Preview refetches discard the query update timestamp, leaving local Markdown image source URLs unchanged even when the query finishes successfully.

  1. apps/app/src/components/secondary-panel/ThreadSecondaryPanelTabContent.tsx:105 forwards data, loading, and refetch state, but not dataUpdatedAt. Its Refresh callback only calls query.refetch().
  2. apps/app/src/components/ui/markdown-file-routing.ts:46 deterministically constructs local image URLs from source identity and file path, with no refresh identity.
  3. apps/app/src/components/secondary-panel/ThreadStorageFilePreview.tsx:218 forwards the routing unchanged to the file preview surface.
  4. apps/app/src/components/ui/markdown-preview.tsx:558 uses that resolver for the actual image source. An unchanged URL does not request that the existing image element load a different resource.

The HTTP cache policy is not a client-side refresh mechanism: apps/server/src/services/hosts/daemon-file-response.ts:17 already provides validators and revalidation headers. Those matter when a request happens. The proven defect is the lack of a changed local image URL after the preview query updates; the renderer does not supply an explicit image reload.

6. Proposed fix and tested repair

Forward the query's existing successful-update timestamp through the shared preview boundary. Wrap only the local-image resolver to append a version query parameter, preserving existing query parameters and fragments. This avoids fetching image metadata separately and handles structurally shared, unchanged Markdown data. Remote image URLs, file-link routing, root confinement, downloads, protocols, and server behavior are untouched.

The focused regression then passes after both the real Refresh click and a background query invalidation. Existing renderer/routing coverage remains green: 56 tests across 3 files. Existing server response contracts remain green: 58 tests across 2 files. App typecheck and lint pass. git diff --check passes. The candidate touches 3 files and 104 added/deleted text lines; no binary, dependency, lockfile, generated module, migration, stored data, or public contract changes.
