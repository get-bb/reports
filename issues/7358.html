#7358 · UI preference failure message scope

Bug Priority: Low Effort: Low ui GitHub issue · 2026-11-10

Trusted main commit: 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high.

1. TL;DR

A failed save of a non-sidebar UI preference produces a notification naming the sidebar. All synced UI preferences share one error handler, but its title describes only a subset of those preferences. A focused behavioral regression reproduces this by rejecting the save for the information-panel collapsed sections, then observing the toast arguments. The same test fails for the same title mismatch in a second clean checkout. Changing only the shared title to name UI preferences fixes the mismatch without altering persistence, retry, or error deduplication.

5. Root cause

Synced preference atoms register any supported key and schedule a write after a local change. The domain key list is broader than the sidebar. A failed non-conflict SDK write propagates into the shared flush catch handler, which calls one deduplicated failure notifier:

appToast.error("Couldn’t sync sidebar preferences", {
  description:
    error instanceof Error ? error.message : "Changes stay on this device.",
});

The title is independent of the failed key, so a failed information-panel write necessarily receives the sidebar title. This is misleading copy in the owner of the error message, not a server, retry, authentication, or stored-data defect. Existing coverage checked one-toast deduplication, invalidation, and retained local values, but did not check the message title.

Composer clarification: the composer consumer resolves plugin composer replacements, and its settings control changes that renderer preference.

6. Proposed fix

Use “Couldn’t sync UI preferences” in the existing shared notifier. Extend the existing failure test to trigger a non-sidebar write first, then a sidebar write, and assert the title as well as existing deduplication, invalidation, and local-state behavior. This introduces no new API, schema, dependency, protocol, generated file, or product decision.
