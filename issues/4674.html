#4674 · Full-turn timeline context defeats the source-work budget

BugHigh priorityEffort: Highthreadsperfconfirmed-repro

GitHub issue · October 2, 2026 · trusted main e7d200a6549cdfb1d0a1e0103e44224eaf3c78a0

REPRODUCED · Root-cause confidence: high

1. TL;DR

A small timeline page can require work proportional to an entire long-running agent turn. The server first chooses a budgeted window, then expands every selected turn back to the context-clear boundary and forward to the snapshot head, before decoding and projecting those events. With a 100-leaf budget, a synthetic open turn containing 3,000 completed commands selects 6,003 events and 12,973,222 bytes of event JSON, yet returns only 100 rows. Appending one command causes another full selection of 6,005 events; an older page selects the same full turn. Both clean checkouts reproduced this source-work growth and the deliberately failing bounded-work assertion.

import { describe, expect, it } from "vitest";
import {
  createConnection,
  createProject,
  createThread,
  getLatestThreadSequence,
  insertEvents,
  migrate,
  noopNotifier,
  upsertHost,
} from "@bb/db";
import type { DbConnection } from "@bb/db";
import {
  encodeClientTurnRequestIdNumber,
  threadScope,
  turnScope,
} from "@bb/domain";
import type { Thread } from "@bb/domain";
import { buildThreadTimelineWithProfile } from "../../../src/services/threads/timeline.js";
import type { ThreadTimelinePageRequest } from "../../../src/services/threads/timeline-pagination.js";

type EventInput = Parameters<typeof insertEvents>[2][number];
const eventBudget = 100;
const turnId = "repro-open-turn";

function setup(itemCount: number, commandChars: number) {
  const db = createConnection(":memory:");
  migrate(db);
  const host = upsertHost(db, noopNotifier, { name: "repro-host" });
  const { project } = createProject(db, noopNotifier, {
    name: "repro-project",
    source: { type: "local_path", hostId: host.id, path: "/tmp/repro-scratch" },
  });
  const created = createThread(db, noopNotifier, {
    projectId: project.id,
    providerId: "claude-code",
  });
  const thread: Thread = { ...created, status: "active" };
  const clientRequestId = encodeClientTurnRequestIdNumber({ value: 1 });
  const events: EventInput[] = [];
  const append = (event: Omit<EventInput, "threadId" | "sequence">) => {
    events.push({ ...event, threadId: thread.id, sequence: events.length + 1 });
  };
  append({
    type: "client/turn/requested",
    scope: threadScope(),
    itemId: null,
    itemKind: null,
    parentToolCallId: null,
    data: JSON.stringify({
      direction: "outbound",
      source: "tell",
      initiator: "user",
      request: { method: "turn/start", params: {} },
      requestId: clientRequestId,
      senderThreadId: null,
      input: [
        { type: "text", text: "Synthetic command workload", mentions: [] },
      ],
      target: { kind: "thread-start" },
      execution: {
        model: "gpt-5",
        serviceTier: "default",
        reasoningLevel: "medium",
        permissionMode: "full",
        source: "client/turn/requested",
      },
    }),
  });
  append({
    type: "turn/started",
    scope: turnScope(turnId),
    providerThreadId: "repro-provider",
    itemId: null,
    itemKind: null,
    parentToolCallId: null,
    data: "{}",
  });
  append({
    type: "turn/input/accepted",
    scope: turnScope(turnId),
    providerThreadId: "repro-provider",
    itemId: null,
    itemKind: null,
    parentToolCallId: null,
    data: JSON.stringify({ clientRequestId }),
  });
  insertEvents(db, noopNotifier, events);
  appendItems(db, thread, 0, itemCount, commandChars);
  return { db, thread };
}

function appendItems(
  db: DbConnection,
  thread: Thread,
  start: number,
  count: number,
  commandChars: number,
) {
  const events: EventInput[] = [];
  let sequence = getLatestThreadSequence(db, { threadId: thread.id });
  for (let index = start; index < start + count; index += 1) {
    const itemId = `repro-command-${index}`;
    for (const completed of [false, true]) {
      sequence += 1;
      events.push({
        threadId: thread.id,
        sequence,
        type: completed ? "item/completed" : "item/started",
        scope: turnScope(turnId),
        providerThreadId: "repro-provider",
        itemId,
        itemKind: "commandExecution",
        parentToolCallId: null,
        data: JSON.stringify({
          item: {
            type: "commandExecution",
            id: itemId,
            command: "x".repeat(commandChars),
            cwd: "/tmp/repro-scratch",
            status: completed ? "completed" : "pending",
            approvalStatus: null,
            ...(completed ? { exitCode: 0, aggregatedOutput: "ok" } : {}),
          },
        }),
      });
    }
  }
  insertEvents(db, noopNotifier, events);
}

function build(
  db: DbConnection,
  thread: Thread,
  budget: number,
  page: ThreadTimelinePageRequest = { kind: "latest", segmentLimit: 20 },
) {
  return buildThreadTimelineWithProfile(db, thread, {
    completedTurnDisplay: "collapse",
    eventBudget: budget,
    includeDiagnosticOperations: false,
    includeNestedRows: false,
    maxInlineOutputChars: 32_000,
    maxSeq: 0,
    page,
  });
}

function logBuild(name: string, result: ReturnType<typeof build>) {
  const { profile, response } = result;
  console.log(
    JSON.stringify({
      name,
      eventBudget,
      eventRowCount: profile.eventRowCount,
      eventDataBytes: profile.eventDataBytes,
      decodedEventCount: profile.decodedEventCount,
      projectedRowCount: profile.projectedRowCount,
      responseRowCount: profile.responseRowCount,
      contentPage: response.timelinePage.contentPage,
      fullSelection: profile.stageTimings.some(
        (entry) => entry.stage === "group-context-query",
      ),
      totalDurationMs: profile.totalDurationMs,
    }),
  );
}

describe("open-turn source selection reproduction", () => {
  it.each([300, 3_000])(
    "records source work for %i command items",
    (itemCount) => {
      const { db, thread } = setup(itemCount, 2_000);
      try {
        const latest = build(db, thread, eventBudget);
        logBuild(`${itemCount}:latest`, latest);
        const unlimited = build(db, thread, 1_000_000);
        expect(latest.profile.eventRowCount).toBe(2 * itemCount + 3);
        expect(latest.profile.eventRowCount).toBe(
          unlimited.profile.eventRowCount,
        );
        const contentPage = latest.response.timelinePage.contentPage;
        expect(contentPage).toBeDefined();
        expect(contentPage!.end - contentPage!.start).toBeLessThanOrEqual(
          eventBudget,
        );
        const beforeCursor = latest.response.timelinePage.olderCursor;
        expect(beforeCursor).not.toBeNull();
        const older = build(db, thread, eventBudget, {
          kind: "older",
          beforeCursor: beforeCursor!,
          segmentLimit: 20,
        });
        logBuild(`${itemCount}:older`, older);
        expect(older.profile.eventRowCount).toBe(latest.profile.eventRowCount);
        appendItems(db, thread, itemCount, 1, 2_000);
        const appended = build(db, thread, eventBudget);
        logBuild(`${itemCount}:after-item-append`, appended);
        expect(appended.profile.eventRowCount).toBe(2 * itemCount + 5);
        expect(
          appended.profile.stageTimings.some(
            (entry) => entry.stage === "group-context-query",
          ),
        ).toBe(true);
      } finally {
        db.$client.close();
      }
    },
  );

  it("bounds source events for a 100-leaf latest page", () => {
    const { db, thread } = setup(300, 2_000);
    try {
      const latest = build(db, thread, eventBudget);
      expect(latest.profile.eventRowCount).toBeLessThanOrEqual(
        2 * eventBudget + 3,
      );
    } finally {
      db.$client.close();
    }
  });
});

5. Root cause

The thread-data route passes the configured timelineWindowEventBudget into the timeline builder. The initial selection computes an event-budget floor. However, turn-group context expansion replaces the window bounds with the whole epoch-to-snapshot span for every touching turn:

...listStoredTimelineTurnEventRows(db, {
  ...windowArgs,
  sequenceStart: epochSequenceStart,
  beforeSequence: maxSeq + 1,
  turnIds,
})

The turn-row database query filters by turn IDs and the expanded sequence span but has no event-budget limit. Consequently, one large retained turn overrides the initial budget floor. There are excluded event types and context-clear boundaries, so this is not literally every event ever stored for the thread.

The decode stage visits all selected rows, and projection precedes pagination. Only then does the response enforce maxLeaves: Math.max(1, options.eventBudget). Full-turn projection provides the leaf-index cursor and total leaf count, so a naive SQL limit would change page contents, cursor meaning, and summary behavior.

The selection memo's appendable set allows streaming deltas/progress, not item start/completion. Its append validation therefore returns a miss for the new lifecycle events in this reproduction. Even a reused selection is still decoded/projected by the builder; the memo stores selection, not an incrementally maintained full projection. The decode cache reduces actual parsing for cache-resident events but does not bound source querying or projection.

Repository history traces the broad turn-context query to commit 8d2a0280ae. The existing large-running-turn test intentionally expects budgeted and unbudgeted event counts to match while the response is paginated. This is an established design limitation, not an accidental missing limit with a safe one-line repair.

6. Proposed fix and simple-fix decision

Preserving the public cursor contract would require a bounded, incrementally maintained turn projection with careful invalidation for lifecycle events, parented content, rewritten events, pruning, context clears, snapshot reads, and active-to-idle transitions. Validate warm append costs against turn length and compare every incremental result with a cold projection across those cases. A sequence-based content window is another direction, but changes cursor/page semantics and is outside the authorized simple-fix criteria.

No pull request: a root-cause repair needs a projection/cache or pagination architecture decision. Limiting the context query breaks current semantics; merely widening the appendable memo list leaves full projection work intact. No production changes, fix branch, dependency, or schema modification were made. No linked open PR was present in the issue timeline or the repository's open-PR search for this numeric issue at the final check.
