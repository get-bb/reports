1. TL;DR

ACP background output is grouped by silence rather than by an actual agent-run boundary. Two completed tools six seconds apart, followed by a reply six seconds later, produce three background turns instead of one. Separately, a successful root-thread status transition advances the unread-attention timestamp even when no message was produced. The real bridge and real migrated SQLite lifecycle implementation reproduce both mechanisms twice. This is a protocol/lifecycle reproduction, not a live Hermes or desktop UI reproduction.

5. Root cause

Quiet time is treated as an authoritative end

AGENT_TURN_QUIET_MS is 5,000 ms. agentTurnHasOpenWork and armAgentTurnQuietTimer hold the timer only for a pending permission, pending question, or unfinished tool. A terminal tool leaves none of these conditions true, although the model can still be computing. The timer calls finishAgentTurn with end_turn; the next output opens another agent turn. Session update handling rearms or opens these turns based on incoming work events.

if (agentTurnHasOpenWork(session)) {
  armAgentTurnQuietTimer(session);
  return;
}
finishAgentTurn(session, "end_turn");

handleAgentNotification immediately discards every method except session/update. The bridge constructs a generation-1 session model; the model state capability and state_update branch do not enable generation-2 run-state reporting for that connection. Increasing a timer cannot distinguish an actual run ending from a longer thinking pause.

Attention is derived from status, not user-facing output

Successful turn completion maps to run.succeeded; completion handling supplies no user-facing-content distinction to lifecycle handling. statusTransitionNeedsAttention returns true for every root active-to-idle transition, and applyThreadLifecycleEvent writes latestAttentionAt=now. Unread detection compares lastReadAt against that timestamp. This explains unread attention even for tool-only successful completions.

Turn duration title mapping also explains why extra completed turns create extra duration rows. That last UI implication is verified by source inspection rather than a live visual capture.

6. Proposed fix

Introduce a deliberately negotiated agent-run lifecycle signal so a cooperative ACP agent can explicitly start and finish background work, with a conservative fallback for agents without that capability. Separately propagate a typed content/attention decision from turn completion to the server-owned unread policy, preserving attention for questions, approvals, failures, and actual replies. Validate compatibility, cancellation, stale or duplicate run signals, and failure handling. This crosses existing boundaries and must not be replaced with a larger arbitrary quiet window.

No fix PR is created: open PR #7136 already declares this issue in its GitHub closing-issue metadata. The automation therefore stops before branching or production edits.
