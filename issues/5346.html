1. TL;DR

The report describes macOS system Dictation starting without delivering text to the desktop composer. This investigation ran on Linux, so the native macOS text-service interaction could not be exercised. In two separate trusted checkouts, a real production prompt editor accepted a browser-style text insertion and synchronized it into its document. Three nearby composer controls also passed in each checkout. These are positive controls, not a reproduction of macOS Dictation and not proof that the report is invalid. No production change or pull request is justified by this evidence.

Diagnostic test

/** @vitest-environment jsdom */
import { Editor } from "@tiptap/core";
import { expect, it, vi } from "vitest";
import { promptEditorExtensions } from "./prompt-editor-extensions";
import { promptEditorValueFromDoc } from "./prompt-editor-serialization";

it("observes browser-delivered text in the production prompt editor", async () => {
  const container = document.createElement("div");
  document.body.append(container);
  const editor = new Editor({
    element: container,
    extensions: promptEditorExtensions({ getPlaceholder: () => "" }),
    content: "<p></p>",
  });
  try {
    const paragraph = editor.view.dom.querySelector("p");
    if (!paragraph) throw new Error("Prompt paragraph is missing");
    editor.view.dom.focus();
    const accepted = editor.view.dom.dispatchEvent(
      new InputEvent("beforeinput", {
        bubbles: true,
        cancelable: true,
        inputType: "insertText",
        data: "spoken control",
      }),
    );
    expect(accepted).toBe(true);
    paragraph.textContent = "spoken control";
    editor.view.dom.dispatchEvent(
      new InputEvent("input", {
        bubbles: true,
        inputType: "insertText",
        data: "spoken control",
      }),
    );
    await vi.waitFor(() => {
      expect(promptEditorValueFromDoc(editor.state.doc)).toEqual({
        text: "spoken control",
        mentions: [],
      });
    });
  } finally {
    editor.destroy();
    container.remove();
  }
});

5. Root cause: not established

The production path uses Tiptap/ProseMirror, not a plain textarea. The prompt extensions configure ordinary text and paragraph nodes. The React composer serializes document updates and calls its change callback. The passing DOM control demonstrates only that this lower-level editor path can accept text after delivery; it does not establish whether macOS delivers an event or mutation to the actual composer.
