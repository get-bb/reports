#6820 · Completion excerpts cross child-turn boundaries

BugPriority: LowEffort: Lowthreads GitHub issue · November 2, 2026 · base 916d684ac23d0b0de82c09cfc7553a50287d2188

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

A child thread can finish a new turn without producing a message. Its parent still receives a completion notice containing the child's earlier result. The notification code asks for the most recent non-empty output of the whole thread, instead of the output of the completed turn. Two event-ingestion regressions reproduce this with real migrated SQLite and the normal parent notification queue. The same agent repeated both failures in a second clean checkout; no reporter-provided code or linked PR code was executed.

5. Root cause

The root completion follow-up carries status and thread identity but not the completed turn ID. getChildThreadCompletionOutput consequently invokes getLastThreadOutput(db, childThread.id). getLastThreadOutput calls the database query without a turn constraint. getLatestThreadOutputEventRow selects the latest non-empty agent or manager output from anywhere in the thread, ordered by sequence.

return getLastThreadOutput(deps.db, args.childThread.id);

The empty message is excluded by the SQL non-empty predicate; no message adds no candidate at all. The earlier result therefore remains the latest eligible output and becomes the new notice's excerpt. The normal output route needs thread-wide behavior; the completion path needs a narrower query, not a global redefinition.

6. Proposed fix

Carry the completed root turn ID through the server-only notification follow-up. Scope the completion output query to that exact turn and root agent messages, including an empty final message so it cannot fall back to earlier content. Keep the existing no-output fallback notice and preserve the thread-wide last-output route. No protocol or stored-data change is needed.
