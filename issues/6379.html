#6379 · Provider maintenance bypasses compaction admission

BugHighEffort: Mediumproviders · threads · provider-pi

GitHub issue · October 27, 2026 · Base b6743a36bd9eae1408c35cfc2c7ab1d2419dc79d

Verdict: REPRODUCED at the server dispatch boundary. Root-cause confidence: high.

1. TL;DR

A message arriving during a provider-owned maintenance turn is dispatched immediately rather than retained until compaction finishes. The server recognizes manual compaction from a bb command request, not from the provider's own maintenance events. Pi emits a separate turn and a context-compaction item for manual compaction even when bb did not request it. A focused public send-route test fails on untouched main in two clean checkouts: expected queued, received sent. This reproduces the admission defect; an authenticated live Pi extension run and its full error/message-loss chain were not executed.

5. Root cause

plugins/provider-pi/src/delta-translation.ts:727-L743 translates manual compaction into its own turn and compaction item. packages/provider-bridge-protocol/src/assembler/delta-assembler.ts:775-L783 turns that delta into a contextCompaction item.

apps/server/src/services/threads/thread-events.ts:865-L889 only recognizes an active manual compaction when its associated request, or the last thread request, is a standalone built-in compact command. A provider-owned maintenance turn has no matching client request. Therefore a valid compaction item does not satisfy this predicate.

apps/server/src/services/threads/dispatch-attempt.ts:490-L500 uses that predicate as the compaction wait gate. When it returns false, the active-turn send proceeds toward steering. The dependency's AgentSession.prompt rejects prompts whenever its manual compaction controller exists. That explains the reported rejection, but the complete live rejection/error cascade remains a source-supported inference, not a reproduced transcript.

6. Proposed fix

Preserve the existing command-request guard. For an active provider-owned turn without an accepted bb request, inspect that turn's root contextCompaction lifecycle and wait while its item is open. Use a targeted thread/turn query, not a whole-thread event scan. Preserve steering during ordinary requested turns, including provider automatic compaction that does not own a separate maintenance turn. No provider protocol, persisted schema, or product-policy change is required. The added route-level regression must fail before the fix and pass afterward, including queue drain.
