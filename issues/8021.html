#8021 · Cached message navigation can remain hidden

Bug Priority: Medium Effort: Low threads · 2026-11-22 · GitHub issue

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

Trusted main commit: 796cdcc0f4bf8a55e23664035c54e8db6fe9d272. Same agent repeated the reproduction in a second clean checkout; this is not an independent review.

1. TL;DR

A link to a newer message can be classified as missing while the cached timeline is being refreshed. That terminal path records the navigation as handled, but does not record it as settled. When the reply subsequently arrives, the reveal flag becomes pending and the timeline renderer hides its rows; the handled guard then prevents the reveal from running. Two regression tests fail on unchanged main in two separate checkouts. A small hook-only production fix waits for the exact thread timeline query to finish and settles missing targets as well as successful reveals.

async function renderControllerWithPendingOlderPage() {
  const olderPage = createDeferredPromise<ThreadTimelineResponse>();

    .mockResolvedValueOnce(
      makeTimelineResponse({
        rows: [newestLoadedRow],

          historySnapshot: "snapshot-1",

          olderRowsSourceSeqEnd: null,
        },

    .mockReturnValueOnce(olderPage.promise);

  const { queryClient, wrapper } = createQueryClientTestHarness();
  const { result } = renderHook(
    () => useThreadTimelineController({ threadId: "thread-1" }),
    { wrapper },

  await waitFor(() => {
    expect(result.current.hasOlderTimelineRows).toBe(true);

  const settleOlderPage = async () => {
    olderPage.resolve(
      makeTimelineResponse({
        rows: [olderPageRow],
        maxSeq: 1,
        timelinePage: { historySnapshot: "snapshot-1" },
      }),
    );
    await act(async () => {
      await olderRequest;
    });
  };
  const failOlderPage = async (error: BbHttpError) => {
    olderPage.reject(error);
    await act(async () => {
      await expect(olderRequest).rejects.toBe(error);
    });
  };
  const publishLatest = (response: ThreadTimelineResponse) => {
    act(() => {
      queryClient.setQueryData(TIMELINE_QUERY_KEY, response);
    });
  };

  return { failOlderPage, publishLatest, result, settleOlderPage };
}

async function withReactSchedulerOutsideAct(
  run: () => Promise<void>,
): Promise<void> {
  const previousActEnvironment: unknown = Reflect.get(
    globalThis,
    "IS_REACT_ACT_ENVIRONMENT",
  );
  Reflect.set(globalThis, "IS_REACT_ACT_ENVIRONMENT", false);
  try {
    await run();
  } finally {
    Reflect.set(globalThis, "IS_REACT_ACT_ENVIRONMENT", previousActEnvironment);
  }
}

interface ProfiledController {
  latest: () => UseThreadTimelineControllerResult;
  profilerCommitCount: () => number;
}

function renderProfiledController(
  wrapper: (props: { children: ReactNode }) => ReactNode,
): ProfiledController {
  const latestResult: { current: UseThreadTimelineControllerResult | null } = {
    current: null,
  };
  let profilerCommits = 0;
  const onRender: ProfilerOnRenderCallback = () => {
    profilerCommits += 1;
  };

  function ControllerHost() {
    const controller = useThreadTimelineController({ threadId: "thread-1" });
    useLayoutEffect(() => {
      latestResult.current = controller;
    });
    return null;
  }

  render(
    <Profiler id="timeline-controller" onRender={onRender}>
      <ControllerHost />
    </Profiler>,
    { wrapper },
  );

  return {
    latest: () => {
      if (latestResult.current === null) {
        throw new Error("The timeline controller has not committed yet");
      }
      return latestResult.current;
    },
    profilerCommitCount: () => profilerCommits,
  };
}

function flushQueryNotifications(): Promise<void> {
  return notifications.flush();
}

async function renderSettledController(
  wrapper: (props: { children: ReactNode }) => ReactNode,
  expectedRowIds: string[],
): Promise<ProfiledController> {
  const view = renderProfiledController(wrapper);
  await waitFor(() => {
    expect(view.latest().timelineLoading).toBe(false);
    expect(rowIds(view.latest())).toEqual(expectedRowIds);
  });
  await flushQueryNotifications();
  return view;
}

When the query later supplies the row, targetIsMissing becomes false and removes the temporary exception from isInitialRevealPending. settledLocationKey remains null, while handledKeyRef stops the effect from revealing the row. The real renderer applies visibility:hidden whenever this pending result is true. This is a navigation lifecycle inconsistency, not missing server data or a virtualizer dropping the row.

6. Proposed fix and verification

Subscribe to fetching state for the exact threadTimeline query only when this hook reports a navigation target. Defer missing-target resolution until the refresh finishes. Schedule the terminal missing notification on a cancellable animation frame so committed row/query notifications can reconcile; guard it against navigation changes. Mark that terminal location settled as well as handled, keeping late row updates from hiding the list again. Existing older-history loading and successful reveal behavior remain intact.

The implementation changes one existing timeline hook and its existing regression test file: 2 files, 140 changed text lines (134 additions + 6 deletions). No dependency, generated file, stored data, public API, daemon protocol, security, or product-policy change is involved.
