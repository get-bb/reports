#7897 · Machine launcher selection diverges after updates

BugPriority: MediumEffort: Mediumdesktop, cliGitHub issue2026-11-20

Base: fab82665a3299fae8910f55d7519a3b034a03b9a, fetched from trusted origin/main and checked again after both reproductions.

Verdict: REPRODUCED · Root-cause confidence: high · Label: confirmed-repro.

1. TL;DR

The machine installer publishes a shell command that keeps selecting its enrollment npm executable even when the same installation has a newer maintained launcher. A fresh external shell therefore does not follow that launcher's update. The actual server CLI-command service recognizes the installer shim as a machine command and refuses installation with cli_command_blocked (409). Both results repeat in a second clean checkout with unchanged production code. This is a focused executable dispatch reproduction, not a live enrollment, server move, or downloaded-version upgrade.

5. Root cause

  1. apps/server/src/assets/install-machine.sh:555–584 only publishes when the PATH command is absent. Its destinations are explicit-data-dir npm, the captured enrollment npm path, and other machine npm paths; it has no branch for the maintained launcher. Re-running enrollment does not rewrite an existing shim.
  2. packages/bb-app/src/app-update/npm-revision.ts:58–69 and packages/bb-app/src/app-update/npm-revision.ts:104–149 place updates under the versioned installation directory, not the enrollment npm prefix.
  3. packages/bb-app/src/cli-launcher.ts:61–69 defines the maintained launcher under the installation's bin directory. packages/bb-app/src/launcher.ts:2046–2070 writes that launcher, and packages/bb-app/src/launcher.ts:4258–4261 calls it on eligible packaged full-stack startup. It does not update the separate machine shim.
  4. apps/server/src/services/system/cli-command.ts:186–198 detects the installer marker and classifies the command as machine-owned. apps/server/src/services/system/cli-command.ts:292–306 then rejects any shadowing command, including this recognized shim. This is the second half of the defect: the installation repair cannot switch the external-shell command.

Relevant production excerpts

cli_path_quoted=$(printf '%s' "$data_dir/npm/bin/bb" | sed "s/'/'\\''/g")
if [ -n "${BB_DATA_DIR:-}" ] && [ -x "$BB_DATA_DIR/npm/bin/bb" ]; then
  exec "$BB_DATA_DIR/npm/bin/bb" "$@"
fi

const shadow = await shadowingCommand(context);

The separately inspected launcher also prefers persisted server URL configuration over the environment (packages/bb-app/src/launcher.ts:1053–1058), but the report makes no runtime claim about the separate remote authentication symptom.

6. Proposed fix and safety gate

Have the machine-owned command follow a maintained current CLI destination while retaining a fallback for machines with only the enrollment package. Cover newly generated commands, existing installed commands, explicit machine selection, command cycles, and preservation of unrelated executables. Repair must address already-published shims, not just future enrollment.

No autopilot fix or PR: the verified root-cause repair changes installer/launcher packaging behavior, which this rule explicitly excludes from simple fixes. Replacing existing commands also needs installer ownership and multi-installation compatibility review. No production fix was applied or pushed. The 69-line test-only patch is published as evidence, not proposed as a completed fix.

No linked open pull request was found in issue timeline metadata or the open-PR issue-number search. No pull-request branch was checked out or executed.
