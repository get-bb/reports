#4935 · Pi image completion classification

BugPriority: LowEffort: Lowproviders · provider-piOctober 5, 2026

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high

1. TL;DR

Successful Pi native reads containing image data finish as generic tool calls rather than image-view items. This classification defect reproduces through the real provider translator and shared delta assembler in two clean checkouts of current trusted main. The original tool ID and path are available, but completion preserves the generic shape and reduces the content to text. The app selects its existing image preview body only for an image-view row. This report proves the translation gap, not a live Pi session, browser expansion, or host-file delivery; those UI claims remain unverified.

import { describe, expect, it } from "vitest";
import { experimental_createDeltaAssembler as createDeltaAssembler } from "@get-bb/plugin-sdk/provider-bridge/testing";
import { createPiDeltaTranslator } from "./delta-translation.js";

const imageBlock = {
  type: "image",
  data: "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAQAAAC1HAwCAAAAC0lEQVR42mP8/x8AAwMCAO+aVZkAAAAASUVORK5CYII=",
  mimeType: "image/png",
};

function createHarness() {
  const translator = createPiDeltaTranslator({
    resolveModelContextWindow: () => null,
  });
  const assembler = createDeltaAssembler({
    providerId: "pi",
    entropyPrefix: "image-read",
    textDeltaFlushMs: 0,
  });
  return (event: unknown, threadId = "thread-a") =>
    assembler.assemble({
      threadId,
      deltas: translator.translate(event, { threadId }),
    });
}

describe("Pi native image read completion", () => {
  it.each([
    {
      name: "successful image read",
      args: { path: "/workspace/asset.png" },
      result: { content: [imageBlock] },
      toolName: "read",
      isError: false,
      imagePath: "/workspace/asset.png",
    },
    {
      name: "mixed text and image without an image extension",
      args: { path: "/workspace/asset" },
      result: { content: [{ type: "text", text: "scaled" }, imageBlock] },
      toolName: "read",
      isError: false,
      imagePath: "/workspace/asset",
    },
    ...[
      {
        name: "text at an image path",
        result: { content: [{ type: "text", text: "source" }] },
      },
      {
        name: "failed image read",
        result: { content: [imageBlock] },
        isError: true,
      },
      {
        name: "unrelated image tool",
        result: { content: [imageBlock] },
        toolName: "inspect",
      },
      { name: "missing path", result: { content: [imageBlock] }, args: {} },
      {
        name: "non-string path",
        result: { content: [imageBlock] },
        args: { path: 123 },
      },
      {
        name: "empty path",
        result: { content: [imageBlock] },
        args: { path: "" },
      },
      {
        name: "whitespace path",
        result: { content: [imageBlock] },
        args: { path: " " },
      },
      {
        name: "missing image data",
        result: { content: [{ type: "image", mimeType: "image/png" }] },
      },
      {
        name: "empty image data",
        result: { content: [{ ...imageBlock, data: "" }] },
      },
      {
        name: "invalid image MIME",
        result: { content: [{ ...imageBlock, mimeType: "text/plain" }] },
      },
      { name: "malformed content", result: { content: "image" } },
      { name: "null block", result: { content: [null] } },
    ].map((control) => ({
      toolName: "read",
      args: { path: "/workspace/asset.png" },
      isError: false,
      imagePath: null,
      ...control,
    })),
  ])("preserves the correct item shape for $name", (scenario) => {
    const translate = createHarness();
    translate({ type: "agent_start" });
    const started = translate({
      type: "tool_execution_start",
      toolCallId: "read-1",
      toolName: scenario.toolName,
      args: scenario.args,
    }).find((event) => event.type === "item/started");
    expect(started).toMatchObject({
      item: { type: "toolCall", tool: scenario.toolName, status: "pending" },
    });
    const completed = translate({
      type: "tool_execution_end",
      toolCallId: "read-1",
      toolName: scenario.toolName,
      result: scenario.result,
      isError: scenario.isError,
    })
      .filter((event) => event.type === "item/completed")
      .at(-1);
    expect(completed?.item.id).toBe(started?.item.id);
    if (scenario.imagePath !== null) {
      expect(completed?.item).toEqual({
        type: "imageView",
        id: started?.item.id,
        path: scenario.imagePath,
      });
    } else {
      expect(completed?.item).toMatchObject({
        type: "toolCall",
        tool: scenario.toolName,
        status: scenario.isError ? "failed" : "completed",
      });
    }

    const translate = createHarness();
    for (const threadId of ["thread-a", "thread-b"]) {

      translate(
        {
          type: "tool_execution_start",
          toolCallId: "shared-read",
          toolName: "read",
          args: { path: `/workspace/${threadId}.png` },
        },
        threadId,
      );

    for (const threadId of ["thread-b", "thread-a"]) {

        {
          type: "tool_execution_end",
          toolCallId: "shared-read",
          toolName: "read",
          result: { content: [imageBlock] },
          isError: false,
        },
        threadId,
      )
        .filter((event) => event.type === "item/completed")
        .at(-1);
      expect(completed?.item).toMatchObject({
        type: "imageView",
        path: `/workspace/${threadId}.png`,

5. Root cause

Tool classification recognizes command and file-edit tools but leaves read as a generic tool with its original arguments. Tool completion uses extractResultText and the remembered start shape without classifying image-bearing successful results. The result becomes [image], while the known path remains inside generic tool arguments instead of the image-view contract.

const terminalShape =
  startedToolShapes.get(shapeKey) ??
  classifyPiToolResultFallback(piEvent.data.toolName);
startedToolShapes.delete(shapeKey);

The existing imageView shape already carries a path. The existing assembler supports changing the terminal shape while retaining the minted item ID. On a shape change it emits a generic completion followed by the promoted final completion, so the regression inspects the last completion, not the first. The timeline detail selector chooses the image body for image-view; The image body resolves the host path and provides the larger viewer. These renderer consequences are source deductions, not live UI observations.

6. Proposed fix

Within Pi completion translation only, promote a successful native read when its remembered read arguments contain a nonblank string path and its result contains at least one validated image block. Require nonempty image data and an image MIME type. Reuse the original path and existing imageView shape. Leave errors, text reads, unrelated tools, missing paths, malformed blocks, and closes without starts generic. Preserve the existing thread-scoped cache and provider item key; do not alter Codex, the UI, protocols, schemas, dependencies, or persisted data.

A local implementation satisfies this proposal: the focused sixteen cases pass; the complete provider checks pass (199 tests, one existing Bun-runtime skip); lint and typecheck succeed. Recorded Pi parity passes all four replayable cells; model-list is process-scoped and skipped.
