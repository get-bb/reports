#6391 · App shell leaves font smoothing implicit

BugPriority: LowEffort: Lowui · desktop · partial-reproGitHub issue2026-10-27

Base: 7125b90a6f7812e40d8e8509f53cecd301c84881

PARTIALLY REPRODUCED · Root-cause confidence: medium

1. TL;DR

The report concerns text that appears heavier or less clear in the macOS desktop app. On trusted main, the app's base body rule does not choose an explicit font-smoothing mode; a real production build also contains no smoothing declaration in its main stylesheet. Three embedded surfaces explicitly request antialiasing, so the application's styling policy is inconsistent. The same agent repeated this artifact-level finding in a second clean checkout. This Linux host has neither macOS/Retina hardware nor an available Chrome executable, so the reported visual degradation, browser default, and improvement from changing smoothing are not verified.

5. Root cause

The verified mechanism is an omitted shell-level rendering preference, not a demonstrated defect in a font file or Chromium. The application imports app.css from main.tsx, which imports theme.css. Its base body rule sets only background, foreground, and font family:

body {
  @apply bg-background text-foreground;
  font-family: var(--font-sans);
}

By contrast, Docs, Tasks, and inline visualization frames set -webkit-font-smoothing: antialiased. The compiled artifact confirms this omission survives the build. That discrepancy is a plausible contributor to the reported platform-specific difference, but determining causation requires native measurement and visual comparison. Confidence is high for the omission, medium for its relationship to the reported symptom.

6. Proposed fix and safety gate

Next experiment: on macOS desktop at the pinned trusted commit, compare the same text, font, size, colors, display scale, and zoom before and after a temporary shell-level smoothing preference. Record computed styles and real screenshots, and compare nested editor surfaces. If that isolates the effect and the visual policy is accepted, centralize the preference in the existing base stylesheet rather than adding per-component overrides.

No production fix or pull request: the macOS visual bug was not reproduced. Artifact inspection is not a focused regression test that fails before and passes after a behavioral fix; no such test was invented. The autopilot simple-fix gate therefore does not pass. No source branch was pushed.
