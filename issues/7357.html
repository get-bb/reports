#7357 · Packaged bridge smoke inherits caller configuration

BugMedium priorityLow effortdesktopsecurityGitHub issueNovember 10, 2026 · base 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro.

1. TL;DR

The packaging smoke test creates a temporary bridge data directory but does not give the bridge a temporary home or provider configuration environment. Consequently, the bridge workers retain the caller's home and provider configuration roots even though their working directory is temporary. In two clean source checkouts, the real built worker and the real Claude Code, Codex, and Pi plugin artifacts all initialized successfully while retaining synthetic caller configuration. An observation preload could read synthetic marker files outside the smoke-owned directory in all six launch cases per checkout. This establishes configuration exposure, not an observed provider write, credential disclosure, or data corruption.

5. Root cause

spawnPackedBridge, lines 633–646 creates only a plugin data directory. Its spawn options set cwd and stdio but omit env. Node therefore passes the caller's environment through unchanged. A temporary current working directory does not change HOME, USERPROFILE, or explicit provider configuration overrides.

const dataDir = join(tempRoot, "bridge-data", pluginId);
mkdirSync(dataDir, { recursive: true });
…
{ cwd: tempRoot, stdio: ["pipe", "pipe", "pipe"] }

The model-list smoke function calls this launcher. The real bootstrap receives only module path, plugin ID, and data directory; no provider home is derived from the data directory.

The provider-side conventions independently agree with the observed exposure: Claude configuration uses CLAUDE_CONFIG_DIR or homedir()/.claude; Codex home uses CODEX_HOME or .codex; Pi native roots use PI_CODING_AGENT_DIR or .pi/agent. The report proves the inherited context and readability with synthetic files; it does not claim these specific helpers run during initialize or that all are called by model/list.

6. Proposed fix and autopilot safety gate

Have the packaging smoke launcher own a fresh per-plugin home and explicit provider configuration roots, create them before spawn, and pass that environment to its workers. Cover both explicit parent overrides and absent overrides, and retain legitimate temporary/runtime process requirements. Audit any other provider-specific config-root inputs before claiming complete isolation. Environment redirection is not an OS filesystem sandbox and does not by itself sanitize every inherited credential.
