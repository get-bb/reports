#6141 · Initialization probes leave atomic-save files after interrupted flushes

BugPriority: LowEffort: Lowprovidersprovider-claude-codeconfirmed-reproIssue #61412026-10-22 · base 937cca40b740b76b75411f109273117039bf28c8

Verdict: REPRODUCED · Root-cause confidence: high for the interrupted-save leak and missing bb cleanup. The exact shutdown actor is not established.

1. TL;DR

Model and command discovery start a short-lived Claude Code process. The real lockfile-pinned CLI can leave a temporary global-config save behind when shutdown interrupts a slow flush. The normal-I/O control leaves no such file. Both a first run and a second clean checkout reproduced this through bb's actual initialization probe, actual SDK, and actual native CLI, without credentials, a real bb instance, or user configuration. bb currently closes the query without tracking or cleaning that child's unfinished atomic saves.

A local PID-scoped cleanup candidate makes four focused regressions pass, but it is not pushed: the existing provider suite has five failures, also reproduced without the fix. The automation's requirement that relevant existing tests pass therefore prevents a pull request.

Delay helper

Download the complete helper. It is compiled into the test's temporary directory, not installed globally.

#define _GNU_SOURCE
#include <dlfcn.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

static void record_event(const char *event) {
  const char *trace = getenv("BB_PROBE_TRACE");
  if (!trace) return;
  int output = open(trace, O_WRONLY | O_CREAT | O_APPEND, 0600);
  if (output < 0) return;
  dprintf(output, "%s pid=%d\n", event, getpid());
  close(output);
}

__attribute__((constructor)) static void started(void) {
  record_event("started");
}

int fsync(int descriptor) {
  static int (*original_fsync)(int);
  if (!original_fsync) original_fsync = dlsym(RTLD_NEXT, "fsync");
  const char *gate = getenv("BB_PROBE_DELAY_GATE");
  char descriptor_path[64];
  char target[4096];
  snprintf(descriptor_path, sizeof(descriptor_path), "/proc/self/fd/%d", descriptor);
  ssize_t length = readlink(descriptor_path, target, sizeof(target) - 1);
  if (length > 0) {
    target[length] = 0;
    if (gate && access(gate, F_OK) == 0 && strstr(target, ".claude.json.tmp.")) {
      record_event("delayed-fsync-enter");
      struct timespec delay = {.tv_sec = 12};
      while (nanosleep(&delay, &delay) < 0) {}
      record_event("delayed-fsync-return");
    }
  }
  return original_fsync(descriptor);
}

5. Root cause

plugins/provider-claude-code/src/bridge/initialization-probe.ts:20 starts a query with a message-free input stream and persistSession: false. On successful initialization or initialization failure, its finally block immediately aborts the input and calls session.close():

try {
  return await session.initializationResult();
} catch (error) {
  throw translateMissingClaudeCliCatalogError(error);
} finally {
  promptEnd.abort();
  session.close();
}

persistSession: false does not prevent the CLI from saving global configuration. In both experiments the native CLI opened a PID-tagged config temporary file; its fsync remained blocked when the process exited, leaving the pre-rename file on disk. The probe has neither the child PID nor a post-exit filesystem cleanup. The SDK's installed transport source also has a finite graceful-close path, so closing a query is not a guarantee that every filesystem write completes. We did not prove whether SDK escalation or a CLI-internal exit caused the observed interruption.

plugins/provider-claude-code/src/bridge/model-list.ts:5 and plugins/provider-claude-code/src/bridge/provider-commands.ts:130 both use this helper. plugins/provider-claude-code/src/bridge/bridge.ts:814 memoizes those calls for two minutes; memoization reduces frequency but does not remove the vulnerable lifecycle.

6. Proposed fix and safety gate

Track only the process created by this probe using the existing SDK spawn hook. After that child exits, best-effort remove only regular files matching its exact PID and the known 12-hex atomic-save suffix, from the effective config directory. Preserve the committed config, other PIDs, nonmatching suffixes, and non-file entries. Do not sweep the user's config directory broadly, or treat a slower/gentler close as a sufficient guarantee.
