#2825 · Claude Code Fable 5.1 metadata drift

Bug Medium Effort: Low providers provider-claude-code open on GitHub 2026-09-01 · base 026572964150eabdcbfc452369c42bacdc22463d

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The Claude Code provider keeps curated model data in several static lists. Those lists still identify the prior Fable version. A probe payload for the new version therefore produces an old curated entry and a second entry with the generic probe name. The context resolver also returns 200,000 tokens for both new native 1M identifiers. A focused test reproduced all four failures in two clean checkouts.

5. Root cause

The active catalog still declares the prior Fable identifier and display name in model-catalog-data.ts. The model builder first adds every active catalog entry. It then appends each discovered resolved identifier that does not match an active entry. See model-list.ts. A version change prevents de-duplication, so the generic discovered name remains visible beside the old curated name.

The context resolver recognizes 1M models through a suffix or an exact static set. The set contains only the prior Fable identifier and two aliases. See the context set and the resolver. The new resolved identifiers have no suffix, so the resolver uses its 200,000 default.

The two alias descriptions are separate static strings in model-list.ts. All visible failures come from model-version data repeated across these three locations.

6. Proposed fix

Update the active catalog to the current Fable identifier and display text. Retain the prior identifier and the entitlement-limited Mythos identifier in the selected-only catalog. Add both new identifiers to the 1M context set. Update the two alias descriptions. Add catalog, model-list, and context regression assertions.
