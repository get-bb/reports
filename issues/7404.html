#7404 · Host-managed routing drops settings-sourced model overrides

1. TL;DR

Account Pooler marks Claude Code sessions as host-managed to keep them away from the machine’s personal login. Claude Code also uses that marker to reject model-routing environment variables loaded from local settings. A credential-free local API fixture reproduced the effect with the repository-pinned Claude Code binary: a subagent inherited the parent model instead of the configured override. Moving the override into the process environment restored the selected subagent model. The rejected setting produced a debug-log warning but no warning in the CLI’s normal JSON output or stderr.

5. Root cause

Account Pooler’s provider-environment contribution always supplies CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1 while routing Claude. The adjacent rationale is prevention of personal-login refresh-token consumption. This is an authentication-isolation measure, not a model setting.

name: "CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST",
value: "1",
reason:
  "Claude Code otherwise refreshes this machine's own Claude login while routed, which can spend its single-use refresh token and sign it out",

The provider’s session-options builder preserves the supplied process environment; it does not promote project settings env into it. SDK startup asks Claude to load user, project, and local settings and passes that environment unchanged.

settingSources: ["user", "project", "local"],
persistSession: true,
env: this.options.env ?? process.env,
stderr: onStderr,

The isolated real-CLI experiment establishes the downstream policy: settings-sourced ANTHROPIC_MODEL and CLAUDE_CODE_SUBAGENT_MODEL are rejected when the marker is set; process-env equivalents are honored. The loss occurs in Claude’s settings application, not because BB rewrites the requested subagent model. The stderr callback only buffers text for errors; the observed ignored-setting warnings do not even reach that callback because they are debug-only.

Provider settings expose subagent and Workflow enable/disable switches, but no corresponding model-default replacement. The pool routing documentation explains the login-isolation flag, not this model-setting side effect.

6. Proposed fix and safety decision

Preserve the host-managed authentication marker. Choose and document a supported model-default configuration path with explicit precedence; alternatively surface an actionable ignored-settings notice. Any bridge from settings-file env into process env must be narrowly reviewed so it cannot promote provider/auth routing overrides across the host-managed boundary. A blanket settings-env merge or removal of the marker is not safe.

No automatic fix PR: the remedy requires a product decision about model configuration and precedence, and the tempting flag-removal shortcut changes an authentication boundary. These fail the autopilot simple-fix conditions even though the reproduction is conclusive. No fix branch, production change, or push to the target repository was made.
