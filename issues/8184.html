#8184 · Markdown parser work is repeated after component remount

BugPriority: MediumEffort: Lowui · perfGitHub issue2026-11-25 · base fb045a046653cc127656ca3c7243d44ae4c94f3f

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

Returning to an already-rendered message repeats Markdown parsing instead of reusing the earlier parse. A direct test mounted the real MarkdownPreview under the real message-slot registry provider, unmounted it, and mounted it again with unchanged source. The real remark parser ran once on each mount, even though the resulting HTML was identical. An unchanged rerender within the first mount did not increase the parser count. The same agent repeated this in a second clean trusted checkout and saw the same failure; this is not an independent-agent verification.

import type { Processor } from "unified";
import { afterEach, expect, it, vi } from "vitest";
import { MarkdownPreview } from "./markdown-preview";
import { MessageSlotRegistriesProvider } from "./message-markdown-slots";

const observed = vi.hoisted(() => ({ parserRuns: 0 }));

vi.mock("remark-gfm", async (importOriginal) => {
  const original = await importOriginal<typeof import("remark-gfm")>();
  return {
    ...original,
    default: function (
      this: Processor,
      ...options: Parameters<typeof original.default>
    ) {
      original.default.apply(this, options);
      const parser = this.parser;
      if (parser === undefined) {
        throw new Error("Expected the real remark parser to be installed");
      }
      this.parser = (...parameters) => {
        observed.parserRuns += 1;
        return parser(...parameters);
      };
    },
  };
});

afterEach(cleanup);

it("does not parse unchanged message text again after a timeline-style remount", () => {
  const content = [
    "# Lifecycle probe 8184",
    "A **complete** response with unchanged source.",
    "- Read the input\n- Render the result",
    "| Phase | State |\n| --- | --- |\n| First | Ready |",
  ].join("\n\n");
  const preview = (
    <MessageSlotRegistriesProvider>
      <MarkdownPreview
        content={content}
        incrementalBlocks
        tableLayout="contained"
      />
    </MessageSlotRegistriesProvider>
  );
  const first = render(preview);
  expect(first.container.querySelector("strong")?.textContent).toBe("complete");
  expect(first.container.querySelector("table")).not.toBeNull();
  const firstHtml = first.container.innerHTML;
  const firstRuns = observed.parserRuns;
  expect(firstRuns).toBe(1);
  first.rerender(preview);
  expect(observed.parserRuns).toBe(firstRuns);
  first.unmount();
  const second = render(preview);
  expect(second.container.innerHTML).toBe(firstHtml);
  console.log(
    JSON.stringify({
      firstMountParses: firstRuns,
      afterRemountParses: observed.parserRuns,
      identicalHtml: true,
    }),
  );
  expect(observed.parserRuns).toBe(firstRuns);
});

5. Root cause

MarkdownPreview owns its piece cache in component state; remounting discards it and runs the real remark parser again for identical source. The cold resolver has no retained entries and calls parseMarkdownPiece over the complete body. That function immediately invokes ReactMarkdown and its synchronous parser pipeline. Same-mount reuse exists, but there is no cache with a lifetime spanning remounts.

A broader reusable cache must also account for parser syntax and configuration. The remark plugin list is component-local, and the directive registry is memoized within the provider. These are secondary cache-key/lifetime considerations, not a replacement explanation for the discarded piece cache.

6. Proposed fix

Retain a bounded cache of parser-stage trees keyed by exact source and all syntax-affecting options beyond individual component mounts. Clone cached trees before mutable transform plugins run. Leave mount-specific link routing, components, directive mounting, and later transformations outside this reusable cache. Stabilize equivalent parser configuration identities, and test syntax changes and eviction in addition to this remount regression. Avoid retaining every streaming prefix. No production fix was attempted because an open pull request already links this issue.
