#7547 · Provider badge disappears with a server-only directory

BugPriority: LowEffort: Lowuiprovider-acpIssue · November 14, 2026

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high

1. TL;DR

The sidebar component renders no provider badge when its directory omits the thread’s provider, even when the thread carries a remote host and environment. A fresh two-case component test demonstrates this on unchanged production code, and the same agent repeated it in a second clean checkout at the same trusted commit. The directory supplied by the real sidebar comes from an unscoped provider-list hook; server discovery without a scope uses the primary host, not each thread’s environment. Existing server integration tests separately confirm host-dependent discovery. A real enrolled remote machine and a desktop/browser end-to-end reproduction were not exercised, so the verdict intentionally remains partial.

5. Root cause

  1. ProjectList:1316 reads experimental_useProviders() once and passes its directory to rows through context at lines 1837–1839.
  2. useProviders:291 calls useSystemProviders() with no lookup scope.
  3. systemProvidersQueryOptions:234 calls the SDK with environmentId or hostId only when explicitly supplied; otherwise it makes an unscoped list request.
  4. resolveSystemLookupHostId:14 maps an unscoped request to requireConnectedPrimaryHostId. Provider discovery:272 computes installed provider visibility for that one selected host.
  5. ThreadRow:355 looks up only thread.providerId in the supplied context directory. It does not use the thread’s environment or host to repair a miss.
  6. ThreadRow:630 gates the entire tooltip, accessible wrapper and ProviderIcon behind a successful lookup. Missing metadata therefore removes the whole icon region rather than selecting a fallback artwork.

Contrast: Thread detail:623 supplies the actual thread environment when resolving provider information. This explains why opening a thread and rendering its sidebar row can disagree.

Existing integration owner: provider routing contract test. Its synthetic hosts intentionally expose different installed-only providers and prove that explicit environment scoping changes the returned directory.

6. Proposed fix and autopilot decision

Resolve sidebar provider metadata for the thread’s environment or host, with shared/deduplicated requests and correct offline behavior, rather than treating the primary-host directory as a universal catalog. Preserve the existing provider-list picker contract; changing a public SDK hook to return a cross-machine union should be a deliberate API decision, not an incidental cosmetic patch. The browser SDK already supports scoped provider listing; the remaining work is the sidebar’s lookup/caching path and its integration test.
