#7399 · Outline reuse gaps on busy threads

Bug Priority: Medium Effort: Medium threads perf partial-repro

GitHub issue · 2026-11-10 · Base f241192234ed3ca14d121c36f37e43b7447951ec

PARTIALLY REPRODUCED · Root-cause confidence: high for the two measured replay paths

1. TL;DR

Some busy-thread changes still cause full outline history replay on trusted main. Changing only the supplied thread status from active to idle reselected all 3,000 synthetic event rows, versus three rows on a warm active load. Appending one manager message to a thread containing only manager messages reselected all 1,001 rows. However, the broad claim that there is no incremental builder is false on this base: appending a completed turn to 1,000 completed turns selected only six rows. These database-only reproductions establish avoidable synchronous work, not the reported production latency distribution, multi-megabyte payloads, or browser skeleton duration.

Complete reproduction test (copy into the path above)
import { performance } from "node:perf_hooks";
import { describe, expect, it } from "vitest";
import {
  getLatestStoredConversationOutlineSequence,
  getLatestThreadSequence,
} from "@bb/db";
import { loadThreadConversationOutline } from "../../../src/services/threads/timeline.js";
import {
  appendRows,
  withTestThread,
  type RowSpec,
  type TestThread,
} from "../../helpers/timeline-cache-fixture.js";

function measure(testThread: TestThread, label: string) {
  const raw = testThread.db.$client;
  const originalPrepare = raw.prepare;
  let selectedRows = 0;
  raw.prepare = function (source: string) {
    const statement = originalPrepare.call(raw, source);
    if (source.includes('from "events"') && source.includes('"created_at"')) {
      const originalAll = statement.all.bind(statement);
      statement.all = function (...params: unknown[]) {
        const rows = originalAll(...params);
        selectedRows += rows.length;
        return rows;
      };
    }
    return statement;
  };
  const started = performance.now();
  try {
    const threadId = testThread.thread.id;
    const result = loadThreadConversationOutline(testThread.db, testThread.thread, {
      completedTurnDisplay: "collapse",
      includeClearedContextHistory: false,
      maxSeq: getLatestThreadSequence(testThread.db, { threadId }),
      outlineSequence: getLatestStoredConversationOutlineSequence(testThread.db, {
        threadId,
      }),
    });
    const observation = {
      label,
      selectedRows,
      items: result.items.length,
      bytes: Buffer.byteLength(JSON.stringify(result.items)),
      elapsedMs: Math.round(performance.now() - started),
    };
    console.log(JSON.stringify(observation));
    return observation;
  } finally {
    raw.prepare = originalPrepare;
  }
}

function turn(index: number): RowSpec[] {
  const turnId = `repro-turn-${index}`;
  return [
    { type: "turn/started", turnId },
    {
      type: "item/completed",
      turnId,
      itemId: `repro-message-${index}`,
      itemKind: "agentMessage",
      data: {
        item: {
          id: `repro-message-${index}`,
          type: "agentMessage",
          text: "Synthetic completed response. ".repeat(10),
        },
      },
    },
    { type: "turn/completed", turnId, data: { status: "completed" } },
  ];
}

describe("outline reuse across busy-thread changes", () => {
  it("appends to completed history without replaying the prefix", () => {
    withTestThread((testThread) => {
      appendRows(testThread, Array.from({ length: 1000 }, (_, index) => turn(index)).flat());
      measure(testThread, "completed-cold");
      appendRows(testThread, turn(1000));
      expect(measure(testThread, "completed-append").selectedRows).toBeLessThan(25);
    });
  });

  it("retains completed history across a status-only transition", () => {
    withTestThread((testThread) => {
      appendRows(testThread, Array.from({ length: 1000 }, (_, index) => turn(index)).flat());
      measure(testThread, "status-cold-active");
      measure(testThread, "status-warm-active");
      testThread.thread = { ...testThread.thread, status: "idle" };
      expect(measure(testThread, "status-idle").selectedRows).toBeLessThan(25);
    });
  });

  it("does not replay notification-only history after an append", () => {
    withTestThread((testThread) => {
      const notification: RowSpec = {
        type: "system/manager/user_message",
        data: { text: "Synthetic manager update. ".repeat(10) },
      };
      appendRows(testThread, Array.from({ length: 1000 }, () => notification));
      measure(testThread, "notifications-cold");
      appendRows(testThread, [notification]);
      expect(measure(testThread, "notifications-append").selectedRows).toBeLessThan(25);
    });
  });
});

5. Root cause

Status invalidates both cache layers

The key builder includes both outline sequence and thread status. A stored miss calls the incremental projection with the same key builder, passing zero for sequence. Sequence advances therefore do not inherently invalidate that inner checkpoint, but a status change does. The reuse check requires equal keys and otherwise starts from the empty checkpoint:

entry.key === args.key
...
let checkpoint = canReuseEntry && ... ? entry.checkpoint : empty;

This explains the warm three-row load followed by a full 3,000-row load when only status changes. The work runs inside runEventLoopWorkSync, so synchronous history selection, decoding and projection delay other work in that process.

Turn-free history never advances the checkpoint

Checkpoint construction advances its boundary through turn-start/completion bookkeeping. Thread-scope manager messages skip this logic:

if (event.scope.kind !== "turn") continue;
...
if (boundary <= previous.sequenceStart) return previous;

A manager-only fixture never creates a nonempty reusable checkpoint. A new message changes the route and stored projection keys, so the next service load selects the entire history again. This is a particularly clear instance of a broader concern: turn-boundary checkpoints cannot bound an indefinitely growing turn-free tail. The experiment does not prove that every mixed coordinator history has the same behavior.

Important qualifications

The HTTP route's response cache returns a matching response before calling this service; unchanged active opens do not necessarily rebuild. Idle/error-only materialization is real, but not equivalent to the absence of active-thread caching. The existing incremental implementation also predates this report: incremental outlines landed October 2, 2026, and a further projection improvement landed November 9, 2026.

6. Proposed fix and simple-fix assessment

Preserve a status-independent, demonstrably settled prefix while rebuilding the status-dependent tail; define safe checkpoints for thread-scope messages between turns. Validate prefix reuse against full projection through active/idle/error transitions, pending requests, late child events, rewinds and context clears. Persisting a resumable projection across restarts is a separate concern: the current stored JSON is an exact response, not the incremental builder's checkpoint state.

No pull request opened. Simply removing status from the key is not a proven-safe repair: status controls pending-message preservation and projection finalization. Correctly splitting stable and mutable history requires checkpoint-design work, not a safe key deletion. Pagination changes the public response contract; adding resumable stored checkpoint state changes stored data. Neither is eligible for the authorized simple-fix path. No production edits, branch push or PR were attempted. No linked open PR was found in issue cross-references or the open-PR search at investigation time.
