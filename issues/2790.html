#2790 · Claude resume transcript integrity

Bug High Effort: Medium providers threads provider-claude-code open on GitHub 2026-09-01 · base 688eb4251c5b5c53c5a56f85baae6d47966355ec

Verdict: NOT REPRODUCED · Root-cause confidence: low

1. TL;DR

The report says that a resumed Claude turn can omit an earlier tool result. I tested the closest complete case from repository evidence. The test ended a persisted transcript on a tool result. It then resumed the session through the bundled Claude binary. The next model request contained the exact tool output in two clean runs. The issue does not include the exact transcript state, so this result does not refute every possible resume case.

5. Root cause

No causal defect was identified. The trusted bridge calls SdkSession.start() with the requested provider thread identifier. See bridge.ts lines 2031–2057.

SdkSession enables transcript persistence and passes the same identifier as the SDK resume option. See sdk-session.ts lines 244–264.

The tested dependency is Claude Agent SDK 0.3.245. See package.json lines 34–38.

The issue lacks the exact provider transcript. A different parent chain, compact entry, subagent entry, or concurrent append could still select another resume path. Repository evidence cannot identify which path caused the reported result.

6. Proposed fix

No code fix is safe from the available evidence. The next test must use a redacted form of the exact failing provider transcript. It must preserve entry order, UUID links, compact entries, and parent tool identifiers. The same local mock endpoint can then show which entry disappears.
