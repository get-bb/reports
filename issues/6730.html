1. TL;DR

A report describes Computer Use continuing after Codex work should have ended, but does not identify a failing turn or the termination action. This investigation cannot reproduce the native symptom on its Linux host. Two fresh checkouts of trusted main each pass 45 existing lifecycle checks and 47 checks after adding two narrowly scoped Computer Use cancellation probes. The probes exercise bb's real bridge against its trusted fake app-server child, not a native Computer Use session. These passing results do not rule out a macOS-specific or upstream Codex problem, and do not justify a speculative cleanup patch.

5. Root cause and source evidence

Not established. Trusted bridge cancellation, interrupt/release, and child shutdown checks pass; the native macOS Computer Use session was not available to observe. The following mechanisms explain the healthy test results; none establishes the cause of the reported native symptom.

Pending elicitation cancellation is translated explicitly

The shared result builder returns the native cancellation response when an MCP interaction rejects. The added cases exercise this with the repository's Computer Use fixture through the actual bridge request path.

plugins/provider-codex/src/interactive-requests.ts:343

export function buildCodexInteractiveResult(
  payload: DecodedInteractiveRequest["payload"],
  runtimeResult: PromiseSettledResult<unknown>,
): CodexInteractiveResponse {
  if (
    payload.kind === CODEX_MCP_ELICITATION_KIND &&
    (runtimeResult.status === "rejected" ||
      !requestAnswerResolutionSchema.safeParse(runtimeResult.value).success)
  ) {
    return CODEX_MCP_ELICITATION_CANCEL_RESPONSE;
  }
  if (runtimeResult.status === "rejected") {
    throw runtimeResult.reason;
  }
  return buildCodexInteractiveResponse(
    providerInteractionOutcomeSchema.parse({
      payload,
      resolution: runtimeResult.value,
    }),
  );
}

Normal turn settlement is not synonymous with killing a provider process

A turn boundary removes the open-turn ID and resolves settlement waiters. This path does not itself release the session. The existence of an idle app-server process therefore does not demonstrate continued native control.

Explicit Stop and release have cleanup paths

The release intent awaits session release. A valid interrupt requests the native turn interrupt, waits for settlement (or emits a bounded fallback), clears exited-child translation state and then awaits release. Error and missing-active-turn branches differ, so a failing trace must identify which branch ran before a fix can be designed.

plugins/provider-codex/src/bridge/bridge.ts:2196

async function handleThreadStop(
  id: string | number,
  params: ThreadStopParamsShape,
): Promise<void> {
  const session = sessionsByBbThreadId.get(params.threadId);

  if (params.intent === "release") {
    if (session) {
      await releaseSession(session);
    }
    sendResult(id, { ok: true });
    return;
  }

  if (
    !session ||
    session.closing ||
    session.connection === null ||
    session.connection.exited ||
    session.codexThreadId === null ||
    params.activeTurnId === null
  ) {
    sendResult(id, { ok: true });
    return;
  }

  if (session.goalStatus === "active") {
    await pauseActiveGoalForInterrupt(session, session.codexThreadId);
  }
  const interruptFailure = await interruptCodexTurn(
    session,
    session.codexThreadId,
    params.activeTurnId,
  );
  if (interruptFailure !== null) {
    sendError(
      id,
      BRIDGE_JSON_RPC_ERRORS.BRIDGE_ERROR,
      interruptFailure.message,
    );
    return;
  }
  const settled = await waitForCodexTurnSettlement(
    session,
    params.activeTurnId,
    INTERRUPT_SETTLEMENT_TIMEOUT_MS,
  );
  if (!settled) {
    sendThreadDeltas(session, [
      {
        kind: "turn.boundary",
        providerTurnId: params.activeTurnId,
        status: "interrupted",
      },
    ]);
  }
  sendThreadDeltas(
    session,
    session.translator.clearExitedChildThreadState({
      providerThreadId: session.codexThreadId,
    }),
  );
  await releaseSession(session);
  sendResult(id, { ok: true });
}

Session release delegates to the child connection's asynchronous kill path and waits for the exit promise:

plugins/provider-codex/src/bridge/bridge.ts:522

function releaseSession(session: CodexBridgeSession): Promise<void> {
  if (session.releasePromise !== null) {
    return session.releasePromise;
  }
  session.closing = true;
  if (sessionsByBbThreadId.get(session.bbThreadId) === session) {
    sessionsByBbThreadId.delete(session.bbThreadId);
  }
  const previousChildExit = session.previousChildExit;
  session.previousChildExit = null;
  const currentChildExit = session.connection?.kill() ?? Promise.resolve();
  session.connection = null;
  const releasePromise =
    previousChildExit === null
      ? currentChildExit
      : Promise.all([previousChildExit, currentChildExit]).then(
          () => undefined,
        );
  session.releasePromise = releasePromise;
  return releasePromise;
}

Child shutdown offers cleanup, then escalates

The app-server transport closes stdin, offers SIGTERM after one second and escalates to SIGKILL after four seconds when necessary. Existing tests supervise real Node children and verify graceful cleanup, SIGTERM cleanup and forced termination. This is not a test of a native cua_repl descendant or operating-system ownership.

plugins/provider-codex/src/bridge/app-server-connection.ts:168

      if (!finalized && exitStatus === null) {

    termination.unref?.();
    const escalation = setTimeout(() => {

        experimental_killPortableProcess(child, "SIGKILL");
      }
    }, KILL_ESCALATION_MS);
    escalation.unref?.();
    child.stdin?.end();
    return exitPromise;

6. Proposed fix / next experiment

No production fix is justified yet. On an isolated macOS host, capture a failing provider thread/turn, exact termination action, native cua_repl activity and control ownership before and after normal completion, Stop, and archive separately. Correlate the native interrupt/completion replies and app-server exit; distinguish a live Computer Use session from reusable idle processes before changing cleanup.

For each action, record timestamp, OS/app/CLI build, provider thread and turn IDs, cancellation/interrupt replies, pending interaction state and the exact remaining native controller or UI. A process inventory without attribution is not sufficient. Do not terminate unrelated processes as a diagnostic shortcut.
