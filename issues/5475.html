#5475 · Mention candidate freshness and coverage

BugMedium priorityMedium effortuiGitHub issue

2026-10-14 · trusted origin/main a7d5dfcc8c27df1fea42847526ee62a338fe8052

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The mention hook omits matching threads after the first 200 sidebar candidates, keeps server-side title and project changes invisible when no realtime update reaches its cache, and returns files for the previous query while a new query is pending. Five newly authored regression cases fail on unchanged trusted main in two clean checkouts. The existing two composer-hook cases pass in both runs. The path problem persists beyond the debounce into the replacement HTTP request because query placeholder data retains earlier results.

import type { SidebarBootstrapResponse } from "@bb/server-contract";
import { makeThreadListEntry } from "@bb/test-helpers/domain-fixtures";
import { createQueryClientTestHarness } from "@/test/queryClientTestHarness";
import {
  makeProjectWithThreadsResponse,
  makeSidebarBootstrapResponse,
} from "@/test/fixtures/projects";
import { makeSystemConfig } from "@/test/fixtures/system-config";
import { sdk } from "@/lib/sdk";
import { resetSidebarBootstrapCacheForTest } from "@/lib/sidebar-bootstrap-cache";
import { sidebarNavigationQueryKey } from "./queries/query-keys";
import { usePromptMentions } from "./usePromptMentions";

const queryClients: ReturnType<
  typeof createQueryClientTestHarness
>["queryClient"][] = [];

afterEach(() => {
  cleanup();
  for (const queryClient of queryClients.splice(0)) queryClient.clear();
  vi.unstubAllGlobals();
  vi.restoreAllMocks();
  resetSidebarBootstrapCacheForTest();
  window.localStorage.clear();

function navigation(count = 1): SidebarBootstrapResponse {
  return makeSidebarBootstrapResponse({
    projects: [
      makeProjectWithThreadsResponse({
        id: "proj_picker",
        name: "Picker project",
        threads: Array.from({ length: count }, (_, index) =>
          makeThreadListEntry({
            id: `thr_picker_${index}`,
            projectId: "proj_picker",
            title: `Catalog entry ${index}`,
            titleFallback: null,
            createdAt: index + 1,
            updatedAt: index + 1,
          }),
        ),
      }),
    ],
  });
}

function setup(initial: SidebarBootstrapResponse) {
  let serverNavigation = initial;
  const pathQueries: string[] = [];
  vi.spyOn(sdk.system, "config").mockResolvedValue(makeSystemConfig());
  vi.stubGlobal(
    "fetch",
    vi.fn(async (input: RequestInfo | URL) => {
      const url = new URL(
        input instanceof Request ? input.url : input.toString(),
        "http://localhost",
      );
      let body: unknown;
      if (url.pathname === "/api/v1/sidebar-bootstrap") {
        body = serverNavigation;
      } else if (url.pathname === "/api/v1/plugins/contributions") {
        body = { threadActions: [], mentionProviders: [] };
      } else if (url.pathname === "/api/v1/projects/proj_picker/paths") {
        const query = url.searchParams.get("query") ?? "";
        pathQueries.push(query);
        if (query === "Catalog entry") return new Promise<Response>(() => {});
        body = {
          paths:
            query === "cedar"
              ? [
                  {
                    kind: "file",
                    path: "notes/cedar.md",
                    name: "cedar.md",
                    score: 100,
                    positions: [],
                  },
                ]
              : [],
        };
      } else if (url.pathname === "/api/v1/threads") {
        body = serverNavigation.projects.flatMap((project) => project.threads);
      } else {
        throw new Error(`Unexpected request: ${url.pathname}`);
      }
      return new Response(JSON.stringify(body), {
        headers: { "content-type": "application/json" },
      });
    }),
  );
  const { queryClient, wrapper } = createQueryClientTestHarness();
  queryClients.push(queryClient);
  queryClient.setQueryData(sidebarNavigationQueryKey(), initial);
  const hook = renderHook(
    () =>
      usePromptMentions("proj_picker", {
        environmentId: null,
      }),
    { wrapper },
  );
  return {
    ...hook,
    pathQueries,
    updateServer(next: SidebarBootstrapResponse) {
      serverNavigation = next;
    },
    search(query: string | null) {
      act(() => hook.result.current.setQuery(query, "@"));
    },
  };
}

  initial: SidebarBootstrapResponse,

      ...project,
      threads: project.threads.map((thread) => ({
        ...thread,
        title: "Revised checklist",
      })),

  };

  const initial = navigation();
  const picker = setup(initial);

  await waitFor(() =>

it.each(["debounce", "request"])(

5. Root cause

Candidate coverage is capped before matching

Candidate selection slices deduplicated sidebar candidates to 200 before the mention matcher sees the query. The later exact match cannot recover a thread that has already been excluded.

return Array.from(candidatesById.values()).slice(0, limit);

Freshness depends entirely on cache patch delivery

Sidebar candidates override the list fetch disables the fallback fetch as soon as sidebar candidates exist. The shared sidebar query uses the Infinity-staleness policy. Re-enabling the mention hook does not fetch a new baseline. This is a recovery gap when an event does not reach the cache, not proof that normal realtime updates fail.

Path source publishes data without checking query ownership

Debounced input state identifies pending input, but The path result assembly does not gate on that state. The project path query retains previous data as placeholder data. Thus hiding paths only during the debounce would still let old rows return once the new request starts. The mention adapter forwards those rows unchanged. Loading aggregation can hide pending source work when any other row exists.

6. Proposed fix and checked repair

A contained client-hooks patch makes the mention observer request a fresh sidebar baseline when re-enabled, without changing the default sidebar cache policy. It removes the pre-match cap from the complete sidebar candidate set while retaining existing hidden/archive filtering and the final display limit. At the path source boundary it suppresses rows during debounce and excludes per-source placeholder data during replacement requests.

The existing sidebar endpoint assembles all active project threads; no new endpoint or protocol is needed. The startup-only list fallback remains capped at 200; once the complete bootstrap arrives it is superseded. This repair does not introduce server-side mention search, change ranking policy, or promise freshness during an event loss while the same picker stays open.
