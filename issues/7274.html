#7274 · Unicode query casing changes path recall

2026-11-09 · Bug · Priority: Medium · Effort: Low · Area: ui
Trusted base: 55135d1e5045d6c5d3c24f5a4d5556ed3e11cb00

REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. Summary

The path matcher used by workspace mentions loses lowercase Cyrillic filenames when the query contains an uppercase Cyrillic letter. A synthetic candidate, notes/drafts/журнал.md, is found for журнал, but not for Журнал, жУрнал, or ЖУРНАЛ. This happens in plain queries, exact directory-prefix queries, and structured directory queries. Two separately installed clean checkouts reproduce the same five failing assertions with six passing controls.

The mechanism is the path matcher's explicit smart-case policy, not an indexing or filesystem failure. ASCII uppercase exhibits the same exclusion. Generic text matching is explicitly case-insensitive and does retain the same Cyrillic candidate. Choosing to remove path smart-case altogether or to change its Unicode trigger is a product-policy decision; this report does not silently make that choice.

5. Root cause

  1. The host's listed-path ranking adapter delegates to fuzzyMatchPaths.
  2. Plain path ranking explicitly requests casing: "smart-case". An uppercase Cyrillic query switches the installed fzf dependency to case-sensitive matching, so it cannot match the lowercase synthetic candidate.
  3. The same option is used for structured segments and exact-directory-prefix tails. Changing only plain matching would leave inconsistent recall or ranking between query forms.
  4. The repository's own comparison helper likewise preserves case whenever query !== query.toLowerCase(). This is not solely dependency behavior.
  5. Candidate prefiltering returns no ASCII needle for a Cyrillic query; candidate collection therefore keeps the supplied item. It is subsequently rejected during ranking.
  6. Text ranking explicitly uses case-insensitive, explaining the passing text control. The fzf implementation is an npm dependency declared by this package, not a vendored matcher implementation in the host file.

6. Fix proposal and automatic-fix safety

First choose whether path search should be case-insensitive for every query or retain ASCII smart-case while treating non-ASCII uppercase differently. Both address the demonstrated recall problem, but they are different user-visible policies. The latter must explicitly define mixed-script queries. Then apply the chosen policy consistently to plain matching, structured segments, exact-prefix tails, and path comparison/ranking helpers. Extend the regression table to cover uppercase directory names, reverse case direction, and mixed-script queries.

No automatic pull request: the verified behavior is the existing explicit smart-case policy, including ASCII. Selecting a replacement requires a product-policy decision, which fails the rule's no-product-decision simple-fix condition. No production patch was applied, committed, or pushed. 9. Complete reproduction test

The complete test follows. Raw run logs remain outside the public repository; exact failure output and counts are included above.

import { describe, expect, it } from "vitest";
import { fuzzyMatchPaths, fuzzyMatchText } from "../src/index.js";

describe("issue 7274: path query case recall", () => {
  const path = "notes/drafts/журнал.md";

  it.each([
    "журнал",
    "Журнал",
    "жУрнал",
    "ЖУРНАЛ",
    "notes/drafts/журнал",
    "notes/drafts/Журнал",
    "drafts/журнал",
    "drafts/Журнал",
  ])("retains the lowercase path for %s", (query) => {
    expect(
      fuzzyMatchPaths({
        items: [path],
        query,
        getPath: (item) => item,
        limit: 16,
      }).map((match) => match.item),
    ).toEqual([path]);
  });

  it("keeps a lowercase ASCII control discoverable", () => {
    expect(
      fuzzyMatchPaths({
        items: ["notes/journal.md"],
        query: "journal",
        getPath: (item) => item,
        limit: 16,
      }).map((match) => match.item),
    ).toEqual(["notes/journal.md"]);
  });

  it("also excludes lowercase ASCII paths for uppercase queries", () => {
    expect(
      fuzzyMatchPaths({
        items: ["notes/journal.md"],
        query: "Journal",
        getPath: (item) => item,
        limit: 16,
      }),
    ).toEqual([]);
  });

  it("retains the same Cyrillic candidate through text matching", () => {
    expect(
      fuzzyMatchText({
        items: [path],
        query: "Журнал",
        getText: (item) => item,
        limit: 16,
      }).map((match) => match.item),
    ).toEqual([path]);
  });
});
