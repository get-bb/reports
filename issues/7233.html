#7233 · Runtime glyph animation and main-thread rendering

Bug · Priority: Medium · Effort: Low · ui, perf · November 7, 2026

Trusted origin/main base: e61446e15a0bb3e6df551e45c3aba5c5187ffad3

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium · Reproduction label: partial-repro

1. TL;DR

The runtime status glyph really does apply its spinning transform to the SVG itself. Rendering three actual ThreadStatusGlyph components from trusted main produced repeated main-thread style, prepaint, and layerization work; pausing their animations removed nearly all of that work. A second clean checkout produced the same result. However, this automation browser has GPU compositing disabled, and rotating an HTML container did not eliminate that work either. This supports the animation-work portion of the report, but cannot establish the SVG-specific hardware-compositor limitation, the reported high-refresh CPU costs, or the proposed fix.

3. Environment and isolation

  • Two fresh detached worktrees of the same trusted base, referred to as $WORK/base-one and $WORK/base-two. Neither tracked production source tree was modified.
  • Build environment: Linux x86-64, kernel 4.19.0-gvisor; Node 22.19.0; pnpm 9.15.0.
  • Browser Automation plugin: isolated local headless Chrome 149.0.0.0 on Linux x86-64 with a fresh plugin-owned profile. Reduced motion was false.
  • Browser GPU: ANGLE / SwiftShader; GPU compositing and rasterization disabled_software. LayerTree returned no composited layers.
  • Each checkout generated its own self-contained local HTML file, transferred explicitly to the browser machine. No application server, host daemon, provider, account, user database, or real thread was used. No product data directory was needed. An initial Vite server used port 47331, but the browser could not reach the container loopback; all measurements instead used isolated local file URLs, with no network service port.
  • The plugin's live preview remained attached for all variants. About five rendering updates per second were observed, not physical-display vsync. Do not extrapolate these timings to a normal visible desktop browser.

requestAnimationFrame(() => {
  requestAnimationFrame(() => {
    const animations = document.getAnimations();
    if (mode === "paused") {
      for (const animation of animations) animation.pause();
    }
    if (mode === "html-control") {
      for (const animation of animations) {
        if (!(animation.effect instanceof KeyframeEffect)) continue;
        const target = animation.effect.target;
        if (!(target instanceof SVGElement)) continue;
        const parent = target.parentElement;
        if (!parent) throw new Error("Missing glyph container");

measure.js

const page = await browser.getPage("main");
const protocol = await page.createCDPSession();
const fixture = page.url().split("?")[0];
await protocol.send("Performance.enable");
const results = [];
for (const mode of ["paused", "original", "html-control", "original"]) {
  await page.goto(fixture + "?mode=" + mode);
  await page.waitForSelector("html[data-ready=true]");
  await new Promise(resolve => setTimeout(resolve, 1000));
  const before = (await protocol.send("Performance.getMetrics")).metrics;
  await page.tracing.start({ categories: ["devtools.timeline", "disabled-by-default-devtools.timeline", "blink.animations"] });
  await new Promise(resolve => setTimeout(resolve, 4000));
  const trace = JSON.parse(Buffer.from(await page.tracing.stop()).toString("utf8"));
  const after = (await protocol.send("Performance.getMetrics")).metrics;
  const events = {};
  for (const event of trace.traceEvents) {
    if (!["UpdateLayoutTree", "PrePaint", "Layerize", "Paint", "Commit", "Layout"].includes(event.name)) continue;
    const entry = events[event.name] ??= { count: 0, milliseconds: 0 };
    entry.count += 1;
    entry.milliseconds += (event.dur ?? 0) / 1000;
  }
  const metrics = {};
  for (const name of ["TaskDuration", "RecalcStyleCount", "RecalcStyleDuration", "LayoutCount"]) {
    metrics[name] = after.find(metric => metric.name === name).value - before.find(metric => metric.name === name).value;
  }
  results.push({ mode, seconds: 4, events, metrics });
}
await protocol.detach();
console.log(JSON.stringify(results));

6. Root cause and source evidence

ThreadStatusGlyph.tsx:167–178 selects the core Loading icon and puts animate-spin motion-reduce:animate-none on that icon. icon.tsx:385–403 passes that className directly to HugeiconsIcon. The resulting real browser DOM confirms that the animation target is SVG, not an HTML rotation container.

case "runtime":
  return (
    <Icon
      name="Loading"
      className={cn(
        "animate-spin motion-reduce:animate-none",
        SIDEBAR_WORKING_STATUS_COLOR_CLASS,
        iconSizeClass,
      )}
      aria-label={threadIndicatorLabel(indicator) ?? undefined}
    />
  );

The direct observation is that keeping this transform animation active drives repeated style/prepaint/layerization work in the tested software-rendering configuration. Pausing changes neither source markup nor application state and removes that work. This establishes animation causality in the probe, not an SVG-specific compositor failure. Because even the HTML control cannot use GPU compositing here, the deeper browser limitation remains unverified; claiming otherwise would overstate the evidence.

7. Verification in the second clean checkout

The same agent repeated the reproduction; this is not an independent-agent check. A second fresh detached worktree was created at the recorded full base commit. Frozen install and both scoped Turbo builds succeeded again. The same three author-written probe files were copied into that checkout, rebuilt there, and inlined into a separate HTML file; both generated files had identical SHA-256 digests. Tracked git diff --exit-code remained clean. The second page used its own local HTML path and no shared product data or port.

The exact build and measurement commands above were repeated for base-two and issue-7233-two.html. Running the same measurement script produced the second table and structured output. Both original samples again had 20 style/prepaint/layerization events; the paused control had no prepaint/layerization; the HTML control again had 20. The final report therefore retains the partial verdict and explicitly excludes a validated wrapper fix.

8. Proposed next experiment and safe-fix decision

Repeat this A/B experiment on a GPU-composited, visible browser and record SystemInfo/LayerTree alongside the trace. If only the SVG variant has recurring main-thread rendering, move rotation to a properly sized HTML container in the runtime glyph, keeping the SVG static, its accessible label, and the reduced-motion override. Then add a focused regression at the rendering boundary that fails before and passes after the change and run the existing glyph tests.

No pull request is opened. No open pull request linked to #7233 was found in the issue timeline or the open-PR number search. The proposed optimization does not improve the measured rendering-event regression in this GPU-disabled environment, so a focused pre-fix-fail/post-fix-pass proof is unavailable. A DOM-class assertion alone would not prove compositor behavior. The simple-fix gate therefore fails before any production patch, branch, commit, or push.
