#7342 · ACP translation drops nested output ownership

BugPriority: MediumEffort: Mediumprovidersprovider-acp GitHub issue2026-11-10 · base 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

Nested ACP updates lose their owning tool-call identity during translation. A deterministic test feeds interleaved main and nested output through the real ACP translator and real delta assembler: the resulting main messages contain child text, and the child command has no parent. Opening the child command also splits the main message. The assembler already supports parent-aware streams; the ACP translator omits the existing ownership key. This report reproduces the event/data defect, not a screenshot or a live authenticated Claude session.

5. Root cause

The inbound session-update schemas retain unknown metadata, but the translator never uses the nested owner when constructing delta keys. The following links target the immutable base, not a moving branch:

  • Inbound text/tool schemas retain extra fields.
  • Assistant and thought updates use only channel keys.
  • Every tool opening closes the root streams and opens without a parent.
  • Tool updates, output snapshots, and progress also omit ownership.
  • Assembler stream identity includes parentRef and Parent references resolve to public item IDs.

Without a parent-aware key, main and child text address the same stream. A child command therefore closes that shared stream and becomes a root item. Merely adding ownership to opening events is insufficient: subsequent snapshots, progress, and close events must reuse the opening identity, including an intentionally absent root parent.

6. Proposed fix

Validate the optional owner metadata against the existing delta-key contract. Preserve the opening owner on each tool call, ignore invalid or self-referential owners, and include it on text, tool, progress, and output keys. Track active nested stream owners per thread, close only the relevant streams during a tool opening, close an owner's nested streams when that call ends, and flush all remaining owners at turn completion or interruption. This uses the existing protocol without changing its schema or meaning.

The local candidate changes only the ACP translator and its existing test file, with no new dependency, stored data, public API, or wire-schema change. Additional tests cover command snapshots, generic progress, conflicting later metadata, multiple owners at completion/interruption, and invalid/self ownership.
