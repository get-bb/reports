#7225 · Default picker opens mutate document-wide overlay state

Bug Priority: Medium Effort: Medium ui perf partial-repro

GitHub issue · November 7, 2026 · trusted main e61446e15a0bb3e6df551e45c3aba5c5187ffad3

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high for the document-wide modal state changes; browser performance impact remains unmeasured here.

1. TL;DR

The reported symptom is slow opening and closing of composer pickers. A focused runtime test of the real model picker confirms that opening it with its production default sets body[data-scroll-locked="1"], sets body.style.pointerEvents = "none", and hides the composer through an aria-hidden ancestor. Escape removes the scroll lock and restores body pointer events. Opening the same component with modal={false} satisfies a no-body-style-mutation assertion. The same agent repeated this result in a second clean checkout of trusted main; neither run measures browser style-recalculation time or recreates the reporter's plugin installation, so the performance claim is only partially reproduced.

5. Root cause

Trusted composer code renders the model picker without overriding modal behavior: ExecutionControls. The picker then supplies an explicitly true default to the shared responsive Popover. On noncompact viewports, the shared primitive forwards that value to Radix unchanged. The installed, lockfile-selected Radix Popover modal-content path invokes hideOthers, wraps content in RemoveScroll, and enables outside-pointer suppression.

Existing test helper:257Explicitly supplies false, concealing the production-default behavior from its usual test cases.

In the installed dependencies, react-remove-scroll-bar uses the data-scroll-locked body attribute and the --removed-body-scroll-bar-size custom property; Radix DismissableLayer sets and later restores ownerDocument.body.style.pointerEvents. Body-level inherited values can invalidate descendant styles, so these are plausible document-wide style invalidation sources. The DOM transitions are established by execution; the affected-element count, number of recalculation events, forced getComputedStyle call chain, and plugin-dependent time cost are not established by these jsdom runs.

6. Proposed fix and autopilot boundary

Prefer explicit nonmodal defaults in the six affected picker implementations, preserving callers that deliberately request modal behavior. Stop overriding the production default in the primary test fixture and add behavioral assertions for scroll lock, body pointer events, Escape, outside interaction, focus, and model selection. Verify the unchanged compact responsive-drawer path separately, including Safari. A real Chromium trace with synthetic or isolated plugin content is the next experiment for quantifying style invalidation; it must not use the owner's runtime data.

No fix branch or PR is safe under this rule. The complete scoped default correction touches at least six existing implementation files before tests, exceeding the five-file autopilot limit. A global primitive change would alter unrelated menus and still cannot undo the explicit true defaults in four pickers. A model-only change would leave the other reported families unfixed. No production patch, commit, or branch was pushed.
