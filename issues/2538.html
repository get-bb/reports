#2538 · Bug - Refusing to start a competing turn for thread “<threadid>” while another turn is active or starting (Codex)

Bug Priority: High Effort: not set providers threads provider-codex open on GitHub 2026-08-27 · base ad79bbb5ec90

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

After BB recreates a Codex translator, followup_task can resume a historical child.

The new translator does not know that child.

It ignores the interacted event and emits the child turn without parentToolCallId.

The runtime then treats the child as foreground work.

BB can reject the next user prompt while the child remains active.

5. Root cause

The translator keeps child correlation only in local maps.

A recreated translator starts with empty maps.

The interacted branch only restores a child that the same translator already tracks as terminal.

const tracked = findTrackedSubAgentByAgentThreadId(
  activity.item.agentThreadId,
);
if (tracked?.terminal) {
  tracked.pendingFollowups += 1;
  rearmTrackedSubAgent(tracked);
  ...
}
return [];

Source: translator.ts lines 1053–1120.

An unknown historical child therefore gets no map entry and no FIFO link.

The next turn.open cannot find a parent and remains unparented.

Source: translator.ts lines 887–939.

The shared runtime correctly skips parented child turns and records unparented turns as foreground.

if (event.type === "turn/started") {
  if (event.parentToolCallId) {
    return;
  }
  ...
  this.activeTurnIdByThreadId.set(event.threadId, turnId);
}

Source: runtime-turn-state.ts lines 73–83.

The turn guard then rejects the next prompt because the child owns the foreground slot.

Source: runtime.ts lines 929–936.

The runtime guard is not the defect. The Codex projection lacks the durable parent link.

6. Proposed fix (first principles)

The Codex bridge must restore intent and child identity after translator recreation.

  1. Use the raw followup_task call when Codex supplies it.
  2. Store an unknown rawless interacted event until a child turn proves a resume.
  3. Match that turn by its agent thread identity.
  4. Discard a message-only interaction at its parent turn boundary.
  5. Do not infer a child from an unrelated root-thread turn.
  6. Increment the host daemon protocol version because turn-parent meaning changes across the boundary.

A durable call identifier from Codex would remove the need for any ambiguous root-thread fallback.
