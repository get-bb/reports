#5419 · Desktop Home mounts compact-only recent content

Bug Priority: Medium Effort: Low ui perf

GitHub issue · October 13, 2026 · trusted base e9dafb6c0245a37c6972dffa71134d546f3d497e

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Desktop Home mounts content intended only for the compact Home layout. The recent-thread section uses CSS to hide itself on desktop, but hiding does not prevent React from creating its DOM subtree. A regression with 1,000 representative rows fails on unchanged trusted main because the desktop branch mounts the supplied compact list. A second clean checkout produces the same failure. Removing the compact content from the desktop branch fixes the regression while retaining the compact list during resizing.

The added regression body is:

it("mounts compact scroll content only while the compact home layout is active", () => {
  const compactContent = (
    <ul data-testid="compact-recents">
      {Array.from({ length: 1000 }, (_, index) => (
        <li key={index}>Thread {index}</li>
      ))}
    </ul>
  );
  const content = (isCompactViewport: boolean) => (
    <CompactViewportOverrideProvider isCompactViewport={isCompactViewport}>
      <RootComposeSecondaryContent
        compactScrollContent={compactContent}
        isCompactHomeLayout={isCompactViewport}
        isSecondaryPanelOpen={false}
        onToggleSecondaryPanel={noop}
        secondaryPanel={createSecondaryPanel(false)}
      >
        <div data-testid="root-compose-content" />
      </RootComposeSecondaryContent>
    </CompactViewportOverrideProvider>
  );
  const view = render(content(false));
  expect(screen.queryByTestId("compact-recents")).toBeNull();
  expect(screen.getByTestId("root-compose-content")).not.toBeNull();
  expect(screen.getByTestId("plugin-homepage-sections")).not.toBeNull();
  view.rerender(content(true));
  expect(screen.getByTestId("compact-recents").children).toHaveLength(1000);
  expect(screen.getByTestId("root-compose-content")).not.toBeNull();
  expect(screen.getByTestId("plugin-homepage-sections")).not.toBeNull();
  view.rerender(content(false));
  expect(screen.queryByTestId("compact-recents")).toBeNull();
  expect(screen.getByTestId("root-compose-content")).not.toBeNull();
  expect(screen.getByTestId("plugin-homepage-sections")).not.toBeNull();
});

5. Root cause

RootComposeView passes the actual recent-thread component as compactScrollContent and selects the compact layout using the existing viewport hook. RootComposeSecondaryContent renders that content in both branches. The desktop branch places it after the composer, before plugin homepage sections.

{children}
{compactScrollContent}
<PluginHomepageSections />

RootComposeMobileRecents applies md:hidden and maps all recent rows to components. CSS display suppression does not unmount React elements. The row-building helper has no list-size limit. Together these paths explain unnecessary desktop DOM growth as the eligible thread list grows.

6. Proposed fix

Remove only the desktop branch's compactScrollContent child. Keep the existing compact branch, viewport selection, composer, and plugin sections unchanged. The regression checks desktop → compact → desktop transitions, including 1,000 rows on compact and absence on desktop. This requires no new API, wire change, dependency, stored data, or product decision. Mobile list capping or virtualization is a separate concern and is intentionally not introduced in this minimal desktop fix.
