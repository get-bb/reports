#6484 · Inline-code clipboard serialization

Bug Priority: Medium Effort: Low ui · GitHub issue · October 28, 2026

Trusted base: 1f31987e42856eab6e5a0f0fb2161c765ef72f0e

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

Selecting only the contents of an inline-code span and copying it writes Markdown backticks into the plain-text clipboard payload. The shared serializer already treats selections inside fenced code as raw text, but does not extend that exception to inline code. The timeline copy handler therefore writes the fenced inline representation rather than the selected visible characters. Four focused copy-event cases fail identically in two separate checkouts of trusted main; a mixed-message control passes. This is a shared client-side serialization defect, not provider-specific behavior.

Complete added regression, using the existing copyRange helper which dispatches document copy and captures clipboardData.setData. The complete baseline test file with imports and helpers is also saved:

it.each(["text", "element", "paragraph", "partial", "message"] as const)(
  "copies an inline code %s selection without code delimiters unless mixed with prose",
  (mode) => {
    const content = "**Check:**\n\n`pnpm --version`";
    const { container } = render(
      <SelectableMessageProse>
        <MarkdownPreview content={content} />
      </SelectableMessageProse>,
    );
    const code = container.querySelector("code")!;
    const range = document.createRange();
    let expected = "pnpm --version";
    if (mode === "message") {
      range.selectNodeContents(container.firstElementChild!);
      expected = content;
    } else if (mode === "paragraph") {
      range.selectNodeContents(code.closest("p")!);
    } else if (mode === "element") {
      range.selectNode(code);
    } else {
      range.setStart(code.firstChild!, mode === "partial" ? 5 : 0);
      range.setEnd(code.firstChild!, code.textContent!.length);
      if (mode === "partial") expected = "--version";
    }
    const { data, accepted } = copyRange(range);
    expect(accepted).toBe(false);
    expect(data.get("text/plain")).toBe(expected);
    expect(data.get("text/html")).toContain("<code>");
  },
);

5. Root cause

The timeline document copy handler clips the selection to message roots, serializes each part, and writes the resulting text into text/plain.

selectionClipboard normalizes the selected range but records only the enclosing pre. Its final text branch is:

const text =
  pre && end && pre.contains(end)
    ? range.toString()
    : childrenMarkdown(container).trim();

Trusted-base branch. An inline-only selection takes the Markdown branch. The CODE serializer deliberately calls codeSpan, adding backticks. Auto-linked inline file references use a marked anchor instead of CODE, so they need the same raw-copy treatment without removing authored link semantics elsewhere.

6. Proposed fix

Use raw selected text when the entire normalized copy selection is contained in one CODE, PRE, or renderer-marked inline-code anchor. Keep rich HTML unchanged. Pass an explicit plain-code versus Markdown mode through the existing shared serializer: copy uses plain-code mode, while Add to chat keeps Markdown. Preserve Markdown for mixed selections, including selections spanning messages. No new UI, SDK method, protocol, dependency, schema, or storage change is necessary.

The candidate fix passes all 119 tests across five focused clipboard, selection, Add to chat, and secondary-panel test files, plus app lint, typecheck, and build. Existing auto-linked path coverage is updated to expect raw text for code-only copies while preserving Markdown for mixed content. An added Add to chat case protects inline-code formatting, and a cross-message control protects Markdown when code and prose are selected together. The candidate changes 132 text lines (95 additions, 37 deletions) across five files within the existing selection-clipboard subsystem.
