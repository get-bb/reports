However, supplying a child reference does not create a thread link in the native delegation title, even before grouping. Root cause

Delegation projection preserves childRef on a work row. isSummarizableActivityRow excludes approvals, questions, and workflows, but accepts delegations irrespective of childRef. closeOpenStepAtBoundary groups multiple work rows into a step-summary. buildTimelineViewRows invokes this grouping at conversation boundaries or when closedScope is true. Summary body rendering puts those rows inside the expandable body.

The deeper identity/link condition is unresolved: mapDelegationTitle generates label/description/type segments without attaching a thread link. Codex translation takes childRef from provider receiverThreadIds, so arbitrary references cannot safely be treated as BB thread IDs. In contrast, Generated child notification titles build explicit links from typed thread subjects.

Proposed next step and simple-fix decision

Capture or construct a trusted server-boundary case with a provider child reference resolved to an existing BB child thread. Verify the identity mapping and the link destination, then test exactly one visible link outside activity while task detail stays inside. Merely excluding all delegations from grouping would change unrelated activity and would not create a valid link.
