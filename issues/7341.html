#7341 · ACP lifecycle boundaries discard unfinished tool state

Bug Priority: Medium Effort: Low providers provider-acp
GitHub issue · November 10, 2026 · base 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

An ACP command can remain pending in the emitted timeline when a provider fails or announces a turn or compaction start before finishing that command. The translator forgets the command before emitting its completion, and does not close active assistant or reasoning text at these boundaries. Passing real translator output through the real delta assembler confirms that none of the three paths emits the expected completions. Six regression cases fail on the trusted main commit, and the same agent repeated all six failures in a second clean checkout. This report proves the provider-bridge event defect; it does not claim to have reproduced a live provider or a visible app hang.

5. Root cause

The production bridge forwards notifications to the translator in bridge/bridge.ts. The translator owns the merged tool-call state needed to construct a final tool result. Its clearThreadCalls deletes that state without emitting any delta:

for (const [key] of threadCallEntries(context)) {
  mergedToolCalls.delete(key);
  injectedToolBindings.delete(key);
}
pendingInjectedCalls.delete(context?.threadId ?? "");

The provider-error path, turn-start path, and compaction-start path invoke that destructive reset directly. The existing flushOpenTurnWork already closes both text channels and drains active tools into terminal deltas. Normal turn completion uses this mechanism, but the three reset paths bypass it.

At the next layer, provider.error with settlesTurn finishes the turn. finishTurn removes non-thread-attached open items without inventing item completions. It therefore cannot recover the discarded command or finish its accumulated text after that reset. For start notifications, the assembler keeps the existing turn open, so the defect is missing settlement, not necessarily a new turn ID.

6. Proposed fix

Before destructive cleanup, flush open text and tool work using the existing helper and emit those deltas before the error or start deltas. Preserve pending injected-tool cleanup and turn-local file tracking. Use failed status for a provider failure and interrupted for replacement turn/compaction starts. This is a local translator correction, not a schema or public protocol change. The regression protects event completion, content, identity, status, scope, ordering, and no duplicate completion.
