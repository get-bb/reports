#5493 · Rail visibility editor activates destinations

BugPriority: LowEffort: Lowui GitHub issue2026-10-14 · base f526a8b9b3de387c23e3840cdda8a5cf0b556fd0

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The navigation rail has a visibility editor reached through its More menu. Clicking an item's title in that editor activates its destination instead of changing its checkbox. A real rail component reproduction demonstrates this for a registered plugin destination and the built-in search command, on both desktop and compact layouts. The editor supplies navigation callbacks to a shared visibility control that already supports toggling rows when those callbacks are absent. Removing those callbacks from the rail editor restores visibility toggling while leaving normal rail navigation and the shared component unchanged.

5. Root cause

The rail editor supplies onActivate and onExit, mapping a row directly to state.actions.activate(item.id, ...) and closing customization afterward.

onActivate={(item, event) =>
  state.actions.activate(item.id, {
    openInSplit: event.metaKey || event.ctrlKey,
  })
}
onExit={() => onClose(false)}

The shared control invokes activation and requests exit whenever those callbacks are supplied. Its row click handler chooses activation instead of checkbox toggling:

if (onActivate)
  onActivate({ metaKey: event.metaKey, ctrlKey: event.ctrlKey });
else onCheckedChange(!checked);

The checkbox has its own visibility-change handler, so existing checkbox-only tests pass while clicks on the title take a different path. This is incorrect callback wiring at the rail editor boundary, not a router, plugin, checkbox, or stored-data defect. The generic no-activation row-toggle path already exists and has separate coverage.

6. Proposed fix and verification

Remove the activation and exit callbacks from SidebarNavigationCustomize, retaining Done, reorder, visibility updates, and the shared component's default row-toggle behavior. Do not change the generic shared API or the ordinary rail/More navigation controls.

The proposed patch changes two existing files in the sidebar subsystem: 46 text lines (39 additions and 7 deletions). It adds no dependency, migration, generated artifact, stored-data change, public protocol, authentication change, or new product design.
