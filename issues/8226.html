#8226 · Compiler transforms bypass persistence outside production builds

BugPriority: MediumEffort: Mediumui · perf · confirmed-reproGitHub issue

2026-11-26 · trusted origin/main b0ddaad731565d7e4de68d824120d802fc78f7d5

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Unchanged components go through the React Compiler again after an app development server or test environment restarts. The production build wrapper deliberately skips cache initialization for Vite's serve command, and the test preset bypasses that wrapper entirely. A real Vite reproduction compiles one component twice in development and twice in a test-mode SSR environment; both modes create zero compiler-cache entries. A production-build control creates one entry and records a warm hit. The same agent repeated this result in a second clean checkout; the report does not validate the submitter's full-shard timings or projected speedup.

import assert from "node:assert/strict";
import { execFileSync } from "node:child_process";
import { mkdtemp, rm, writeFile } from "node:fs/promises";
import { join } from "node:path";
import { fileURLToPath } from "node:url";
import react from "@vitejs/plugin-react";
import * as cacache from "cacache";
import { build, createServer } from "vite";
import { cachedReactCompiler, testReactCompiler } from "./vite-react-compiler.ts";

const app = fileURLToPath(new URL("./", import.meta.url));
const fixture = await mkdtemp(join(app, ".slopcop-8226-"));
const input = join(fixture, "greeting.tsx");
const common = execFileSync("git", ["rev-parse", "--path-format=absolute", "--git-common-dir"], { cwd: app, encoding: "utf8" }).trim();
const defaults = join(common, "bb-cache/react-compiler");
const failures: string[] = [];
const originalEnv = { ...process.env };

async function entries(directory: string) {
  return Object.keys(await cacache.ls(directory)).length;
}

try {
  delete process.env.ENABLE_REACT_COMPILER_TIMINGS;
  delete process.env.BABEL_SHOW_CONFIG_FOR;
  await writeFile(input, 'export function Greeting({ label }: { label: string }) { const message = "Cache " + label; return <p>{message}</p>; }');
  for (const kind of ["build", "development", "test"] as const) {
    process.env.NODE_ENV = kind === "build" ? "production" : kind;
    const directory = kind === "test" ? defaults : join(fixture, kind);
    const before = await entries(directory);
    const results: Array<{ compiled: boolean; cacheEntries: number; code: string }> = [];
    for (const phase of ["cold", "warm"]) {
      const plugin = kind === "test" ? await testReactCompiler() : await cachedReactCompiler(directory);
      let code: string;
      if (kind === "build") {
        const output = await build({
          configFile: false,
          root: fixture,
          mode: "production",
          logLevel: "silent",
          plugins: [react(), plugin],
          build: { write: false, minify: false, rolldownOptions: { input, external: [/^react(?:\/|$)/], preserveEntrySignatures: "strict" } },
        });
        assert(!Array.isArray(output) && "output" in output);
        code = output.output.filter((item) => item.type === "chunk").map((item) => item.code).join("\n");
      } else {
        const server = await createServer({
          configFile: false,
          root: fixture,
          mode: kind,
          logLevel: "silent",
          plugins: [react(), plugin],
          server: { middlewareMode: true, ws: false, watch: null, preTransformRequests: false },
          optimizeDeps: { noDiscovery: true, include: [] },
        });
        try {
          const environment = kind === "test" ? server.environments.ssr : server.environments.client;
          const result = await environment.transformRequest("/greeting.tsx");
          assert(result);
          code = result.code;
        } finally {
          await server.close();
        }
      }
      const compiled = code.includes("react/compiler-runtime") || code.includes("react_compiler-runtime");
      const cacheEntries = (await entries(directory)) - before;
      console.log(JSON.stringify({ kind, phase, compiled, newCacheEntries: cacheEntries }));
      assert(compiled, kind + " must actually run the React Compiler");
      results.push({ compiled, cacheEntries, code });
    }
    assert.equal(results[0].code, results[1].code, kind + " output must be stable across restarts");
    if (results[0].cacheEntries === 0) failures.push(kind + ": expected persisted compiler output, observed 0 new cache entries");
    assert.equal(results[0].cacheEntries, results[1].cacheEntries);
  }
  for (const failure of failures) console.error("FAIL " + failure);
  assert.equal(failures.length, 0, "Every compiler entry point should persist reusable output");
} finally {
  for (const key of Object.keys(process.env)) if (!(key in originalEnv)) delete process.env[key];
  Object.assign(process.env, originalEnv);
  await rm(fixture, { recursive: true, force: true });
}

The script checks that emitted code imports the React Compiler runtime before diagnosing missing entries, so disabled compilation cannot masquerade as a cache miss. Both restarts produce identical compiled output. The production control verifies cache eligibility, writable storage and actual warm reuse, rather than merely assuming the harness can cache this component.

5. Root cause

The shared app Vite config installs cachedReactCompiler(), and the development config spreads that shared configuration. In the wrapper configuration hook, cache starts null and the hook returns before initializing it for every command other than build:

  const root = resolve(fileURLToPath(new URL("../../", import.meta.url)));
  let cache: { directory: string; namespace: string } | null = null;
  let warned = false;
  const stats = { hits: 0, misses: 0 };
  plugin.configResolved = async function (this: void, config: ResolvedConfig) {
    await configResolved.call(this, config);
    if (
      config.command !== "build" ||
      process.env.ENABLE_REACT_COMPILER_TIMINGS === "1" ||
      process.env.BABEL_SHOW_CONFIG_FOR
    )
      return;

The transform handler takes its direct Babel path whenever the cache is null. Neither a lookup nor a put occurs. This is why cache statistics stay zero rather than reporting ordinary misses.

  transform.handler = async function (code, id, options) {
    const key =
      cache &&
      compilerTransformKey(
        cache.namespace,
        root,
        id,
        code,
        options?.moduleType ?? "js",
        this.environment.name,
      );
    if (!cache || !key) return handler.call(this, code, id, options);
    try {
      const entry = await cacache.get(cache.directory, key);
      const result = transformResult.parse(
        JSON.parse(entry.data.toString("utf8")),
      );
      stats.hits++;
      return result;

The app test configuration selects testReactCompiler(). That separate test factory constructs the Babel plugin directly, broadening compiler environment applicability and excluding plugin sources, but never using the cache wrapper:

export function testReactCompiler() {
  const preset = reactCompilerPreset();
  const pluginSources = resolve(
    fileURLToPath(new URL("../../plugins/", import.meta.url)),
  ).replaceAll("\\", "/");
  return babel({
    presets: [
      {
        ...preset,
        rolldown: {
          ...preset.rolldown,
          filter: {
            ...preset.rolldown.filter,
            id: {
              exclude: new RegExp(
                `^${pluginSources.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")}/`,
              ),
            },
          },
          applyToEnvironmentHook: () => true,
        },
      },
    ],
  });
}

The current cache lifecycle regression exercises production builds only. All four existing tests pass on the affected base, so they do not cover restart reuse in development or test environments.

6. Proposed fix

Use one cache-owning Babel wrapper for both existing presets and allow serve-mode initialization. Preserve the test factory's environment and source exclusions, compiler diagnostics bypasses, invalidation inputs, corrupt-entry repair and absolute-path safeguards. Check that distinct effective presets cannot collide, and add restart-reuse coverage for client development and test SSR, including sourcemap and configuration invalidation behavior. Restoring or saving app-shard caches in CI is a separate storage-policy decision and is not required to reproduce or repair local caching.
