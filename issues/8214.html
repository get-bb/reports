#8214 · Repeated validator compilation during workflow reads

BugPriority: MediumEffort: Mediumplugins · workflows · perfGitHub issue

2026-11-26 · trusted origin/main b0ddaad731565d7e4de68d824120d802fc78f7d5

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Reading workflow progress performs avoidable synchronous validator compilation in the server process. Each displayed run reconstructs every stored call's options and validates its schema using a newly compiled Ajv validator; constructing the view additionally runs the full workflow source validator just to obtain display metadata. A fresh regression test against the real plugin RPC and CLI entry points measures one compilation per stored call, plus two source-schema compilations for each RPC in this fixture. The same agent repeated the test in a second clean trusted checkout with identical counts. This establishes the repeated work, not the issue's exact latency measurements or a live multi-client refetch rate.

import { createFakePluginHost } from "@get-bb/plugin-sdk/testing";
import Ajv from "ajv";
import { expect, it, vi } from "vitest";
import { claimQueuedRun, createRun, startCall } from "./data.js";
import { parseWorkflowSource } from "./parser.js";
import plugin from "./server.js";
import { DEFAULT_WORKFLOW_SETTINGS } from "./settings.js";
import { parseAgentOptions } from "./validation.js";

it("reads persisted workflow progress without compiling validators", async () => {
  const observations: Array<{ calls: number; surface: string; compiles: number }> = [];
  for (const callCount of [0, 7, 23]) {
    const { bb, harness } = createFakePluginHost({ pluginId: "workflows" });
    try {
      await plugin(bb);
      const source = `export const meta = {
        name: "read-cost-probe",
        description: "Progress read probe",
        phases: [{ title: "Probe", detail: "Collect values" }],
        outputSchema: { type: "integer" }
      };
      return await agent("Return an integer", { outputSchema: { type: "integer" } });`;
      parseWorkflowSource(source);
      const database = bb.storage.database();
      const run = createRun(database, {
        projectId: "project-test",
        originThreadId: "thread-test",
        environmentId: "environment-test",
        originProvider: "codex",
        originModel: "test-model",
        originReasoningLevel: "medium",
        originPermissionMode: "full",
        name: "read-cost-probe",
        source,
        sourceHash: "read-cost-probe",
        argsJson: "null",
        settingsJson: JSON.stringify(DEFAULT_WORKFLOW_SETTINGS),
        resumedFromRunId: null,
      });
      expect(claimQueuedRun(database, 1)?.id).toBe(run.id);
      const options = parseAgentOptions({
        outputSchema: { type: "integer" },
        title: "Collect integer",
        phase: "Probe",
      });
      for (let callIndex = 0; callIndex < callCount; callIndex += 1) {
        startCall(database, {
          runId: run.id,
          callIndex,
          cacheKey: `probe-${callIndex}`,
          prompt: "Return an integer",
          options,
          selection: {
            providerId: "codex",
            model: "test-model",
            reasoningLevel: "medium",
            permissionMode: "full",
          },
          replay: null,
        });
      }
      const compile = vi.spyOn(Ajv.prototype, "compile");
      try {
        const view = await harness.callRpc("workflowRunView", {
          threadId: "thread-test",
          runId: run.id,
        });
        expect(view).toMatchObject({ run: { description: "Progress read probe" } });
        observations.push({ calls: callCount, surface: "run-view", compiles: compile.mock.calls.length });
        compile.mockClear();
        const active = await harness.callRpc("workflowActiveRuns", { threadId: "thread-test" });
        expect(active).toMatchObject({ runs: [{ id: run.id }] });
        observations.push({ calls: callCount, surface: "active-runs", compiles: compile.mock.calls.length });
        compile.mockClear();
        const history = await harness.runCli(["history", run.id, "--limit", "100"], {
          threadId: "thread-test",
          projectId: "project-test",
        });
        expect(history.exitCode).toBe(0);
        observations.push({ calls: callCount, surface: "history", compiles: compile.mock.calls.length });
      } finally {
        compile.mockRestore();
      }
    } finally {
      await harness.dispose();
    }
  }
  console.log(JSON.stringify(observations));
  expect(observations.map((observation) => observation.compiles)).toEqual(Array(9).fill(0));
});

5. Root cause

Both RPC handlers build views from service inspections. Inspection maps every stored call through inspectCall, which deserializes the options through parseStoredAgentOptions. That function performs the full assertValidJsonSchema check, including new Ajv(...).compile(schema). No validator cache is retained across calls or requests in this path.

options: parseStoredAgentOptions(parseJson(call.optionsJson, "workflow call options"))
assertValidJsonSchema(options.outputSchema, "stored agent outputSchema")
new Ajv({ strict: false, allErrors: true }).compile(schema)

View construction calls parseWorkflowSource only to obtain metadata. The full source inspection walks the body, checks each literal agent schema, and validates meta input/output schemas. These steps explain the extra two compiles with no stored calls. Paged call inspection uses the same inspectCall function, explaining CLI history's linear per-returned-call cost without the extra source compiles.

Run progress invalidates runs:<originThreadId> and multiple progress paths call it. These are synchronous function calls in the service read path, so compilation consumes the calling server process's event loop; this test does not profile a live production server.

6. Proposed fix

Separate safe structural/subset checking of stored schemas from validator compilation. Keep bounds and unsafe-keyword rejection on persisted-data reads; do not remove that guard. Compile on admission or actual value validation instead. Give the view a metadata-only reader that does not validate workflow body schemas, while retaining full source validation before execution. The start path already parses the full source. Protect the read-side behavior across both RPCs and history with the attached regression test. No production fix was attempted in this investigation because an existing open PR links this issue.
