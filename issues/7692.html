#7692 · Repeated pending-buffer byte accounting

Bug Medium priority Low effort host · perf · confirmed-repro

November 17, 2026 · Issue #7692 · trusted base 1320c88e8abdd3f145bc9a5c305eace269fb2f28

Verdict: REPRODUCED · Root-cause confidence: high.

1. TL;DR

A long provider message arriving in many chunks makes the line reader repeatedly measure all bytes accumulated so far. A 24 MiB JSON line delivered in 32 KiB chunks passes more than 9.67 billion characters to byte-length accounting, 384.5 times the payload. Two clean checkouts reproduce the same deterministic work amplification and a failing linear-work assertion. The synchronous feed takes several seconds on this host, although exact timings depend on the environment. No duplicate fix was attempted because open PR #7699 already closes this issue.

Complete reproduction source
import assert from "node:assert/strict";
import { performance } from "node:perf_hooks";
import { resolve } from "node:path";
import { PassThrough } from "node:stream";
import { pathToFileURL } from "node:url";

const repository = process.argv[2];
assert.ok(repository, "Pass the trusted repository root");
const { readBoundedLines } = await import(
  pathToFileURL(resolve(repository, "packages/provider-bridge-protocol/src/bridge-kit/bounded-line-reader.ts")).href
);
const chunkBytes = 32 * 1024;
const sizes = [2, 8, 24];
const observations = [];

function exercise(line, instrument) {
  const input = new PassThrough();
  let emitted = 0;
  let observedLine;
  let overflows = 0;
  let measuredCharacters = 0;
  readBoundedLines({
    input,
    onLine(value) {
      emitted += 1;
      observedLine = value;
    },
    onOverflow() {
      overflows += 1;
    },
  });
  const original = Buffer.byteLength;
  if (instrument) {
    Buffer.byteLength = function (value, encoding) {
      if (typeof value === "string") measuredCharacters += value.length;
      return original(value, encoding);
    };
  }
  const started = performance.now();
  try {
    for (let offset = 0; offset < line.length; offset += chunkBytes) {
      input.write(line.subarray(offset, offset + chunkBytes));
    }
    input.write(Buffer.from("\n"));
  } finally {
    Buffer.byteLength = original;
    input.end();
  }
  const milliseconds = performance.now() - started;
  assert.equal(emitted, 1);
  assert.equal(overflows, 0);
  assert.equal(observedLine, line.toString("utf8"));
  return { milliseconds, measuredCharacters };
}

exercise(Buffer.from('{"payload":"warmup"}'), false);
console.log(`Node ${process.version}; chunks=${chunkBytes} bytes; ASCII JSON lines`);
for (const mebibytes of sizes) {
  const bytes = mebibytes * 1024 * 1024;
  const line = Buffer.from('{"payload":"' + "a".repeat(bytes - 14) + '"}');
  assert.equal(line.length, bytes);
  const timing = exercise(line, false);
  const measured = exercise(line, true);
  const scanRatio = measured.measuredCharacters / bytes;
  observations.push({ bytes, measuredCharacters: measured.measuredCharacters });
  console.log(`${mebibytes} MiB: ${timing.milliseconds.toFixed(2)} ms; byteLength input=${measured.measuredCharacters}; scan/payload=${scanRatio.toFixed(1)}x`);
}
const linear = observations.every(({ bytes, measuredCharacters }) => measuredCharacters <= 2 * bytes);
console.log(`Linear-work budget (at most twice the payload): ${linear ? "PASS" : "FAIL"}`);
assert.ok(linear, "Byte-length accounting repeatedly scans prior chunks instead of linear total input");

5. Root cause

Reader, lines 13–49 appends each tail to pending and immediately measures the entire pending string:

pending += tail;
if (Buffer.byteLength(pending) > maxLineBytes) {
  discarding = true;
  discardedBytes = Buffer.byteLength(pending);
  pending = "";
}

For k chunks of c bytes, the arguments total c × k × (k + 1) / 2 characters before the newline. Payload is c × k, so work amplification is (k + 1) / 2. The measurements match this formula exactly. This work happens synchronously in a data listener, so the reader's event loop cannot service other callbacks during that work.

The runtime attaches this reader to child stdout. The default cap allows the tested payload sizes.

6. Proposed fix

Account for each newly decoded tail once and maintain a pending-byte total, resetting it at line boundaries, after entering overflow discard mode, and at close. Preserve the decoder, line output, overflow reporting, and existing limits. Validate multibyte chunks, newline resets, discard recovery, and a deterministic linear-work budget. This is a contained reader change, but no candidate patch was made because a linked open PR already exists.
