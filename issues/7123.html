#7123 · Credential errors bypass Codex recovery

Bug Medium priority Medium effort providers provider-codex GitHub issue
November 5, 2026 · trusted main fa30b0a7dcdf745f7baf8e41721f754b7d3198fe

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high for the bridge recovery gap

1. TL;DR

A credential-loading failure delivered by Codex can end a BB turn without arranging a fresh Codex child session for the next turn. Running BB's actual bridge and translator against a controlled app-server process confirms this for a missing category, an unknown category, and a stream-disconnection category. The first two cases miss the authentication text matcher; the third exits before text matching. A structured unauthorized control does rebuild and retains the provider thread identity, while a plain stream-disconnection control does not rebuild. We did not reproduce AWS SSO expiration itself or demonstrate that restarting Codex repairs a real AWS credential provider; those parts remain unverified.

5. Root cause

Two classifier paths miss the credential-specific failure

Authentication text matching and category precedence: the matcher recognizes HTTP 401/403 and auth/unauthorized words, but not the fixture's credential-loading diagnostic. A known category other than unauthorized or rate-limit returns before this fallback. Thus widening only the matcher would still miss the tested stream category.

const CODEX_AUTH_REQUIRED_TEXT_PATTERN =
  /\b(?:40[13]|auth(?:entication|orization)?|unauthori[sz]ed)\b/i;
const CODEX_RATE_LIMITED_TEXT_PATTERN =
  /\b(?:429|credits?|quota|rate[-\s]?limit(?:ed)?|usage limit)\b/i;

function classifyTerminalAccountError(
  delta: Extract<ThreadDelta, { kind: "provider.error" }>,
): "authRequired" | "rateLimited" | null {
  const category = delta.errorInfo?.category;
  if (category === "unauthorized") {
    return "authRequired";
  }
  if (category === "rate-limit") {
    return "rateLimited";
  }
  if (category !== undefined && category !== "unknown") {
    return null;
  }
  const text = [delta.message, delta.detail]
    .filter((part) => part !== undefined)
    .join("\n");
  if (CODEX_AUTH_REQUIRED_TEXT_PATTERN.test(text)) {
    return "authRequired";
  }
  if (CODEX_RATE_LIMITED_TEXT_PATTERN.test(text)) {
    return "rateLimited";
  }
  return null;
}

No classification means no pending reconstruction

Terminal error recovery notification returns without setting rebuildBeforeNextTurnReason when classification returns null. A recognized unauthorized event sets the flag and emits a non-retryable authRequired hint.

function emitTerminalAccountErrorHint(
  session: CodexBridgeSession,
  delta: Extract<ThreadDelta, { kind: "provider.error" }>,
): void {
  const kind = classifyTerminalAccountError(delta);
  if (kind === null) {
    return;
  }
  const message = delta.detail ?? delta.message;
  session.rebuildBeforeNextTurnReason =
    kind === "authRequired"
      ? "codex session restarted after an authentication failure so a new login can take effect."
      : "codex session restarted after a rate limit so a refreshed account state can take effect.";
  sendNotification(BRIDGE_NOTIFICATION_METHODS.providerRecovery, {
    threadId: session.bbThreadId,
    kind,
    message,
    retryable: false,
  });
}

Reconstruction and bounded automatic replay are separate contracts

Runtime hint handling forwards recovery hints and only schedules a bridge restart for restartRecommended. A broader solution must not assume mapping this diagnostic to authRequired supplies a one-shot automatic retry, prevents completed tool replay, identifies expired SSO login, or proves that process replacement repairs AWS state. None of those claims was established by this controlled reproduction.

6. Proposed fix and safety decision

At the provider bridge, recognize a narrow credential-loading signature from the diagnostic before generic stream-category early returns, while preserving structured unauthorized/rate-limit behavior and the plain-disconnect negative control. Reuse the existing restoration path and add a bridge-level regression like this artifact, rather than exporting a new test-only classifier. Do not classify every transport or AWS failure as expired login.

Before adding automatic retry, capture the real native category and establish, using a dedicated isolated test account, whether an expired credential provider is recovered by a fresh process or requires SSO reauthentication. Validate a strict retry budget, stable thread history, and no completed-tool replay at the actual retry owner. A restart must not be presented as a substitute for reauthentication.

No pull request was attempted. Only the deterministic bridge gap was reproduced, not the real credential-expiry workflow. Authentication recovery is also expressly excluded from this rule's simple-fix scope. No production source was modified, no fix branch was pushed, and no dependency, protocol, or stored data was changed.
