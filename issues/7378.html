#7378 · Cursor Auto alias is forwarded as a native ACP model identifier

BugPriority: MediumEffort: Lowprovidersprovider-acpIssue

2026-11-10 · trusted base 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high for the bridge identifier defect.

1. TL;DR

bb represents Cursor Auto as the catalog family default, but the native agent selection uses auto. Session parameter construction does not translate the family back to the native identifier. A focused regression reproduces that mismatch in two clean checkouts of trusted main; an existing subprocess fixture corrected to advertise native Auto also rejects startup, resume, and fork. No live Cursor account was used, so the reporter's exact external-agent error and Windows/WSL environment remain unverified. The fix belongs at the outbound session selection boundary, preserving existing catalog ids and saved selections.

5. Root cause

bareCursorFamilyId / cursorParameterizedSelection create the catalog alias and then return it as a modelId:

const familyId = model === "auto" ? "default" : agentModelFamilyId(model);
const selection = CURSOR_LEGACY_FAMILY_SELECTIONS[familyId] ?? {
  modelId: familyId,
};

cursorCatalogModel uses that result for catalog ids. buildAcpModelSelection reuses the helper for parameterized Cursor sessions but never resolves default back to auto. selectAcpNativeModel forwards selection.modelId as session/set_config_option.params.value. If the value is rejected and absent from native models, it rethrows the failure.

The shared alias direction dates to the rebuilt adapter commit fe1a02d7b9. Existing tests expected default as an outbound identifier and the parameterized fake agent advertised default; these assumptions masked the mismatch. Exact real-agent rejection text was not reproduced.

6. Proposed fix and validation

For Cursor's parameterized picker only, translate the normalized default family to auto when constructing the outbound model selection. Preserve catalog discovery and its primary-model filtering, legacy saved selections, all named-model normalization, the synthetic acp-default sentinel, reasoning levels, and service tiers. No stored rows, public protocol fields, dependencies, or migrations change.

A broader attempted fix changed the catalog id too; existing discovery coverage exposed that it would interfere with primary-model filtering. That attempt was discarded. The final change is limited to session parameter construction and three existing test/support files.
