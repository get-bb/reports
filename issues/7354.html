#7354 · Cascade activity is omitted from archive confirmation

Bug Medium priority Low effort threads · November 10, 2026
GitHub issue · trusted base 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

Archiving a parent also reaches its descendants. The confirmation dialog warns that work will stop only when one of the explicitly selected threads is running, even though an unselected descendant can be running. A regression through the actual action provider and dialog reproduced the missing warning for starting, active, and stopping descendants. The same test failed again on a second clean checkout at the identical trusted commit. The server does request cancellation during archive teardown, but active threads receive a 30-second Undo grace period; this investigation did not launch a real provider session or measure live cancellation.

5. Root cause

ThreadArchiveDialog.tsx:76–99 derives active exclusively from target.threads, and gates the stop-work sentence on that boolean:

const active = threads.some(
  (thread) =>
    thread.status === "starting" ||
    thread.status === "active" ||
    thread.status === "stopping",
);

ThreadActionsProvider.tsx:447–465 passes only the explicitly selected unarchived threads to the dialog. Descendant count opens confirmation, but descendant status never enters the request. This is an incomplete warning predicate, not a missing cascade or a failure to open confirmation.

The selection planner already retains the descendant IDs per selected root. The existing cached-thread lookup can resolve their thread records without introducing a new RPC or wire field.

Archive lifecycle effects and tree traversal reach the descendants. The active-only grace guard, 30-second duration, and periodic teardown sweep explain why immediate cancellation is too strong a claim for an active child.

6. Proposed fix

Compute an explicit stop-work flag when building the archive request, from the selected unarchived threads and cached, unarchived descendants belonging to that selection plan. Count starting, active, and stopping states. Pass the flag to the existing dialog. Preserve confirmation settings, selection roots, archive mutation behavior, cancellation, and Undo. Do not warn for unrelated running threads, archived descendants, or absent cache records.

This is an app-local warning fix: no public SDK, CLI, server contract, schema, protocol, stored-data, dependency, or release change. Cache misses and state changes after confirmation planning remain limitations; this change does not claim an atomic server-side running-work snapshot.
