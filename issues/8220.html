#8220 · Late-created ignored directories leak watcher events

BugPriority: MediumEffort: Mediumhost · perf · confirmed-reproIssue2026-11-26

Trusted main base: b0ddaad731565d7e4de68d824120d802fc78f7d5

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Build output can repeatedly refresh Git status even though Git ignores every file being written. The workspace watcher discovers ignored directories from a Git status read when its root subscription starts, rather than continuously applying ignore rules. A directory created later is absent from that fixed ignore list, so its writes are forwarded as workspace content changes. In two clean main checkouts, twelve writes in a late-created ignored directory produced twelve content-change callbacks and three flushes of the actual Git plugin invalidator; the same writes in an already-existing ignored directory produced none. A tracked-file edit still produced one callback and one flush. An existing open pull request already targets this issue, so no duplicate fix was created.

import { execFile } from "node:child_process";
import fs from "node:fs/promises";
import os from "node:os";
import path from "node:path";
import { setTimeout as delay } from "node:timers/promises";
import { promisify } from "node:util";
import { expect, it, vi } from "vitest";
import { watchWorkspaceStatus } from "../src/watch-status.js";
import {
  createCoalescedInvalidator,
  tagsForEnvironmentChanges,
} from "../../../plugins/git/server/invalidation.js";

const execute = promisify(execFile);

it("suppresses ignored output regardless of directory creation time", async () => {
  const root = await fs.mkdtemp(path.join(os.tmpdir(), "watch-8220-"));
  const git = async (...args: string[]) =>
    (await execute("git", args, { cwd: root, encoding: "utf8" })).stdout;
  const phases = {
    existing: { events: 0, flushes: 0 },
    late: { events: 0, flushes: 0 },
    tracked: { events: 0, flushes: 0 },
  };
  let phase: keyof typeof phases = "existing";
  let ready = false;
  const errors: string[] = [];
  const deliveredPaths = new Set<string>();
  const invalidator = createCoalescedInvalidator(() => {
    phases[phase].flushes += 1;
  });
  let stop: (() => Promise<void>) | undefined;

  try {
    await git("init", "-q");
    await fs.writeFile(
      path.join(root, ".gitignore"),
      "existing-output/\nlate-output/\n",
    );
    await fs.writeFile(path.join(root, "tracked.txt"), "initial\n");
    await fs.mkdir(path.join(root, "existing-output"));
    await fs.writeFile(
      path.join(root, "existing-output", "seed.txt"),
      "seed\n",
    );
    await git("add", ".gitignore", "tracked.txt");
    await git(
      "-c",
      "user.name=Watcher Reproduction",
      "-c",
      "user.email=watcher@example.invalid",
      "commit",
      "-qm",
      "Initialize watcher fixture",
    );

    stop = watchWorkspaceStatus(root, {
      onReady: () => {
        ready = true;
      },
      onWatchError: (error) => {
        errors.push(error.message);
      },
      onChange: (event) => {
        if (!event.changeKinds.includes("workspace-content-changed")) return;
        phases[phase].events += 1;
        for (const changedPath of event.changedPaths) {
          deliveredPaths.add(path.relative(root, changedPath));
        }
        invalidator.invalidate(
          "repro",
          tagsForEnvironmentChanges("repro", ["work-status-changed"]).tags,
        );
      },
    });
    await vi.waitFor(() => expect(ready).toBe(true), { timeout: 5000 });
    await delay(300);

    for (const directory of ["existing-output", "late-output"]) {
      phase = directory === "existing-output" ? "existing" : "late";
      await fs.mkdir(path.join(root, directory), { recursive: true });
      for (let index = 0; index < 12; index += 1) {
        await fs.writeFile(
          path.join(root, directory, `part-${index}.txt`),
          "output\n",
        );
        await delay(180);
      }
      await delay(1300);
    }

    const statusBeforeTrackedEdit = await git(
      "--no-optional-locks",
      "status",
      "--porcelain=v1",
    );
    const ignoredDirectories = (
      await git(
        "--no-optional-locks",
        "status",
        "--porcelain=v1",
        "--ignored=matching",
      )
    )
      .trim()
      .split("\n");
    phase = "tracked";
    await fs.appendFile(path.join(root, "tracked.txt"), "changed\n");
    await delay(1500);

    console.log(
      "REPRO_8220",
      JSON.stringify({
        writesPerDirectory: 12,
        writeIntervalMs: 180,
        phases,
        statusBeforeTrackedEdit,
        ignoredDirectories,
        errors,
        deliveredPaths: [...deliveredPaths].sort(),
      }),
    );
    expect(errors).toEqual([]);
    expect(statusBeforeTrackedEdit).toBe("");
    expect(ignoredDirectories).toEqual([
      "!! existing-output/",
      "!! late-output/",
    ]);
    expect(phases.existing).toEqual({ events: 0, flushes: 0 });
    expect(phases.tracked).toEqual({ events: 1, flushes: 1 });
    expect(
      phases.late,
      "ignored output must not invalidate workspace status",
    ).toEqual({ events: 0, flushes: 0 });
  } finally {
    await stop?.();
    invalidator.dispose();
    await fs.rm(root, { recursive: true, force: true });
  }
}, 25000);

The existing-directory workload is a negative control and the tracked edit is a positive control. These controls and the empty Git status assertion pass before the late-directory assertion fails. No native watcher, database, clock, or production implementation is mocked.

5. Root cause

  1. Ignore discovery reads Git status with --ignored=matching and extracts ignored directory records. This enumerates existing ignored directories; it is not a reusable matcher for directories that do not exist yet.
  2. The discovered directories form a returned ignore array; subscription setup computes it once and passes it as options: { ignore }. Neither this setup path nor the event handler reclassifies newly created directories.
  3. Every workspace-root event is classified as workspace-content-changed after path containment checks, with no dynamic Git ignore check.
  4. The daemon immediately forwards content changes as work-status-changed. The Git plugin's timing constants and coalescing implementation cap flush frequency rather than suppressing ignored activity.
  5. For actively watched status/file queries, environment changes enqueue invalidation and the publish path probes a Git snapshot. Discarding unchanged results happens after that work, not before it.
const { failures, ignore } = await resolveWorkspaceRootIgnores({
  cwd: this.args.cwd,
  gitRoot: this.gitWorkspace,
});
...
this.startWatchSubscription({
  kind: "workspace-root",
  options: { ignore },
  rootPath,
});

The distinction is ignored directories observed at setup versus Git ignore rules. Built-in static globs can cover some late directories, but arbitrary repository-specific ignored output has no such protection. The general setup-only limitation is also visible in the history that introduced nested-repository ignore discovery; this main base has not repaired it.

6. Proposed fix

Keep the existing start-time exclusions, but classify new output directory ancestors before publishing workspace-root content changes. Use each path's owning repository, preserve tracked files and ordinary content notifications, and fail open if Git classification fails. Batch and cache directory classifications so the filter does not run Git once per written file. Cover nested repositories, directory-only creation events, lookup errors, and ignore-rule changes explicitly. A blanket Git-status gate on content notifications would remove unrelated legitimate content signals and is not the targeted repair.

It adds a directory-ancestor git check-ignore filter in workspace-root-ignores.ts, passes it through the workspace-root subscription, and filters paths before enqueueing notifications. Static residual risk, low severity: listAncestorDirectories excludes the event path itself, so a directory-only initial create event can pass before any child event classifies that directory.
