#6795 · Updater requests discard configured proxy headers

Bug Priority: Medium Effort: Low host · GitHub issue · November 1, 2026

Trusted main: 916d684ac23d0b0de82c09cfc7553a50287d2188

Verdict: REPRODUCED · Root-cause confidence: high. Scope: the real self-updater HTTP code, automatic attempt and forced retry. A full enrolled-daemon protocol-bump/reconnect lifecycle was not run.

1. TL;DR

The daemon's updater does not send its configured server headers when checking the server version or downloading its package. A real local HTTP fixture that requires one synthetic header returns 401, and the updater returns failed, even though an authenticated control request succeeds. A forced retry repeats the failure. The same updater succeeds against the fixture without the header gate, isolating the defect from artifact integrity and installation setup. The application also omits these headers when constructing the updater, so both configuration plumbing and request construction need correction.

Complete original reproduction test
import { createHash } from "node:crypto";
import { once } from "node:events";
import { mkdtemp, readFile, rm } from "node:fs/promises";
import { createServer } from "node:http";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { HOST_DAEMON_PROTOCOL_VERSION } from "@bb/host-daemon-contract";
import { expect, it } from "vitest";
import type { HostDaemonLogger } from "./logger.js";
import { createProtocolSelfUpdater } from "./protocol-self-update.js";

it.each(["version", "tarball", "none"])(
  "completes self-update with configured headers when gate=%s",
  async (gate) => {
    const dataDir = await mkdtemp(join(tmpdir(), "bb-6795-repro-"));
    const headerName = "x-bb-repro-key";
    const headerValue = "fixture-only";
    const tarball = Buffer.from("local fixture artifact");
    const digest = createHash("sha256").update(tarball).digest("hex");
    const requests: { path: string; hasHeader: boolean; status: number }[] = [];
    const errors: string[] = [];
    const installed: string[] = [];
    const logger: HostDaemonLogger = {
      debug() {},
      info() {},
      warn() {},
      error(fields, message) {
        if (fields.err instanceof Error) errors.push(fields.err.message);
        errors.push(message);
      },
    };
    const server = createServer((request, response) => {
      const path = request.url ?? "";
      const hasHeader = request.headers[headerName] === headerValue;
      const gated =
        (gate === "version" && path === "/install/version") ||
        (gate === "tarball" && path === "/install/bb-app.tgz");
      const status = gated && !hasHeader ? 401 : 200;
      requests.push({ path, hasHeader, status });
      response.statusCode = status;
      if (status === 401) {
        response.end("fixture gate requires configured header");
      } else if (path === "/install/version") {
        response.setHeader("content-type", "application/json");
        response.end(
          JSON.stringify({
            version: "9.0.0-repro",
            protocolVersion: HOST_DAEMON_PROTOCOL_VERSION + 1,
          }),
        );
      } else {
        response.setHeader("content-type", "application/gzip");
        response.setHeader("content-length", String(tarball.byteLength));
        response.setHeader("x-bb-artifact-sha256", digest);
        response.end(tarball);
      }
    });
    server.listen(0, "127.0.0.1");
    await once(server, "listening");
    try {
      const address = server.address();
      if (address === null || typeof address === "string") {
        throw new Error("Expected local TCP listener");
      }
      const serverUrl = `http://127.0.0.1:${address.port}`;
      const probePath =
        gate === "tarball" ? "/install/bb-app.tgz" : "/install/version";
      const probe = await fetch(new URL(probePath, serverUrl), {
        headers: { [headerName]: headerValue },
      });
      await probe.arrayBuffer();
      expect(probe.status).toBe(200);
      requests.length = 0;
      const options = {
        dataDir,
        enabled: true,
        logger,
        serverUrl,
        serverHeaders: { [headerName]: headerValue },
        installTarball: async (path: string) => {
          installed.push(await readFile(path, "utf8"));
        },
      };
      const updater = createProtocolSelfUpdater(options);
      const outcomes = [
        await updater.handleProtocolMismatch(),
        await updater.handleProtocolMismatch({ force: true }),
      ];
      console.log(
        JSON.stringify({ gate, outcomes, requests, errors, installed }),
      );
      expect(outcomes).toEqual(["updated", "updated"]);
      expect(installed).toEqual([tarball.toString(), tarball.toString()]);
    } finally {
      server.closeAllConnections();
      await new Promise<void>((resolve, reject) => {
        server.close((error) => (error ? reject(error) : resolve()));
      });
      await rm(dataDir, { force: true, recursive: true });
    }
  },
);

5. Root cause

There are two losses of configuration. The app constructor supplies serverHeaders to the session but not to the nested updater. The updater options have no serverHeaders field, so even supplying an object containing the field directly cannot affect its requests.

The version fetch supplies only a method:

const versionResponse = await fetchFn(versionUrl, { method: "GET" });

The package fetch supplies no headers on the first download, and only a cache validator when an installed digest exists:

headers: {
  "if-none-match": `"sha256-${installedDigest}"`,
}

In contrast, the normal client header builder merges the configured headers. For the same origin, ordinary daemon API calls and updater downloads therefore authenticate differently.

The updater catches non-success responses and returns failed. The connection handler passes its retry flag into the updater and requests restart only when the result is updated. This explains why retry does not fix the missing-header failure; it does not prove a complete live enrollment lifecycle.

6. Proposed fix and automation safety

Carry the existing typed server-header configuration from the app into the updater, then use it on both install requests while preserving the digest cache validator. Keep the existing secure-transport and integrity checks. Add a real request-boundary regression for automatic and forced attempts; include cache-header coexistence and ordinary no-header behavior.

No automated fix PR: sending previously omitted proxy credentials changes authentication behavior on installer HTTP requests. That fails this rule's explicit no-authentication/security-boundary-change condition, even though the mechanical patch is small. Maintainer review should settle credential forwarding and redirect/destination handling. No claim of an exploitable vulnerability is made.
