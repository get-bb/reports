#7890 · Viewport height override survives silent geometry recovery

Bug Priority: Medium Effort: Medium mobile · ui · partial-repro
November 20, 2026 · base 351cb84dc6391d3c6d16295e66578fe97232a25e · GitHub issue

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high (hook mechanism only)

1. TL;DR

The app shell can retain a keyboard-sized height after its viewport has returned to normal. A focused test of the unchanged production hook reproduced that stale override in two separate clean checkouts of trusted main. Blur initially clears the override, but a subsequent resize with old measurements puts it back; no further pass notices silent recovery. An explicit later resize clears it, isolating the missing resampling rather than a CSS-removal failure. The live composer and native iOS timing were not verified, so the overall verdict is partial rather than a claim of device reproduction.

Complete reproduction test
// @vitest-environment jsdom

import { act, cleanup, render, screen } from "@testing-library/react";
import { useState } from "react";
import { afterEach, expect, it, vi } from "vitest";
import { useMobileVisualViewportHeight } from "./useMobileVisualViewportHeight";

class ControlledViewport extends EventTarget {
  height = 900;
  offsetTop = 0;
  scale = 1;
}

function Shell() {
  const [shell, setShell] = useState<HTMLDivElement | null>(null);
  useMobileVisualViewportHeight(shell, true);
  return <div ref={setShell} data-testid="shell"><textarea data-testid="editor" /></div>;
}

async function settle(milliseconds = 60) {
  await act(async () => {
    await new Promise((resolve) => window.setTimeout(resolve, milliseconds));
  });
}

afterEach(() => {
  cleanup();
  vi.restoreAllMocks();
  vi.unstubAllGlobals();
});

it("restores the shell after dismissal geometry recovers without a second event", async () => {
  const viewport = new ControlledViewport();
  vi.stubGlobal("visualViewport", viewport);
  vi.spyOn(document.body, "clientHeight", "get").mockReturnValue(900);
  vi.spyOn(window, "scrollTo").mockImplementation(() => {});
  render(<Shell />);
  const shell = screen.getByTestId("shell");
  const editor = screen.getByTestId("editor");
  act(() => editor.focus());
  await settle();
  act(() => {
    viewport.height = 580;
    viewport.dispatchEvent(new Event("resize"));
  });
  await settle();
  expect(shell.style.height).toBe("580px");
  act(() => editor.blur());
  expect(shell.style.height).toBe("");
  act(() => viewport.dispatchEvent(new Event("resize")));
  await settle();
  console.log("early resize:", JSON.stringify({ viewport: viewport.height, shell: shell.style.height }));
  viewport.height = 900;
  await settle(1200);
  const afterSilentRecovery = {
    viewport: viewport.height,
    shell: shell.style.height,
    published: document.body.style.getPropertyValue("--bb-shell-height"),
  };
  console.log("silent recovery:", JSON.stringify(afterSilentRecovery));
  act(() => viewport.dispatchEvent(new Event("resize")));
  await settle();
  expect(shell.style.height).toBe("");
  expect(document.body.style.getPropertyValue("--bb-shell-height")).toBe("");
  console.log("control resize: shell and published override cleared");
  expect(afterSilentRecovery.shell).toBe("");
  expect(afterSilentRecovery.published).toBe("");
});

5. Root cause

The update and scheduler run one animation frame per observed event. The geometry mismatch branch applies a short shell override without requiring editor focus. The focus-out handler and listeners clear current geometry but neither schedule bounded post-dismissal reconciliation nor stop a later resize from reapplying old geometry. Once the height getter recovers without an event, no work is pending.

  const scheduleUpdate = () => {
    if (animationFrame !== null) {
      window.cancelAnimationFrame(animationFrame);
    }
    animationFrame = window.requestAnimationFrame(updateHeight);
  };

  const handleFocusOut = (event: FocusEvent) => {
    if (!isKeyboardFocusTarget(event.target)) return;
    if (isKeyboardFocusTarget(event.relatedTarget)) return;
    viewportHeightBeforeKeyboard = null;
    setKeyboardInset(false);
    if (!restoreImmediatelyOnKeyboardDismissal) return;
    if (animationFrame !== null) {
      window.cancelAnimationFrame(animationFrame);
      animationFrame = null;
    }
    clearViewportOverride();
  };

The published custom property is consumed by the shell root height rules; keeping it short explains a raised bottom-aligned composer. The layout caller enables immediate blur restoration for iOS WebKit. The observable defect is the stale style, not the choice of CSS viewport unit. A 320 px layout-versus-shell difference is measured by the test; an actual composer displacement was not measured.

6. Proposed fix

Bound iOS viewport resampling after focus and viewport transitions, reconcile late geometry, cancel sampling on unmount, and preserve non-iOS pan behavior. Preserve keyboard-to-keyboard focus transfers, pinch zoom, hardware-keyboard focus, and safe-area restoration. A bounded settle window must outlast delayed geometry but must not spin indefinitely while a real keyboard remains open. Validate those cases on physical iOS before claiming native correctness.
