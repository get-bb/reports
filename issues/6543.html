#6543 · Inherited-property settings checks and late RPC validation

BugPriority: MediumEffort: MediumpluginsGitHub issueOctober 29, 2026

Verdict: REPRODUCED · Root-cause confidence: high

Trusted base: 3bacfac9ed69d42392076e5b3da2815bec822cd8. Repeated by the same investigator in two separate clean worktrees. This is a service/hook-level reproduction, not a macOS live-app reproduction.

1. TL;DR

Plugin settings validation mistakes properties inherited from JavaScript’s object prototype for declared settings. Through the real plugin service, undeclared constructor and toString settings are accepted and written to a real migrated SQLite database, while an ordinary undeclared key is correctly refused. A plugin that explicitly declares constructor fails to start because registration incorrectly regards the inherited property as an existing setting. Separately, the real SDK query hook calls its host transport once for an unknown method or invalid input before reporting the corresponding validation error. Both clean runs show the same five expected regression failures and three passing controls; the performance comparison in the issue is not verified.

    queryClient.clear();
  }

5. Root cause

Settings membership is prototype-aware rather than declaration-aware

packages/plugin-sdk/src/internal/host-policy.ts:273 uses key in target when registering settings. An empty ordinary object already inherits constructor and toString, so legitimate declarations collide before descriptor parsing.

if (key in target) {
  throw new Error(`setting "${key}" is already defined`);
}

packages/plugin-sdk/src/internal/host-policy.ts:358 looks up descriptors[key] and only checks its truthiness. For the tested inherited names, this produces a function instead of no descriptor. A string update falls through the descriptor-type-specific checks and passes validation.

apps/server/src/services/plugins/plugin-service.ts:1996 calls that validator and then the settings writer. apps/server/src/services/plugins/plugin-settings.ts:102 repeats a prototype-aware descriptor lookup and builds a row update. packages/db/src/data/plugin-storage.ts:90 persists these own enumerable row updates. The database observation therefore comes from the actual writer, not from a mocked store.

RPC transport precedes method/input checks

packages/plugin-sdk/src/internal/rpc-query-host.ts:107 awaits host.call, checks JSON response validity, and only afterward resolves the method contract and validates its input. A JSON-returning host therefore necessarily receives both rejected requests. A transport error can also win before local validation, but that additional behavior was not separately probed.

raw = await host.call(pluginId, method, input);
const result = jsonValueSchema.safeParse(raw);
const methodContract = contract[method];
const parsedInput = await methodContract.input["~standard"].validate(input);

packages/plugin-sdk/src/internal/rpc-query-host.ts:261 additionally parses keyed results with jsonRecordSchema.parse(response.result), after callRpc has already parsed JSON. packages/domain/src/json-value.ts:15 defines the recursive union schema. This establishes repeated traversal from source, not a quantified performance defect.

6. Proposed fix and automatic-fix safety

Use own-property membership for registered settings and settings lookups; define reserved-name behavior explicitly rather than relying on the object prototype. Resolve only owned RPC methods and validate the input before invoking transport, preserving response validation and error normalization. Keep JSON-parser optimization separate until acceptance semantics and benchmarks are established.

No automatic fix PR: the verified repair changes validation at the plugin/host trust boundary, which the caller explicitly excludes from simple automatic fixes. No production patch, fix branch, code push, protocol change, stored-data migration, or dependency change was made. No vulnerability or authorization bypass is asserted by this report. The tests demonstrate failures before any repair, not a passing post-fix result.
