#5416 · Plugin CSS selector construction and menu invalidation

BugPriority: MediumEffort: Mediumui · plugins · perf · partial-reproGitHub issue

October 13, 2026 · Trusted base e9dafb6c0245a37c6972dffa71134d546f3d497e

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: low for the reported interaction latency; high for the demonstrated compiler construction.

1. TL;DR

The reported symptom is a delayed thread menu on a populated, plugin-enabled client. Two clean builds of trusted main reproduce a compiler property that could contribute: nested utility selectors become :is() alternatives containing complex plugin scopes, including an anonymous-root fallback. However, a 7,013-element synthetic browser diagnostic does not show a consistent performance penalty from those styles. The real menu, first-character timing, production plugin mix, and claimed speedup were not reproduced. This report establishes the selector construction, not the claimed half-second menu delay or a validated fix.

5. Root cause and limits

packages/plugin-build/src/build-plugin-app.ts:374 scopes raw compiler.build output. Later packages/plugin-build/src/build-plugin-app.ts:480 runs Tailwind optimize on that already-scoped CSS. packages/plugin-build/src/scope-plugin-utilities.ts:65 emits descendant/self alternatives before nested rules are flattened. Flattening therefore needs an :is() containing those scoped alternatives. packages/plugin-build/src/scope-plugin-utilities.ts:15 adds an anonymous-root branch shared by plugin stylesheets.

return scopePluginUtilities(
  compiler.build([...candidates]),
  pluginScopeRoots(pluginId),
);

const css = optimize(tailwindCss + authoredCss, { minify }).code;

This ordering is the demonstrated cause of selector complexity. Complex selector matching is a plausible contributor to expensive restyles, but the causal link to this issue's latency remains unproven: our synthetic workload shows no clear additional expense. The broader anonymous-root branch also means ownership cannot always prune matching early; its measured cost is not established here.

apps/app/src/components/thread/ThreadActionsMenu.tsx:135 and apps/app/src/components/thread/ThreadActionsMenu.tsx:229 do not pass modal=false. packages/shared-ui/src/components/ui/context-menu.tsx:81 aliases the primitive root. The inherited-pointer-events change was simulated in the diagnostic rather than observed from a live BB menu. That distinction prevents claiming an end-to-end menu reproduction.

Portal ownership is already represented in apps/app/src/lib/portal-scope.ts:14 and packages/shared-ui/src/lib/portal-scope.ts:12. The shared helper's owner is optional, so removal of any fallback still requires compatibility evidence; this report does not establish that every existing artifact stamps an owner.

6. Proposed fix or next experiment

Not confident enough to approve a latency fix from this experiment. Next, seed an isolated trusted-main BB instance with a representative plugin mix and thousands of synthetic thread rows, then record native contextmenu-to-rendered-frame and CDP style CPU. Compare independent changes to compiler ordering and nonmodal menu behavior while holding DOM, assets, and notifications constant. Add browser-rendered checks for root/descendant utilities, owner-stamped portals, other-plugin isolation, sibling containment, hover and focus, and test WebKit.

A first-principles selector simplification would flatten nested utility rules before adding zero-specificity descendant/self scopes, while preserving selector semantics. Any narrowing of anonymous-root support requires compatibility validation for existing portal consumers and prebuilt artifacts. Avoid native CSS @scope, which trusted repository guidance prohibits. Nonmodal menus need keyboard, Escape, focus-return, and outside-interaction verification.
