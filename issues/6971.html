#6971 · Thread storage deletion removes installed plugin sources

BugHighEffort: MediumthreadspluginsGitHub issue

November 4, 2026 · trusted origin/main ea980cbbba15184a846f96fe941478b128bde2da

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

A locally installed plugin continues to depend on the directory it was installed from. When that directory is in thread storage, removing the storage removes its source code as well. The real plugin service installs successfully with zero warnings, cannot reload from disk after deletion, and reports the plugin as missing after a service restart. Its setting remains in SQLite; preserving configuration alone does not preserve executable source. This was reproduced twice against unchanged production code, using a new isolated database and temporary source directory each time.

5. Root cause

Thread storage and installed-plugin source have incompatible lifetimes, with no ownership handoff between them. Registration records the supplied local root unchanged. The warning covers environment-managed workspaces, but thread storage is outside that classifier. Later, storage cleanup recursively removes that same directory without coordinating with the plugin service.

  path: string;

The host daemon removes the thread storage directory

export async function deleteThreadStorage(
  command: CommandOf<"thread.storage.delete">,
  options: CommandDispatchOptions,
): Promise<void> {
  const storagePath = requireContainedPath(
    options.threadStorageRootPath,
    path.join(options.threadStorageRootPath, command.threadId),
    "Thread storage path escapes the storage root",
  );
  await killProcessesWithCwdUnder({ directories: [storagePath] });
  await fs.rm(storagePath, { recursive: true, force: true });
}

Retention is an additional entry point, not a second root cause: its delete action invokes the same thread-delete SDK operation. Database configuration survives because it is not stored in the removed source directory.

6. Proposed fix and simple-fix decision

Before deleting a source-containing directory, preserve the plugin in durable plugin-owned storage and re-register it through the existing path-relocation flow, keeping its identity and settings. Keep local installs in place until cleanup so ordinary plugin development is not silently redirected. Test failed relocation, existing backups, symlinks and dependencies, restart, orphan cleanup, and nonlocal host paths.

No duplicate fix or pull request was created: an open ready PR, #6973, already links this issue with a closing reference. This directly triggers the automation's no-duplicate-PR rule. The focused desired-behavior regression fails on the unchanged base; no production fix was applied in this investigation.
