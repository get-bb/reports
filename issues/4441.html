Reports · Issue #4441

A later model-capacity update changes the context-ring scale

2026-09-30 · Bug · Low priority · Medium effort

PARTIALLY REPRODUCED · High confidence in the tested normalization, projection and display behavior.

Claim, expected result and observed result

The issue reports a 256K compact-window display changing to 1M during a Claude turn and back afterward. The requested behavior is to retain the applicable compact-window denominator while separately recording model capacity and updating usage.

A synthetic sequence calls the real Claude context-report normalizer and SDK usage extractor, creates context-usage events, and passes them to the real thread projection. An optimized browser fixture renders the actual context ring and card. The first three inputs keep used tokens at 128,000. Both clean runs change the projected denominator and actual displayed ratio from 256,000 / 50% to 1,000,000 / 13%, then back to 256,000 / 50%. The middle update also removes the snapshot from the projected output. The ring SVG offset, accessible label and card text all agree; this is a scale change, not increased token usage.

The last control changes synthetic SDK metadata only; it does not perform an actual model switch. Snapshot autoCompactThreshold is deliberately separate: 240,000 for the 256K snapshot and 496,000 for the 512K snapshot. The display uses rawMaxTokens/contextWindowTokens, not that threshold.

Root cause and proposed next change

The real normalizer copies rawMaxTokens to contextWindowTokens and stores autoCompactThreshold separately. The SDK extractor emits a modelContextWindow from model usage, without a snapshot. The projection scans newest events first and resolves both usedTokens and modelContextWindow from the later aggregate update, stopping before the older snapshot. Its snapshot guard cannot retain a snapshot that was never selected. The percentage helper divides usedTokens by modelContextWindow. The card and the ring display that same ratio.

Source inspection also shows post-turn snapshot publication sends snapshot.contextWindowTokens as the context-window size. That lifecycle call was inspected, not executed in this fixture. The test constructs domain events at the boundary; it does not run the bridge transport or server persistence path.

Proposed fix: represent model capacity separately from the applicable display/compact capacity, retain the latter across aggregate usage updates only while its model/session context remains valid, and invalidate or refresh it on model/context-setting changes. Do not retain stale category counts when usage changes. Add transition tests for compact mode enabled/disabled, model changes and fresh snapshots, then exercise a real Claude session to verify metadata origin and ordering. No production fix or PR was created.

import { writeFileSync } from "node:fs";
import assert from "node:assert/strict";
import { normalizeClaudeContextUsage } from "../../../plugins/provider-claude-code/src/bridge/context-usage";
import { extractClaudeContextWindowUsage } from "../../../plugins/provider-claude-code/src/sdk-extraction";
import { extractThreadContextWindowUsage } from "../../../packages/thread-view/src/thread-context-window-usage";
import { threadScope } from "@bb/domain";
const metadata = {capturedAt:"2026-09-30T00:00:00.000Z",providerSessionId:"synthetic-session",providerTurnId:null};
const snapshot = (capacity:number, used=128000) => normalizeClaudeContextUsage({categories:[{name:"Messages",tokens:used}],totalTokens:used,rawMaxTokens:capacity,model:"claude-sonnet-4-6",isAutoCompactEnabled:true,autoCompactThreshold:capacity-16000},metadata);
const streamed = (capacity:number,used=128000,model="claude-sonnet-4-6") => extractClaudeContextWindowUsage({fallbackModelContextWindow:256000,latestRequestContextTokens:used,message:{modelUsage:{[model]:{contextWindow:capacity}}} as never});
const fromSnapshot = (capacity:number,used=128000) => {const s=snapshot(capacity,used);return {snapshot:s,usedTokens:s.usedTokens,modelContextWindow:s.contextWindowTokens,estimated:true};};
const event = (seq:number,contextWindowUsage:any) => ({meta:{seq,id:`synthetic-event-${seq}`,createdAt:Date.parse(metadata.capturedAt)},event:{type:"thread/contextWindowUsage/updated",threadId:"synthetic-thread",providerThreadId:"synthetic-session",scope:threadScope(),contextWindowUsage}} as const);
const signals = [fromSnapshot(256000),streamed(1000000),fromSnapshot(256000),streamed(256000,160000),fromSnapshot(512000),streamed(200000,128000,"claude-haiku-4-5")];
const labels = ["Compact snapshot","Streamed model capacity","Next compact snapshot","Control: increased usage, same capacity","Control: new compact capacity","Control: model capacity transition"];
const steps = signals.map((input,index)=>({label:labels[index],input,usage:extractThreadContextWindowUsage(signals.slice(0,index+1).map((s,i)=>event(i+1,s)))}));
assert.deepEqual(steps.map(s=>s.usage?.modelContextWindow),[256000,1000000,256000,256000,512000,200000]);
assert.deepEqual(steps.map(s=>s.usage?.usedTokens),[128000,128000,128000,160000,128000,128000]);
assert.deepEqual(steps.map(s=>Boolean(s.usage?.snapshot)),[true,false,true,false,true,false]);
writeFileSync(new URL("steps.json",import.meta.url),JSON.stringify(steps,null,2));
console.log(JSON.stringify({checks:"PASS",steps},null,2));
