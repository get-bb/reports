#8111 · Relative file routing requires a resolved workspace root

Bug Priority: Medium Effort: Medium ui GitHub issue · November 24, 2026 · base 718e4e738b

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium

1. TL;DR

The reported browser-versus-desktop difference was not reproduced end to end. On current trusted main, the real message-routing hook and Markdown renderer successfully intercept a relative file link when the workspace root is supplied. Removing only that root leaves the raw relative href and allows the browser's default action; the file-opening callback is never reached. This conditional failure was repeated in a second clean checkout, but it does not establish that the operator's browser was missing its environment data. No live browser navigation, 404 page, or desktop comparison was captured, so this report does not claim full reproduction.

Complete authored reproduction test
// @vitest-environment jsdom

import { cleanup, fireEvent, render, screen } from "@testing-library/react";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { MemoryRouter } from "react-router-dom";
import { afterEach, expect, it, vi } from "vitest";
import {
  ThreadTimelineNavigationProvider,
  useMessageLinkRouting,
} from "@/components/thread/timeline/ThreadTimelineNavigationContext";
import { AppNavigationHostProvider } from "@/lib/app-navigation-host";
import { RouteNavigationProvider } from "./app-route-anchor";
import { LazyMarkdownHtml } from "./lazy-markdown-html";
import { MarkdownPreview } from "./markdown-preview";

await LazyMarkdownHtml.preload();

afterEach(cleanup);

function Message() {
  const routing = useMessageLinkRouting("thr_probe");
  return (
    <MarkdownPreview
      content="[Probe artifact](artifacts/probe.txt)"
      linkRouting={routing}
    />
  );
}

function renderMessage(workspaceRootPath: string | undefined) {
  const openFile = vi.fn(() => true);
  const openUrl = vi.fn(() => false);
  const client = new QueryClient({ defaultOptions: { queries: { retry: false } } });
  render(
    <QueryClientProvider client={client}>
      <MemoryRouter>
        <RouteNavigationProvider>
          <AppNavigationHostProvider capabilities={{ openUrl }}>
            <ThreadTimelineNavigationProvider
              environmentId="env_probe"
              hostId={null}
              onOpenLocalFileLink={openFile}
              resolveMentionLink={() => null}
              threadId="thr_probe"
              workspaceRootPath={workspaceRootPath}
            >
              <Message />
            </ThreadTimelineNavigationProvider>
          </AppNavigationHostProvider>
        </RouteNavigationProvider>
      </MemoryRouter>
    </QueryClientProvider>,
  );
  return { openFile, openUrl };
}

it("observed: browser routing previews relative files when the root is known", async () => {
  const { openFile, openUrl } = renderMessage("/sandbox/project");
  const anchor = await screen.findByRole("link", { name: "Probe artifact" });
  expect(anchor.getAttribute("href")).toBe("file:///sandbox/project/artifacts/probe.txt");
  expect(fireEvent.click(anchor)).toBe(false);
  expect(openFile).toHaveBeenCalledExactlyOnceWith({
    path: "/sandbox/project/artifacts/probe.txt",
    lineRange: null,
    openTargetId: null,
  });
  expect(openUrl).not.toHaveBeenCalled();
});

it("observed: missing root leaves a relative URL and allows default navigation", async () => {
  const { openFile, openUrl } = renderMessage(undefined);
  const anchor = await screen.findByRole("link", { name: "Probe artifact" });
  expect(anchor.getAttribute("href")).toBe("artifacts/probe.txt");
  expect(fireEvent.click(anchor)).toBe(true);
  expect(openFile).not.toHaveBeenCalled();
  expect(openUrl).toHaveBeenCalledExactlyOnceWith({ url: "artifacts/probe.txt" });
});

it("desired: a workspace file click never escapes while the root is unavailable", async () => {
  renderMessage(undefined);
  const anchor = await screen.findByRole("link", { name: "Probe artifact" });
  expect(fireEvent.click(anchor)).toBe(false);
});

5. Root cause and limits

The conditional fallback is fully explained by the current core path:

  1. ThreadDetailView obtains environment data from a query, then passes environment?.path ?? undefined into timeline navigation. A query that has not supplied data therefore leaves the root absent. This is a possible state, not a captured explanation of the original user's session.
  2. useMessageLinkRouting installs the local-file callback, but omits relativeLinks when workspaceRootPath is undefined: 
    const relativePaths =
  workspaceRootPath === undefined
    ? undefined
    : { baseDir: workspaceRootPath, rootPath: workspaceRootPath };
  3. Relative resolution returns null without relative routing. resolveMarkdownLinkTarget then classifies the href as a generic URL.
  4. openMarkdownLinkTarget only cancels the generic URL click when a URL opener accepts it. With no accepting host URL opener, the click falls through.
  5. MarkdownAnchor keeps the unresolved href and sets target="_blank" for non-fragment links. Ordinary browser resolution would use the document URL as the base; this does not prove same-tab navigation or the exact final URL.

Confidence is high in this conditional mechanism and medium in its relevance to the report. No browser-only branch in the tested routing hook was needed to produce either result. The cause of any actual cross-client difference remains unknown. Current code has also been reorganized since the source paths cited by the filer; this report links only files verified at the recorded current main commit.

6. Proposed fix / next experiment

First inspect the failing browser's environment query and timeline inputs at click time, and compare with desktop: environment ID, query status, and presence of a workspace path. In an isolated real app, delay or fail that environment request and compare a click before and after it resolves. If the missing-root state is the real trigger, preserve file-link routing until the environment is ready or explicitly defer the click; do not invent an absolute root or broaden file-path trust. The intended behavior for unresolved relative links needs to be established before selecting a patch.

No fix PR was opened. The normal known-root control works on trusted main, the original client difference remains unverified, and treating every unresolved relative URL as a workspace file would make an unsupported routing-policy decision. No existing linked open PR was found in the issue's connected/cross-referenced metadata; no PR branches or external patches were checked out.
