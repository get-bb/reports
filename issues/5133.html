#5133 · Credential forwarding requires a primary host

Bug Priority: Medium Effort: Low host

2026-10-07 · GitHub issue · Trusted base 0146d8122e6fa84f84e3add46baf7a93362bf571

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

A server without a local host daemon can report that its built-in GitHub login is ready while contributing no credentials to an enrolled machine. The server-side environment resolver requires a non-null primary-host identifier before it loads the automatic GitHub environment bundle. Missing local-host state therefore suppresses that bundle even when credential forwarding is enabled and the credential loader succeeds. A focused test exercises the real resolver, database, environment encryption and status function with a synthetic GitHub CLI; no real accounts or private repositories are used. This reproduces the credential-selection defect, not a complete Kubernetes deployment or a live private clone.

Full reproduction test
import { createConnection, migrate, noopNotifier, setAppSettings, upsertHost } from "@bb/db";
import { defaultAppSettings } from "@bb/domain";
import { mkdir, mkdtemp, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import { delimiter, join } from "node:path";
import { expect, it, vi } from "vitest";
import { resolveHostEnvironment } from "./host-environment.js";
import { machineEnvironmentView, replaceMachineEnvironment } from "../machines/environment-settings.js";

it("forwards enabled GitHub credentials without a local host daemon", async () => {
  const db = createConnection(":memory:");
  const dataDir = await mkdtemp(join(tmpdir(), "bb-issue-5133-"));
  try {
    migrate(db);
    upsertHost(db, noopNotifier, { id: "fixture-remote", name: "Fixture remote" });
    setAppSettings(db, { ...defaultAppSettings, machineGitCredentialsEnabled: true });
    const binDir = join(dataDir, "bin");
    await mkdir(binDir);
    await writeFile(join(binDir, "gh"), `#!/bin/sh
case "$1" in
  auth) printf 'synthetic-fixture-value\\n' ;;
  api) printf '{"login":"fixture-user","id":123,"email":null}\\n' ;;
  *) exit 1 ;;
esac
`, { mode: 0o700 });
    vi.stubEnv("PATH", `${binDir}${delimiter}${process.env.PATH ?? ""}`);
    const deps = { db, config: { dataDir } };
    const context = { hostId: "fixture-remote", projectId: null };
    const status = await machineEnvironmentView(db);
    expect(status.builtInGit.status).toBe("logged in");
    const serverOnly = await resolveHostEnvironment(deps, context);
    console.log(`SERVER_ONLY ${JSON.stringify({ status: status.builtInGit.status, names: serverOnly.map((entry) => entry.name) })}`);

    await writeFile(join(dataDir, "host-id"), "fixture-primary");
    const withPrimary = await resolveHostEnvironment(deps, context);
    expect(withPrimary.some((entry) => entry.name === "GH_TOKEN")).toBe(true);
    expect(withPrimary.some((entry) => entry.name === "GIT_CONFIG_COUNT")).toBe(true);
    console.log("NON_PRIMARY_CONTROL token_present=true git_config_present=true");

    await writeFile(join(dataDir, "host-id"), "fixture-remote");
    expect(await resolveHostEnvironment(deps, context)).toEqual([]);
    console.log("PRIMARY_CONTROL forwarded_entries=0");

    await rm(join(dataDir, "host-id"));
    setAppSettings(db, { ...defaultAppSettings, machineGitCredentialsEnabled: false });
    expect(await resolveHostEnvironment(deps, context)).toEqual([]);
    console.log("DISABLED_CONTROL forwarded_entries=0");

    await replaceMachineEnvironment(db, dataDir, { variables: [{ name: "GH_TOKEN", value: "synthetic-override-value", note: null }] });
    const overridden = await resolveHostEnvironment(deps, context);
    expect(overridden.some((entry) => entry.name === "GH_TOKEN")).toBe(true);
    expect(overridden.some((entry) => entry.name === "GIT_CONFIG_COUNT")).toBe(true);
    console.log("OVERRIDE_CONTROL token_present=true git_config_present=true");

    expect(serverOnly.map((entry) => entry.name)).toContain("GH_TOKEN");
    expect(serverOnly.map((entry) => entry.name)).toContain("GIT_CONFIG_COUNT");
  } finally {
    vi.unstubAllEnvs();
    db.$client.close();
    await rm(dataDir, { recursive: true, force: true });
  }
});

5. Root cause

The primary-host reader returns null if its identity file is absent, unreadable or blank. The environment resolver then treats that absence as a reason not to load any automatic credentials:

const builtIn =
  primaryHostId !== null &&
  primaryHostId !== context.hostId &&
  getAppSettings(deps.db).machineGitCredentialsEnabled
    ? await resolveGitCredentials()
    : [];

The null check conflates “there is no local daemon to exclude” with “do not forward to any enrolled host.” The host-existence/destroyed check and the automatic-forwarding setting remain separate gates.

The status function checks the setting, overrides and server-side credential health, but not the primary-host gate. Its logged in result truthfully describes the server credential source; it does not establish successful machine delivery. This mismatch makes the resolver failure hard to diagnose.

Explicit global/project values are merged separately; if a user GH_TOKEN exists and the automatic bundle is empty, the resolver adds Git configuration. That path explains the working override control.

The affected owner is shared by thread runtime setup, project clone preparation, environment attachment and host environment snapshots. These are static caller traces, not claims of end-to-end execution.

6. Proposed fix and automation safety

Evaluate forwarding from the enrolled-host identity, the forwarding setting and whether the target equals a real primary host; do not make primary-host existence a prerequisite for all forwarding. Preserve primary-host exclusion, disabled-forwarding behavior, missing/destroyed-host rejection and explicit-user precedence. Retain the regression test and consider clarifying that the status field describes source health rather than successful per-machine delivery.

No automatic fix or pull request: this change expands the machines receiving server GitHub authentication credentials.
