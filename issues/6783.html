1. TL;DR

The Claude Code provider drops a command's human-readable description when constructing its command presentation. It also replaces every failed command's exit status with 1, even when the result explicitly reports another status. Replaying provider messages through the real translator and shared event assembler reproduces both losses. The same agent repeated the test in a second clean checkout, with identical results. This is a translation-level reproduction, not a browser or authenticated live-Claude test.

5. Root cause

The Bash parser only constructs command, cwd, background and sandbox metadata; it does not propagate description:

interface ClaudeBashCommand {
  command: string;
  cwd: string | null;
  background: boolean;
  sandboxOverridden: boolean;
}

export function parseClaudeBashCommand(
  input: unknown,
): ClaudeBashCommand | null {
  const parsed = bashArgsSchema.safeParse(input);
  if (!parsed.success) {
    return null;
  }
  const command = toOptionalString(parsed.data.command);
  if (!command) {
    return null;
  }
  const background = claudeBackgroundFlagSchema.safeParse(input);
  const sandboxOverride = claudeSandboxOverrideFlagSchema.safeParse(input);
  return {
    command,
    cwd: toOptionalString(parsed.data.cwd) ?? null,
    background:
      background.success && background.data.run_in_background === true,
    sandboxOverridden:
      sandboxOverride.success &&
      sandboxOverride.data.dangerouslyDisableSandbox === true,
  };

Command presentation always uses the raw command as its title. Classification forwards only the parsed metadata.

export function commandPresentation(args: {
  command: string;
  background: boolean;
  sandboxEscaped: boolean;
}): DeltaPresentation {
  const presentation = withTitle(
    {
      label: args.background
        ? {
            pending: "Starting background command",
            completed: "Started background command",
          }
        : { pending: "Running command", completed: "Ran command" },
      icon: { glyph: "Terminal" },
    },
    presentationTitle(args.command),
  );

Terminal close fields derive exitCode solely from the boolean error flag:

function terminalCloseFields(
  shape: DeltaItemShape,
  outputText: string | undefined,
  isError: boolean,
): Pick<
  Extract<ThreadDelta, { kind: "item.close" }>,
  "exitCode" | "aggregatedOutput" | "resultText"
> {
  switch (shape.type) {
    case "command":
      return {
        exitCode: isError ? 1 : 0,
        ...(outputText === undefined ? {} : { aggregatedOutput: outputText }),
      };
    case "fileRead":
    case "search":
    case "delegation":
      return {};
    default:
      return outputText === undefined ? {} : { resultText: outputText };
  }

The completion path has the original result content but never parses its exit-status header. Output extraction prefers structured stdout/stderr, so parsing only the displayed output would still miss some headers. A trusted recorded transcript also contains a real failed-command header with code 2 (fixture).

Deeper rendering constraint

The shared timeline renderer deliberately excludes command rows from its presentation-title path and then selects raw command text. Consequently, merely preserving the description in the provider presentation does not make it visible in command titles. Both UI and CLI text formatting rely on this shared title builder (renderer; CLI formatting).

function mapExecutionTitle(row: TimelineExecutionWorkRow): TimelineTitle {
  const status = displayStatus({
    approvalStatus: row.approvalStatus,
    status: row.status,
  });
  const isCommand = row.workKind === "command";
  if (
    row.presentation &&
    status !== "waiting" &&
    status !== "denied" &&
    !isCommand
  ) {
    return presentedTitle({
      presentation: row.presentation,
      status,
      startedAt: row.startedAt,
      completedAt: row.completedAt,
    });
  }
  const content = isCommand
    ? row.command
    : formatToolCallCommand(row.toolName, row.toolArgs);

6. Proposed fix and stopped local candidate

Preserve the optional provider description using the existing presentation title, retaining raw command data and its fallback title. Parse only a leading failure-result exit-code header, validate it as a safe integer, and keep the existing 0/1 fallback. Read the original result text independently of aggregated stdout/stderr. A complete user-visible repair also needs a shared renderer change, with UI/CLI regression coverage and preservation of command approval behavior.
