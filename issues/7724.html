#7724 · Panel selection tears down terminal client sessions

BugPriority: MediumEffort: MediumuiperfGitHub issueNovember 17, 2026

Trusted base: 7889bd2b5d960b6a414d0708e8bae06ddc9d95a2 (origin/main, fetched and compared with the target repository).

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high · Reproduction label: partial-repro

1. TL;DR

Selecting another side-panel tab unmounts the terminal content instead of retaining its client session. A behavioral regression against the real secondary-panel component starts the same content twice and cleans it up once after a round trip; this fails the expected single-mount assertion in two separate trusted checkouts. Separately, two fresh instances of the production WebSocket transport each request sinceSeq=0 and receive the same roughly 518 KB of actual retained terminal output, verified against two fresh local server/daemon instances. The source connects these observations: terminal cleanup disposes xterm and its transport, and the next mount recreates both. The exact visible scrolling, elapsed return delay, and macOS desktop/thread-navigation journey were not driven, so this is deliberately a partial rather than full end-to-end reproduction.

Complete real-transport replay helper
import assert from "node:assert/strict";
import { createHash } from "node:crypto";
import { resolve } from "node:path";
import { pathToFileURL } from "node:url";

const { TerminalWebSocketTransport } = await import(pathToFileURL(resolve(
  process.cwd(),
  "packages/client-core/src/terminal/terminal-websocket-transport.ts",
)).href);
const [port, terminalId] = process.argv.slice(2, 4);
const url = "ws://127.0.0.1:" + port + "/ws/terminals/" + terminalId;
const attachments = [];

async function attach() {
  const socketUrls = [];
  const chunks = [];
  let replayEnd = null;
  let complete;
  let fail;
  const finished = new Promise((resolve, reject) => {
    complete = resolve;
    fail = reject;
  });
  const timeout = setTimeout(() => fail(new Error("Replay did not finish")), 10000);
  const transport = new TerminalWebSocketTransport({
    url,
    shouldReconnect: () => false,
    createSocket: (socketUrl) => {
      socketUrls.push(socketUrl);
      return new WebSocket(socketUrl);
    },
    onMessage: (message) => {
      if (message.type === "error") fail(new Error(message.message));
      if (message.type === "attached") {
        replayEnd = message.nextSeq;
        if (message.replayStartSeq === replayEnd) complete();
      }
      if (message.type === "output") {
        chunks.push({ seq: message.chunk.seq, bytes: Buffer.from(message.chunk.dataBase64, "base64") });
        transport.acknowledgeOutput(message.chunk.seq + 1);
        if (message.chunk.seq + 1 === replayEnd) complete();
      }
    },
  });
  try {
    transport.start();
    await finished;
    const output = Buffer.concat(chunks.map((chunk) => chunk.bytes));
    assert.ok(output.length > 0, "terminal must have output to replay");
    return {
      sinceSeq: new URL(socketUrls[0]).searchParams.get("sinceSeq"),
      outputMessages: chunks.length,
      replayBytes: output.length,
      firstSeq: chunks[0].seq,
      nextSeq: replayEnd,
      sha256: createHash("sha256").update(output).digest("hex"),
    };
  } finally {
    clearTimeout(timeout);
    transport.dispose();
  }
}

attachments.push(await attach(), await attach());
console.log(JSON.stringify({ attachments }, null, 2));
assert.equal(attachments[0].sinceSeq, "0");
assert.equal(attachments[1].sinceSeq, "0");
assert.equal(attachments[0].sha256, attachments[1].sha256);
assert.ok(attachments[1].replayBytes > 100000);
console.log("Two fresh transports replayed the identical retained output from sinceSeq=0.");

5. Root cause

The client lifetime is incorrectly tied to selected panel content. The session and retained output exist on the server/daemon, but the xterm screen buffer and browser transport are local to one mounted terminal view.

  1. The panel renders only its active non-browser tab: 
    const surfaceContent =
  activeSurfaceTab === null || isBrowserSurfaceActive || holdsPanelContent
    ? null
    : activeSurfaceTab.renderContent(paneRenderContext);
    Changing to another tab therefore removes the terminal content from that surface. This is what the behavioral test observes.
  2. The terminal effect cleanup destroys both client resources: 
    transport?.dispose();
terminal?.dispose();
terminalRef.current = null;
    The effect returns that cleanup and is keyed by session identity. Thread changes that replace the owning view or session consequently cannot retain this client through the existing effect.
  3. A mount creates a new xterm terminal and a new transport. Each transport starts at output sequence zero; connect builds its socket URL from that sequence. Both live checks confirm the zero-offset reattach.
  4. Browser attachment asks the daemon for a bounded tail. The limit is 512 × 1024 bytes. Completion sends attached metadata followed by output chunks. This is an ordinary attach/replay, not evidence that the PTY restarted.
  5. Replay still calls xterm's writer, and each received output message is decoded and written. That explains why a newly visible empty renderer can paint history while the replay arrives, though this run does not measure its paint timing.

The browser deck has a separate retained rendering path. Adding keepMounted to a child loader alone cannot prevent unmount when its parent stops rendering that loader.

6. Proposed fix and simple-fix gate

Separate terminal client ownership from the currently selected panel/thread view. Retain xterm and its active transport by terminal identity while hiding or reparenting presentation; notify the transport of visibility changes, re-fit on show, and avoid stale focus/selection/link callbacks when another thread owns the visible surface. Dispose on terminal closure and define bounded eviction/cleanup for hidden sessions so repeated thread navigation cannot accumulate renderers, sockets, or WebGL contexts indefinitely. Saving only the sequence cursor is insufficient because a newly created xterm would lack the prior screen buffer.

No production fix or PR was attempted. A tab-only retention change cannot address thread-navigation lifetime. Selecting the cross-thread owner and its eviction/cleanup policy is an architecture/lifecycle decision, which fails this rule's simple-fix condition even if a small patch could hide one symptom. The exact desktop journey is also unverified. The failing test is preserved inline as evidence, not landed as a failing repository test.

No linked open PR or matching open PR was found in the issue timeline and GitHub search. A closed, unmerged proposal appeared during the final metadata check; its diff was read only, as described below. No PR branch was checked out or executed.
