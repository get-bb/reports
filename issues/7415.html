#7415 · Account shell omitted from terminal fallback

BugPriority: LowEffort: Lowhost, workspaces GitHub issue2026-11-11 · base 9816b9420d76b47c3cbff99fcc620c38527f0388

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

On the Unix terminal-opening path, an absent, empty, or unusable inherited SHELL makes bb choose an executable hardcoded shell rather than the shell stored in the user's account. A focused test reaches the real terminal manager and resolver with a synthetic account-shell executable and observes the executable handed to the PTY adapter. Both clean trusted checkouts choose /bin/bash instead of that account shell on this Linux host; macOS would try /bin/zsh first if it is executable. The tested repair inserts account-shell discovery before the hardcoded candidates without changing explicit environment precedence, Windows handling, or the wire protocol.

5. Root cause

apps/host-daemon/src/terminals/terminal-manager.ts:394 builds candidates from the environment followed only by hardcoded Unix paths. The account database is never consulted. An executable path known only through the account shell cannot win because it is not a candidate.

const candidates = [
  process.env.SHELL,
  "/bin/zsh",
  "/bin/bash",
  "/bin/sh",
].filter(isNonEmptyString);

for (const candidate of candidates) {
  if (await pathIsExecutable(candidate)) {
    return candidate;
  }
}

apps/host-daemon/src/terminals/terminal-manager.ts:520 installs this resolver when no override is supplied. apps/host-daemon/src/terminals/terminal-manager.ts:602 awaits it and passes the result directly as the PTY executable. Thus no UI rendering, CLI parsing, or PATH probe is needed to explain the wrong program selection.

Additional static evidence: packages/process-utils/src/host-toolchain.ts:190 and packages/local-open-targets/src/index.ts:1336. These are separate consumers, not prerequisites for repairing the terminal manager.

6. Proposed and tested fix

On Unix, obtain the account shell from the operating system and try it after the inherited environment shell but before the hardcoded fallbacks. Keep executable checks for every candidate, keep the Windows branch unchanged, and tolerate account lookup failure. The repair touches only the existing host terminal subsystem.

let loginShell: string | undefined;
try {
  loginShell = os.userInfo().shell ?? undefined;
} catch {}
const candidates = [
  process.env.SHELL,
  loginShell,
  "/bin/zsh",
  "/bin/bash",
  "/bin/sh",
].filter(isNonEmptyString);
