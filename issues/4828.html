#4828 · Codex SSE completion incorrectly depends on EOF

BugMedium priorityLow effort providersprovider-codex GitHub issue2026-10-03 · base 76a1ebcaf5fa038d8638daaad7aad3dafe2ae709

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

The Codex helper-inference client can time out even after the server has sent its final text and an explicit completion event. Its SSE reader records that text but continues waiting for the HTTP body to close; it also ignores the [DONE] sentinel. An offline regression test at the real inference boundary reproduces this on trusted main, and a second clean checkout repeats the same failures. The narrow fix ends reading at a successful terminal event and cancels the remaining body, preserving error handling and text validation. This does not establish the cause of the originally reported live five-second naming timeout.

function setupFetchMock(): FetchMock {

function sseResponse(events: JsonValue[]): Response {
  return new Response(
    `${events.map((event) => `data: ${JSON.stringify(event)}`).join("\n\n")}\n\ndata: [DONE]\n\n`,
    {
      status: 200,
      headers: {
        "content-type": "text/event-stream",
      },
    },
  );
}

function stalledSseResponse(): Response {
  return new Response(new ReadableStream<Uint8Array>(), {
    status: 200,
    headers: {
      "content-type": "text/event-stream",
    },
  });
}

function openSseResponse(events: JsonValue[]): {
  response: Response;
  wasCanceled: () => boolean;
} {
  let canceled = false;
  const bytes = new TextEncoder().encode(
    `${events.map((event) => `data: ${event === "[DONE]" ? event : JSON.stringify(event)}`).join("\n\n")}\n\n`,
  );
  return {
    response: new Response(
      new ReadableStream<Uint8Array>({
        start(controller) {
          controller.enqueue(bytes);
        },
        cancel() {
          canceled = true;
        },
      }),
      {
        status: 200,
        headers: {
          "content-type": "text/event-stream",
        },
      },
    ),
    wasCanceled: () => canceled,
  };
}

function delayedSseResponse(delayMs: number, events: JsonValue[]): Response {
  const bytes = new TextEncoder().encode(
    `${events.map((event) => `data: ${JSON.stringify(event)}`).join("\n\n")}\n\ndata: [DONE]\n\n`,
  );
  return new Response(
    new ReadableStream<Uint8Array>({
      start(controller) {
        setTimeout(() => {
          try {
            controller.enqueue(bytes);
            controller.close();
          } catch {}
        }, delayMs);
      },
    }),
    {
      status: 200,
      headers: {
        "content-type": "text/event-stream",
      },
    },
  );
}

function requiredFetchCall(fetchMock: FetchMock, index: number) {
  const call = fetchMock.mock.calls[index];
  if (!call) {
    throw new Error(`Missing fetch call at index ${index}`);
  }
  return call;
}

function headersFromInit(init: RequestInit | undefined): Headers {
  const headers = init?.headers;
  if (!(headers instanceof Headers)) {
    throw new Error("Expected request headers to be a Headers instance");
  }
  return headers;
}

function textBodyFromInit(init: RequestInit | undefined): string {
  const body = init?.body;
  if (typeof body !== "string") {
    throw new Error("Expected request body to be a string");
  }
  return body;
}

function formDataBodyFromInit(init: RequestInit | undefined): FormData {
  const body = init?.body;
  if (!(body instanceof FormData)) {
    throw new Error("Expected request body to be FormData");
  }
  return body;
}

5. Root cause

The registered AI service uses a five-second inference deadline and calls codex.ai.complete. The host handler delegates to completeCodexInference and converts failures to service results. completeCodexInference passes the response to the exact SSE reader exercised by the test.

The reader's outer loop only exits normally when reader.read() returns done=true. The inner loop recognizes successful completion solely to store finalText; it does not exit the outer loop. It explicitly skips [DONE]. Thus the next body read waits for EOF, and the shared deadline rejects despite usable output.

Existing tests covered immediate EOF, stalled streams, aborts, size limits, and terminal failures, but not a successfully completed response whose transport remained open. No server policy, auth, database, schema, or public wire change is required.

6. Proposed fix

Treat response.completed, response.done, and [DONE] as terminal after checking provider failures. Stop reading and best-effort cancel the body. Prefer final response output when present; otherwise retain collected deltas. Run the existing empty-output validation after cancellation. Keep deadline, abort, payload limits, and stream-error classification unchanged.
