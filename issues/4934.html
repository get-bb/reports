#4934 · Native image result retains file-read classification

Bug Priority: Low Effort: Low providers provider-claude-code partial-repro GitHub issue

October 5, 2026 · trusted origin/main base 0bd81a2523a11e1d39cb815683fce36578c91181

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high

1. TL;DR

A successful native Claude Read result containing image data still becomes an ordinary file-read timeline item. The translator preserves the classification chosen when the tool started, before its result was known. Two clean trusted-source runs reproduce this gap through the actual translator and shared delta assembler. The existing app renderer selects its expandable image body only for image-view items, so this classification explains the missing preview. Live Claude delivery, actual host-file fetching, and browser rendering were not exercised; this report does not claim a visual end-to-end reproduction.

function startTool(
  harness: ReturnType<typeof createClaudeDeltaHarness>,
  input: Record<string, unknown>,
  toolName = "Read",
  threadId = "",
) {
  return harness.translate(
    {
      type: "assistant",
      message: {
        role: "assistant",
        content: [{ type: "tool_use", id: "read-1", name: toolName, input }],
      },
      session_id: "session-1",
    },
    { threadId },
  );
}

function completeTool(
  harness: ReturnType<typeof createClaudeDeltaHarness>,
  content: unknown,
  isError = false,
  threadId = "",
) {
  return harness.translate(
    {
      type: "user",
      message: {
        role: "user",
        content: [
          {
            type: "tool_result",
            tool_use_id: "read-1",
            content,
            is_error: isError,
          },
        ],
      },
      session_id: "session-1",
    },
    { threadId },
  );
}

5. Root cause

Read start classification creates a fileRead shape and read presentation for a valid path. This is appropriate before the result arrives:

    case "Read": {
      const parsed = claudeReadArgsSchema.safeParse(input);
      const path = parsed.success
        ? (toOptionalString(parsed.data.file_path) ??
          toOptionalString(parsed.data.path))
        : undefined;
      return path
        ? {
            shape: { type: "fileRead", path },
            presentation: fileReadPresentation(path),
          }
        : genericTool(toolName, input);

Result extraction retains raw result content, including image blocks, but does not identify them. Completion translation selects the stored classification and emits its original shape and presentation unchanged:

      const base =
        started ??
        classifyClaudeToolResultFallback(result.toolName, sessionCwd);
      const status = result.isError ? "failed" : "completed";
      deltas.push({
        kind: "item.close",
        key: { providerItemId: result.toolUseId, ...parentRefField },
        status,
        ...terminalCloseFields(base.shape, outputText, result.isError),
        item: terminalToolShape(base.shape, outputText),
        presentation: base.presentation,
      });
      if (resultToolName !== undefined) {

The raw text extractor cannot establish an image-view classification. The missing step is successful, validated native image-result recognition at completion, with the already-known Read path preserved.

The shared assembler already supports imageView. The timeline renderer already routes image-view to the image body but returns no details for file-read. That body resolves the host path and opens the larger viewer. No shared UI or protocol addition is necessary for the classification repair.

6. Proposed fix and safety gate

Validate image content at the native result boundary using the SDK's base64 or URL image-source shapes. Only a successful result with a prior fileRead classification and known path should complete as imageView, using the existing presentation vocabulary and the same item key. Preserve text-only, malformed, missing-path, unrelated-tool, and failed-result behavior.

A local candidate implements this contained provider-only change: four files, 293 text lines changed (291 added, 2 removed), no dependency, binary, generated file, protocol, or stored-data change. Four permission failures are consistent with the suite running as uid 0 and the existing root bypass guard; the discovery failure was not further diagnosed. They were not changed, bypassed, or hidden to satisfy the gate.
