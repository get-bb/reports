#4793 · Prepend compensation waits for an unrelated shell commit

Bug Medium priority Low effort ui · GitHub issue · October 3, 2026

Trusted base: 32efd2e3f2cd5fe072d56c880c6c94db61612089, fetched from get-bb/bb main.

Verdict: REPRODUCED at the production component boundary. Root-cause confidence: high. Reproduction label: confirmed-repro.

1. TL;DR

Loading earlier messages records a position that should be compensated when the content grows. The scroll shell notices growth through its ResizeObserver, but that callback does not consume the prepend anchor. A later scroll updates the anchor's position while retaining its old content height. An unrelated shell render then adds the already-completed growth to the reader's new position. In a controlled production-component test the scroll value becomes 850 instead of staying at 550; the same result occurs in a second clean checkout.

5. Root cause

Capture and consume save height and offset in a ref. Consumption is in a layout effect without dependencies; a nonpositive delta leaves the ref alive.

const delta = scrollArea.scrollHeight - anchor.scrollHeight;
if (delta <= 0) return;
scrollArea.scrollTop = anchor.scrollTop + delta;
pendingPrependAnchorRef.current = null;

Scroll synchronization updates only pendingPrependAnchorRef.current.scrollTop for direct user input while a capture is pending. The resize handler updates geometry and performs saved-row/bottom restoration, but never consumes this prepend capture. Descendant rendering or other DOM growth can therefore complete before a scroll-shell commit.

The loader captures before awaiting the older-page callback. This connects the tested context operation to pagination, but the report does not claim a live request trace.

6. Proposed fix and checked implementation

Reuse the existing compensation logic in a stable callback, invoked both by the layout effect and at the start of the existing resize handler. Clear the capture at the first observed positive growth, before any later user movement can reuse its old height. Keep layout-time compensation for synchronous shell commits and the existing continued-scrolling behavior during an in-flight load.

The checked candidate changes two files and 44 total text lines (41 additions, 3 deletions). The earlier native-anchor test now expects compensation at resize rather than at the next shell commit.
