#7518 · Child-card header inherits activity-row elevation

BugPriority: LowEffort: Mediumui GitHub issue2026-11-13 · base 88cf8f644c81fca797ad80bc31bb36a61ce5cc9b

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium · reproduction label: partial-repro

1. TL;DR

The reported symptom is an uneven lower edge on the collapsed child-thread card in the macOS light theme. Two clean checkouts of current main render a header carrying shadow-xs ring-1 ring-border/60 inside a separately bordered, clipped card. The light-theme shadow token has a two-pixel downward offset, giving a concrete candidate for asymmetric lower-edge paint; this elevation comes from the activity-row helper, not the outer card token. The disclosure divider is indeed transparent while collapsed. This investigation confirms the nested styling but does not confirm the visible defect: the available Linux host has no Chrome executable, and macOS desktop is unavailable. No screenshot, pixel measurement, production patch, or passing visual regression is claimed.

5. Root cause: verified styling and remaining hypothesis

The child-card composition supplies a full-width header through activityRowClass("active", ...). The active-row helper includes shadow-xs ring-1 ring-border/60. Class merging replaces dimensions and rounding, but does not remove these elevation utilities: both actual DOM runs confirm they survive.

The outer card uses border-and-background chrome and clips overflow. The light-theme shadow token points two CSS pixels down. The collapsed body reserves a transparent top border at zero opacity. This combination plausibly permits extra header elevation to affect the bottom interior edge while the card clips other edges, but that pixel-level interaction is a hypothesis, not an observed result.

It would be incorrect to diagnose two visible disclosure borders solely from the reserved top border. The strongest confirmed finding is nested header elevation, and the uncertain part is whether removing it resolves the reported macOS appearance.

6. Proposed next experiment and fix safety
