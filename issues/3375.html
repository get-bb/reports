#3375 · Fork eligibility omits archive state

BugPriority: MediumEffort: LowthreadsGitHub issue · 2026-09-10

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The client considers an archived source eligible for forking whenever it has an environment and its provider supports forks. The same helper controls both the timeline fork action and the navigation into the fork composer. The server rejects an archived source during thread creation. A focused regression demonstrates the wrong eligibility result in two clean trusted-base runs. This is a functional eligibility reproduction; the complete desktop/BB Connect interaction and rendered button were not replayed.

  return makeThreadFixture({

      reasoningLevel: "high",
      serviceTier: "fast",

    });
  });

  it("omits unsupported service tier", () => {
    const request = buildForkThreadRequest({
      environmentId: "env_source",
      input: [{ type: "text", text: "Continue from here", mentions: [] }],
      model: "gpt-5",
      permissionMode: "auto",
      projectId: "proj_test",
      providerId: "codex",
      providerSupportsFork: true,
      reasoningLevel: "medium",

      sourceThreadId: "thr_source",
      sourceThreadTitle: "Investigate flaky test",
    });

    expect(request).not.toHaveProperty("serviceTier");
  });

  it("builds a fork request for a generic ACP provider", () => {
    expect(
      buildForkThreadRequest({
        environmentId: "env_source",
        input: [{ type: "text", text: "Continue from here", mentions: [] }],
        model: "gpt-5",
        permissionMode: "auto",
        projectId: "proj_test",
        providerId: "acp-amp",
        providerSupportsFork: true,
        reasoningLevel: "medium",
        serviceTier: undefined,
        sourceSeqEnd: undefined,
        sourceThreadId: "thr_source",
        sourceThreadTitle: "Investigate flaky test",
      }),
    ).toMatchObject({
      originKind: "fork",
      providerId: "acp-amp",
      sourceThreadId: "thr_source",
    });
  });

  it("returns null when the provider cannot fork sessions", () => {
    expect(
      buildForkThreadRequest({
        environmentId: "env_source",
        input: [{ type: "text", text: "Continue from here", mentions: [] }],
        model: "unknown-model",
        permissionMode: "auto",
        projectId: "proj_test",
        providerId: "not-a-provider",
        providerSupportsFork: false,
        reasoningLevel: "medium",
        serviceTier: undefined,
        sourceSeqEnd: undefined,
        sourceThreadId: "thr_source",
        sourceThreadTitle: "Investigate flaky test",
      }),
    ).toBeNull();
  });
});

describe("isThreadForkable", () => {
  it("rejects an archived source and permits it after unarchiving", () => {
    const source = makeThread({ archivedAt: 123 });

    expect(isThreadForkable(source, true)).toBe(false);
    expect(isThreadForkable({ ...source, archivedAt: null }, true)).toBe(true);
  });

  it("is true only with an environment id and a fork-capable provider", () => {
    expect(
      isThreadForkable(makeThread({ environmentId: "env_source" }), true),
    ).toBe(true);
    expect(isThreadForkable(makeThread({ environmentId: null }), true)).toBe(
      false,
    );
    expect(
      isThreadForkable(makeThread({ providerId: "not-a-provider" }), false),
    ).toBe(false);
    expect(isThreadForkable(null, true)).toBe(false);
  });
});

5. Root cause

The helper only includes environmentId and providerId in its input type. Its body returns false for a missing source or environment, then returns the provider capability without consulting archivedAt.

if (sourceThread === null || sourceThread.environmentId === null) {
  return false;
}
return providerSupportsFork;

ThreadDetailView uses that result and supplies the timeline fork handler when true. The fork hook checks the same helper before fetching execution defaults and navigating. MessageActionBar includes the fork action when a callback exists. Meanwhile, thread creation rejects archived sources with sourceThreadId must reference an unarchived thread. The dedicated fork service also rejects archived sources. This is an omitted client lifecycle check against an existing server policy.

6. Proposed fix

Require archivedAt in the shared thread eligibility input and return false when it is non-null. Both existing callers already pass complete threads, so this suppresses the action and prevents the hook from initiating a fork for an archived source. Keep request construction checking provider capability directly: its validated seed has an environment but is not a live thread snapshot. Unarchiving restores eligibility. The server remains authoritative if a source is archived after the composer opens.

The candidate changes 25 text lines (14 additions, 11 deletions) across two existing client-core files. No dependency, stored-data change, migration, generated file, public wire/schema change, or server policy change. The test fails before the fix and passes afterward, including the unarchive control.
