#7314 · Delegated timeline detail request ownership

Bug Priority: Medium Effort: Medium threads provider-codex · GitHub issue

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

Expanding a subagent can load its activity successfully while a second expansion, for a command inside it, requests details using the wrong owner. The command keeps its child turn identity and narrow event range, but the server detail endpoint projects enclosing top-level turns. The client therefore needs the enclosing delegation's turn and source range while retaining the child's item ID. A component regression demonstrates the incorrect request, and a real migrated SQLite fixture reproduces the server rejection and the successful enclosing-scope request. Both reproductions were repeated by the same agent in a second clean checkout.

5. Root cause

The client builds deferred request identity directly from the child row. Its turnId is a subagent turn and its source window covers the command, not the enclosing delegation. The same mistake occurs in both the preload path and the eventual content request; retained-output hydration also reconstructs identity directly from the child.

  • Client identity construction and preloading
  • Expanded deferred content request
  • Retained full-output request
  • Projection requires a matching top-level turn entry
  • Server turns projection mismatch into a 400 error
  • Server locates the child item recursively after projecting the correct enclosing scope
const includesRequestedTurn = projection.entries.some(
  (entry) =>
    entry.kind === "turn" &&
    entry.turn.turnId === args.options.turnId &&
    entry.turn.sourceSeqEnd >= args.options.sourceSeqStart,
);
if (!includesRequestedTurn) {
  return { kind: "missing-match" };
}

Persisted child lifecycle events are insufficient: delegation projection nests their work rather than exposing the subagent as a top-level turn match. Retrying the identical identity repeats the same deterministic error. Changing only the turn ID is also insufficient to preserve the enclosing materialization context; retain the delegation range too.

6. Proposed fix and tested candidate

Carry an enclosing detail source through delegation rendering and resolve child detail identities against that source when the thread matches. Keep the child item ID unchanged. Use the same helper for preload, expanded deferred content, nested delegation loading, and retained full output. Normal top-level rows continue to use their own source. Nested delegations inherit the already-resolved enclosing source; different-thread rows do not adopt another thread's source.

The tested candidate changes five files within the existing app timeline subsystem, totaling 226 text lines (150 additions + 76 deletions). It adds no dependency, generated file, stored-data change, public API, schema, protocol, or security-boundary change.
