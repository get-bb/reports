PARTIALLY REPRODUCED · root-cause confidence: high
The category loss and missing details button reproduce at the real projection and React-rendering boundaries in two clean-source runs. The separate transient disappearance of the ring has not been reproduced.

1. TL;DR

The context total can continue updating while its category breakdown disappears. The shared event projection takes the snapshot only from the event that supplies the latest token count; aggregate-only events therefore replace a previously measured snapshot with no snapshot. The real context card then omits its details button because it has no categories. This is not merely a token-equality comparison problem: older details are discarded even when a later event reports an unchanged total. Neither reproduction made usage null, so they do not explain a ring disappearing immediately after a send.

5. Root cause

  1. The Claude translator has an estimated aggregate context path with no snapshot. A separate bridge path publishes measured snapshots. This establishes the input shapes, not their frequency in a real session.
  2. The shared projection walks newest-first. When it accepts the latest count, it executes snapshot = signal.snapshot. It does not fall back to an older snapshot: assignment. Its final equality guard additionally rejects mismatched snapshot totals and capacity. Changing that guard alone is insufficient.
  3. The card derives details from snapshot categories and only renders the toggle when details exist. The rendering regression executes this exact card, without mocking it.
  4. The server's head-state reader uses the same shared projection. This is not just a local hover-state problem.
  5. Current regression tests deliberately require discarding older details and rejecting mismatched snapshots. The existing focused suite passes all nine cases. These tests date to the measured-breakdown implementation, rather than being a recent accidental equality check.

The separate ring-loss claim needs a client lifecycle trace: the composer gates the ring on non-null usage, but both reproduced projections return non-null usage. This report makes no claim that the send lifecycle is correct.

6. Proposed fix and simple-fix gate

Keep the current aggregate and the last valid measured breakdown as distinct information. A historical breakdown can be shown with its capture time; it must not imply that old category totals sum to the newest aggregate. Invalidate historical data at context-clear, provider-session, capacity, and compaction boundaries as appropriate. Add coverage for unchanged aggregates, increases, decreases, resets, and replacement snapshots.

No pull request: the current shared freshness contract explicitly rejects carrying an older breakdown. Choosing historical breakdowns versus inferred live categories is a product/contract decision; adding an explicit historical field would also change the public context schema. Silently weakening the existing snapshot invariant is not a safe simple fix under this automation's constraints.
