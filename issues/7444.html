#7444 · ACP registry branding coverage drifts from the published catalog

Bug Priority: Low Effort: Low providers provider-acp

GitHub issue · November 11, 2026 · trusted origin/main: 030b1b729f28acedc6f86cd65a71cb3678da8124

REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

Four entries in the published ACP catalog have no corresponding entry in bb’s bundled icon inventory. Calling the real registry-view and configured-provider functions gives null and Toolbox, respectively, for Bob, Kimi Code, Kiro CLI and OpenCode V2. The legacy Kimi and OpenCode entries still resolve to branded icons. This is deterministic ID-to-artwork drift, not a provider startup or malformed-setting problem. Two separate clean checkouts reproduced the same four failures, while all 85 existing ACP tests passed.

import { readFileSync } from "node:fs";
import { describe, expect, it } from "vitest";
import { customAcpAgentDefinition, customAcpAgentSchema } from "./agents.js";
import { describeRegistryAgents, parseAcpRegistry } from "./registry.js";

const snapshot: unknown = JSON.parse(
  readFileSync(new URL("./registry-icon-coverage.snapshot.json", import.meta.url), "utf8"),
);
const { agents } = parseAcpRegistry(snapshot);

describe("published registry branding coverage", () => {
  it.each(agents)("supplies registry artwork for $id", (agent) => {
    const [view] = describeRegistryAgents({
      agents: [agent],
      settingValue: "[]",
      reservedProviderIds: new Set(),
    });
    expect.soft(view?.icon, `${agent.id}: registry view`).not.toBeNull();
    const configured = customAcpAgentSchema.parse({
      id: agent.id,
      displayName: agent.name,
      command: "unused-reproduction-command",
    });
    expect(customAcpAgentDefinition(configured).icon, `${agent.id}: provider definition`).not.toBe("Toolbox");
  });
});

5. Root cause

  1. The registry icon inventory and resolver recognize exactly 41 IDs. The resolver only returns an icon name for an exact set membership match. It has no alias or catalog-driven synchronization.
  2. The registry view turns a missing mapping into icon: null. The registry row then selects Toolbox.
  3. Configured-provider construction independently selects Toolbox when the same resolver returns undefined. No provider launch is needed to reach this branch.
  4. Existing coverage checks that each already-listed ID has a same-named declared asset. It does not compare that inventory to an independently captured catalog.
registryAgentIcon(id) === undefined
  → registry view: null → row renderer: Toolbox
  → configured provider: Toolbox

The network-loaded catalog and static bundled-art inventory have separate lifecycles. A new or renamed upstream ID remains addable without gaining branded art. The asset pipeline is demonstrably functional for already-listed IDs; this does not support a general SVG-mask rendering failure.

6. Proposed fix and simple-fix safety check

Sync the four verified missing IDs with reviewed brand artwork and manifest declarations, retaining generic fallback behavior for genuinely unknown custom agents. The existing Kimi and OpenCode marks can inform any explicitly reviewed alias strategy.
