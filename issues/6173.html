Recursive skill discovery exhausts its scan budget

2026-10-23 · Bug · Priority: Medium · Effort: Low · providers, provider-pi

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

Summary

The host daemon stops finding recursive skills after unrelated supporting files consume its 1,000-entry scan budget. The same budget is shared across roots, so exhausting one root also hides skills in later roots. A filesystem-only regression reproduces both failures in the actual exported skills and commands discovery functions. The same agent repeated all four failures in a second clean checkout at the same trusted main commit.

Regression test source

import { mkdir, mkdtemp, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import path from "node:path";
import { afterEach, beforeEach, describe, expect, it } from "vitest";
import {
  discoverProviderCommands,
  discoverSkills,
  type SkillScanRoot,
} from "./command-discovery.js";

let tempRoot: string;

beforeEach(async () => {
  tempRoot = await mkdtemp(path.join(tmpdir(), "bb-skill-budget-"));
});

afterEach(async () => {
  await rm(tempRoot, { recursive: true, force: true });
});

async function writeSkill(directory: string): Promise<void> {
  await mkdir(directory, { recursive: true });
  await writeFile(
    path.join(directory, "SKILL.md"),
    "---\ndescription: test skill\n---\n",
  );
}

function roots(): SkillScanRoot[] {
  return ["primary", "secondary"].map((name) => ({
    rootPath: path.join(tempRoot, name),
    shape: "skill-recursive",
    namePrefix: "",
    source: "skill",
    origin: "user",
    identitySeed: name,
    rootKind: "provider-user",
  }));
}

describe.each([
  ["commands", discoverProviderCommands],
  ["skills", discoverSkills],
] as const)("recursive %s discovery budgets", (_surface, discover) => {
  it("lists later and nested skills despite large supporting-file directories", async () => {
    const primarySkill = path.join(tempRoot, "primary", "first");
    const assets = path.join(primarySkill, "assets");
    await writeSkill(primarySkill);
    await mkdir(assets);
    for (let index = 0; index < 1_005; index += 1) {
      await writeFile(
        path.join(assets, `asset-${index}.txt`),
        "supporting data",
      );
    }
    await writeSkill(path.join(primarySkill, "nested", "inner"));
    await writeSkill(path.join(tempRoot, "secondary", "second"));

    const records = await discover({ roots: roots() });

    expect(records.map((record) => record.name).sort()).toEqual([
      "first",
      "inner",
      "second",
    ]);
  });

  it("continues with another root after exhausting a directory budget", async () => {
    const primary = path.join(tempRoot, "primary");
    await mkdir(primary);
    for (let index = 0; index < 1_005; index += 1) {
      await mkdir(path.join(primary, `directory-${index}`));
    }
    await writeSkill(path.join(tempRoot, "secondary", "second"));

    const records = await discover({ roots: roots() });

    expect(records.map((record) => record.name)).toEqual(["second"]);
  });
});

Root cause

  1. Depth and entry limits set a 24-level and 1,000-entry bound.
  2. readDirEntries decrements the budget for every entry, including files that cannot lead to another skill.
  3. walkSkillTree records a skill and keeps descending. Supporting-file directories consume the remaining budget even though their files are irrelevant to directory traversal.
  4. discoverProviderCommands and discoverSkills each allocate one budget outside their root loop.
  5. Pi's native-root declaration makes both user roots recursive. History commit 9daa623b3 enabled recursive Pi roots, exposing this pre-existing budget behavior to those roots.

The skills RPC delegates to discoverSkills; server listing assembles the returned per-provider results. Thus the missing records arise before presentation, not in a particular picker or CLI formatter.

Proposed repair and limits

Give each recursive skill root its own bounded budget and charge only candidate directory entries (including permitted user-origin symlinks), not unrelated regular files or excluded directories. Keep descending inside skills. Preserve depth limits, project-root containment, project symlink refusal, user symlink cycle detection, and exclusions. Leave Markdown command discovery's existing entry accounting unchanged.

This does not promise unbounded enumeration: directory-heavy roots can still hit the existing 1,000-candidate limit, and deeply nested roots can still hit the depth limit. It removes file-count truncation and cross-root starvation without removing those traversal safeguards.
