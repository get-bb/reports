#6349 · Canonical tab collisions block synchronization

BugMedium priorityLow effortuiGitHub issue2026-10-26 · base 748a96524eddedbf58d5eb5bd139f1b8b5c4f536

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Saved thread tabs can contain an old built-in tab alongside its current plugin-backed replacement. The app converts both entries to the same identifier, but keeps both entries. Its outgoing validation rejects that duplicate before making an SDK update, leaving the saved state unchanged and future writes blocked. The same normalization also affects local-tab migration. A small client-only fix keeps the first occurrence of each normalized identifier.

5. Root cause

The shared app helper filters nonpersistent tabs, then maps old built-in kinds to plugin-fixed tabs without deduplicating the resulting identifiers. It feeds list equivalence, reconciliation, merge, and migration. Distinct input identifiers can therefore collide after mapping.

apps/app/src/lib/thread-tabs-sync.ts:48

function persistedThreadTabs(
  tabs: readonly (FixedPanelTab | ThreadTab)[],
): readonly PersistedThreadFixedPanelTab[] {
  return tabs
    .filter(
      (tab): tab is PersistedThreadFixedPanelTab =>
        tab.kind !== "side-chat" && tab.kind !== "plugin-page-fixed",
    )
    .map((tab) =>
      tab.kind === "git-diff"
        ? createGitDiffFixedPanelTab()
        : tab.kind === "thread-info"
          ? createThreadInfoFixedPanelTab()
          : tab,
    );

The persistence path deliberately writes when legacy kinds are present. Its schema parse happens during argument evaluation, before the SDK call; migration has the same validation order.

apps/app/src/lib/thread-tabs-sync.ts:253

async function persistThreadTabs({
  previousTabs,
  tabs,
  queryClient,
  threadId,
}: PersistThreadTabsArgs): Promise<void> {
  let current = await readCurrentThreadTabs({ queryClient, threadId });
  for (let attempt = 1; attempt <= MAX_WRITE_ATTEMPTS; attempt++) {
    const tabsToPersist = mergeThreadTabChanges(
      current.tabs,
      previousTabs,
      tabs,
    );
    if (
      !current.tabs.some(
        (tab) => tab.kind === "git-diff" || tab.kind === "thread-info",
      ) &&
      areThreadTabListsEquivalent(current.tabs, tabsToPersist)
    ) {
      return;
    }
    try {
      const response = await sdk.threads.tabs.update({
        expectedRevision: current.revision,
        tabs: threadTabsSchema.parse(tabsToPersist),
        threadId,
      });
      setCachedThreadTabs(queryClient, threadId, response);
      return;
    } catch (error) {
      if (!isThreadTabsConflict(error) || attempt === MAX_WRITE_ATTEMPTS) {
        throw error;
      }
      current = await sdk.threads.tabs.get({ threadId });
      setCachedThreadTabs(queryClient, threadId, current);
    }
  }
}

async function migrateLocalThreadTabs({
  queryClient,
  tabs,
  threadId,
}: MigrateLocalThreadTabsArgs): Promise<void> {
  const current = await readCurrentThreadTabs({ queryClient, threadId });
  if (current.revision !== 0) {
    return;
  }
  const tabsToPersist = persistedThreadTabs(tabs);
  const response = await sdk.threads.tabs.update({
    expectedRevision: 0,
    tabs: threadTabsSchema.parse(tabsToPersist),
    threadId,
  });
  setCachedThreadTabs(queryClient, threadId, response);

The contract checks uniqueness of the supplied raw identifiers, not logical equivalence across historical aliases. This admits the mixed original list and rejects the normalized duplicate list. Rejection prevents a successful update, so the original legacy state survives. This report does not change the public schema.

6. Proposed fix and local verification

After existing normalization, filter by identifier with a local Set, preserving the first occurrence and order of unrelated tabs. Keep the public contract, wire protocol, dependency graph, and database unchanged. This fixes every caller of the shared helper rather than adding retries or masking the validation error.
