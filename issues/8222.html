#8222 · HTTP content encoding is ignored by tunnel compression

BugMedium priorityLow effortremote · connect · perf IssueNovember 26, 2026 · base b0ddaad731565d7e4de68d824120d802fc78f7d5

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro.

1. TL;DR

The Connect tunnel applies WebSocket deflate to HTTP response bodies even when the origin already encoded them with brotli or gzip. This is a redundant transformation of already-compressed bytes, not a corruption of the response. Two clean checkouts of trusted main show the compression bit set on every encoded body message, while preserving the original body bytes. The exact CPU overhead and production Cloudflare extension negotiation were not measured in this investigation.

Complete reproduction test

import { once } from "node:events";
import { randomBytes } from "node:crypto";
import { createServer } from "node:http";
import { brotliCompressSync, gzipSync } from "node:zlib";
import { expect, it } from "vitest";
import { WebSocket, WebSocketServer } from "ws";
import { decodeFrame, encodeFrame } from "@bb/tunnel-contract";
import { TunnelSession } from "../src/session.js";

it.each(["br", "gzip", "identity"])(
  "preserves %s response bytes without redundant WebSocket compression",
  async (encoding) => {
    const source = randomBytes(192 * 1024);
    const body =
      encoding === "br"
        ? brotliCompressSync(source)
        : encoding === "gzip"
          ? gzipSync(source)
          : Buffer.alloc(source.length, "a");
    const origin = createServer((_request, response) => {
      response.setHeader("Content-Length", body.length);
      if (encoding !== "identity") {
        response.setHeader("Content-Encoding", encoding);
      }
      response.end(body);
    });
    const gate = new WebSocketServer({
      host: "127.0.0.1",
      port: 0,
      perMessageDeflate: true,
    });
    let tunnel: WebSocket | undefined;
    let session: TunnelSession | undefined;
    try {
      const originReady = once(origin, "listening");
      origin.listen(0, "127.0.0.1");
      await Promise.all([originReady, once(gate, "listening")]);
      const originAddress = origin.address();
      const gateAddress = gate.address();
      if (
        originAddress === null ||
        typeof originAddress === "string" ||
        typeof gateAddress === "string"
      ) {
        throw new Error("expected local TCP listeners");
      }
      let pending = Buffer.alloc(0);
      const compressionFlags: boolean[] = [];
      const connected = new Promise<WebSocket>((resolve) => {
        gate.once("connection", (socket, request) => {
          request.socket.prependListener("data", (chunk: Buffer) => {
            pending = Buffer.concat([pending, chunk]);
            while (pending.length >= 2) {
              const firstByte = pending[0]!;
              const secondByte = pending[1]!;
              const lengthCode = secondByte & 127;
              const extendedBytes =
                lengthCode === 126 ? 2 : lengthCode === 127 ? 8 : 0;
              const maskBytes = (secondByte & 128) === 0 ? 0 : 4;
              const headerBytes = 2 + extendedBytes + maskBytes;
              if (pending.length < headerBytes) break;
              const payloadBytes =
                lengthCode === 126
                  ? pending.readUInt16BE(2)
                  : lengthCode === 127
                    ? Number(pending.readBigUInt64BE(2))
                    : lengthCode;
              if (pending.length < headerBytes + payloadBytes) break;
              if ((firstByte & 15) === 2) {
                if ((firstByte & 128) === 0) {
                  throw new Error("unexpected fragmented message");
                }
                compressionFlags.push((firstByte & 64) !== 0);
              }
              pending = pending.subarray(headerBytes + payloadBytes);
            }
          });
          resolve(socket);
        });
      });
      tunnel = new WebSocket(`ws://127.0.0.1:${gateAddress.port}`);
      const opened = once(tunnel, "open");
      const peer = await connected;
      await opened;
      expect(tunnel.extensions).toContain("permessage-deflate");
      session = new TunnelSession({
        tunnel,
        log: {
          warn: (message) => {
            throw new Error(message);
          },
        },
        resolveOrigin: () => ({
          kind: "ok",
          resolved: {
            origin: `http://127.0.0.1:${originAddress.port}`,
            publicOrigin: "https://unit.invalid",
          },
        }),
      });
      session.start();
      const receivedChunks: Buffer[] = [];
      const bodyFlags: boolean[] = [];
      let messageIndex = 0;
      const completed = new Promise<void>((resolve, reject) => {
        peer.on("error", reject);
        peer.on("message", (data: Buffer, binary) => {
          if (!binary) return;
          const compressed = compressionFlags[messageIndex++];
          if (compressed === undefined) {
            reject(new Error("missing raw WebSocket header"));
            return;
          }
          const frame = decodeFrame(data);
          if (frame.type === "body-chunk") {
            receivedChunks.push(Buffer.from(frame.data));
            bodyFlags.push(compressed);
          } else if (frame.type === "body-end") {
            resolve();
          } else if (frame.type === "close-stream") {
            reject(new Error(frame.reason));
          }
        });
      });
      peer.send(
        encodeFrame({
          type: "open-http",
          streamId: 11,
          method: "GET",
          path: "/",
          headers: [],
          hasBody: false,
        }),
      );
      await completed;
      expect(Buffer.concat(receivedChunks)).toEqual(body);
      expect(bodyFlags.length).toBeGreaterThan(0);
      const compressedBodyMessages = bodyFlags.filter(Boolean).length;
      console.log(
        JSON.stringify({
          encoding,
          bodyBytes: body.length,
          bodyMessages: bodyFlags.length,
          compressedBodyMessages,
          originPort: originAddress.port,
          gatePort: gateAddress.port,
          integrity: "preserved",
        }),
      );
      expect(compressedBodyMessages).toBe(
        encoding === "identity" ? bodyFlags.length : 0,
      );
    } finally {
      session?.dispose();
      tunnel?.terminate();
      for (const client of gate.clients) client.terminate();
      await new Promise<void>((resolve) => gate.close(() => resolve()));
      origin.closeAllConnections();
      await new Promise<void>((resolve) => origin.close(() => resolve()));
    }
  },
);

5. Root cause

  1. plugins/connect/src/tunnel.ts:443-L451 constructs the tunnel WebSocket without overriding ws compression negotiation. ws 8.22.1 defaults perMessageDeflate to true.
  2. packages/tunnel-client/src/session.ts:448-L462 emits a response header and then converts each origin body chunk into tunnel frames without consulting Content-Encoding:
    for (const frame of chunkBody(streamId, value)) this.send(frame);
  3. packages/tunnel-client/src/session.ts:255-L277 passes every encoded tunnel message through the same raw send:
    this.options.tunnel.send(data);
    The installed ws implementation defaults the send option compress to true, disabling it only if the extension is absent. With a negotiated extension, the response body therefore receives a second compression layer.
  4. apps/server/src/api-response-compression.ts:75-L105 selects and applies an accepted encoding, then sets Content-Encoding. apps/server/src/server.ts:537-L545 installs both JSON and general compression. The raw Node origin HTTP client returns these encoded bytes without decompression.

The deeper mismatch is an unconditional transport-level optimization on a multiplexed channel carrying both already-encoded HTTP bytes and useful-to-compress data. Turning off deflate on the entire tunnel would also disable compression for unencoded responses and realtime traffic.

packages/tunnel-client/src/session.ts:515-L521 already disables compression on the separate loopback relay; that does not disable compression on the main tunnel. The relevant trusted history is the realtime compression change associated with PR #6209.

6. Proposed fix

Choose compression per HTTP response at the body-frame send boundary. For brotli/gzip and other non-identity encodings, pass compress: false only for those body messages. Keep the default for other tunnel messages and unencoded responses. Treat an explicit identity encoding as uncompressed content if that header is supported. Retain buffer backpressure and byte accounting. Use the real-wire regression above and controls for unencoded HTTP and realtime traffic before landing.

No new fix branch or PR was created: GitHub metadata shows an existing open PR #8223 explicitly closes #8222. Creating another would duplicate ongoing work.

7. Static review of linked PR #8223

PR #8223 adds a compression choice to the send helpers and disables it on response-body frames when Content-Encoding is present. That targets the demonstrated root cause while retaining default compression elsewhere. Only GitHub metadata and the diff were read; its branch and tests were never checked out or executed.

  • Low, test-quality limitation: packages/tunnel-client/test/tunnel-compression.test.ts:27 starts a header-driven synthetic response; the body uses repeated zero bytes rather than a real brotli stream. This still detects the send-policy regression, but does not itself validate a genuine encoded response. The separately authored reproduction here supplies valid brotli and gzip bytes.
  • Compatibility edge to consider: packages/tunnel-client/src/session.ts:458 bases the choice on header presence, so explicit Content-Encoding: identity would also skip compression. This does not affect the reproduced brotli/gzip cases; that edge was not executed.
  • Verdict: statically aligned with the root cause; no runtime pass or merge-safety claim about the untrusted branch.
