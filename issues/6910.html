Verdict: NOT REPRODUCED · Root-cause confidence: low · Reproduction label: no-repro

No Android device, emulator, Android SDK, Java runtime, or APK was available. This report does not reproduce the Android failure and does not refute it. A real TLS diagnostic against the production JavaScript probe passes in two clean source checkouts under Node.js. That is not evidence of Android user-CA behavior.

1. TL;DR

The reporter describes an Android direct connection being refused after a private root CA was installed on the device, while a browser can connect. Trusted source confirms that Add Server delegates its health check to the platform fetch implementation, then displays a transport failure without saving the server. The inspected mobile source has no explicit private/user-CA trust configuration, making a native trust-store mismatch a plausible explanation, not a confirmed root cause. A local HTTPS fixture demonstrates that the same production JavaScript probe rejects an untrusted CA, succeeds when Node explicitly trusts that CA, and still rejects a hostname mismatch. Because Node is not Android and no native runtime was available, the issue itself remains unverified and no production fix or pull request is proposed for automatic landing.

Complete diagnostic source
import { execFile } from "node:child_process";
import { once } from "node:events";
import { mkdtemp, readFile, rm, writeFile } from "node:fs/promises";
import { createServer } from "node:https";
import { tmpdir } from "node:os";
import path from "node:path";
import { fileURLToPath } from "node:url";
import { promisify } from "node:util";
import { expect, it } from "vitest";

const execute = promisify(execFile);

it("diagnoses the real probe with untrusted, trusted, and hostname-invalid TLS", async () => {
  const temporary = await mkdtemp(path.join(tmpdir(), "bb-6910-tls-"));
  const port = Number(process.env.BB_6910_PORT ?? "56191");
  const caKey = path.join(temporary, "ca.key");
  const caCertificate = path.join(temporary, "ca.pem");
  const serverKey = path.join(temporary, "server.key");
  const serverRequest = path.join(temporary, "server.csr");
  const serverCertificate = path.join(temporary, "server.pem");
  const extensions = path.join(temporary, "server.ext");
  const requests: string[] = [];
  let server: ReturnType<typeof createServer> | undefined;

  try {
    await execute("openssl", [
      "req", "-x509", "-newkey", "rsa:2048", "-nodes", "-days", "1",
      "-subj", "/CN=BB isolated diagnostic CA", "-keyout", caKey,
      "-out", caCertificate, "-addext", "basicConstraints=critical,CA:TRUE",
      "-addext", "keyUsage=critical,keyCertSign,cRLSign",
    ]);
    await execute("openssl", [
      "req", "-newkey", "rsa:2048", "-nodes", "-subj", "/CN=127.0.0.1",
      "-keyout", serverKey, "-out", serverRequest,
    ]);
    await writeFile(extensions, [
      "basicConstraints=critical,CA:FALSE",
      "keyUsage=critical,digitalSignature,keyEncipherment",
      "extendedKeyUsage=serverAuth",
      "subjectAltName=IP:127.0.0.1",
      "",
    ].join("\n"));
    await execute("openssl", [
      "x509", "-req", "-in", serverRequest, "-CA", caCertificate,
      "-CAkey", caKey, "-CAcreateserial", "-days", "1", "-out",
      serverCertificate, "-extfile", extensions,
    ]);
    server = createServer({
      key: await readFile(serverKey),
      cert: await readFile(serverCertificate),
    }, (request, response) => {
      requests.push(request.url ?? "");
      response.setHeader("content-type", "application/json");
      response.end(JSON.stringify(request.url === "/health"
        ? { ok: true }
        : { serverUrl: "http://127.0.0.1", primaryHostId: null }));
    });
    server.listen(port, "127.0.0.1");
    await once(server, "listening");

    const probeSource = fileURLToPath(new URL("./probe.ts", import.meta.url));
    const program = [
      'import { createRequire } from "node:module";',
      `const { probeServer } = createRequire(import.meta.url)(${JSON.stringify(probeSource)});`,
      "let errorCause = null;",
      "const observedFetch = async (url, init) => {",
      "  try { return await fetch(url, init); }",
      "  catch (error) { errorCause = error.cause?.code; throw error; }",
      "};",
      "const result = await probeServer(process.argv[1], observedFetch);",
      "console.log(JSON.stringify({ result, errorCause }));",
    ].join("\n");
    const runProbe = async (hostname: string, trustCa: boolean) => {
      const { stdout } = await execute(process.execPath, [
        "--dns-result-order=ipv4first", "--import", "tsx",
        "--input-type=module", "--eval", program,
        `https://${hostname}:${port}`,
      ], {
        env: {
          PATH: process.env.PATH,
          ...(trustCa ? { NODE_EXTRA_CA_CERTS: caCertificate } : {}),
        },
        timeout: 12_000,
      });
      return JSON.parse(stdout.trim());
    };

    const untrusted = await runProbe("127.0.0.1", false);
    expect(untrusted.result).toMatchObject({
      ok: false, stage: "health", error: "fetch failed",
    });
    expect(untrusted.errorCause).toBe("UNABLE_TO_VERIFY_LEAF_SIGNATURE");
    expect(requests).toEqual([]);

    const trusted = await runProbe("127.0.0.1", true);
    expect(trusted.result).toMatchObject({ ok: true, advertisedServerUrl: null });
    expect(trusted.errorCause).toBeNull();
    expect(requests).toEqual(["/health", "/api/v1/system/config"]);

    requests.length = 0;
    const hostnameInvalid = await runProbe("localhost", true);
    expect(hostnameInvalid.result).toMatchObject({
      ok: false, stage: "health", error: "fetch failed",
    });
    expect(hostnameInvalid.errorCause).toBe("ERR_TLS_CERT_ALTNAME_INVALID");
    expect(requests).toEqual([]);
    console.log(JSON.stringify({
      runtime: "Node.js surrogate, not Android",
      untrusted, trusted, hostnameInvalid,
    }));
  } finally {
    if (server?.listening) {
      server.closeAllConnections();
      await new Promise<void>((resolve, reject) => {
        server?.close((error) => error ? reject(error) : resolve());
      });
    }
    await rm(temporary, { recursive: true, force: true });
  }
}, 30_000);

5. Root cause: confirmed path, unconfirmed native mechanism

Confirmed: AddServerScreen lines 51–78 calls probeServer(serverUrl, fetch). On failure, lines 60–66 construct the visible connection error and return before profile persistence. probe.ts lines 33–80 uses the supplied transport, catches its exception, exposes its message, and marks the health stage as failed. No CA-loading policy lives in that JavaScript call path.

const probe = await probeServer(serverUrl, fetch);
if (!probe.ok) {
  ...
  setSubmit({ phase: "failed", message: ... });
  return;
}

Source observation: app.json lines 100–109 only sets usesCleartextTraffic in the build-properties plugin; app.config.js lines 22–63 merges Android variant and service configuration without supplying an explicit private/user-CA rule. profile.ts lines 5–26 defines direct profiles with URL and display metadata, not per-server CA trust. These observations explain why a platform trust rejection is not repaired by an app-level CA option in the inspected source; they do not prove which trust anchors the released APK actually loads.

Leading hypothesis, low confidence: native HTTPS is not using the same root trust set as the reporter's browser. Alternative explanations still include a missing intermediate certificate, differences between the installed certificate and the active native trust store, and a build/version mismatch. None can be ruled out without the native experiment. The Node diagnostic demonstrates the transport-to-probe failure mechanism and the need to preserve hostname checks, not Android's defaults or the correctness of the reporter's deployment.

6. Proposed next experiment and fix gate

  1. Build the trusted-main Android release variant and record APK versionCode, target SDK, merged AndroidManifest, network-security XML, and installed artifact hash. Also capture the reporter's actual APK identity.
  2. On a clean Android device/emulator, serve the same health/config fixture at a reachable synthetic hostname with a complete certificate chain and matching SAN. Verify the chain before testing and install only that throwaway root in the Android user CA store.
  3. Compare browser, native Add Server fetch, and the shell WebView. Record native TLS failures with and without the root installed. Include trusted-public-CA, absent-root, expired-leaf, and wrong-hostname controls.
  4. Only after reproducing, choose the trust model explicitly: platform user-root opt-in or scoped per-server trust. Review native fetch and WebView behavior together; retain certificate-chain and hostname verification and cover the trust decision with native tests.

No automatic fix: the bug has not been reproduced on Android against trusted main. Furthermore, accepting additional CA roots changes a security trust boundary and selecting global versus per-server trust needs a product/security decision; both are outside the simple-fix policy. No production code, dependency, branch, push, or pull request was created in get-bb/bb. The passing Node diagnostic is not a failing-before/passing-after Android regression.
