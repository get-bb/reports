#5838 · CLI transport lacks managed-run write protection

BugHighEffort: LowcliGitHub issueOctober 20, 2026

Verdict: REPRODUCED · Root-cause confidence: high
Trusted base: b0bb68655adcc6cd79e495d3484f4011a0640e2e

1. TL;DR

The CLI can attempt a plugin settings write against its default local production address even when a managed-job marker is present. The real built CLI selected port 38886, fetched a synthetic setting schema, dispatched a PUT to the intercepted transport, and exited successfully. The same result occurred with an explicit default URL and with localhost. Configuration chooses a production fallback and the shared HTTP transport performs no managed-job check. Two clean trusted checkouts produced identical results; this establishes the routing defect, not the cause of a historical credential incident.

issue-5838-fetch-recorder.mjs

import { appendFileSync } from "node:fs";

globalThis.fetch = async function recordOnly(resource, options = {}) {
  const address = resource instanceof Request ? resource.url : String(resource);
  const method = options.method ?? (resource instanceof Request ? resource.method : "GET");
  appendFileSync(process.env.REPRO_REQUESTS, `${JSON.stringify({ address, method })}\n`);
  const destination = new URL(address);
  if (!destination.pathname.endsWith("/settings")) {
    throw new Error("Unexpected synthetic endpoint");
  }
  return Response.json({
    ok: true,
    schema: { ceiling: { type: "number", label: "Ceiling", default: 2 } },
    values: { ceiling: 2 },
  });
};

issue-5838-reproduce.mjs

import assert from "node:assert/strict";
import { spawnSync } from "node:child_process";
import { existsSync, mkdirSync, mkdtempSync, readFileSync, rmSync } from "node:fs";
import { tmpdir } from "node:os";
import { dirname, join, resolve } from "node:path";
import { fileURLToPath } from "node:url";

const checkout = resolve(process.argv[2]);
const fixture = join(dirname(fileURLToPath(import.meta.url)), "issue-5838-fetch-recorder.mjs");
const sandbox = mkdtempSync(join(tmpdir(), "transport-reproduction-"));
const cases = [
  { name: "managed implicit default", marked: true, target: null, blocked: true },
  { name: "managed explicit default", marked: true, target: "http://127.0.0.1:38886", blocked: true },
  { name: "managed localhost default", marked: true, target: "http://localhost:38886", blocked: true },
  { name: "managed alternate port control", marked: true, target: "http://127.0.0.1:49873", blocked: false },
  { name: "unmanaged default control", marked: false, target: null, blocked: false },
];
const observations = [];

try {
  for (const [index, scenario] of cases.entries()) {
    const home = join(sandbox, `case-${index}`);
    mkdirSync(home);
    const record = join(home, "requests.ndjson");
    const env = {
      PATH: process.env.PATH,
      HOME: home,
      TMPDIR: home,
      NODE_ENV: "production",
      BB_CLI_ERROR_LOG: "0",
      REPRO_REQUESTS: record,
    };
    if (scenario.marked) env.HOST_CARE_JOB_ID = "synthetic-managed-run";
    if (scenario.target !== null) env.BB_SERVER_URL = scenario.target;
    const child = spawnSync(process.execPath, [
      "--import", fixture,
      join(checkout, "apps/cli/dist/index.js"),
      "plugin", "config", "synthetic-limits", "set", "ceiling", "7", "--json",
    ], { cwd: checkout, env, encoding: "utf8", timeout: 20000 });
    assert.ifError(child.error);
    const requests = existsSync(record)
      ? readFileSync(record, "utf8").trim().split("\n").filter(Boolean).map((line) => JSON.parse(line))
      : [];
    const observation = {
      scenario: scenario.name,
      expected: scenario.blocked ? "nonzero exit and no write dispatched" : "successful write",
      exit: child.status,
      requests,
      stdout: child.stdout.trim(),
      stderr: child.stderr.trim(),
    };
    console.log(JSON.stringify(observation));
    observations.push({ scenario, observation });
  }
  for (const { scenario, observation } of observations.filter(({ scenario }) => !scenario.blocked)) {
    assert.equal(observation.exit, 0, `${scenario.name}: control must succeed`);
    assert.equal(observation.requests.filter(({ method }) => method === "PUT").length, 1);
  }
  const unexpectedWrites = observations.filter(({ scenario, observation }) => scenario.blocked &&
    (observation.exit === 0 || observation.requests.some(({ method }) => !["GET", "HEAD", "OPTIONS"].includes(method))));
  assert.equal(unexpectedWrites.length, 0, "Managed requests reached the default-port write transport");
} finally {
  rmSync(sandbox, { recursive: true, force: true });
}

5. Root cause

  1. Production constants select port 38886 and loopback 127.0.0.1.
  2. CLI configuration fallback selects that address when no server URL is configured. An explicit URL is passed through the configured-value branch.
  3. Runtime context resolution loads this configuration and returns its server URL without rewriting it from project or thread context.
  4. Plugin configuration mutation fetches the schema and then calls the PUT path. Plugin HTTP helper sends both requests through the shared transport.
  5. Shared CLI HTTP transport unconditionally calls fetch and also supplies that fetch function to the Node SDK:
    export function cliFetch(
  input: RequestInfo | URL,
  init?: CliRequestInit,
): Promise<Response> {
  return fetch(input, init);
}
    There is no target-, method-, or managed-job-dependent rejection here. This missing policy explains the observed dispatch and successful synthetic response.

High priority reflects accidental configuration corruption risk, not a demonstrated privilege escalation. Low effort reflects a contained CLI transport change using existing URL/error plumbing. The test detects a real request reaching that transport; no production-only test seam was added.

6. Proposed fix

Put accidental-routing protection at the existing shared CLI fetch boundary, before transport dispatch, and make the effective Request/init method and normalized destination explicit. Keep intentional reads and isolated targets working; preserve ordinary invocations. Propagate a structured error through both core and plugin CLI entry paths and document any override. This is defense against accidental targeting, not authentication or a security boundary. Extend the primary boundary test with read methods, aliases, Request precedence, overrides, SDK mutations and re-exec.

No new fix branch or PR was created: the open linked PR below already addresses this issue.
