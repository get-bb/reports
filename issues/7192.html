#7192 · Lifecycle hooks lose authenticated CLI routing

BugPriority: MediumEffort: Mediumworkspaces · cli · connectGitHub issueNovember 6, 2026 · base bcfdf1ca3c3a6ff60385ab323c5a551f943a0bff

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high · reproduction label: partial-repro

1. TL;DR

Repository lifecycle scripts cannot inherit the authenticated server endpoint that works for agent processes. Both real lifecycle runners erase that endpoint before launching Bash, and the actual CLI configuration loader then falls back to its production loopback default. In isolated tests, the built CLI also fails authentication when explicitly pointed at an upstream that requires a machine header, even when the matching header is present in an environment variable. The same CLI succeeds when the hook explicitly uses the real machine-auth proxy instead. These mechanisms reproduce in two clean trusted main checkouts; native Windows, a real hosted Connect enrollment/server move, and the remote terminal-creation workflow were not exercised, so the overall verdict is partial rather than a claim of full end-to-end reproduction.

Complete reproducible test

This test exercises actual lifecycle subprocesses and the built CLI. It never sends a request to the fallback production endpoint. The test is inline rather than published as a separate script, following the reports repository’s artifact policy.

import { mkdtemp, readFile, rm, writeFile } from "node:fs/promises";
import { createServer, type Server } from "node:http";
import { tmpdir } from "node:os";
import { dirname, join } from "node:path";
import { fileURLToPath } from "node:url";
import { afterAll, beforeAll, describe, expect, it } from "vitest";
import { loadCliConfig } from "@bb/config/cli";
import { runSetupScript, runTeardownScript } from "./environment-lifecycle-script.js";
import { startMachineAuthProxy, type MachineAuthProxy } from "./machine-auth-proxy.js";

function shellQuote(value: string): string {
  return `'${value.replaceAll("'", "'\\''")}'`;
}

describe.skipIf(process.platform === "win32")("issue 7192 lifecycle CLI access", () => {
  let directory: string;
  let upstream: Server;
  let upstreamUrl: string;
  let proxy: MachineAuthProxy;
  const requests: { authenticated: boolean; path: string }[] = [];
  const cliPath = fileURLToPath(new URL("../../cli/dist/index.js", import.meta.url));

  beforeAll(async () => {
    directory = await mkdtemp(join(tmpdir(), "bb-7192-repro-"));
    upstream = createServer((request, response) => {
      const authenticated = request.headers["x-bb-connect-machine"] === "fixture-machine";
      requests.push({ authenticated, path: request.url ?? "" });
      response.setHeader("content-type", "application/json");
      if (!authenticated) {
        response.writeHead(401);
        response.end(JSON.stringify({ error: "machine_auth_required" }));
        return;
      }
      response.end("[]");
    });
    await new Promise<void>((resolve) => upstream.listen(0, "127.0.0.1", resolve));
    const address = upstream.address();
    if (address === null || typeof address === "string") throw new Error("No TCP listener");
    upstreamUrl = `http://127.0.0.1:${address.port}`;
    proxy = await startMachineAuthProxy({
      serverUrl: upstreamUrl,
      serverHeaders: { "x-bb-connect-machine": "fixture-machine" },
    });
    console.log(JSON.stringify({ upstreamUrl, proxyUrl: proxy.serverUrl }));
  });

  afterAll(async () => {
    await proxy?.close();
    upstream?.closeAllConnections();
    if (upstream) await new Promise<void>((resolve) => upstream.close(() => resolve()));
    if (directory) await rm(directory, { recursive: true, force: true });
  });

  function inheritedEnv(): NodeJS.ProcessEnv {
    return {
      PATH: `${dirname(process.execPath)}:/usr/bin:/bin`,
      HOME: directory,
      USERPROFILE: directory,
      NODE_ENV: "production",
      BB_SERVER_URL: proxy.serverUrl,
      BB_SERVER_HEADERS: JSON.stringify({ "x-bb-connect-machine": "fixture-machine" }),
      BB_THREAD_ID: "fixture-thread",
    };
  }

  it.each(["setup", "teardown"] as const)(
    "%s retains a usable machine endpoint while removing thread identity",
    async (kind) => {
      const endpointFile = join(directory, `${kind}-endpoint`);
      const identityFile = join(directory, `${kind}-identity`);
      await writeFile(join(directory, `.bb-env-${kind}.sh`),
        `printf '%s' "\${BB_SERVER_URL-}" > ${shellQuote(endpointFile)}\nprintf '%s' "\${BB_THREAD_ID-}" > ${shellQuote(identityFile)}\n`);
      const run = kind === "setup" ? runSetupScript : runTeardownScript;
      await run({ workspacePath: directory, timeoutMs: 5000, env: inheritedEnv() });
      const endpoint = await readFile(endpointFile, "utf8");
      const config = loadCliConfig({ env: endpoint ? { BB_SERVER_URL: endpoint } : {}, homeDir: directory, mode: "prod" });
      console.log(JSON.stringify({ kind, hookEndpoint: endpoint, resolvedCliUrl: config.BB_SERVER_URL }));
      expect(await readFile(identityFile, "utf8")).toBe("");
      expect(config.BB_SERVER_URL).toBe(proxy.serverUrl);
    },
  );

  it.each(["setup", "teardown"] as const)(
    "%s CLI rejects a direct URL with BB_SERVER_HEADERS but succeeds through the actual proxy",
    async (kind) => {
      const run = kind === "setup" ? runSetupScript : runTeardownScript;
      for (const [route, url] of [["direct", upstreamUrl], ["proxy", proxy.serverUrl]] as const) {
        const outputFile = join(directory, `${kind}-${route}-output`);
        const exitFile = join(directory, `${kind}-${route}-exit`);
        await writeFile(join(directory, `.bb-env-${kind}.sh`),
          `export BB_SERVER_URL=${shellQuote(url)}\nexport BB_SERVER_HEADERS='{"x-bb-connect-machine":"fixture-machine"}'\n${shellQuote(process.execPath)} ${shellQuote(cliPath)} machine list --json > ${shellQuote(outputFile)} 2>&1\nprintf '%s' "$?" > ${shellQuote(exitFile)}\n`);
        const requestCount = requests.length;
        await run({ workspacePath: directory, timeoutMs: 10000, env: inheritedEnv() });
        const exit = await readFile(exitFile, "utf8");
        const output = await readFile(outputFile, "utf8");
        const observed = requests.slice(requestCount);
        console.log(JSON.stringify({ kind, route, exit, output: output.trim(), requests: observed }));
        expect(observed.length).toBeGreaterThan(0);
        expect(observed.every((request) => request.path.startsWith("/api/v1/hosts"))).toBe(true);
        if (route === "direct") {
          expect(exit).toBe("1");
          expect(output).toContain("401");
          expect(observed.every((request) => !request.authenticated)).toBe(true);
        } else {
          expect(exit).toBe("0");
          expect(JSON.parse(output)).toEqual([]);
          expect(observed.every((request) => request.authenticated)).toBe(true);
        }
      }
    },
  );
});

5. Root cause

  1. The daemon creates the machine-auth proxy and places its loopback URL in runtime shell context: apps/host-daemon/src/start-host-daemon.ts:134.
  2. The hook command handler merges runtime shell environment into the inherited environment: apps/host-daemon/src/command-handlers/environment-hook.ts:64.
  3. The lifecycle runner explicitly requests inherited-environment sanitization: apps/host-daemon/src/environment-lifecycle-script.ts:173. apps/host-daemon/src/operation-environment.ts:4 sanitizes first, then adds explicitly contributed values. With no overriding contribution, there is no restoration of the machine endpoint.
  4. The shared sanitizer intentionally removes all BB_ variables and NODE_ENV: packages/process-utils/src/environment.ts:6. This strips machine routing together with thread-local context before either platform’s Bash launcher is selected.
  5. The CLI config loader selects the production loopback URL when no explicit endpoint is supplied: packages/config/src/cli.ts:19. Its URL resolver reads an explicit value, an environment value, or development defaults—not persisted machine headers: packages/config/src/server-url.ts:16.
  6. The CLI SDK factory supplies a URL and a fetch implementation, not machine headers: apps/cli/src/client.ts:6. Restoring only a direct remote URL therefore does not reproduce the proxy’s authentication behavior.

The deeper mismatch is that sanitization intentionally removes daemon/thread-specific context, while there is no replacement machine-scoped CLI routing contract at the lifecycle boundary. The proxy itself works: the positive controls reach the same fixture upstream with the correct synthetic header.

6. Proposed fix and safety decision

Define an explicit machine-scoped CLI endpoint contract for lifecycle subprocesses, then inject only the approved loopback proxy endpoint after sanitization. Keep thread identifiers and raw credentials out of inherited hook context; do not weaken the shared sanitizer globally. Cover setup, teardown, local-server mode, moved-server mode, proxy lifetime, and native Windows casing/launch behavior. Document the contract through the CLI guide and environment hook documentation.

No automatic fix PR: propagating machine-authenticated routing into repository hooks changes authentication-context behavior and requires a security/product decision. That fails the caller’s simple-fix eligibility rule regardless of patch size. No production patch, fix branch, commit, or code push was made.
