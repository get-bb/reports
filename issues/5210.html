#5210 · Delegation snapshots duplicate descendant trees

BugHighEffort: Mediumthreadsperfconfirmed-reproGitHub issueOctober 8, 2026 · base f135a001e72942cee9118d2693208ec0725e2f18

Verdict: REPRODUCED · Root-cause confidence: high for the projection amplification mechanism. The private-thread desktop crash and its specific heap size were not replayed.

1. TL;DR

A timeline can become much larger than its stored message contexts when nested delegations have repeated snapshots. The projection builder attaches every matching snapshot as a separate child, then recursively builds the same descendants beneath each snapshot. A synthetic branching tree with 29 contexts and 15 distinct message ids produces 85 messages instead of 15 on unchanged main. Two separate clean checkouts give the same result. The server also serializes omitted update subtrees before checking their byte budget, which cannot prevent that serialization allocation; the reported desktop out-of-memory event itself remains unverified here.

Binary branching alone yields 2level logical nodes. With two retained snapshots per child, the builder instead yields 4level expanded nodes. At depth 3: input contexts = 1 + 2 × (2 + 4 + 8) = 29; expected messages = 1 + 2 + 4 + 8 = 15; actual messages = 1 + 4 + 16 + 64 = 85.

Complete reproduction test
import { describe, expect, it } from "vitest";
import type {
  EventProjection,
  EventProjectionDelegationMessage,
  EventProjectionMessage,
} from "../src/event-projection-types.js";
import { getProjectionEntryMessages } from "../src/event-projection-flatten.js";
import { normalizeEventProjection } from "../src/normalize-event-projection.js";

function emptyProjection(): EventProjection {
  return {
    state: {
      activeThinking: null,
      activeWorkflows: [],
      activeBackgroundCommands: [],
    },
    entries: [],
  };
}

function makeSnapshot(
  callId: string,
  sequence: number,
  status: "pending" | "completed",
  parentToolCallId?: string,
): EventProjectionDelegationMessage {
  return {
    kind: "delegation",
    id: `message-${callId}`,
    threadId: "synthetic-thread",
    sourceEvent: { seq: sequence, part: 0 },
    sourceSeqStart: sequence,
    sourceSeqEnd: sequence,
    createdAt: sequence,
    scope: { kind: "turn", turnId: "synthetic-turn" },
    toolName: "Task",
    callId,
    childRef: null,
    background: false,
    output: status === "completed" ? "done" : "",
    completedAt: status === "completed" ? sequence : null,
    status,
    childProjection: emptyProjection(),
    ...(parentToolCallId === undefined ? {} : { parentToolCallId }),
  };
}

function collectMessages(
  projection: EventProjection,
): EventProjectionMessage[] {
  return projection.entries.flatMap((entry) =>
    getProjectionEntryMessages(entry).flatMap((message) => [
      message,
      ...(message.kind === "delegation"
        ? collectMessages(message.childProjection)
        : []),
    ]),
  );
}

describe("delegation snapshot cardinality", () => {
  it.each([1, 2, 3])(
    "keeps each logical child once with its final state in a branching tree of depth %i",
    (depth) => {
      const input = emptyProjection();
      const expectedIds: string[] = [];
      let sequence = 0;
      const appendBranch = (
        callId: string,
        remainingDepth: number,
        parentToolCallId?: string,
      ): void => {
        expectedIds.push(`message-${callId}`);
        const statuses: ("pending" | "completed")[] =
          parentToolCallId === undefined
            ? ["completed"]
            : ["pending", "completed"];
        for (const status of statuses) {
          sequence += 1;
          input.entries.push({
            kind: "projected-message",
            message: makeSnapshot(callId, sequence, status, parentToolCallId),
          });
        }
        if (remainingDepth > 0) {
          appendBranch(`${callId}-left`, remainingDepth - 1, callId);
          appendBranch(`${callId}-right`, remainingDepth - 1, callId);
        }
      };
      appendBranch("leader", depth);
      const actual = collectMessages(normalizeEventProjection(input));
      console.log(
        JSON.stringify({
          depth,
          inputContexts: input.entries.length,
          uniqueInputIds: expectedIds.length,
          normalizedMessages: actual.length,
        }),
      );
      expect(actual.map((message) => message.id)).toEqual(expectedIds);
      expect(
        actual.every(
          (message) =>
            message.kind === "delegation" &&
            message.status === "completed" &&
            message.output === "done",
        ),
      ).toBe(true);
    },
  );
});

5. Root cause

The normalizer's parent-attachment loop appends every context to an array keyed only by parent call id. The attached-id set suppresses root items; it does not deduplicate the children.

const children = this.childrenByParentCallId.get(parentToolCallId) ?? [];
children.push(context);
this.childrenByParentCallId.set(parentToolCallId, children);
this.attachedMessageIds.add(context.message.id);

Each retained child is then passed through recursive semantic expansion. A repeated delegation call id looks up the same descendants again, producing a new expanded subtree for every copy. This work and allocation happens before the response budget can reject any content.

entries: contexts.map((context) => ({
  kind: "projected-message",
  message: this.toSemanticMessage(context.message),
}))

const childProjection = this.buildFlatChildProjection(
  this.childrenByParentCallId.get(message.callId) ?? [],
);

buildDetailedProjection calls this normalizer in the normal projection path. The server's omitted-row pagination check is an additional allocation risk:

const reported =
  Buffer.byteLength(JSON.stringify(updates)) > remainingBytes
    ? []
    : changed;

This serializes the complete updates array before deciding it is too large. An already-enormous tree may exhaust memory or string capacity here. The exact desktop abort, heap peak and private input distribution are not established by this bounded test.

6. Proposed fix

At the attachment boundary, key child contexts by both parent call id and message identity. Replace a child's earlier context with its final context while keeping its first position; keep different child identities intact. Avoid a global identity deduplication that could collapse call-id reuse across root turns. The repository already has a later-turn call-id reuse test for that constraint.

Separately, measure serialized row shells and child-array overhead incrementally and stop once the remaining byte budget is exceeded. Verify exact UTF-8 and escaping accounting at the pagination boundary. This prevents whole-update serialization, but is not a universal heap ceiling: individual row payloads and earlier projection allocation still need their own bounds.
