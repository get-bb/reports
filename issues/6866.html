#6866 · Codex child processes ignore the selected session home

BugPriority: MediumEffort: Mediumproviders · provider-codex · confirmed-reproGitHub issue

November 2, 2026 · trusted origin/main de578a74eef20cc15c2bb68d890e7e9bce55a68e

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The native Codex bridge receives an environment override selecting a different Codex home, but the child app-server process does not receive it. The launch helper starts with the bridge environment and forwards only two Account Pool routing variables from the supplied session environment. Actual child-process probes reproduce this on start, resume, fork, model discovery, and two simultaneously open sessions. A changed home also does not invalidate a live session, so a subsequent turn can continue in the old child process. This verifies the launch and lifecycle defects, not a real wrong-account inference request or macOS desktop workflow.

5. Root cause

appServerLaunchEnv and buildAppServerEnv show that the incoming environment is not generally merged. The helper preserves process.env and selectively overlays only CODEX_OPENAI_BASE_URL and CODEX_POOL_AUTH_TOKEN. CODEX_HOME never reaches the environment sanitizer as a supplied override:

function appServerLaunchEnv(
  envVars: Readonly<Record<string, string>> | undefined,
): NodeJS.ProcessEnv {
  const poolBaseUrl = envVars?.[CODEX_POOL_BASE_URL_ENV];
  const poolAuthToken = envVars?.[CODEX_POOL_AUTH_TOKEN_ENV];
  return {
    ...process.env,
    ...(poolBaseUrl === undefined
      ? {}
      : { [CODEX_POOL_BASE_URL_ENV]: poolBaseUrl }),
    ...(poolAuthToken === undefined
      ? {}
      : { [CODEX_POOL_AUTH_TOKEN_ENV]: poolAuthToken }),
  };
}

function buildAppServerEnv(
  envVars: Readonly<Record<string, string>> | undefined,
): NodeJS.ProcessEnv {
  return withoutBridgeRuntimeEnv(
    sanitizeInheritedChildProcessEnv({
      env: appServerLaunchEnv(envVars),
    }),
  );
}

spawnChildConnection uses this result to create the actual app-server process. Session construction supplies session envVars to that function, and Maintenance children use the same launch path. Model discovery passes model/list envVars into the maintenance path. Therefore the environment is lost after it reaches the provider bridge, not because the probe omitted it or invoked a copied helper.

There is a second, related lifecycle omission. constructionSignature includes the workspace, reasoning/memory/subagent choices and a hashed pool route, but not the selected home:

function constructionSignature(
  cwd: string,
  sessionOptions: CodexSessionOptions,
): string {
  const poolBaseUrl = sessionOptions.envVars?.[CODEX_POOL_BASE_URL_ENV];
  const poolToken = sessionOptions.envVars?.[CODEX_POOL_AUTH_TOKEN_ENV];
  return JSON.stringify({
    cwd,
    reasoningLevel: sessionOptions.reasoningLevel ?? null,
    memoryEnabled: sessionOptions.memoryEnabled ?? null,
    providerSubagentsEnabled: sessionOptions.providerSubagentsEnabled ?? null,
    poolRoute:
      poolBaseUrl === undefined || poolToken === undefined
        ? null
        : {
            baseUrl: poolBaseUrl,
            tokenHash: createHash("sha256").update(poolToken).digest("hex"),
          },
  });
}

6. Proposed fix and automation safety

Preserve the environment sanitation pipeline and apply a validated effective CODEX_HOME at the child-launch boundary. Treat it consistently for start/resume/fork and maintenance/model discovery without forwarding unrelated project variables. A home-only change must not silently reuse the old child. Before enabling home-based replacement, specify how an existing saved provider session stays bound to its original home, or return an explicit recoverable error when it cannot safely be resumed. Test independent homes, no-override defaults, pool routing, and rollout lookup in the intended home.

No automated PR: changing the selected home changes authentication/configuration and saved-session storage. The simple-fix rule explicitly excludes authentication changes and changes requiring a product/architecture decision. Choosing existing-session home affinity, migration, or refusal semantics is not safe to invent in a narrow launch patch. No production patch, branch, target-repository commit, or push was attempted.

No linked open pull request was present in the issue timeline, and a separate open-PR metadata search for issue 6866 returned none.
