#3499 · ACP file input lacks text fallback

Bug · Medium priority · Medium effort · providers / provider-acp / opencode
2026-09-11 · base 921b741393dbcd81f42d399b6273cb7ebf91586f · Issue

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium (high for the bridge transformation).

1. TL;DR

The bridge sends a Markdown file as an ACP resource link without a readable file-path text fallback. Two focused assertions fail on unchanged main production code, for an initial attachment and an attachment following a successful text turn. The tests use the repository fake agent with the OpenCode dialect; they do not execute OpenCode inference. The exact provider error and persistent failure of later text-only turns remain unverified.

2. Claims vs findings

ClaimFinding
Local files become resource links without capability handling.Verified by captured session/prompt requests and source.
A Markdown attachment fails real OpenCode inference.Unverified; OpenCode was unavailable on PATH. The fake agent accepts the link.
Later text-only turns retain the failure.Unverified; this test does not simulate provider-side persisted history.
Existing bridge tests omit local-file coverage.No localFile/resource_link matches existed in bridge.test.ts before these probes.

3. Environment

Darwin 25.6.0 arm64; Node v22.22.3; pnpm 9.15.0 via Corepack; Vitest 4.1.1. No live BB instance, account, network listener, or production data directory was used. Each test creates and removes a separate temporary workspace. The first checkout was detached at trusted main; the second was a newly created detached worktree at the same commit.

4. Minimal reproduction

  1. Check out the recorded base commit in get-bb/bb.
  2. Run corepack pnpm install --frozen-lockfile --prefer-offline. Ensure pnpm on PATH resolves to that Corepack version for Turbo children.
  3. Save the following test-only patch as repro.patch and run git apply repro.patch. It writes a real Markdown file and uses existing fake-agent request logging.
  4. Run pnpm exec turbo run test --filter=@bb/provider-bridge-acp -- --testNamePattern="issue 3499".

Expected: a text block containing the staged filename. Actual: both assertions fail with resource_link output. The fake-agent turns complete successfully; this is a fallback contract probe, not a reproduction of the real inference error.

5. Root cause

buildPromptContentBlocks checks image support for local images but unconditionally constructs a resource_link for localFile. Session initialization retains image capability only. The fake agent advertises image:false and no file-input capability, yet receives the resource link with no text fallback.

Prompt dispatch and error handling sends current pending input and clears active prompt state on rejection. This alone does not establish where a rejected attachment might persist in OpenCode. The cause of later failures remains unverified.

6. Proposed fix and safety decision

Verify the captured request against an installed supported OpenCode version in an isolated session, including a failed attachment followed by a fresh text-only turn. A staged file-path text fallback is a plausible small fix. No PR was opened because partial reproduction does not meet the rule's reproduced-bug gate. No production code was changed, committed, or pushed.

7. Verification

The same agent repeated the test in a second clean temporary checkout at the full base SHA, with a separate frozen dependency install and new temporary test workspaces. Only the test patch was applied. The same Turbo command exited 1 with 2 failed assertions and 312 skipped tests. Both failures show resource-link output. This supports the narrow bridge finding, so the report limits the verdict to partial reproduction. No independent verifier is claimed.
