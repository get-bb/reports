Reports · Issue #4432

Old-instance disposal interrupts a new-instance startup question

2026-09-30 · Bug · Medium priority · Medium effort

REPRODUCED · High confidence in the server-side reload and interaction lifecycle defect.

Tested claim and exact conditions

An isolated integration test invokes the actual plugin install/reload service, plugin requestInput API, pending-interaction lifecycle and real test database. A synthetic plugin raises an ordinary display-color question from its factory. The first instance's question remains pending and can be submitted successfully. After that submission, the test writes a second-generation factory and reloads the same plugin. Reload reports success, but the new factory's question is immediately interrupted with plugin-disposed and its promise resolves cancelled/plugin-disposed.

This directly reproduces cancellation of an admitted new-instance startup request by old-instance disposal. The initial form is deliberately settled before reload: a preliminary attempt left it pending on the same thread and encountered the current one-pending-interaction guard, which rejects the new request before cleanup. That attempt is not counted as the two-run reproduction. The final test includes this admission condition, uses the same settled-first-form sequence in both checkouts, and does not claim that two simultaneous pending forms on one thread are accepted.

No browser renderer is registered or opened. The evidence is the persisted interaction state and settled API promise, not a screenshot of a disappearing form. No production plugin, user runtime, provider inference, authorization decision, plugin update delivery mechanism or separate timeout-documentation claim was tested. The ordinary question has no abort signal, and no timeout is advanced. No production fix was applied.

Complete derived test

import { mkdir, writeFile } from "node:fs/promises";
import { join } from "node:path";
import { eq } from "drizzle-orm";
import { expect, it } from "vitest";
import { pendingInteractions } from "@bb/db";
import { createTestAppHarness } from "../../helpers/test-app.js";
import { seedEnvironment, seedHostSession, seedProjectWithSource, seedThread } from "../../helpers/seed.js";

it("4432 preserves the new instance question across reload", async () => {
  const globals = globalThis as typeof globalThis & {
    __fixture4432?: { generation: number; outcome: unknown }[];
  };
  const previous = globals.__fixture4432;
  globals.__fixture4432 = [];
  const harness = await createTestAppHarness();
  try {
    const { host } = seedHostSession(harness.deps, { id: "host-synthetic-reload" });
    const { project } = seedProjectWithSource(harness.deps, { hostId: host.id });
    const environment = seedEnvironment(harness.deps, { hostId: host.id, projectId: project.id });
    const thread = seedThread(harness.deps, { projectId: project.id, environmentId: environment.id });
    const pluginId = "synthetic-reload-question";
    const root = join(harness.config.dataDir, "fixtures", "bb-plugin-synthetic-reload-question");
    await mkdir(root, { recursive: true });
    await writeFile(join(root, "package.json"), JSON.stringify({
      name: "bb-plugin-synthetic-reload-question", version: "0.1.0",
      bb: { name: "Synthetic question", description: "Isolated reload fixture", branding: { icon: "Zap" }, server: "./server.ts" },
    }));
    const writeFactory = async (generation: number) => {
      await writeFile(join(root, "server.ts"), `
        export default function start(bb) {
          const pending = bb.ui.requestInput({
            threadId: ${JSON.stringify(thread.id)}, rendererId: "synthetic-color",
            title: "Choose a display color", payload: { generation: ${generation}, choices: ["blue", "green"] }
          });
          pending.then(outcome => globalThis.__fixture4432.push({ generation: ${generation}, outcome }));
        }
      `);
    };
    const rows = () => harness.db.select({ status: pendingInteractions.status, reason: pendingInteractions.statusReason,
      payload: pendingInteractions.payload }).from(pendingInteractions).where(eq(pendingInteractions.pluginId, pluginId)).all()
      .map(row => ({ status: row.status, reason: row.reason, payload: JSON.parse(row.payload) }));
    await writeFactory(1);
    await harness.pluginService.installPath(root);
    const initial = rows();
    console.log(JSON.stringify({ phase: "first-load", rows: initial }));
    expect(initial).toHaveLength(1);
    expect(initial[0]?.status).toBe("pending");
    expect(globals.__fixture4432).toEqual([]);
    const initialRow = harness.db.select({ id: pendingInteractions.id }).from(pendingInteractions)
      .where(eq(pendingInteractions.pluginId, pluginId)).get();
    expect(initialRow).toBeDefined();
    await harness.deps.pendingInteractions.respondToPluginInteraction({
      interactionId: initialRow!.id, threadId: thread.id, value: { color: "blue" },
    });
    await new Promise(resolve => setImmediate(resolve));
    expect(globals.__fixture4432).toEqual([{ generation: 1, outcome: { outcome: "submitted", value: { color: "blue" } } }]);
    console.log(JSON.stringify({ phase: "settled-control", rows: rows(), outcomes: globals.__fixture4432 }));
    await writeFactory(2);
    const reload = await harness.pluginService.reload(pluginId);
    expect(reload.ok).toBe(true);
    await new Promise(resolve => setImmediate(resolve));
    const after = rows();
    const outcomes = globals.__fixture4432;
    console.log(JSON.stringify({ phase: "after-reload", reloadOk: reload.ok, rows: after, outcomes }));
    expect(after).toHaveLength(2);
    expect(outcomes?.find(item => item.generation === 1)?.outcome).toEqual({ outcome: "submitted", value: { color: "blue" } });
    expect.soft(after.filter(row => row.status === "pending")).toHaveLength(1);
    expect.soft(outcomes?.find(item => item.generation === 2)).toBeUndefined();
  } finally {
    await harness.cleanup();
    globals.__fixture4432 = previous;
  }
});

Root cause and verified source permalinks

  • New factory executes before previous instance disposal. New interactions can already exist at that point.
  • Disposal interrupts by plugin ID does not distinguish the old and new instance.
  • Interaction lifecycle interrupt supplies the plugin-disposed reason and settles the interrupted waiters.
  • Database interruption predicate matches plugin origin, plugin ID and pending/resolving status, with no instance-generation filter.

Proposed fix and next useful test

Scope disposal cleanup to interactions owned by the outgoing instance or generation, preserving those admitted by the new factory. Disposing before activation is another option, but its effect on rollback and failed-reload behavior needs explicit design and tests. Preserve the successful-submission control and add cases for failed factories, separate-thread pending forms and repeated reloads. No fix or PR was created.
