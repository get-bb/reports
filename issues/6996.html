#6996 · Multiword mention sessions outlive empty results

Bug Priority: Medium Effort: Low ui · GitHub issue · November 4, 2026 · base 64c2f7099e1a678070dd24d730aa1120b2fb18e1

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

The composer treats ordinary spaces as valid characters inside mention names. That is intentional: real mentions can have multiple words. However, a completed search with no suggestions does not end a multiword mention session, so ordinary prose continues to own an empty suggestion menu. A focused test of the real composer reproduces this in two separate clean checkouts of the same trusted main commit. A separate direct parser probe confirms that the eventual cutoff comes from the bounded scan rather than a semantic end to the query.

5. Root cause

The mention regex, lines 47–58, intentionally admits ordinary spaces. The following trusted excerpt shows why a paragraph of prose can remain a single query:

const queryPattern =
  trigger.kind === "mention" ? `(?:[^\\s${escapedChar}]| )*` : "\\S*";
const boundary = options.windowed ? "([\\s([{])" : "(^|[\\s([{])";
const TRIGGER_SCAN_WINDOW = 256;

The windowed scan, lines 60–81, excludes a start-of-input boundary once the window begins inside a document. After 254 query characters the leading space, trigger, and query still fit; the next character discards the leading space, so the regex stops matching.

The menu policy, lines 2318–2331, hides unmatched commands but has no analogous settled-empty multiword mention condition:

const showTypeaheadMenu =
  !showVoiceActionGroup &&
  activeTrigger !== null &&
  !isCommandTriggerLiteral &&
  !isBareNonDefaultMentionTrigger;

The underlying omission is lifecycle feedback, not an incorrect choice of regex window size. The search has finished and found nothing, but the composer never retires that occurrence. Merely hiding its menu would still leave repeated query updates active.

6. Proposed fix

Keep multiword parsing intact. Once a trimmed mention query contains an internal space, the mention search is ready and not refreshing, and the combined local-attachment and remote suggestion set is empty, retire the occurrence using the existing dismissComposerMenu path. That path records a dismissed range and sends null to the search API, so extending the same prose does not reactivate it. Preserve bare triggers, single-token empty searches, matching multiword mentions, local attachment matches, pending searches, and errors.
