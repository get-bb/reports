1. TL;DR

The navigation rail has larger touch controls, but its stylesheet enables them only on narrow, coarse-pointer viewports. Trusted main contains an AND condition combining a width below 48rem with a coarse primary pointer. At a 16px initial font size, the width limit is 768px, so a 951px viewport cannot activate that rule. Two fresh checkouts produced identical parsed stylesheet evidence. A real browser and physical-device check were unavailable, so this is a partial reproduction rather than a claimed visual confirmation.

No screenshot is presented: the Browser Automation plugin could not start headless Chrome because this host has no Chrome/Chromium executable. Artifact: inspect-rail-css.mjs

import { readFileSync } from "node:fs";
import { createRequire } from "node:module";
import { resolve } from "node:path";

const checkout = resolve(process.argv[2] ?? ".");
const require = createRequire(resolve(checkout, "apps/app/package.json"));
const { transform } = require("lightningcss");
const filename = "apps/app/src/app.css";
const findings = [];

transform({
  filename,
  code: readFileSync(resolve(checkout, filename)),
  visitor: {
    Rule(rule) {
      if (rule.type !== "media") return;
      const declarations = rule.value.rules
        .filter((child) => child.type === "style")
        .flatMap((child) => child.value.declarations.declarations)
        .filter(
          (declaration) =>
            declaration.property === "custom" &&
            declaration.value.name.startsWith("--bb-sidebar-"),
        );
      if (declarations.length === 0) return;
      findings.push({
        file: filename,
        line: rule.value.loc.line + 1,
        queries: rule.value.query.mediaQueries,
        declarations: declarations.map((declaration) => declaration.value),
      });
    },
  },
});

if (findings.length === 0) throw new Error("No sidebar media rules found");
console.log(JSON.stringify(findings, null, 2));

5. Root cause

apps/app/src/app.css makes pointer suitability dependent on a compact-layout breakpoint:

--bb-sidebar-control-size: var(--bb-frame-rail-control-size);
--bb-sidebar-control-icon-size: 16px;

@media (width < 48rem) and (pointer: coarse) {
  :root {
    --bb-sidebar-rail-padding: 12px;
    --bb-sidebar-control-size: 36px;
    --bb-sidebar-control-icon-size: 20px;
  }
}

packages/desktop-contract/src/macos-window-chrome.ts sets the rail default to 24px. apps/app/src/lib/bb-desktop.ts assigns it to the frame variable. packages/shared-ui/src/components/ui/sidebar-row-classes.ts consumes the sidebar control and icon variables in the real rail button classes.

apps/app/src/components/sidebar/navRailWidth.ts derives rail width from those same variables. This supports a small stylesheet fix, but does not prove that every docked layout remains collision-free. History attributes the width-plus-pointer gate to commit a28207d1c6d; it remains present at the recorded main commit.

6. Proposed fix and safety gate

Make rail touch geometry depend on primary pointer capability rather than compact viewport width. Keep fine-pointer desktop geometry and the separate title-bar controls unchanged. Verify actual button bounds, icon bounds, rail width, and sidebar overlap across 390px, 768px, 951px, and 1024px coarse-pointer viewports, plus fine-pointer controls and a resize transition.
