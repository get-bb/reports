#6289 · Responsive pane swaps discard live thread state

BugPriority: MediumEffort: Mediumui GitHub issue · October 26, 2026

Trusted main: 3a2c49a267cd2a62a96ebff880068a7c37074251

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

The responsive thread container replaces its component tree when compact mode changes, even with just one thread open. A focused test of the real container reproduces replacement of both the editor fixture and its scroll element in both directions. Focus disappears, the selected range resets, and scrollTop becomes zero; persisted draft text survives. This is a component lifecycle defect, not evidence that draft text is deleted. The same agent repeated the test in a second clean checkout at the same trusted commit and obtained identical results.

export function useSplitWorkspaceActive(): boolean {
  const isCompactViewport = useIsCompactViewport();
  return !isCompactViewport;

On compact, the container returns StandalonePaneContent; on desktop, the one-pane branch returns a fragment containing command handlers and WorkspacePaneContent. These are different tree shapes and component types, so the thread subtree does not retain identity.

6. Proposed fix and safety decision

Maintain a stable single-thread component path on both sides of the breakpoint; alter surrounding chrome without replacing the mounted editor/timeline owner. Keep route-driven thread selection correct on compact, restrict split commands to their active mode, and retain the separate handling for a new-thread page and collapsed multi-pane workspaces.

No automated fix PR: this is not safely a branch substitution alone. The current paths deliberately differ in pane identity (main versus the layout pane), route resolution, and page/pane rendering surface. Choosing a stable identity and reconciling those semantics needs a product/compatibility decision, which fails the autopilot's simple-fix gate. No external prototype was reviewed or endorsed. No production changes, fix branch, push, or fix PR were made.
