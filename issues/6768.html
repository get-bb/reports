#6768 · ACP progress bypasses output normalization

BugPriority: MediumEffort: Mediumproviders · provider-acpGitHub issue2026-10-31 · base 916d684ac23d

Verdict: REPRODUCED at the production ACP translation boundary · Root-cause confidence: high.

1. TL;DR

When an ACP agent places argument-building snapshots in tool-call text content, bb forwards that content as command output or non-command progress. A fresh synthetic replay against trusted main demonstrates both paths without executing any provider-supplied command. A phase-aware dialect using the existing command-output normalizer suppresses those snapshots for commands while preserving real JSON output; the exact same hook cannot affect non-command progress. The missing normalization boundary is therefore reproducible independently of the third-party provider. Live Kimi emission, the external recording, and browser rendering were not verified, so this verdict is scoped to bb's translator behavior.

Complete regression test
import { describe, expect, it } from "vitest";
import type { ThreadDelta } from "@bb/provider-bridge-protocol";
import { ACP_UPDATE_METHOD } from "./bridge-protocol.js";
import { createAcpDeltaTranslator } from "./delta-translation.js";
import type { AcpDialect } from "./dialect.js";
import type { AcpToolCallUpdateEvent } from "./wire.js";

const kinds = ["execute", "other"] as const;
const input = { command: "synthetic-operation", request: "sample-work" };
const argumentSnapshots = ['{"request":"sample', JSON.stringify(input)];
const realJson = '{"records":[7,11]}';

function createReplay(kind: (typeof kinds)[number], dialect?: AcpDialect) {
  const translator = createAcpDeltaTranslator({ cwd: "/workspace", dialect });
  function send(update: AcpToolCallUpdateEvent) {
    return translator.translateAcpEvent({
      jsonrpc: "2.0",
      method: ACP_UPDATE_METHOD,
      params: { threadId: "synthetic-thread", update },
    });
  }
  const opened = send({
    sessionUpdate: "tool_call",
    toolCallId: "synthetic-call",
    title: "Synthetic work",
    kind,
    status: "pending",
  });
  expect(opened).toContainEqual(expect.objectContaining({ kind: "item.open" }));
  function progress(text: string, rawInput?: typeof input) {
    return send({
      sessionUpdate: "tool_call_update",
      toolCallId: "synthetic-call",
      status: "in_progress",
      content: [{ type: "content", content: { type: "text", text } }],
      ...(rawInput === undefined ? {} : { rawInput }),
    });
  }
  return { send, progress };
}

function displayedText(deltas: ThreadDelta[]): string[] {
  return deltas.flatMap((delta) => {
    if (delta.kind === "command.outputSnapshot") return [delta.text];
    if (delta.kind === "item.progress" && delta.message !== undefined) {
      return [delta.message];
    }
    return [];
  });
}

describe("argument-phase text at the ACP translation boundary", () => {
  it.each(kinds)("does not present argument snapshots as %s output", (kind) => {
    const replay = createReplay(kind);
    const deltas = argumentSnapshots.flatMap((text) => replay.progress(text));
    deltas.push(...replay.progress(JSON.stringify(input), input));
    const observed = displayedText(deltas);
    console.log(JSON.stringify({ scenario: "default", kind, observed }));
    expect(observed).toEqual([]);
  });

  it.each(kinds)("lets a dialect suppress argument echoes for %s", (kind) => {
    const inputSeen = new Set<string>();
    const replay = createReplay(kind, {
      id: "synthetic-phase-aware",
      normalizeCommandEvent(event) {
        const collectingInput = !inputSeen.has(event.toolCallId);
        if (event.rawInput !== undefined) inputSeen.add(event.toolCallId);
        if (event.status === "completed") inputSeen.delete(event.toolCallId);
        return collectingInput ? { ...event, content: [] } : event;
      },
    });
    const deltas = argumentSnapshots.flatMap((text) => replay.progress(text));
    deltas.push(...replay.progress(JSON.stringify(input), input));
    deltas.push(...replay.progress(realJson));
    const observed = displayedText(deltas);
    const terminal = replay.send({
      sessionUpdate: "tool_call_update",
      toolCallId: "synthetic-call",
      status: "completed",
      content: [{ type: "content", content: { type: "text", text: realJson } }],
      rawOutput: realJson,
    });
    const close = terminal.find((delta) => delta.kind === "item.close");
    console.log(JSON.stringify({ scenario: "command-hook", kind, observed }));
    expect(close).toMatchObject({ resultText: realJson });
    expect(observed).toEqual([realJson]);
  });
});

5. Root cause

The wire schema accepts text content on an in-progress update without requiring rawInput. The translator uses that update's content as output without knowing whether the agent is still generating arguments. There is intentionally no universal inference from JSON syntax, because valid command output may also be JSON.

  1. Content extraction joins text blocks and returns that string before considering rawOutput.
  2. In-progress translation calls normalizeCommandEvent only for calls already opened as commands, then emits command.outputSnapshot. The non-command branch extracts from the unnormalized event and emits item.progress.
  3. The dialect interface provides a command-specific normalizer but no corresponding general progress normalizer. Classification and identity hooks do not supply a dedicated output-text filtering contract.
  4. Generic close handling also directly extracts output from its event, bypassing command normalization. A lifecycle-aware solution must address terminal handling as well.
  5. The delta assembler passes the progress message into a tool-call progress event. The reproduction stops at the translator output; it does not claim an end-to-end UI or live delegation recording.
const normalizedEvent = dialect.normalizeCommandEvent?.(event) ?? event;
const streamed = extractAcpStreamedCommandOutput(normalizedEvent);
...
const progressText = extractAcpToolCallOutputText(event);

The positive control isolates the missing boundary: the phase-aware command hook can suppress argument snapshots and retain subsequent JSON output, but non-command progress still contains every argument snapshot. This is not a failure caused by an absent runtime, authentication, or a test mock.

6. Proposed fix

Provide a supported dialect normalization path for non-command progress and terminal result extraction, while preserving existing command normalization and raw event evidence. Implement the provider-specific argument/output phase distinction in its dialect, not as a global JSON filter. Define cleanup for completion, failure, cancellation, and forced turn termination; test interleaved calls, legitimate JSON output, and command-hook interoperability. Since this changes a public dialect contract, API naming, documentation, and compatibility need review rather than an automatic private workaround.

No automatic fix PR: open PR #6769 already links to this issue. A second PR would duplicate existing work; the fix direction also changes a public SDK contract and is outside the autopilot simple-fix gate.
