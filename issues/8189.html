#8189 · Transient availability errors become cached negative capability

BugMedium priorityEffort: LowprovidersGitHub issue2026-11-25

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

Trusted base: fb045a046653cc127656ca3c7243d44ae4c94f3f from origin/main.

1. TL;DR

A nested server asks its parent which pooled providers are available before contributing routing settings. A single failed availability refresh replaces a previously successful answer with both providers unavailable. That error-derived answer is cached for the same 30 seconds as an authoritative successful response, preventing a recovered parent from being contacted during that interval. Real local HTTP reproductions confirm the failure for both a 503 response and a response that exceeds the actual two-second timeout. This report verifies the capability-cache defect; it does not claim an end-to-end reproduction of a provider login error or retry UI.

import { once } from "node:events";
import { createServer } from "node:http";
import { performance } from "node:perf_hooks";
import { expect, it } from "vitest";
import { ParentAvailability } from "./parent-pool.js";

it.each(["http-503", "timeout"])(
  "preserves known parent availability after one transient %s",
  async (failure) => {
    let requests = 0;
    let clock = 0;
    const errors: string[] = [];
    const timers: NodeJS.Timeout[] = [];
    const available = { claude: true, codex: false };
    const server = createServer((_request, response) => {
      requests += 1;
      if (requests === 2 && failure === "http-503") {
        response.writeHead(503).end();
        return;
      }
      if (requests === 2 && failure === "timeout") {
        timers.push(
          setTimeout(() => {
            response.writeHead(200, { "content-type": "application/json" });
            response.end(JSON.stringify(available));
          }, 3_000),
        );
        return;
      }
      response.writeHead(200, { "content-type": "application/json" });
      response.end(JSON.stringify(available));
    });
    server.listen(0, "127.0.0.1");
    await once(server, "listening");
    const address = server.address();
    if (address === null || typeof address === "string") {
      throw new Error("Expected a local TCP listener");
    }
    const client = new ParentAvailability({
      parent: {
        baseUrl: `http://127.0.0.1:${address.port}`,
        token: "synthetic-local-test-token",
      },
      fetch,
      now: () => clock,
      onError: (error) => {
        errors.push(error instanceof Error ? error.name : String(error));
      },
    });
    try {
      const initial = await client.get();
      expect(initial).toEqual(available);
      clock = 30_000;
      const startedAt = performance.now();
      const afterFailure = await client.get();
      const elapsedMs = Math.round(performance.now() - startedAt);
      clock = 59_999;
      const beforeExpiry = await client.get();
      const requestsBeforeExpiry = requests;
      clock = 60_000;
      const recovered = await client.get();
      console.log(
        JSON.stringify({
          failure,
          initial,
          afterFailure,
          beforeExpiry,
          requestsBeforeExpiry,
          recovered,
          totalRequests: requests,
          elapsedMs,
          errors,
        }),
      );
      expect(recovered).toEqual(available);
      expect(afterFailure).toEqual(available);
    } finally {
      for (const timer of timers) clearTimeout(timer);
      server.closeAllConnections();
      await new Promise<void>((resolve, reject) => {
        server.close((error) => (error ? reject(error) : resolve()));
      });
    }
  },
  10_000,
);

5. Root cause

The constants define a 30,000 ms success TTL and a 2,000 ms network timeout. load() turns all exceptions, malformed bodies, and non-OK responses into the same unavailable value. It cannot distinguish an unavailable parent from an unsuccessful measurement.

return UNAVAILABLE_POOL;

get() then assigns that fallback the full success TTL:

const value = await this.load();
const ttlMs = this.options.ttlMs ?? DEFAULT_AVAILABILITY_TTL_MS;
this.cached = { value, expiresAt: this.options.now() + ttlMs };
return value;

The defect is loss of measurement provenance: a failed refresh overwrites known capabilities and is treated as an authoritative negative result. The cache window starts after load finishes. This is why a roughly two-second aborted read can suppress refreshes for another 30 seconds.

canServe() directly returns the provider boolean. contributeFor() only supplies the routed settings when canServe succeeds; otherwise it deletes the retry-route marker and returns neutralized settings for a configured parent. This source path supports the routing consequence without making an unperformed provider-session claim.

6. Proposed fix

Represent a failed availability measurement separately from a valid positive or negative answer. Preserve last-known-good availability for a bounded transient-failure window, retry failed measurements sooner than successful measurements, and eventually report a persistently unreachable parent unavailable. Keep explicit successful negative answers authoritative. Fail closed when there has never been a valid answer, and verify rejection, invalid-response, recovery, and prolonged-outage behavior. Authentication failures need deliberate handling rather than accidentally inheriting a stale-success policy.
