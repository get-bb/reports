#7665 · ACP session metadata has no retry diagnostic translation

BugPriority: Medium Effort: Mediumprovidersprovider-acp GitHub issueNovember 17, 2026

Verdict: REPRODUCED · Root-cause confidence: high, specifically for loss at the translator boundary.

Trusted base: de34f3492e4c69ade967e7b9b1345c9e8d62b03d, fetched from the target repository's main branch. A later fetch reached da39507dd3ad1bbc2b05ba046216f576330045e8; the translator, delta contract, and timeline files cited here were unchanged.

1. TL;DR

A pending provider retry can carry an explanation, but BB's ACP translator does not turn this session metadata into any diagnostic event. Two fresh main-branch checkouts produced no deltas for a retry-only update and only a rename for an update that also had a title. The real translator and real delta assembler were exercised with synthetic input; the running turn stayed open in both cases. This confirms the information-loss mechanism, not live OpenCode emission, the exact user-visible waiting state, or push delivery. No model request, live BB instance, or user database was used.

    import { describe, expect, it } from "vitest";
import { createDeltaAssembler } from "@bb/provider-bridge-protocol/assembler";
import {
  ACP_TURN_STARTED_METHOD,
  ACP_UPDATE_METHOD,
} from "./bridge-protocol.js";
import { createAcpDeltaTranslator } from "./delta-translation.js";

describe("ACP pending retry diagnostics", () => {
  it.each([false, true])("retains diagnostic data with title=%s", (withTitle) => {
    const threadId = "retry-regression-thread";
    const translator = createAcpDeltaTranslator({ cwd: "/workspace" });
    const assembler = createDeltaAssembler({
      providerId: "acp",
      entropyPrefix: "retry-regression",
      textDeltaFlushMs: 0,
    });
    const opening = translator.translateAcpEvent(
      {
        jsonrpc: "2.0",
        method: ACP_TURN_STARTED_METHOD,
        params: { threadId },
      },
      { threadId },
    );
    assembler.assemble({ threadId, deltas: opening });
    const openTurnId = assembler.getOpenTurnId(threadId);
    expect(openTurnId).toBeTruthy();

    const diagnostic = {
      attempt: 3,
      nextRetryAt: "2026-01-01T00:00:30.000Z",
      error: {
        type: "provider.unavailable",
        message: "Synthetic upstream maintenance response",
        status: 503,
      },
    };
    const deltas = translator.translateAcpEvent(
      {
        jsonrpc: "2.0",
        method: ACP_UPDATE_METHOD,
        params: {
          threadId,
          update: {
            sessionUpdate: "session_info_update",
            ...(withTitle ? { title: "Diagnostic test title" } : {}),
            _meta: { "opencode/retry": diagnostic },
          },
        },
      },
      { threadId },
    );
    const events = assembler.assemble({ threadId, deltas });
    console.info(JSON.stringify({ withTitle, deltas, events }));
    expect(assembler.getOpenTurnId(threadId)).toBe(openTurnId);
    expect(events.some((event) => event.type === "turn/completed")).toBe(false);
    if (withTitle) {
      expect(events).toContainEqual(
        expect.objectContaining({
          type: "thread/name/updated",
          threadName: "Diagnostic test title",
        }),
      );
    }
    const preserved = JSON.stringify(events);
    expect(preserved).toContain(diagnostic.error.message);
    expect(preserved).toContain(String(diagnostic.error.status));
    expect(preserved).toContain(diagnostic.nextRetryAt);
    expect(preserved).toContain(String(diagnostic.attempt));
  });
});

5. Root cause

The boundary schema accepts generic session updates with passthrough fields, so metadata can reach the translator: wire.ts:197–211. The bridge validates the session identity before forwarding the update: bridge notification handling, then emits it through ACP_UPDATE_METHOD: emitSessionUpdate. These transport observations are static source evidence; the runtime reproduction begins at that internal ACP notification boundary.

The translator's complete session-info case reads only the title, returns early for a missing or unusable title, and otherwise returns exactly one rename delta:

      case "session_info_update": {
        const title = isJsonObject(update) ? update["title"] : undefined;
        if (
          typeof title !== "string" ||
          title.trim() === "" ||
          title.trimStart().startsWith(SYSTEM_INSTRUCTIONS_OPEN_TAG) ||
          title === lastAgentTitle
        ) {
          return [];
        }
        lastAgentTitle = title;
        return [{ kind: "thread.name", name: title, source: "agent" }];
      }

No metadata is inspected. Because this is a recognized update kind, the default unhandled-event fallback is not reached either. The assembler cannot surface data for which it receives no delta. Title validation and deduplication should remain independent of diagnostic handling.

There is an existing non-terminal error path: provider.error can set willRetry: true without settling the turn: assembler behavior and existing keep-open regression. However, the provider/error event contract has a required message, no retry-status identity, and no null/clear operation. The timeline represents willRetry errors as reconnect rows and collapses consecutive reconnect rows; that is not an explicit transient diagnostic-clear lifecycle.

6. Proposed fix and simple-fix check

Validate the provider extension at the ACP boundary, then translate retry diagnostics independently from title changes. Preserve the source error text, optional status, attempt, and retry time without interpreting every HTTP rate limit as a daily quota problem. Keep the active prompt alive and do not dispatch additional requests. Define how explicit null, successful progress, completion, interruption, and a new prompt clear the active status without losing historical diagnostics or leaking state across threads.

No automatic fix or PR: a translator-only append of provider.error would expose the message but would not implement explicit status clearing. Choosing and wiring a lifecycle-aware presentation contract crosses the existing translator and timeline/domain responsibilities and requires a product/contract decision. That fails the autopilot's one-subsystem, no-product-decision constraints. No production patch or fix branch was created or pushed.

Tests for a future approved fix should add explicit-null clearing, prompt completion and cancellation, repeated titles, malformed metadata, missing HTTP status, and thread isolation at the selected lifecycle owner. If that choice changes server/daemon wire semantics, follow the repository's protocol-version policy.
