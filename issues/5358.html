#5358 · Windows drive roots are absent from directory navigation

BugPriority: MediumEffort: Mediumworkspacespartial-reproGitHub issueOctober 11, 2026 · base 3912f4aaefb7dff55c7e0cb5003b26b5cf1457dc

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium

1. TL;DR

The project folder browser has no way to discover other Windows drive roots by clicking through its directory listing. Trusted main starts browsing at the host's home directory, lists only the current directory's children, and stops parent navigation at the current drive root. A controlled test using Node's Windows path implementation and a simulated filesystem reproduces that navigation limitation, while explicit paths to two other simulated drives work. The same agent repeated the test in a second clean checkout with the same result. Native Windows, Google Drive mounts, and the user's desktop screenshot were not verified; this is a partial reproduction, not evidence that Google Drive itself rejects access.

5. Root cause

browseHostDirectory defaults to home and reads one directory validates one absolute directory, resolves it, then calls fs.readdir. It does not enumerate drive roots. Windows drives are separate roots, not children of the current drive.

6. Proposed fix and safety gate
