#5371 · ACP worker shutdown leaves agent processes running

BugPriority: MediumEffort: Lowproviders · host · provider-acpIssue

October 12, 2026 · trusted origin/main 4b12265e5fb82c01ea67e67cfe8d935533406937

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The ACP bridge starts separate agent processes. Killing its worker with SIGTERM or SIGINT currently bypasses cleanup, so agents that keep working after stdin closes remain alive after their parent exits. Even the normal stdin-close cleanup misses agents used for model discovery because they are not registered thread sessions. A real worker and a small deterministic ACP fixture reproduce both paths without provider credentials. The same six-case regression fails in five cases in two clean trusted checkouts; with the contained fix, all six pass.

  ),

const bridgeModule = fileURLToPath(new URL("./bridge.ts", import.meta.url));

function isAlive(pid: number): boolean {
  try {
    process.kill(pid, 0);
    return true;
  } catch {
    return false;
  }
}

async function waitFor(predicate: () => boolean): Promise<void> {
  const deadline = Date.now() + 10_000;
  while (!predicate()) {
    if (Date.now() >= deadline)
      throw new Error("Timed out waiting for process state");
    await delay(25);
  }
}

The fixture implements only initialization and session creation. Its lifetime deliberately remains independent of stdin EOF; otherwise a cooperative agent could mask the missing parent cleanup.

5. Root cause

The worker bootstrap installs signal handlers only when the bridge exports them. The ACP bridge export supplies only onClose. Node's default signal action therefore exits the worker without running agent cleanup.

export const experimental_providerBridge = experimental_defineProviderBridge({
  handleLine,
  onClose: () => {
    void stopAllSessions().finally(() => {
      process.exit(0);
    });
  },
});

stopAllSessions() enumerates only sessionsByBbThreadId. The model-discovery connection is separate and has an empty exit callback, so that cleanup misses it even on normal close. Both creation sites call the underlying connection factory directly, with no shutdown admission check.

The connection already exposes managed process termination. The missing responsibility is bridge-wide lifecycle ownership, not a new process-control mechanism.

6. Proposed fix

Track all ACP connections in one bridge-owned set, removing them on exit. Gate the shared factory once shutdown starts. Route EOF, SIGTERM and SIGINT into one idempotent shutdown routine. Release registered sessions and stop every tracked connection concurrently with all-settled handling, report cleanup failures to stderr, close the tool bridge, then exit. Reuse the existing managed termination/escalation implementation.

The implemented candidate changes only two files in the ACP subsystem, with 245 additions and 11 deletions: 256 changed text lines. It adds no dependency, generated file, stored-data change, or public protocol/schema change. It leaves thread stop behavior alone.
