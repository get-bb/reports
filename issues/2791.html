#2791 · Thread spawn output with a multi-line prompt

Bug Medium Effort: Low threads cli open on GitHub 2026-09-01 · base 688eb42

Verdict: NOT REPRODUCED · Root-cause confidence: low

1. TL;DR

The report claims that a successful non-JSON spawn can produce empty standard output when the prompt contains multiple lines. Trusted main did not show this behavior. The focused command test passed twice in clean checkouts. The command always writes the new ID before it writes the detailed thread block. The cause of the reported observation remains unknown.

import { describe, expect, it, vi } from "vitest";
import {
  collectLogLines,
  runCommand,
  setupCommandOutputTestEnvironment,
  stubServerApi,
} from "../helpers/command-output-harness.js";
import type { CommandRegistrar } from "../helpers/command-output-harness.js";
import * as fixtures from "../helpers/command-output-fixtures.js";
import { registerThreadCommands } from "../../commands/thread/index.js";

describe("bb thread spawn standard output reproduction", () => {
  setupCommandOutputTestEnvironment();

  const register: CommandRegistrar = (program) =>
    registerThreadCommands(program, () => "http://server");

  it("prints the new thread ID for a multi-line prompt without JSON output", async () => {
    const thread = fixtures.makeThread({
      id: "thread-multiline-prompt",
      projectId: "proj-1",
      providerId: "claude-code",
      status: "starting",
    });
    stubServerApi({ "v1.threads.$post": vi.fn(async () => thread) });

    await runCommand(
      [
        "thread",
        "spawn",
        "--project",
        "proj-1",
        "--provider",
        "claude-code",
        "--prompt",
        ["first line", "second line"].join("\n"),
      ],
      register,
    );

    expect(collectLogLines(vi.mocked(console.log))).toContain(
      "Thread spawned: thread-multiline-prompt",
    );
    expect(collectLogLines(vi.mocked(console.log))).toContain(
      "  ID:       thread-multiline-prompt",
    );
  });
});

5. Root cause

No root cause exists in the tested code path for an empty output result. After the SDK returns a thread, the command checks only the JSON flag. It then writes the first ID line and calls the detailed formatter. See the spawn output path.

if (outputJson(opts, thread)) return;
console.log(`Thread spawned: ${thread.id}`);
printThread(thread);

The formatter writes the same ID again. See the thread formatter.

console.log(`  ID:       ${thread.id}`);

History shows that the first ID write has existed since commit 5b9199822e92b206d6950dc9823ae449fe53b4d6 on 2026-03-25. A stale installed CLI, an outer wrapper, or stream capture could explain the observation. This report has no evidence for any one explanation.

6. Proposed fix

Do not change trusted main without a failing test. The next useful check must record bb --version, the resolved executable path, the exit code, and separate standard-output and standard-error files from an affected installation.
