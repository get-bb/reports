1. TL;DR

Current main preserves list markers, blank lines, indentation, and fenced code when a mixed rendered assistant-message selection is added to the composer. A selection confined to code intentionally becomes bare code, but keeps its line breaks. The live selection is now serialized as Markdown rather than passed through as browser display text; this landed in #5613, merged October 16, 2026 at 04:45:27 UTC. Desktop 0.46.1 was published October 15, 2026 at 15:17:47 UTC, before that change. Both clean checkouts passed the same quote-to-draft-and-real-editor test, so another production fix is not justified; the historical claim that every newline collapsed was not dynamically reproduced.

Complete reproduction test

// @vitest-environment jsdom

import {
  cleanup,
  fireEvent,
  render,
  screen,
  waitFor,
} from "@testing-library/react";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { MemoryRouter } from "react-router-dom";
import { afterEach, expect, it } from "vitest";
import { conversationRow } from "@/test/fixtures/thread-timeline-rows";
import { ThreadTimelineRows } from "./ThreadTimelineRows";
import {
  StoryDraftPromptBox,
  useStoryPromptDraft,
} from "./StoryDraftPromptBox";

const markdown =
  "- First item\n- Second item\n\n```text\nalpha\n  beta\n\nomega\n```";

function QuoteHarness() {
  const draft = useStoryPromptDraft();
  return (
    <>
      <ThreadTimelineRows
        timelineRows={[conversationRow({ role: "assistant", text: markdown })]}
        threadRuntimeDisplayStatus="idle"
        onSelectionAddToChat={draft.addQuote}
        workspaceRootPath={undefined}
      />
      {draft.text !== "" ? <StoryDraftPromptBox draft={draft} /> : null}
      <output data-testid="draft">{draft.text}</output>
    </>
  );
}

afterEach(() => {
  window.getSelection()?.removeAllRanges();
  cleanup();
});

it.each(["mixed", "code-only"] as const)(
  "keeps %s selection structure through Add to chat and the real composer",
  async (mode) => {
    const { container } = render(
      <QueryClientProvider client={new QueryClient()}>
        <MemoryRouter>
          <QuoteHarness />
        </MemoryRouter>
      </QueryClientProvider>,
    );
    const prose = container.querySelector("[data-sidebar-swipe-selectable]")!;
    const range = document.createRange();
    range.selectNodeContents(
      mode === "mixed" ? prose : prose.querySelector("pre code")!,
    );
    const rect = new DOMRect(10, 30, 100, 20);
    Object.defineProperties(range, {
      getBoundingClientRect: { value: () => rect },
      getClientRects: { value: () => ({ length: 1, item: () => rect }) },
    });
    const selection = window.getSelection()!;
    selection.removeAllRanges();
    selection.addRange(range);
    fireEvent(document, new Event("selectionchange"));
    fireEvent.click(await screen.findByRole("button", { name: "Add to chat" }));
    const expected =
      mode === "mixed"
        ? "> - First item\n> - Second item\n>\n> ```text\n> alpha\n>   beta\n>\n> omega\n> ```\n"
        : "> alpha\n>   beta\n>\n> omega\n";
    await waitFor(() => {
      expect(screen.getByTestId("draft").textContent).toBe(expected);
      expect(
        container.querySelector("[contenteditable='true'] blockquote"),
      ).not.toBeNull();
    });
    console.info(
      JSON.stringify({
        mode,
        expected,
        actual: screen.getByTestId("draft").textContent,
      }),
    );
  },
);

5. Root cause

The previously missing boundary was rendered-selection-to-Markdown conversion, not newline prefixing in the shared quote formatter. Before the existing fix, the Add to chat action forwarded currentSelection.text from Selection.toString(). Browser display text has no Markdown list markers or code fences. This explains structure loss, but static evidence alone does not establish the reporter's historical all-newlines-to-spaces symptom.

On the recorded main commit, the selection action calls readSelectedMessageMarkdown() ?? currentSelection.text. The selection reader finds the registered message prose and passes its clipped DOM range to selectionClipboard.

The serializer rebuilds a language-aware fence around a selected PRE block and keeps code text's internal newlines. Its code-only branch returns the selected code verbatim. The shared draft formatter then prefixes every line, including empty quoted lines, and appends a reply line.

const block = trimmed
  .split("\n")
  .map((line) => (line.length > 0 ? `> ${line}` : ">"))
  .join("\n");

The whitespace-collapsing normalizeSelectionText in the prose component is used for selection-boundary membership checks, not the quote payload. Removing it would change unrelated selection validation and is not a justified repair.
