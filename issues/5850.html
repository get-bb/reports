1. TL;DR

A new project-checkout branch can inherit commits from a base other than the repository default. Git creates that branch correctly, but the server plugin does not report the chosen base in its environment result. Core persists an absent merge base and its normal fallback then compares against the default branch. The result includes changes inherited from the selected base even when the thread has changed nothing. Two clean checkouts reproduce the defect using the real plugin server and host entry plus real Git operations; a three-line server-only correction makes the regression pass.

  createFakePluginHost,

import { PROJECT_CHECKOUT_ENVIRONMENT_PROVIDER_ID } from "./provider-id.js";
import plugin from "./server.js";

const execFileAsync = promisify(execFile);

it("keeps inherited commits out of a new checkout branch's diff", async () => {
  const root = await mkdtemp(join(tmpdir(), "bb-checkout-merge-base-"));
  const repo = join(root, "repo");
  const dataDir = join(root, "plugin-data");
  async function git(...args: string[]): Promise<string> {
    const result = await execFileAsync("git", args, {
      cwd: repo,
      env: {
        ...process.env,
        GIT_AUTHOR_NAME: "bb",
        GIT_AUTHOR_EMAIL: "bb@example.com",
        GIT_COMMITTER_NAME: "bb",
        GIT_COMMITTER_EMAIL: "bb@example.com",
      },
    });
    return result.stdout;
  }
  const host = experimental_createHostEntryHarness(createCheckoutHostEntry(), {
    experimental_paths: { dataDir, tempDir: join(root, "tmp") },
  });
  const { bb, harness } = createFakePluginHost({
    pluginId: "environment-project-checkout",
    experimental_callHostRpc: (call) => {
      if (call.method !== "attach") throw new Error("Unexpected host method");
      return host.experimental_call(
        "attach",
        checkoutHostContract.attach.input.parse(call.input),
      );
    },
    sdk: { environments: { list: () => [] }, threads: { list: () => [] } },
  });
  try {
    await mkdir(repo);
    await mkdir(dataDir);
    await git("init", "--initial-branch=main");
    await git("commit", "--allow-empty", "-m", "initial");
    await git("switch", "-c", "topic-base");
    await writeFile(join(repo, "base-only.txt"), "inherited content\n");
    await git("add", "base-only.txt");
    await git("commit", "-m", "base change");
    await git("update-ref", "refs/remotes/origin/topic-base", "HEAD");
    await git("switch", "main");
    await plugin(bb);
    const provider = harness.registrations.environmentProviders.get(
      PROJECT_CHECKOUT_ENVIRONMENT_PROVIDER_ID,
    );
    if (!provider) throw new Error("Missing provider");
    const result = await provider.create({
      project: {
        id: "project-1",
        kind: "standard",
        name: "checkout regression",
        gitRemoteUrl: null,
        createdAt: 1,
        updatedAt: 1,
      },
      host: makeHostResponse({ id: "host-a" }),
      projectCheckout: { path: repo, experimental_ownsPath: false },
      gitRemote: null,
      inputs: { branch: { kind: "new", baseBranch: "origin/topic-base" } },
      thread: makeThreadResponse(),
      suggestedBranchName: "bb/checkout-regression",
      attempt: 1,
      pathKey: "merge-base-regression",
      experimental_claimPath: async () => true,
      report: { step() {}, log() {} },
      signal: new AbortController().signal,

    expect(result.status).toBe("created");
    if (result.status !== "created") throw new Error("Checkout failed");

5. Root cause

Successful provider result returns status, path, and ownership, but omits the new branch's selected base. That base is already available to this server function in its typed branch argument.

return {
  status: "created",
  path: result.path,
  ownsPath: ...
};

Provisioning persistence assigns row.mergeBaseBranch = produced.mergeBaseBranch ?? null. Domain comparison-base resolver selects mergeBaseBranch ?? baseBranch ?? defaultBranch. Missing creation metadata therefore selects main instead of the ref actually used to create the branch. This is metadata loss, not incorrect Git branch creation.

6. Proposed fix and verification

On successful creation, return the already-known selected base through the existing optional mergeBaseBranch provider-result field when branch.kind is new. Keep existing-branch and as-is attachments unchanged. The server owns this product metadata; no additional host RPC field, protocol bump, migration, or dependency is required. The local patch is scoped to initial branch creation, not an expansion of restore behavior.

The regression was added and failed before the production edit. With the server-only correction, all 43 tests across four plugin files pass and plugin typecheck passes under pnpm exec turbo run test typecheck --filter=bb-plugin-environment-project-checkout. git diff --check passes. The patch changes three files, with 114 additions and zero deletions (114 total text lines), including regression and README documentation.
