#5480 · Codex review warnings bypass normalization

Bug Priority: Low Effort: Medium providers provider-codex · GitHub issue

2026-10-20 · trusted origin/main bd93d18896bab97c950c4fa3451b621c1e0569c1

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

BB knows that Codex can send a guardian review notification, but its translator does not handle that notification as a warning. A valid message is therefore emitted as provider/unhandled, carrying the raw JSON instead of the existing human-readable warning event. The timeline's diagnostic renderer explains the raw-event presentation, while the ordinary warning renderer already supports the desired text. The focused regression fails identically in two separate clean checkouts of trusted main. The proposed local repair reuses that existing warning path; it does not approve commands, alter permissions, or introduce a new review UI.

Complete regression test

import { describe, expect, it } from "vitest";
import { experimental_createDeltaAssembler as createDeltaAssembler } from "@get-bb/plugin-sdk/provider-bridge/testing";
import { createCodexEventTranslator } from "./translator.js";
import { threadScope } from "./event-scope.test-support.js";

function translate(params: Record<string, unknown>) {
  const translator = createCodexEventTranslator({
    additionalWorkspaceWriteRoots: [],
  });
  const assembler = createDeltaAssembler({
    providerId: "codex",
    entropyPrefix: "guardian-test",
    textDeltaFlushMs: 0,
  });
  return assembler.assemble({
    threadId: "guardian-test-thread",
    deltas: translator.translateEvent({
      jsonrpc: "2.0",
      method: "guardianWarning",
      params,
    }),
  });
}

describe("Codex guardian warning translation", () => {
  it("preserves the review message as a warning instead of raw diagnostics", () => {
    expect(
      translate({
        threadId: "provider-thread",
        message: "Review completed for a read-only operation.",
      }),
    ).toEqual([
      expect.objectContaining({
        type: "provider/warning",
        category: "general",
        summary: "Review completed for a read-only operation.",
        scope: threadScope(),
      }),
    ]);
  });

  it.each([
    { threadId: "provider-thread" },
    { threadId: "provider-thread", message: 42 },
    { message: "Review completed for a read-only operation." },
  ])("keeps malformed notifications visible as diagnostics: %j", (params) => {
    expect(translate(params)).toEqual([
      expect.objectContaining({
        type: "provider/unhandled",
        rawType: "guardianWarning",
      }),
    ]);
  });
});

5. Root cause

  1. The generated provider contract already defines a string thread identifier and message. The wire format is not missing.
  2. The handled-event union accepts general, deprecation, and configuration warnings, but has no guardian-warning variant. A valid guardian notification therefore fails the handled parser.
  3. The visibility table classifies this known notification as unknown. Structured review-start/review-completion notifications are separately classified as noise; those are not the message-bearing warning.
  4. The translator's failed-parse branch calls the unknown-event fallback, which includes the raw envelope. The real shared delta assembler materializes the unhandled event observed in both tests.
  5. The shared timeline diagnostic renderer explains the raw-event row when diagnostic operations are enabled. With diagnostic operations disabled, it returns no operation for this event. By contrast, the existing warning renderer uses the warning summary as its title.
guardianWarning: "unknown"

const parsed = codexHandledEventSchema.safeParse(rawEvent);
if (!parsed.success) {
  return isHandledCodexMethod(rawEvent.method)
    ? buildUnhandledCodexDeltas({ rawEvent, rawType: rawEvent.method })
    : buildUnhandledCodexDeltas({ rawEvent });
}

This is missing presentation normalization, not evidence of an approval failure, authorization bypass, or failed command execution. Hiding every review event would discard potentially meaningful messages; changing the global diagnostic fallback would affect unrelated unknown events.

6. Proposed fix and validation

Validate the existing guardian notification at the provider boundary, route it to the same general-warning branch as ordinary Codex warnings, and mark its visibility coverage normalized. Preserve malformed notifications as unhandled diagnostics. This changes no public protocol, persisted schema, permission decision, authentication, dependency, CLI command, or SDK surface; the already supported warning event reaches existing consumers.
