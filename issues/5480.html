The Codex provider recognizes the automatic-review notification name but does not normalize its content. Two synthetic, schema-shaped notifications pass through the real provider translator and shared delta assembler as two separate unsupported-event records. import { describe, expect, it } from "vitest";
import { experimental_createDeltaAssembler as createDeltaAssembler } from "@get-bb/plugin-sdk/provider-bridge/testing";
import { createCodexEventTranslator } from "./translator.js";

describe("automatic review notification reproduction", () => {
  it("keeps review messages out of the unsupported-event fallback", () => {
    const translator = createCodexEventTranslator({
      additionalWorkspaceWriteRoots: [],
    });
    const assembler = createDeltaAssembler({
      providerId: "codex",
      entropyPrefix: "review-repro",
      textDeltaFlushMs: 0,
    });
    const events = ["First synthetic review result", "Second synthetic review result"]
      .flatMap((message) => assembler.assemble({
        threadId: "synthetic-bb-thread",
        deltas: translator.translateEvent({
          jsonrpc: "2.0",
          method: "guardianWarning",
          params: { threadId: "synthetic-codex-thread", message },
        }),
      }));
    console.log("Observed normalized events:", JSON.stringify(events, null, 2));
    expect(events.filter((event) => event.type === "provider/unhandled")).toEqual([]);
  });
});

5. Root cause

The trusted generated notification contract contains a thread identifier and message. The notification is explicitly known, but its visibility coverage is unknown. The adjacent structured review-start and review-completion notifications are instead classified as noise; they are different events.

The handled schema has general, configuration, and deprecation warnings, but no handled guardian-warning entry. The translator parses the handled schema and sends unsuccessful parses to fallback. Unknown coverage creates an unhandled delta with the full raw envelope. The shared assembler materializes the observed unsupported-event records.

guardianWarning: "unknown"

const parsed = codexHandledEventSchema.safeParse(rawEvent);
if (!parsed.success) {
  return isHandledCodexMethod(rawEvent.method)
    ? buildUnhandledCodexDeltas({ rawEvent, rawType: rawEvent.method })
    : buildUnhandledCodexDeltas({ rawEvent });
}

The timeline includes those diagnostic operations only when enabled. The shared detail formatter humanizes the raw type and includes the JSON payload, directly explaining the Guardian Warning / Raw event / Payload text. Consecutive notifications remain distinct records and rows in the observed projection.

This is missing provider presentation coverage, not evidence that automatic approval itself fails or that authorization is bypassed. The raw-event fallback is intentional for genuinely unsupported events; deleting it globally or hiding all review-related warnings would conceal potentially important diagnostics.

6. Proposed fix and simple-fix gate

Define which automatic-review outcomes should be shown and whether consecutive successful notices should be grouped. Then validate the notification at the existing Codex boundary, translate it through an existing appropriate delta kind or agreed presentation path, and update visibility coverage consistently. Preserve the review message and legitimate warnings; do not infer approval, risk, or authorization from free-form message text and do not change permission enforcement.
