The report alleges that Claude subscription usage is consumed faster in bb because of its client identity. On the trusted main commit, bb does force CLAUDE_CODE_ENTRYPOINT to cli and removes CLAUDE_AGENT_SDK_CLIENT_APP before handing session options to the Agent SDK. An existing bridge-boundary test confirms that exact environment in two separate clean checkouts. This verifies a local identity-setting mechanism, not the claimed outbound sdk-cli label or any subscription-meter multiplier. No real Claude request, subscription experiment, or account data was used, so changing the label is not a validated billing fix.

5. Root cause and scope

The session builder first merges the host environment and thread configuration, then imposes the CLI identity. It explicitly removes the SDK client-app identifier. These are product-owned environment decisions rather than a value copied verbatim from the user's settings:

function buildSessionEnv(
  envOverrides: Record<string, string>,
): NodeJS.ProcessEnv {
  const sessionEnv: NodeJS.ProcessEnv = {
    ...withoutBridgeRuntimeEnv(process.env),
    ...envOverrides,
    CLAUDE_CODE_ENTRYPOINT: "cli",
  };
  delete sessionEnv.CLAUDE_AGENT_SDK_CLIENT_APP;
  return sessionEnv;
}

Environment construction and boundary validation. The thread attachment path passes this environment into tracked session options. Environment refresh uses the same builder.

Confidence is high for this local mechanism and medium for the issue's overall root cause: the alleged relationship between entrypoint identity and subscription accounting remains outside the evidence. A passing bridge test does not prove a remote billing bug.
