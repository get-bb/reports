#7449 · HOME fixture escapes to system npm

BugPriority: LowEffort: LowhostIssue2026-11-11

Trusted base: 030b1b729f28acedc6f86cd65a71cb3678da8124 (origin/main).

Verdict: REPRODUCED · Root-cause confidence: high · Label: confirmed-repro

1. TL;DR

Three installer tests that check HOME handling leave npm unstubbed. Their simulated server returns an artifact-not-found response, which intentionally sends the installer to its registry fallback. The test environment retains the system executable directories, so a distribution-provided npm can perform a real package installation. An offline boundary probe reproduced all three escapes while the existing three tests still passed. Actual registry traffic, the reported Fedora timings, and load-induced timeouts were not repeated: an inert npm surrogate prevented downloads and package execution.

5. Root cause

The fixture environment puts its own bin directory before /usr/bin:/bin. Its ordinary fixture setup supplies node and sleep, but not npm. The HOME table adds node/id behavior and a 404 curl response without an npm stub.

PATH: [fixture.binDir, "/usr/bin", "/bin"].join(delimiter)
writeCurlArtifactMock(fixture, 404);

require_npm checks only whether npm is resolvable. The artifact-404 branch then calls:

npm install -g "$bb_app_allow_scripts" --prefix "$machine_npm_prefix" bb-app

That is intended installer behavior, not a defect in the fallback itself. The bug is incomplete test isolation. The assertions merely require a nonzero installer exit and particular HOME/shim state; they do not reject the installer reaching a host npm. With npm absent, the installer stops early; with it present, it can download packages and consume the test's time budget. The offline probe demonstrates the unintended command selection without installing or executing a registry package.

6. Proposed fix

Give these HOME cases their own immediate-failure npm executable in the fixture's first PATH directory, keeping the existing HOME assertions. A nonzero stub exit exercises the intended pre-install failure boundary without depending on the host or network. Do not disable the installer's legitimate fallback or increase the timeout to hide the leak. A separate owner-boundary guard can use the probe above to detect any future fixture escape.
