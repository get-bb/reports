The report combines a Cursor model-access rejection with inadequate error context. Two clean checkouts reproduce the diagnostic gap through the real ACP client and a real child-process transport: three different failing requests produce the same error message and no outbound request metadata. This does not establish why Cursor rejects the reported models or whether desktop and CLI entitlements agree. No real Cursor account, desktop session, production bb instance, or private runtime data was accessed.

Complete authored reproduction test
import { describe, expect, it } from "vitest";
import { z } from "zod";
import {
  AcpAgentResponseError,
  createAcpAgentConnection,
} from "./agent-connection.js";

const rejectingAgent = `
const { createInterface } = require("node:readline");
const lines = createInterface({ input: process.stdin });
lines.on("line", (line) => {
  const request = JSON.parse(line);
  process.stdout.write(JSON.stringify({
    jsonrpc: "2.0",
    method: "fixture/received",
    params: { method: request.method, params: request.params },
  }) + "\\n");
  process.stdout.write(JSON.stringify({
    jsonrpc: "2.0",
    id: request.id,
    error: { code: -32000, message: "Request rejected", data: { details: "fixture refusal" } },
  }) + "\\n");
});
`;

describe("ACP failure request identity", () => {
  it.each([
    {
      method: "session/set_config_option",
      params: {
        sessionId: "fixture-session",
        configId: "model",
        value: "fixture-model",
      },
    },
    {
      method: "session/set_model",
      params: { sessionId: "fixture-session", modelId: "fixture-model" },
    },
    {
      method: "session/prompt",
      params: {
        sessionId: "fixture-session",
        prompt: [{ type: "text", text: "fixture-private-prompt" }],
      },
    },
  ])("retains diagnostic context for $method", async ({ method, params }) => {
    let received: unknown;
    const connection = createAcpAgentConnection({
      command: process.execPath,
      args: ["-e", rejectingAgent],
      cwd: process.cwd(),
      env: {},
      recordThreadId: null,
      onNotification(notificationMethod, notificationParams) {
        if (notificationMethod === "fixture/received")
          received = notificationParams;
      },
      onRequest() {},
      onExit() {},
    });

    try {
      const failure = await connection
        .request({
          method,
          params,
          resultSchema: z.unknown(),
          timeoutMs: 3000,
        })
        .then(
          () => {
            throw new Error("Fixture unexpectedly accepted the request");
          },
          (error: unknown) => error,
        );
      expect(received).toEqual({ method, params });
      expect(failure).toBeInstanceOf(AcpAgentResponseError);
      if (!(failure instanceof AcpAgentResponseError)) throw failure;
      console.log(
        JSON.stringify({
          sentMethod: method,
          sentSessionId: params.sessionId,
          errorName: failure.name,
          errorCode: failure.code,
          errorMessage: failure.message,
          errorKeys: Object.keys(failure),
        }),
      );
      expect(failure.code).toBe(-32000);
      expect(failure.data).toEqual({ details: "fixture refusal" });
      expect(failure.message).not.toContain("fixture-private-prompt");
      expect(failure.message).toContain(method);
      expect(failure.message).toContain(params.sessionId);
    } finally {
      await connection.kill();
    }
  });
});

5. Root cause

The loss occurs in the shared ACP connection rather than in a Cursor-specific plan check. The rejection handler has the outbound method and params in its closure, but constructs the error only from the response:

throw new AcpAgentResponseError(
  formatAgentError(error),
  error.code,
  error.data,
);

Request dispatch and error wrapping. The error class and formatter have no request identity field; the formatter combines message and response details only. Supplying no response data leaves the provider message alone.

The native model selection path issues config/model RPCs using the selected id and may fall back from a failed config request to a model request: native model selection. A later rejection has no attached metadata to identify that request. During a prompt failure, the bridge forwards error.message into the error emission path: prompt error forwarding and session error emission. This explains the opaque diagnostics, not Cursor's underlying access decision.

Cursor model normalization also exists in cursor-model-selection.ts; seeing normalization is not evidence that it is incorrect for a particular live model. No account-level root cause was established.

6. Proposed next step and simple-fix decision

A diagnostic improvement can preserve the method and an explicit allowlist of safe request metadata at the connection boundary while retaining response code/data. Do not serialize arbitrary params: prompt blocks, filesystem paths, MCP configuration, authentication, extensions, or config values can be sensitive. Cover the chosen redaction contract with transport-level tests before exposing it in errors.

To resolve the primary access failure, capture a consenting affected account's sanitized failing RPC using the current Cursor CLI in an isolated instance, then compare the exact ACP model id and access response with that account's desktop behavior. This investigation cannot distinguish upstream entitlements, unsupported ACP variants, or a bb mapping error.
