#6369 · Threadless panel rejects host-file navigation

BugPriority: LowEffort: Lowplugins · ui · confirmed-reproGitHub issue2026-10-27 · base b6743a36bd9eae1408c35cfc2c7ab1d2419dc79d

Verdict: REPRODUCED · Root-cause confidence: high. Repeated directly by the same investigator in two separate clean clones of trusted main. This is a functional navigation failure, not a visual-layout report.

1. TL;DR

A plugin's valid absolute host-file request is rejected before a tab is created when the New thread panel has no thread. Core can create a workspace-relative preview request on the same surface. The shared controller knows only thread, environment and host IDs; it has no project-folder context with which to map that absolute file into core's workspace preview. Both clean runs returned false, created zero plugin tabs, and left the panel unrevealed, while the core opener created one workspace tab. An existing open fix, PR #6370, was found during the final linked-PR check, so no duplicate fix branch or PR was created.

5. Root cause

The scope contract contains only thread, environment and host IDs. The host-target branch rejects a scoped call when either thread or environment is absent:

if (
  scope.threadId === null ||
  scope.environmentId === null ||
  target.hostId !== scope.hostId
) {
  return null;
}

The public-intent handler converts that null request to false without calling the tab creator or drawer reveal. Compose passes this scope, and its environment ID is null unless reuse is selected. The thread resolver also explains why reuse can sometimes provide an existing owner thread.

Core avoids this branch: file-search selection creates a relative workspace request. The project routing resolves that request against the selected project source or checkout; workspace-tab rendering supports project previews. In contrast, host-tab rendering still needs a thread and environment. Removing the guard alone would therefore leave a loading tab rather than restore parity.

The existing contract table explicitly expects a host rejection for the threadless surface; it tests an arbitrary host path, not a file mapped into the selected project. The new reproduction supplies the missing core-versus-plugin comparison. History traces the shared controller to commit 68e4918db; the later revision-preview change did not supply project-root mapping.

6. Proposed fix

Give the compose controller the same resolved host/folder context that its workspace preview uses. For a threadless surface, map a valid same-host file strictly inside that folder to a workspace-relative working-tree preview, preserving location and viewer handling. Use the reused checkout when available, otherwise the selected project's source on the chosen host; remain inert while required routing data is missing. Preserve existing thread and plugin-page behavior.

Keep negative coverage for other hosts, sibling prefixes, the root directory itself, traversal/normalization edge cases, and missing roots. Exercise project-default, reused-environment, and unavailable-root surfaces, and compare the accepted request directly with core's opener. Do not bypass scope checks or merely enable host-tab creation.
