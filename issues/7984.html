The real section-aware sidebar model then places the continuation outside the source section and its worktree bucket. 5. Root cause

The handoff seed carries environment/project/source identity, but no sidebar section. The UI builds that same incomplete seed. The handoff request explicitly reuses the environment but sends no section or hierarchy placement. At the server's create boundary, an absent section becomes null. Section-aware sidebar grouping buckets by section before grouping shared worktrees, so the continuation cannot join the source's section-local environment bucket.

  • Handoff seed fields.
  • UI constructs the seed without section membership.
  • Request builder preserves environment but omits section.
  • Create boundary defaults missing section to null.
  • Section partition precedes worktree grouping and the actual section-aware entry point.
  • Unsectioned worktree grouping uses environment identity and requires at least two sibling nodes.

Relevant history: 1983b0dfb5 added the slash-command handoff entry. This is context, not proof that the original issue was introduced there. The test distinguishes the source of persisted placement data from the renderer; changing the renderer to ignore sections would hide the defect and violate existing organization.

6. Proposed fix and simple-fix decision

For the verified custom-section variant, propagate the source section through the existing handoff seed and request, using the already-supported create-request section field. A regression should assert actual persisted section membership and verify grouped and ungrouped sources. Before applying that to this issue, establish the original group's type and the exact continuation entry point; separately test nested hierarchy placement if applicable.

No automatic fix branch or PR was created. The plain shared-worktree control passes, and no live browser reproduction establishes that the original scenario uses the section-aware path. Choosing section inheritance or a hierarchy repair as the issue's fix would therefore exceed the evidence. No linked open PR was present in the issue timeline or the open-PR search at investigation time.
