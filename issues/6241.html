#6241 · Parent notice dispatch status race

BugHighEffort: MediumthreadsIssue2026-10-24 · base 9eb0c09254a21482c0cfd935e0a9908049333e93

Verdict: REPRODUCED · Root-cause confidence: high · Label: confirmed-repro

1. TL;DR

A child completion notice can disappear instead of waking its parent. The server chooses an active-parent or idle-parent dispatch path, then asynchronously prepares the provider command before writing the notice. If the parent's status changes in that interval, the active path returns false without recording the request, while the idle path attempts an illegal lifecycle transition and rolls back the request. Both schedules reproduce deterministically on trusted main and in a second clean checkout. The report establishes the dispatch race, not the reporter's historical loss rate or the alleged contribution of skill discovery.

5. Root cause

The asynchronous preparation is outside the write transaction. Neither dispatch branch can assume the original parent snapshot still describes the transaction's row. The active branch detects a different status but treats it as a terminal non-delivery; the ready branch validates the old snapshot and attempts run.started against the now-active persisted row. Both are dispatch admission failures, not provider failures.

The active branch's preparation await is at line 305; its null-to-false return is at lines 330–331. Ready command preparation precedes its transaction at lines 367–384. Its lifecycle error rolls back the event appended in that same transaction.

6. Proposed fix

Revalidate the current parent status inside each write transaction before appending any event. A changed snapshot should trigger a local delivery retry, not false success or an unrecoverable lifecycle error. The retry re-reads the parent and environment and re-enters the existing active/ready dispatch path under the same context-clear guard. Archival or deletion still declines delivery. No public protocol, database schema, dependency, or product-policy change is needed.

The local repair passes both focused regression rows and all 70 relevant existing notification, dispatch, taxonomy, and context-clear tests. Server typecheck also passes. Exact output is embedded in the appendix.
