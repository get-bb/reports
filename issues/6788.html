#6788 · OpenCode workspace commands missing before a session

Bug Priority: Medium Effort: Low providers provider-acp GitHub issue

November 1, 2026 · trusted origin/main 916d684ac23d0b0de82c09cfc7553a50287d2188

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

BB cannot discover a project's OpenCode Markdown commands before an ACP session has started, although skills in the same project are discoverable. The built-in provider declares skill roots and resolves more skill roots, but supplies no command roots. The host scans only the supplied roots, so an ordinary command file is invisible to the project catalog. A direct filesystem/catalog reproduction fails on trusted main in two fresh checkouts. Returning the missing project command root fixes the reproduction without changing the scanner, wire contract, or session behavior.

import { mkdir, mkdtemp, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import path from "node:path";
import { normalizeProviderNativeRoots } from "@bb/domain";
import { experimental_nativeRootsResolveOutputSchema } from "../../../packages/plugin-sdk/src/native-roots-contract.js";
import { expect, it } from "vitest";
import {
  acpProviderDeclaration,
  KNOWN_ACP_AGENTS,
  resolveAcpNativeRoots,
} from "../../../plugins/provider-acp/src/native-roots/index.js";
import { discoverProviderCommands } from "./command-discovery.js";
import { resolveDeclaredScanRoots } from "./command-handlers/list-commands.js";

it("discovers project commands alongside skills before an ACP session exists", async () => {
  const scratch = await mkdtemp(path.join(tmpdir(), "bb-6788-catalog-"));
  try {
    const cwd = path.join(scratch, "project");
    const homeDir = path.join(scratch, "home");
    await mkdir(path.join(cwd, ".git"), { recursive: true });
    await mkdir(path.join(cwd, ".opencode", "commands"), { recursive: true });
    await mkdir(path.join(cwd, ".opencode", "skills", "catalog-skill"), {
      recursive: true,
    });
    await mkdir(homeDir, { recursive: true });
    await writeFile(
      path.join(cwd, ".opencode", "commands", "catalog-command.md"),
      "---\ndescription: Catalog command fixture\n---\nReply briefly.\n",
    );
    await writeFile(
      path.join(cwd, ".opencode", "skills", "catalog-skill", "SKILL.md"),
      "---\nname: catalog-skill\ndescription: Catalog skill fixture\n---\n",
    );
    const agent = KNOWN_ACP_AGENTS.find(
      (candidate) => candidate.id === "acp-opencode",
    );
    if (agent === undefined) throw new Error("Built-in provider not found");
    const declaration = acpProviderDeclaration(agent);
    const resolved = experimental_nativeRootsResolveOutputSchema.parse(
      await resolveAcpNativeRoots({ agentId: agent.id, cwd, homeDir, env: {} }),
    );
    const roots = await resolveDeclaredScanRoots({
      providerId: agent.id,
      cwd,
      homeDir,
      nativeRoots: {
        skills: normalizeProviderNativeRoots(
          declaration.experimental_nativeSkillRoots,
        ),
        commands: normalizeProviderNativeRoots(
          declaration.experimental_nativeCommandRoots,
        ),
        resolved,
      },
    });
    const commands = await discoverProviderCommands({ roots });
    const catalog = commands.map(({ name, source }) => ({ name, source }));
    console.log(JSON.stringify(catalog));
    expect(catalog).toContainEqual({ name: "catalog-skill", source: "skill" });
    expect(catalog).toContainEqual({
      name: "catalog-command",
      source: "command",
    });
  } finally {
    await rm(scratch, { recursive: true, force: true });
  }
});

5. Root cause

  1. OpenCode registration declares project skill roots but not command roots. Declaration construction exposes those skills plus the native-root resolver capability.
  2. The OpenCode resolver returns only skills: 
    return {
  skills: [ /* user config and optional custom-config skill roots */ ],
};
    The declaration and resolver together therefore supply zero OpenCode command roots.
  3. The server forwards the supplied native root set to the workspace host. The host expands only those roots; the scanner reads only the expanded directories. The command directory never reaches the scanner.
  4. The bridge does not support standalone command listing, so it cannot fill this pre-session gap. Existing ACP sessions process advertised commands separately.
  5. The new-thread composer selects the project/provider catalog. The reproduced missing catalog entry therefore explains the reported picker symptom; the visible UI itself was not driven.

6. Proposed fix and validation

Supply .opencode/commands as an absolute project command root from the existing OpenCode native-root resolver. Mark it for the existing ancestor traversal so commands remain available when composing from a nested workspace; return no project root when the workspace is absent. Preserve the existing skill paths. This is an existing resolver contract, not a new protocol or product policy.

The local candidate changes two files with 44 additions and no deletions: 11 production lines and 33 regression-test lines. Two root-contract regression cases fail on unchanged production code, then pass with the repair; a third case checks the no-workspace path. The real catalog reproduction also passes after the change. Global command directories, alternate OpenCode layouts, and custom configuration precedence are outside this focused fix.
