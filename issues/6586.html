#6586 · Recovery after partial shell discovery

BugPriority: MediumEffort: Lowhost · providers · provider-pi

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The host toolchain can discover a command using a reduced login-shell PATH while missing a directory needed by that command's helper. The command resolves correctly but exits with status 1. Failure invalidation does not retry shell discovery for that status, and the toolchain does not remember that its saved environment came from a fallback probe. Two separate trusted-base checkouts reproduce this behavior for both a failed and a timed-out interactive probe. This verifies the shared toolchain defect, not the exact macOS boot incident or a guarantee that all daemon refreshes stop.

5. Root cause

Probe selection and environment parsing try interactive-login discovery first, then login-only discovery. The returned value contains environment entries but no record of which attempt supplied them.

Refresh retains any prior PATH if a later interactive attempt fails. Retention protects a previously complete environment but does not make an initial fallback complete.

Failure invalidation refreshes only for ENOENT or 127:

if (code === "ENOENT" || code === 127) void this.refresh();

Host process observation already forwards child exit codes to this method. A wrapper may turn its helper's missing-command result into exit 1, bypassing the existing recovery trigger despite the still-incomplete environment.

Important limit: daemon runtime-shell resolution explicitly invokes refresh, and its runtime cache has a separate refresh mechanism. The component result cannot establish why a particular real-world incident persisted for multiple turns.

6. Proposed fix and simple-fix gate

Remember whether the retained environment came from the login-only fallback. While that state persists, a nonzero numeric process exit should trigger the existing coalesced background refresh. A successful preferred probe clears the degraded state; do not broaden ordinary failure recovery after a complete probe or treat a shell supporting only login discovery as degraded.
