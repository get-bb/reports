1. TL;DR

The hosted OAuth service rejects client metadata with a private authentication preference even when that document also lists the public method that bb advertises. A new regression test calls the real exported metadata loader with an injected HTTP response, not a copied or extracted parser. On unchanged main, exactly the shared-public-method case fails; six controls pass. A second fresh clone at the same commit produces the same failure with the test cache bypassed. This confirms the source-level compatibility failure, not an authenticated ChatGPT browser connection or the active production deployment.

5. Root cause

The rejection branch examines only the singular token_endpoint_auth_method. A non-absent value other than none immediately fails. The parser never reads the plural token_endpoint_auth_methods_supported, so the same rejection occurs whether or not that list contains none.

  if (
    document.token_endpoint_auth_method !== undefined &&
    document.token_endpoint_auth_method !== "none"
  ) {
    return {
      ok: false,
      message:
        "only public clients (token_endpoint_auth_method none) are supported",
    };
  }
  return { ok: true, client: { clientId, clientName, redirectUris } };

Server metadata advertises only none and S256. The exported loader performs URL and HTTP-response checks, then invokes this parser. The authorization path propagates its rejection before later redirect matching; the downstream PKCE/resource checks remain in the trusted source. Thus the symptom is an admission-policy mismatch at the metadata boundary, not a reproduced token exchange, grant persistence, or transport failure.

6. Proposed fix and automation limit

A maintainer-reviewed compatibility change could validate the plural methods field at the JSON boundary and explicitly select the server-supported public method when it is offered. Preserve the existing client-identity, redirect, PKCE, resource, and token checks; retain private-only rejection and add malformed-list cases. Decide and document how absent, malformed, or contradictory singular/plural declarations are treated instead of assuming every array is valid.

No automatic fix PR: changing which OAuth clients are accepted changes authentication/admission policy. It therefore fails the rule's simple-fix safety gate regardless of line count. No production fix, fix branch, commit, push, or duplicate pull request was created.
