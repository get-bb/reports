#6329 · Pi assistant stream completion

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Pi can stream an assistant explanation before executing a tool, but BB never completes that explanation as a transcript item. The translator ignores assistant message boundaries. When the tool opens, the shared assembler detaches the still-open assistant stream without completing it, leaving its start and text deltas orphaned. The final assistant message is completed at agent end, so it survives while the earlier explanation does not. A deterministic replay through the real translator and assembler reproduces one orphaned item; the local repair produces both completed messages and zero orphans.

5. Root cause

  1. The boundary schema requires role: z.literal("custom"). An assistant message_end cannot pass it.
  2. The message boundary handler returns no deltas on that parse failure. It consequently sends no item.textClose for assistant text.
  3. Opening a tool item detaches assistant streams through detachAssistantStreams. This removes the open assistant entry rather than inventing a completion. Its previous item/started and item/agentMessage/delta events remain without an item/completed event.
  4. Agent-end fallback extracts text from only the last assistant message. It cannot recover detached earlier explanations.
const piEvent = piCustomMessageBoundaryEventSchema.safeParse(event);
if (!piEvent.success) {
  return [];
}

The shared assembler's text-close behavior also matters to a repair: an explicit text close without an open item can create a new completed item. Thus merely adding boundary closes while retaining the unconditional final-text fallback would duplicate the last answer. This repair tracks completed assistant streams within each thread and parent-tool scope, preserving legacy fallback only when the current stream has not already closed.

6. Proposed fix and local verification

Accept assistant messages at the existing boundary parser; close nonempty assistant text at message_end. Leave custom-message behavior unchanged. Reset closed-stream tracking on agent/message start, new streamed text, and thread reset. Suppress duplicate agent-end text completion only for an already-closed stream. No public wire format, dependency, storage layout, or policy changes are required.

The focused regression was written before production changes. It covers streamed and non-streamed replies, with and without an intervening tool, immediate completion at each boundary, distinct item IDs, matching start/completion IDs, and exactly one completion per message after agent end.
