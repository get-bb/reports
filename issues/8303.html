#8303 · Provider command selection triggers unintended submission

BugPriority: MediumEffort: LowuiGitHub issue2026-11-28 · base b0ddaad731

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro.

1. TL;DR

Selecting a provider command from the composer menu can send the message before the user has typed its arguments. The composer treats every command marked origin: "builtin" as an immediate-submit command, but that origin also describes live provider commands. A focused test against unchanged production code inserts /loop correctly and then observes an unexpected submit callback on both Enter and mouse selection. The same two failures recur in a second clean checkout. This establishes the unintended-submission bug without launching a live provider; phone-specific caret rendering remains unverified.

5. Root cause

The selection chooser and pending-submit effect perform two separate operations: insert the selected item, then schedule submission solely from command kind and built-in origin:

applyTrigger(item);
if (item.kind === "command" && item.origin === "builtin") {
  setPendingCommandSubmit(true);
}

The effect consumes that state and calls submitPrompt(). However, server live-command discovery and timeline command extraction both assign source: "command", origin: "builtin" to live commands, with nullable argument hints. Discovery grouping is therefore being used as execution policy.

The menu row's mouse handler invokes its application callback; the composer supplies chooseSuggestion. The keyboard handler also invokes the chooser for Enter, but calls insertion directly for Tab. That explains both failing selection methods and the passing Tab control without invoking a provider-specific failure.

6. Proposed fix

Separate immediate-execution policy from command origin. Permit automatic submission only for the existing standalone slash-command actions, with an explicit command-source and slash-trigger check; insert other provider commands without scheduling submission. Preserve the existing immediate-command, user-command, and Tab controls. Do not infer argument requirements from a missing hint. Investigate and verify mobile DOM caret behavior separately in a real browser engine before treating the caret claim as proven.
