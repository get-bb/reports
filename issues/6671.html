#6671 · Downstream cancellation leaves HTTP proxy connections open

BugHighEffort: Lowhost · perf · confirmed-reproGitHub issue2026-10-30 · base 9662c45478f4a74f33f11b70187657d97f1e14a7

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The daemon's loopback HTTP proxy keeps its upstream connection open after its caller goes away. A direct test of the trusted main-branch source reproduces this while awaiting response headers, streaming a response, and uploading a request. Each cancelled local connection is closed, but its origin-side socket remains open for the full one-second observation window. Two completed requests reuse one upstream connection normally. This establishes a connection-lifecycle defect, not the reported machine-wide macOS failure: no network exhaustion or real provider requests were attempted.

    import assert from "node:assert/strict";
import { once } from "node:events";
import http from "node:http";
import net, { type AddressInfo, type Socket } from "node:net";
import { setTimeout as delay } from "node:timers/promises";
import { test, type TestContext } from "node:test";
import { startMachineAuthProxy } from "./apps/host-daemon/src/machine-auth-proxy.ts";

async function fixture(
  context: TestContext,
  handler: http.RequestListener,
) {
  const connections = new Set<Socket>();
  const origin = http.createServer(handler);
  origin.on("connection", (socket) => {
    connections.add(socket);
    socket.on("error", () => {});
  });
  origin.listen(0, "127.0.0.1");
  await once(origin, "listening");
  const proxy = await startMachineAuthProxy({
    serverUrl: `http://127.0.0.1:${(origin.address() as AddressInfo).port}`,
    serverHeaders: {},
  });
  context.after(async () => {
    for (const socket of connections) socket.destroy();
    await proxy.close();
    await new Promise<void>((resolve) => origin.close(() => resolve()));
  });
  return new URL(proxy.serverUrl);
}

for (const phase of ["awaiting headers", "streaming response", "uploading request"] as const) {
  test(`client cancellation releases upstream while ${phase}`, { timeout: 5_000 }, async (context) => {
    const observed = Promise.withResolvers<Socket>();
    const url = await fixture(context, (request, response) => {
      request.on("error", () => {});
      if (phase === "streaming response") {
        response.writeHead(200, { "content-type": "text/plain" });
        response.write("stream started");
      }
      if (phase === "uploading request") {
        request.once("data", () => observed.resolve(request.socket));
      } else {
        observed.resolve(request.socket);
        request.resume();
      }
    });
    const client = net.connect(Number(url.port), url.hostname);
    client.on("error", () => {});
    context.after(() => client.destroy());
    await once(client, "connect");
    const firstBytes = phase === "streaming response" ? once(client, "data") : null;
    const head = phase === "uploading request"
      ? `POST /probe HTTP/1.1\r\nHost: ${url.host}\r\nContent-Length: 4096\r\n\r\npartial upload`
      : `GET /probe HTTP/1.1\r\nHost: ${url.host}\r\n\r\n`;
    client.write(head);
    const upstreamSocket = await observed.promise;
    if (firstBytes !== null) await firstBytes;
    const clientClosed = once(client, "close");
    client.destroy();
    await clientClosed;
    const deadline = Date.now() + 1_000;
    while (!upstreamSocket.destroyed && Date.now() < deadline) await delay(10);
    console.log(JSON.stringify({ phase, clientClosed: client.destroyed, upstreamClosed: upstreamSocket.destroyed }));
    assert.equal(upstreamSocket.destroyed, true, "upstream must close after downstream cancellation");
  });
}

test("completed responses preserve upstream keepalive reuse", { timeout: 5_000 }, async (context) => {
  const sockets: Socket[] = [];
  const url = await fixture(context, (request, response) => {
    sockets.push(request.socket);
    response.end("complete");
  });
  const agent = new http.Agent({ keepAlive: true, maxSockets: 1 });
  context.after(() => agent.destroy());
  for (let requestIndex = 0; requestIndex < 2; requestIndex += 1) {
    await new Promise<void>((resolve, reject) => {
      http.get(url, { agent }, (response) => {
        response.on("error", reject);
        response.on("end", resolve);
        response.resume();
      }).on("error", reject);
    });
  }
  assert.equal(sockets.length, 2);
  assert.equal(sockets[0], sockets[1], "completed requests must reuse the upstream connection");
  assert.equal(sockets[0].destroyed, false);
  console.log(JSON.stringify({ completedRequests: sockets.length, reusedUpstream: sockets[0] === sockets[1] }));
});

5. Root cause

The HTTP forwarding handler at the recorded base creates an upstream request, pipes the caller's request into it, and pipes an upstream response back to the caller. Its lifecycle callbacks propagate upstream failures toward the downstream response only:

upstreamResponse.on("error", () => args.response.destroy());
upstreamResponse.on("close", () => {
  if (!upstreamResponse.complete) args.response.destroy();
});
upstreamResponse.pipe(args.response);
...
args.request.pipe(upstream);

There is no downstream request-abort listener or downstream response-close listener to destroy the upstream request. A destroyed pipe destination therefore does not cause this handler to cancel its outstanding origin-side work. The three failing cases exercise both sides of that missing lifecycle transition, including the interval before any upstream response exists. The positive control distinguishes abandoned connections from intentionally reusable, fully completed connections.

The test proves sockets remain open beyond the observation interval until its explicit teardown. It does not establish the precise retained-buffer size, indefinite lifetime, or operating-system exhaustion threshold.

6. Proposed fix

Within the existing HTTP forwarding handler, cancel the upstream request when the downstream upload aborts or when the downstream response closes before finishing. Check writableFinished so normal completion preserves keepalive reuse. If an upstream response arrives after the downstream response is destroyed, release it instead of piping it; suppress attempts to write an error response into an already destroyed downstream. Preserve existing header validation and machine-auth behavior. This proposal requires no wire, authentication, schema, packaging, or public API change.
