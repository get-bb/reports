#7339 · Idle plugin-tool response exceeds the fetch body deadline

BugPriority: MediumEffort: Mediumhost · plugins · partial-reproGitHub issue

2026-11-10 · trusted main 7c1353d80729983b86ea1555d18b42407f320406

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high

1. TL;DR

A plugin computation can lose its agent-facing result when it stays silent for approximately five minutes. Two real-time runs used the real daemon client, the authenticated server route, a real SQLite harness, Hono's HTTP adapter, and Node's unchanged built-in fetch. The HTTP head arrives promptly, but reading the result fails with UND_ERR_BODY_TIMEOUT before the scheduled 310-second completion. The separate claim that this automatically becomes a detached result is not supported: the observed tool signal is aborted and its registry entry is removed. Deliberately detached user-input tools follow a different path.

5. Root cause

apps/host-daemon/src/server-client.ts:315 chooses built-in fetch. apps/host-daemon/src/server-client.ts:520 posts the call and then awaits response.json(), without a request-specific dispatcher. Sending the response head avoids a header timeout, but does not disable the client's idle body timeout.

      const response = await fetchFn(buildInternalUrl("/session/tool-call"), {
        signal,
        method: "POST",
        headers: headers(),
        body: JSON.stringify(payload),
      });

      if (!response.ok) {
        throw await createResponseError("call tool", response);
      }

      return hostDaemonToolCallResponseSchema.parse(await response.json());

apps/server/src/internal/tool-calls.ts:25 creates a stream but emits no application body bytes until the result promise settles. Hono may send a compression preamble, which likewise does not provide ongoing progress. Thus a quiet tool crosses fetch's body-idle deadline even though the computation remains legitimate.

function streamToolCallResponse(
  result: Promise<ToolCallResponse>,
  abortController: AbortController,
): Response {
  const body = new ReadableStream<Uint8Array>({
    cancel() {
      abortController.abort();
    },
    start(controller) {
      void result.then(
        (response) => {
          try {
            controller.enqueue(textEncoder.encode(JSON.stringify(response)));
            controller.close();
          } catch (error) {
            controller.error(error);
          }
        },
        (error) => controller.error(error),
      );
    },
  });
  return new Response(body, {
    headers: { "content-type": "application/json; charset=UTF-8" },
  });

The timeout is not an automatic detachment trigger. apps/server/src/services/plugins/plugin-tool-calls.ts:75 aborts and settles an ordinary failed round trip; detached is set only by detachWith. The route wires disconnect cancellation to the round-trip controller. A plugin ignoring its abort signal may continue work, but that alone does not enqueue its late response as a detached message.

6. Proposed fix and safety assessment

The tested dependency-free repair adds JSON whitespace every 30 seconds while the existing result promise is pending, with Cache-Control: no-transform so Hono's compression cannot buffer those tiny heartbeats. Its interval is unreferenced and cleared on completion, rejection, or stream cancellation. The parsed JSON fields, cancellation ownership, daemon code, and protocol version remain unchanged. This stays within the server subsystem and changes 142 text lines across two files (140 additions, 2 deletions), with no dependency, migration, generated output, or stored-data change.

The focused regression exercises two heartbeats, unchanged result decoding, and cancellation/timer cleanup. Both cases fail on trusted main with “pending tools must send periodic body data: expected null not to be null”; both pass after the repair. All 44 tests in the new regression and the three relevant existing suites pass, as does the server Turbo typecheck. A separate real-time 310-second run uses the unchanged daemon client and default fetch: it passes with the repair, establishing old-client JSON compatibility rather than relying only on accelerated clocks.
