#7899 · Request-key reads scale with event history

BugHigh priorityEffort: HighthreadsperfIssue2026-11-20

Trusted base: fab82665a3299fae8910f55d7519a3b034a03b9a, fetched from get-bb/bb main. A subsequent fetch returned the same commit.

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high · Reproduction label: partial-repro

1. TL;DR

The production request-key lookup searches all request events in each selected thread before filtering JSON request IDs. With the same six keys and the same three returned rows, growing history from 96 to 6,144 request events increased median read time from 1.833 to 98.596 ms in the first run, and 1.897 to 105.753 ms in a second clean checkout. A zero-delay timer scheduled immediately before one synchronous read could not run for about 106.591 ms. Adding an experimental expression index only to the disposable test database changed the actual bound plan to request-ID seeks and reduced the large read to 0.600 ms. This verifies the scan cost and same-process event-loop blocking, not the reported tens-of-seconds production stall or its storage-related timing.

3. Environment

  • Linux 4.19.0-gvisor, x86_64; Node v22.19.0; pnpm 9.15.0; repository better-sqlite3 12.11.1; embedded SQLite 3.53.2.
  • Both runs used separate clean detached checkouts of the recorded main commit, frozen installs, and fresh in-memory databases from createMigratedConnection(). Only the new diagnostic test and generated build artifacts were added locally; no production source was changed.
  • Three synthetic threads; 26,600-character text payload per request; one existing and one absent key per thread. No providers ran, no network service was started, no ports were opened, and no user database was touched.
  • The full monorepo build was attempted in both checkouts and failed in the unrelated GitHub plugin because its installed Plugin SDK runtime dist was absent. The filtered database test pipeline built its required upstream tasks successfully. This report does not claim the full build passed.

Complete diagnostic test

import { performance } from "node:perf_hooks";
import { threadCpuUsage } from "node:process";
import { expect, it } from "vitest";
import { encodeClientTurnRequestIdNumber, threadScope } from "@bb/domain";
import { createMigratedConnection } from "../../src/testing.js";
import { upsertHost } from "../../src/data/hosts.js";
import { createProject } from "../../src/data/projects.js";
import { createThread } from "../../src/data/threads.js";
import {
  insertEvents,
  listStoredClientTurnRequestRowsByKeys,
} from "../../src/data/events.js";
import { noopNotifier } from "../../src/notifier.js";

it("measures request-key reads against growing migrated event histories", async () => {
  let observedSql = "";
  let observedParams: string[] = [];
  const db = createMigratedConnection({
    queryPlanObserver: () => ({
      observeFirstExecution(source, params) {
        if (!source.startsWith("select") || !source.includes("json_extract")) return;
        observedSql = source;
        observedParams = params.map((parameter) => {
          if (typeof parameter !== "string") throw new Error("Non-string lookup binding");
          return parameter;
        });
      },
    }),
  });
  try {
    const host = upsertHost(db, noopNotifier, { name: "request-key-repro" });
    const { project } = createProject(db, noopNotifier, {
      name: "request-key-repro",
      source: { type: "local_path", hostId: host.id, path: "/tmp/request-key-repro" },
    });
    const threads = Array.from({ length: 3 }, () => createThread(db, noopNotifier, {
      projectId: project.id,
      providerId: "codex",
    }));
    const wanted = encodeClientTurnRequestIdNumber({ value: 1 });
    const absent = encodeClientTurnRequestIdNumber({ value: 9999999 });
    const keys = threads.flatMap((thread) => [
      { threadId: thread.id, requestId: wanted },
      { threadId: thread.id, requestId: absent },
    ]);
    const expectedThreads = threads.map((thread) => thread.id).sort((left, right) => left.localeCompare(right));
    const payload = "history-cost-probe ".repeat(1400);
    function seed(first: number, last: number) {
      for (const thread of threads) {
        for (let start = first; start <= last; start += 64) {
          insertEvents(db, noopNotifier, Array.from({ length: Math.min(64, last - start + 1) }, (_, offset) => {
            const sequence = start + offset;
            return {
              threadId: thread.id,
              sequence,
              scope: threadScope(),
              type: "client/turn/requested" as const,
              itemId: null,
              itemKind: null,
              parentToolCallId: null,
              data: JSON.stringify({
                direction: "outbound",
                requestId: encodeClientTurnRequestIdNumber({ value: sequence }),
                source: "tell",
                initiator: "user",
                input: [{ type: "text", text: payload, mentions: [] }],
                target: { kind: "new-turn" },
                request: { method: "turn/start", params: {} },
                execution: {
                  model: "test-model",
                  reasoningLevel: "medium",
                  permissionMode: "workspace-write",
                  source: "client/turn/requested",
                  serviceTier: "auto",
                },
              }),
            };
          }));
        }
      }
    }
    function measure() {
      const cpuStart = threadCpuUsage();
      const wallStart = performance.now();
      const rows = listStoredClientTurnRequestRowsByKeys(db, { keys });
      const wallMs = performance.now() - wallStart;
      const cpu = threadCpuUsage(cpuStart);
      expect(rows.map((row) => row.threadId)).toEqual(expectedThreads);
      expect(rows.map((row) => row.sequence)).toEqual([1, 1, 1]);
      return { wallMs, cpuMs: (cpu.user + cpu.system) / 1000 };
    }
    function sample() {
      measure();
      const readings = Array.from({ length: 5 }, () => measure());
      return readings.sort((left, right) => left.wallMs - right.wallMs)[2];
    }
    function plan() {
      return db.$client.prepare(`EXPLAIN QUERY PLAN ${observedSql}`).all(...observedParams);
    }
    seed(1, 32);
    const small = sample();
    seed(33, 2048);
    const large = sample();
    const unindexedPlan = plan();
    const heartbeatStart = performance.now();
    const heartbeat = new Promise<number>((resolve) => {
      setTimeout(() => resolve(performance.now() - heartbeatStart), 0);
    });
    const blockedRead = measure();
    const timerDelayMs = await heartbeat;
    db.$client.exec("CREATE INDEX events_request_lookup_probe_idx ON events(thread_id, type, json_extract(data, '$.requestId'), sequence)");
    const indexed = sample();
    const indexedPlan = plan();
    console.log(JSON.stringify({
      node: process.version,
      sqlite: db.$client.prepare("SELECT sqlite_version() AS version").get(),
      historyRows: { small: 96, large: 6144 },
      requestedKeys: keys.length,
      returnedRows: 3,
      payloadCharacters: payload.length,
      small,
      large,
      growthRatio: large.wallMs / small.wallMs,
      blockedRead,
      timerDelayMs,
      indexed,
      indexSpeedup: large.wallMs / indexed.wallMs,
      sql: observedSql,
      bindingArgumentCount: observedParams.length,
      unindexedPlan,
      indexedPlan,
    }, null, 2));
    expect(indexed.wallMs).toBeLessThan(large.wallMs / 4);
  } finally {
    db.$client.close();
  }
}, 60000);

5. Root cause

The JSON request-ID expression is used by listStoredClientTurnRequestRowsByKeys. The function groups keys by thread, applies a thread-ID plus JSON-ID predicate per group, then calls .all(). Key batching limits SQL variables and expression depth; it does not bound how many historical rows each branch must inspect.

const turnRequestIdSql = sql<string>`json_extract(${events.data}, '$.requestId')`;
...
and(eq(events.threadId, threadId), inArray(turnRequestIdSql, requestIds))
...
.where(and(eq(events.type, requestType), or(...keyConditions)))
.orderBy(events.threadId, events.sequence)
.all();

The event schema and indexes include events_thread_type_sequence_idx, but no request-ID expression index. SQLite therefore locates each thread/type range, loads candidate JSON data to check request IDs, and sorts the selected results. The sort remains even with the experimental index; eliminating the historical JSON reads, not eliminating the small output sort, explains the large improvement.

The better-sqlite3 statement wrapper calls the native synchronous all method on the calling thread. The timeline context loader and The open-turn runtime state reader call the lookup directly. Declaring their callers async would not make this native operation yield. The timer observation establishes synchronous blocking in the test process; the server-wide incident magnitude is not inferred from it.

6. Proposed fix and automation safety

An expression index beginning with thread ID, event type, and extracted request ID is supported by this experiment. The tested full index was events(thread_id, type, json_extract(data, '$.requestId'), sequence), and the real bound query used it without changing production SQL. This is a fix direction, not a settled migration design: compare full versus partial index usability under bound predicates, index size, write overhead, index-build duration, and upgrade impact on a representative disposable database. Continue to preserve thread/sequence ordering across request IDs and SQL batches.

No fix PR was opened. The evidenced repair needs a persisted index and schema migration, which this automation explicitly excludes from simple fixes. Offloading reads to a worker would be a larger execution-boundary change and would leave history-scan cost intact. No production fix branch, dependency, migration, or stored-data change was created or pushed.

A future regression should exercise the real migrated query with fixed request keys and growing histories; verify both selected-row semantics and bounded lookup cost, including missing IDs, duplicate keys, cross-thread IDs, and large key batches. The existing functional tests pass despite the current cost defect.
