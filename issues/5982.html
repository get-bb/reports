#5982 · Sole editor hard breaks do not survive Markdown persistence

BugPriority: MediumEffort: Mediumui · docs · partial-reproGitHub issue2026-10-21 · base d1627a473684d29920567b3cf9c05bd68edb2d97

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high for the existing break-loss defect; the PR-only visible HTML-source symptom was not executed or verified.

1. Summary

A paragraph whose only content is one intentional editor hard break loses that break after save and reload on trusted main. The loss reproduces inside ordinary paragraphs, bullet lists, and blockquotes. Main saves only whitespace or an empty container marker, not an HTML break tag. Consequently this investigation confirms the persistence gap, but does not confirm the reported visible HTML-source symptom on main. No original document text remains in the edited fixture by design; the lost content is the intentional break, not unrelated prose.

function open(markdown: string) {
  const editor = new Editor({
    extensions: [
      StarterKit,
      Link.configure({ openOnClick: false, autolink: true }),
      Image,
      TaskList,
      TaskItem.configure({ nested: true }),
      Table.configure({ resizable: true }),
      TableRow,
      TableHeader,
      TableCell,
      HtmlBlock,
      HtmlSource,
      Markdown.configure({
        html: true,
        tightLists: true,
        bulletListMarker: "-",
        linkify: true,
      }),
    ],
    content: "",
  });
  const blocks = loadMarkdownBlocks(editor, markdown, (source) => source, false);
  const save = () =>
    saveMarkdownBlocks(editor, blocks, (nodes) =>
      editor.storage.markdown.serializer.serialize(
        editor.schema.topNodeType.create(null, nodes),
      ),
    );
  return { editor, save };
}

function textPosition(editor: Editor, text: string) {
  let position = -1;
  editor.state.doc.descendants((node, pos) => {
    if (position < 0 && node.isText && node.text?.includes(text))
      position = pos + node.text.indexOf(text);
  });
  return position;
}

function topLevelRange(editor: Editor, text: string) {
  let range = { from: 0, to: 0 };
  editor.state.doc.forEach((node, offset) => {
    if (!range.to && node.textContent.includes(text))
      range = { from: offset, to: offset + node.nodeSize };
  });
  return range;
}

5. Root cause

Docs installs the default StarterKit hardBreak node and Markdown extension. The installed tiptap-markdown 0.8.10 src/extensions/nodes/hard-break.js serializer scans later siblings and writes a break only if it finds a subsequent node of a different type. For a sole hard break there is no subsequent sibling, so the serializer writes nothing. This is also why trailing breaks are subject to the same library behavior; this report only tests the sole-break case.

The real editor save path delegates edited nodes to that Markdown serializer. saveMarkdownBlocks then removes trailing newline characters from edited output; nothing in that layer reconstructs a missing break. On reload, blank content or an empty list/quote marker creates an empty paragraph rather than a paragraph containing a hardBreak.

The separate HTML-source behavior has a different gate: HtmlBlock renders generic HTML-block tokens as escaped source, while HtmlSource allows a bare inline break tag. A proposed serializer that emits a standalone HTML break would therefore need to handle block classification deliberately; this is a static risk, not a reproduced main symptom.

6. Fix proposal and automation limit

Define a narrowly scoped, unambiguous persistence representation for break-only paragraphs, paired with a loader rule that restores editor hardBreak nodes without turning arbitrary raw HTML into rendered markup. Use the three-context regression table above and retain the raw-HTML source tests. An unconditional raw-HTML parser exception would change existing source-rendering semantics and should not be assumed safe.
