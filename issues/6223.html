1. TL;DR

Plugin pages can lose their original route when a pane URL is parsed into layout content and rebuilt. Two host-side parsers retain URL-escaped wildcard text instead of semantic text. The existing route builder correctly escapes semantic path segments, so it escapes those retained percent signs again. Direct tests of both production boundaries reproduce the problem without installing any third-party plugin. The smallest repair decodes matched plugin parameters once and makes both boundaries use the same parser.

5. Root cause

paneContentForPathname, lines 103–114 passes the raw pathname to matchPath and copies panel.params["*"] straight into PaneContent.subPath. SplitWorkspaceRoute, lines 28–60 independently performs the same parse and stores the same undecoded wildcard.

const panel = matchPath(PLUGIN_PANEL_ROUTE_PATH, pathname);
...
subPath: panel.params["*"] ?? ""

The installed, lockfile-pinned React Router matcher substitutes uppercase escaped slashes but does not generally decode URI components. getPluginPanelRoutePath, lines 182–196 treats subPath as semantic text:

const encoded = subPath
  .split("/")
  .filter((segment) => segment.length > 0)
  .map((segment) => encodeURIComponent(segment))
  .join("/");

Consequently a stored %3A is treated as literal percent text and necessarily rebuilt as %253A. Repeated parsing preserves the increasingly escaped value. The builder is not the defective boundary and should continue to encode once.

Slash semantics: a wildcard is one semantic slash-delimited string. An actual escaped slash canonicalizes to a normal separator, matching the existing uppercase-slash behavior; byte-for-byte preservation of every noncanonical URL is not promised. Literal text %2F, supplied as %252F in a URL, must stay literal and must not receive a second decode. The regression explicitly distinguishes those cases and covers lowercase escaped separators and malformed percent input.

6. Proposed fix and verified candidate

Decode matched plugin parameters with decodeURIComponent once after matching, retaining the original value on malformed escapes. Decode after the match, not before it, so literal escape-looking text is not consumed again by the matcher's slash substitution. Reuse paneContentForPathname for the workspace's plugin routes while retaining its existing root/thread and legacy-compose routing decisions.

The tested candidate changes three files in the existing app-routing subsystem: 109 additions plus 38 deletions, 147 changed text lines. Production routing accounts for 55 lines; tests account for 92. There are no dependencies, lockfile changes, generated files, migrations, data-schema changes, wire changes, permission changes, or new public APIs.
