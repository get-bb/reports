5. Root cause

Not established. Repository inspection establishes the relevant integration boundary, not an operating-system defect:

  • RootLayout wraps the application in KeyboardProvider.
  • ProfileWebViewScreen renders the native shell WebView inside WebViewKeyboardFrame; ShellWebView delegates to WebView.
  • The default platform wrapper is just export { View as WebViewKeyboardFrame } from "react-native";. An Android-only wrapper is not evidence for this iOS report.
  • The existing shell-send flow focuses and types in the composer, but does not set up the reported native split-window arrangement.

The proposed explanation is a timing-dependent native layout fault during keyboard attachment. That remains a hypothesis: TypeScript tests or an emulated layout model cannot demonstrate a UIKit memory fault. Neither the first attachment condition nor the proposed deferral was observed here.
