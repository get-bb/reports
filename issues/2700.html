#2700 · Tasks CLI pagination is present

Bug Medium Effort: Low tasks cli open on GitHub 2026-08-29 · base 3414fda

Verdict: NOT REPRODUCED · Root-cause confidence: medium

1. TL;DR

The report says that task rows after row 500 are not available through the CLI.

The tested main commit returns an opaque cursor after row 500. The next request returns the remaining 366 rows.

Human output also prints a clear continuation message. The 0.39.0 release source contains the same behavior.

The affected installation probably had a different Tasks plugin asset. This report could not inspect that external installation.

Reproduction file: issue-2700.repro.test.ts.

import { createFakePluginHost } from "@get-bb/plugin-sdk/testing";
import { describe, expect, it } from "vitest";

import { createStore } from "../api";
import plugin from "../server";

describe("issue 2700", () => {
  it("makes every task reachable beyond the maximum page size", async () => {
    const { bb, harness } = createFakePluginHost({ pluginId: "tasks" });
    await plugin(bb);
    const store = createStore(bb);
    const project = store.tasks.createProject({
      name: "Pagination",
      prefix: "PAGE",
      color: "blue",
    });

    for (let index = 0; index < 866; index += 1) {
      store.tasks.createTask({ projectId: project.id, title: `Task ${index + 1}` });
    }

    const firstResult = await harness.runCli([
      "list", "--project", "PAGE", "--limit", "500", "--json",
    ]);
    const first = JSON.parse(firstResult.stdout);
    expect(first.tasks).toHaveLength(500);
    expect(first.nextCursor).toEqual(expect.any(String));

    const secondResult = await harness.runCli([
      "list", "--project", "PAGE", "--limit", "500",
      "--cursor", first.nextCursor, "--json",
    ]);
    const second = JSON.parse(secondResult.stdout);
    expect(second.tasks).toHaveLength(366);
    expect(second.nextCursor).toBeNull();
    await harness.dispose();
  });
});

6. Root cause

The tested repository does not contain the reported defect.

The CLI passes the cursor into the typed list request. See CLI request construction.

The database reads one extra row and creates a keyset cursor when more rows exist. See task pagination.

JSON output returns nextCursor. Human output prints the continuation command. See CLI output.

Commit d3e8267 added this behavior on 2026-07-17.

The 0.39.0 release commit contains that earlier commit. Its source also includes the cursor and marker.

The remaining explanation is runtime version skew or a stale installed plugin. This report has no direct evidence for either condition.

7. Proposed fix

Do not change the repository code for this report.

Collect the affected installation's Tasks plugin version and bb tasks list --help output.

Then compare the installed plugin asset with the 0.39.0 release asset.
