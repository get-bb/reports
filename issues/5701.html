#5701 · Server-native resolution corrupts remote Windows preview paths

Bug Medium Effort: Low plugins · inline-vis · confirmed-repro open on GitHub 2026-10-17 · base 6a639cfc0d66e0c789a1bd7309266973228d1a80

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The inline preview RPC can report a missing file even when the correct host and source root are selected. Its server-side path resolver uses the server operating system's syntax for a root that belongs to a remote host. On Linux, a Windows drive or UNC root becomes a relative POSIX string, so the server's current directory is prepended and the wrong path is sent to the host. A focused test of the actual plugin RPC reproduces this for both workspace and thread-storage sources in two clean checkouts. This is an in-process reproduction with a path-keyed SDK file fixture, not a new live Windows enrollment or browser reproduction.

import { createFakePluginHost } from "@get-bb/plugin-sdk/testing";
import { describe, expect, it } from "vitest";
import { z } from "zod";
import plugin from "./server";

const roots = [
  {
    name: "POSIX",
    rootPath: "/preview-root",
    absolutePath: "/preview-root/reports/view.html",
  },
  {
    name: "Windows drive",
    rootPath: "R:\\preview-root",
    absolutePath: "R:\\preview-root\\reports\\view.html",
  },
  {
    name: "Windows UNC",
    rootPath: "\\\\preview-machine\\share\\preview-root",
    absolutePath:
      "\\\\preview-machine\\share\\preview-root\\reports\\view.html",
  },
];

describe.each(["workspace", "thread-storage"])("%s host paths", (source) => {
  it.each(roots)(
    "prepares an existing $name file",
    async ({ rootPath, absolutePath }) => {
      const content = "<!doctype html><h1>Remote preview</h1>";
      const fileResult = {
        content,
        contentEncoding: "utf8",
        sizeBytes: Buffer.byteLength(content),
        sha256: "fixture",
      };
      const hostId = "host_preview";
      const file = "reports/view.html";
      const { bb, harness } = createFakePluginHost({
        pluginId: "inline-vis",
        sdk: {
          threads: {
            get: () => ({
              id: "thr_preview",
              environment: { id: "env_preview", hostId, path: rootPath },
            }),
            storageLocation: () => ({ hostId, storageRootPath: rootPath }),
          },
          files: {
            read: async (input: unknown) => {
              const args = z
                .object({
                  path: z.string(),
                  rootPath: z.string(),
                  hostId: z.string(),
                })
                .parse(input);
              expect(args.rootPath).toBe(rootPath);
              expect(args.hostId).toBe(hostId);
              if (args.path !== absolutePath) {
                console.info(
                  JSON.stringify({
                    expectedPath: absolutePath,
                    actualPath: args.path,
                  }),
                );
                throw Object.assign(
                  new Error("No file at requested host path"),
                  { status: 404 },
                );
              }
              return fileResult;
            },
          },
        },
      });
      await plugin(bb);
      await expect(
        bb.sdk.files.read({ path: absolutePath, rootPath, hostId }),
      ).resolves.toMatchObject({ content });
      await expect(
        harness.callRpc("preparePreview", {
          threadId: "thr_preview",
          file,
          source,
        }),
      ).resolves.toMatchObject({
        kind: "html",
        content,
        file,
        source,
        target: { kind: source, path: file },
        url: expect.stringContaining("/reports/view.html"),
      });
    },
  );
});

5. Root cause

resolveContainedPreviewPath, lines 69–84 uses imported native node:path for resolution, relative containment, separators, and absolute-path checks:

export function resolveContainedPreviewPath(
  rootPath: string,
  relativeFile: string,
): string {
  const root = path.resolve(rootPath);
  const absolute = path.resolve(root, relativeFile);
  const relative = path.relative(root, absolute);
  if (
    relative === ".." ||
    relative.startsWith(`..${path.sep}`) ||
    path.isAbsolute(relative)
  ) {
    throw new Error(`"file" must not escape its source: ${relativeFile}`);
  }
  return absolute;
}

For a root like R:\preview-root, Linux resolves the path under its current working directory instead of retaining the drive root. UNC roots suffer the same conversion. The lexical containment check succeeds relative to this incorrect POSIX root.

The handler's source selection forwards the correct root and host. The read and error mapping sends the malformed absolute path to files.read and translates a 404 into not-found. This explains why choosing the right host does not avoid the failure.

The core file-route helpers explicitly distinguish Windows and POSIX syntax; their code supports the architectural diagnosis, but no live core HTTP request was made here.

6. Proposed fix and autopilot safety decision

Select path semantics from the owning absolute root, rather than from the server OS, and use that same path implementation for resolution and containment. Preserve existing host targeting, UTF-8/size checks, and source-relative input validation. Before landing, test drive and UNC roots, POSIX roots, absolute/drive-relative inputs, traversal, mixed separators, cross-drive paths, and sibling-prefix escapes.

No autopilot PR: the necessary change touches the lexical source-root containment security boundary in resolveContainedPreviewPath. The rule explicitly excludes security-boundary changes even if their textual diff is small. No production patch, branch, commit, or push to get-bb/bb was made. This is not a claim that an exploitable escape was found; it is a scope restriction on automated changes to the containment decision.
