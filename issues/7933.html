#7933 · Digit-row shortcut normalization

Bug Priority: Medium Effort: Low ui confirmed-repro

GitHub issue · November 20, 2026 · base 66e94b287d1fa805cc773104fd110470e860dcab

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The shared shortcut matcher rejects number shortcuts when the keyboard reports punctuation or an accented Latin character from a physical digit key. A physical Digit1 event carrying an ampersand normalizes to the ampersand, not 1. The existing physical-key fallback handles non-Latin letters and some Option combinations, but skips this digit-row case. The recorder uses the same normalizer, explaining why it saves a symbol instead of the digit. A focused test reproduces the defect in two trusted source checkouts; a one-line normalization change makes the test pass.

5. Root cause

normalizeAppShortcutInputKey and matchesAppShortcutKey select physical keys only for a narrow set of characters:

const usePhysicalKey = input.altKey
  ? !isAsciiAlphanumeric(input.key)
  : isNonLatinCharacter(input.key);

Without Alt, an ampersand is not a non-Latin letter/number, and an accented Latin letter is excluded too. This bypasses the existing Digit-code decoder and returns layoutAppShortcutKey instead. The matcher then compares the symbol to the expected decimal key. The fallback layout comparison cannot repair that mismatch. With Shift, the US-specific punctuation table can even translate a French quote event to an unrelated base character; using the digit code first avoids that path.

The recorder uses the same normalizer. numberedChatBindings creates decimal keys; its thread and pane callers are at the default binding definitions. AppCommandProvider uses matchesAppShortcut to dispatch them.

6. Proposed fix and verification

Normalize valid Digit0–Digit9 codes to their decimal key before the layout-dependent fallback. Keep exact modifier checks and the existing character fallback for saved symbol overrides. Do not remap Latin letter keys or change defaults, protocols, settings schemas, or stored data. The production fix is one added line in the existing domain shortcut subsystem.

if (/^Digit[0-9]$/u.test(input.code)) return input.code.slice(5);

After this change, all 47 focused tests pass; all 361 domain tests pass; domain lint and typecheck pass; all 33 selected app matcher, DOM-focus, recorder, and conflict tests pass. No native keyboard claim is implied by these automated checks.
