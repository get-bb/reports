5. Root cause and limits

  1. apps/app/vite.config.ts:35 leaves target selection at the installed Vite default. Resolving the actual configuration produces chrome111, edge111, firefox114, safari16.4, ios16.4; Chrome 92 is outside that compilation target. This is a build target, not proof that every lower browser always fails.
  2. apps/app/src/app.css:1 imports the shared theme and uses native cascade layers. apps/app/src/components/ui/theme.css:500 and apps/app/src/components/ui/theme.css:741 define core canvas/ink values in OKLCH. The diagnostic checks the emitted CSS, not only source declarations. This supports a capability mismatch but does not prove that CSS alone produces the complete black screen.
  3. apps/mobile/src/screens/webview/ProfileWebViewScreen.tsx:355 mounts react-native-webview without an engine-version gate. apps/mobile/src/screens/webview/ProfileWebViewScreen.tsx:436 promotes a load-completion callback to ready; native errors cover transport/HTTP failures, not successful React paint.
  4. apps/mobile/src/lib/shell/shell-state.ts:67 keeps loading/ready pages in the WebView and does not reveal a native failure for those states. Its state contract has no capability-failure alternative.
  5. apps/app/index.html:101 starts with an empty React root. apps/app/src/main.tsx:42 installs the React error boundary only as part of the application render; it is not a pre-module compatibility screen. An exception before this point or unsupported styles cannot be diagnosed by that boundary alone.
  6. apps/mobile/src/app-shell/LaunchSplash.tsx:68 has an eight-second splash deadline which reveals the app, not an unsupported-engine warning. The splash is therefore not demonstrated to be permanently stuck.

Supported causal hypothesis: a modern web payload is allowed into an older embedded engine without a compatibility failure path.
