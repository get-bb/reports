#5016 · Codex transcription request budget mismatch

Bug Medium Effort: Low providers provider-codex · GitHub issue · October 6, 2026

Trusted base: fd31b75fb9c7f40e68747089c911b098763aa851

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

Voice transcription through the Codex service aborts requests after 10 seconds even though the core voice task allows 70 seconds. A deterministic reproduction loads the actual service registration and actual host transcription implementation, then substitutes only credentials, HTTP response timing, and the host transport. Successful HTTP responses scheduled after 12 seconds and 64 seconds both fail with the production timeout error. A second clean checkout at the same trusted main commit produces the same failures. This verifies the deadline defect, not the report's live-endpoint latency measurements or an audio-duration threshold.

5. Root cause

The server-side Codex service chooses TRANSCRIBE_TIMEOUT_MS = 10_000. It sends that value as the existing host request's timeoutMs and gives the host RPC only one additional second. The host transcription implementation creates a deadline from that input and aborts HTTP when it expires. The core's longer task deadline cannot extend either inner deadline.

  • Service budget: TRANSCRIBE_TIMEOUT_MS = 10_000 and HOST_CALL_GRACE_MS = 1_000.
  • Both inner deadlines receive that budget.
  • Host request cancellation and timeout classification.
  • Transcription creates and uses that deadline.
  • Core voice budget: 70 seconds; existing cloud transcription budget: 65 seconds.

6. Proposed fix

Raise the Codex service transcription budget to the existing 65-second cloud transcription budget. Its host RPC then automatically becomes 66 seconds, leaving headroom beneath core's 70-second budget. Preserve the existing size limit, cancellation signal, text-completion budget, and host contract. The existing host implementation accepts an explicit positive timeout and can enforce the new value without a schema or protocol change; the regression uses that unchanged implementation.
