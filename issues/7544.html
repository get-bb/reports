#7544 · ACP bridge discards idle user input

BugPriority: MediumEffort: Mediumproviders · provider-acpGitHub issue2026-11-14 · base f024a372f0e1e0670f6fd7452ebcd1341f639c95

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The ACP bridge can display an agent's unsolicited answer without the user input that prompted it. An idle user_message_chunk starts agent work, but the translator classifies it as noise and emits no timeline delta. Subsequent assistant chunks do produce timeline items. A repository-native bridge test reproduces the missing message in two clean checkouts of trusted main; no user configuration, real account, or issue-provided program was used.

5. Root cause

The session model treats a decoded message chunk as agent activity. The bridge applies that update and opens an agent-initiated turn while idle. It then sends the update through the delta translator. The translator has no user-message case: its default path calls unhandledDeltas, which returns an empty array for anything classified as non-unknown. Visibility metadata unconditionally classifies user chunks as noise. Assistant chunks follow a recognized translation path, so the answer survives without the input.

6. Proposed fix

Have the bridge explicitly allow user input only during agent-initiated work, not prompted turns or compaction. Translate validated text through the existing input.provider delta. Coalesce adjacent user chunks, ignore interleaved metadata as message boundaries, and flush before assistant/tool output or at turn completion. Retain history suppression. The local implementation passes focused coverage for external text and echo/replay guards; full package checks are recorded with the eventual pull request.

Scope limits: no wire or persisted schema change, new CLI surface, or new label design is required to preserve text. Existing provider-input presentation uses its existing system-message card; a specialized “another client” badge and non-text ACP input remain separate design work, not claims made by this repair.
