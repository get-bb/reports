#5729 · Source server cache compiles before lookup

BugPriority: MediumEffort: Mediumplugins · perf GitHub issue2026-10-18 · base f9eae1c44cd67e3dcbf807809bda8999926f7967

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The source-build cache preserves the finished plugin artifact but does not avoid compiling it again. Two fresh Node processes using identical source, SDK version, bb version, and a shared cache each invoke the real compiler. They return exactly the same artifact path and digest, so this is a compile-before-cache-lookup defect, not a failure to retain the output. A plugin whose prebuilt bundle fails the SDK compatibility check reaches this source-build path. The focused regression fails for this precise reason in two clean trusted-main checkouts.

Complete reproduction test

import { execFile } from "node:child_process";
import {
  appendFile,
  mkdir,
  mkdtemp,
  readFile,
  rm,
  writeFile,
} from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { fileURLToPath, pathToFileURL } from "node:url";
import { promisify } from "node:util";
import { resolvePluginBuildToolchain } from "@bb/plugin-build";
import { expect, it } from "vitest";

const run = promisify(execFile);

it("reuses a source-built server across fresh processes without compiling again", async () => {
  const workDir = await mkdtemp(join(tmpdir(), "bb-server-cache-reuse-"));
  try {
    const rootDir = join(workDir, "plugin");
    await mkdir(rootDir);
    await writeFile(join(rootDir, "server.ts"), "export default () => 42;\n");
    const marker = join(workDir, "builds.txt");
    await appendFile(marker, "");
    const toolchain = await resolvePluginBuildToolchain(
      join(workDir, "toolchain"),
    );
    const compilerPath = join(workDir, "compiler.mjs");
    await writeFile(
      compilerPath,
      `import * as compiler from ${JSON.stringify(toolchain.esbuild)};
import { appendFile } from "node:fs/promises";
export const transform = compiler.transform;
export async function build(options) {
  await appendFile(${JSON.stringify(marker)}, "build\\n");
  return compiler.build(options);
}
`,
    );
    const workerPath = join(workDir, "worker.mjs");
    const cacheModule = new URL(
      "../../../src/services/plugins/plugin-server-cache.ts",
      import.meta.url,
    ).href;
    await writeFile(
      workerPath,
      `import { buildCachedPluginServer } from ${JSON.stringify(cacheModule)};
const result = await buildCachedPluginServer({
  rootDir: ${JSON.stringify(rootDir)},
  dataDir: ${JSON.stringify(join(workDir, "data"))},
  pluginId: "cache-reuse",
  sdkVersion: "0.6.54",
  bbVersion: "0.46.1",
  validatedConfig: ${JSON.stringify({ serverEntry: join(rootDir, "server.ts"), packageName: "bb-plugin-cache-reuse", pluginVersion: "1.0.0" })},
  toolchain: async () => (${JSON.stringify({ ...toolchain, esbuild: pathToFileURL(compilerPath).href })}),
  runtimeImports: {},
  fallbackResolve: () => undefined,
});
console.log(JSON.stringify(result));
`,
    );
    const argumentsList = [
      "--conditions=source",
      "--import",
      fileURLToPath(import.meta.resolve("tsx")),
      workerPath,
    ];
    const first = await run(process.execPath, argumentsList);
    expect(await readFile(marker, "utf8")).toBe("build\n");
    const second = await run(process.execPath, argumentsList);
    expect(second.stdout).toBe(first.stdout);
    expect(await readFile(marker, "utf8")).toBe("build\n");
  } finally {
    await rm(workDir, { recursive: true, force: true });
  }
}, 30_000);

5. Root cause

At cache: compile, hash, then look up, buildCachedPluginServer creates a staging directory and always calls buildPluginServer. Only after that call does it hash the output and derive the final cache directory. isCompleteCacheEntry is consequently too late to prevent a build. The output-addressed cache currently provides artifact reuse and bounded retention, not pre-build memoization.

const built = await buildPluginServer(...);
const digest = await hashFile(built.jsPath);
const cacheDir = pluginServerCacheDirectory(...);
if (await isCompleteCacheEntry(cacheDir)) {
  return { path: join(cacheDir, "server.cjs"), digest };
}

SDK mismatch selects the source builder explains how a stale community prebuild reaches the failing path. The compatibility restriction is intentional and does not need relaxing.

The underlying safety constraint is that compiler inputs are not limited to the entry file or even the plugin's source directory. The existing bundled-dependency invalidation test changes an installed dependency while leaving the entry unchanged and requires a new artifact. installed-package and fallback resolution can bundle a fallback-resolved package from outside the plugin root. The compiler result and build options currently exposes only output paths, not a dependency or resolution fingerprint.

6. Proposed fix and simple-fix assessment

Introduce a pre-build input fingerprint with a clearly defined invalidation contract: source and bundled dependency contents, resolution-affecting package/configuration files, selected runtime imports, validated build options, and SDK/bb/Node/toolchain versions. Validate a complete cached artifact against that fingerprint before invoking the compiler; preserve atomic staging, retention, and conservative rebuilding on missing or invalid cache information.

Do not substitute a hash of only server.ts or only ordinary source files: that would miss the dependency changes the current test already protects, and may miss fallback-resolved inputs outside the plugin root. A compiler-produced dependency/resolution manifest would require coordinated plugin-build and server-runtime changes and a persisted cache-input representation.

No automatic fix PR: the safe path needs a cache-input design spanning the compiler and runtime, rather than a verified one-subsystem local repair. That does not meet this rule's one-subsystem/no-architecture-decision simple-fix gate. No production patch, commit, or branch was pushed. The regression test is retained inline for the eventual implementation; a post-fix pass is not claimed.

Minimum acceptance for a future fix: this test passes; dependency/source/configuration and SDK changes still rebuild; incomplete artifacts rebuild; deleted, newly shadowed, or retargeted dependency resolutions cannot serve stale output.
