A direct check against its current production parser reproduces that rejection when the metadata is deliberately added. However, the trusted main server no longer sends that metadata: it explicitly returns only ok and result. The repair landed in #6073 on October 21, 2026 at 19:51:37 UTC, before this issue was created on October 22. Two fresh checkouts passed both the existing wire regression and all Usage plugin tests; no additional repair PR is warranted.

5. Root cause

The card's strict success schema permits only ok and result. Its fetch path parses the whole response and maps any failure to a refresh error. Consequently, leaking internal metadata into an otherwise valid response prevents data from reaching the card.

The mismatch was at the producer/transport boundary, not provider authentication. The historical main change, inspected only as a diff, returned the service outcome wholesale after spreading the tag helper's output into it. The current HTTP route instead constructs:

return context.json({ ok: true, result: outcome.result });

The service still derives and broadcasts invalidations but returns no metadata. The SDK query host derives its own tags from the shared contract. The existing wire regression locks down the repaired public response shape and retained invalidation behavior.
