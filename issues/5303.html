#5303 · Media attachments omit transcription guidance

Bug Priority: Medium Effort: Low providers · cli · provider-claude-code

GitHub issue · October 9, 2026 · trusted main ba77afe213c92588c44d04fca01e91cd9ba7c9f4

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The Claude Code provider turns every local attachment into a text notice directing the agent to use its Read tool. For audio and WebM media, this notice does not point to BB's existing transcription command, even though it receives the attachment MIME type. The injected BB introduction and top-level CLI guide also omit that command. A focused test exercised the real bridge JSON-RPC turn path and captured the prompt handed to the SDK; three media cases failed the transcription-guidance assertion in two separate clean checkouts. The command itself is already documented deeper in the guide, so this is a discovery and prompt-routing defect, not a demonstrated transcription-service failure.

5. Root cause

localAttachmentMarker uses MIME only as descriptive text and ends unconditionally with:

return `[Attached ${args.kind}${namePart}${suffix}. It is on disk at ${args.path} — use the Read tool to view it.]`;

The localFile branch already supplies MIME, path, name, and size, so the required distinction is available without changing a wire format. The injected introduction and overview template provide no fallback discovery cue. The existing CLI handler calls the SDK transcription service, and the customization chapter already documents the command. Thus the command exists but is not advertised where an agent receives media.

6. Proposed fix and automatic-fix gate

Make media attachment guidance MIME-aware, point to the configured transcription command, and preserve ordinary file/image instructions. Quote the file path safely when constructing a runnable command, including paths containing spaces or apostrophes. Add a short discovery entry to the BB introduction and top-level guide. Retain the prompt-boundary regression and the existing non-media controls.

No production fix or pull request was pushed: the complete verified defect requires changes to the provider bridge and the separate guide/introduction/template subsystem. It therefore fails this run's explicit requirement that an automatic simple fix stay within one existing subsystem. A provider-only repair would leave the separately reproduced guide-discovery defect unresolved. The diagnostic patch is 30 added test lines and is published only as report evidence; it is not a stopped implementation branch.
