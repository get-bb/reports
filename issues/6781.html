#6781 · Whole-transcript allocations hide fork failures

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A Claude Code transcript can exist on disk yet produce a misleading “Session not found” error when bb tries to fork it. The adapter reads the entire JSONL file into one JavaScript string, which fails at Node's maximum string length, then suppresses the read error and reports the session as absent. Both a checkpoint fork and a full fork fail on a synthetic 536,981,786-byte ASCII transcript; both succeed on the small control. A second clean trusted checkout reproduces the same results. The output writer also aggregates the fork into one string, so correcting only the reader would leave another size-limited allocation.

import assert from "node:assert/strict";
import { constants } from "node:buffer";
import { randomUUID } from "node:crypto";
import { createWriteStream } from "node:fs";
import { mkdir, mkdtemp, readFile, rm, stat } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { pipeline } from "node:stream/promises";
import { forkClaudeSession } from "./src/bridge/session-fork.ts";

const configDirectory = await mkdtemp(join(tmpdir(), "fork-boundary-"));
const projectDirectory = join(configDirectory, "projects", "synthetic-project");
const failures: string[] = [];
await mkdir(projectDirectory, { recursive: true });

async function exercise(large: boolean): Promise<void> {
  const sourceSessionId = randomUUID();
  const firstMessageId = randomUUID();
  const sourcePath = join(projectDirectory, `${sourceSessionId}.jsonl`);
  const payload = large ? "p".repeat(256 * 1024) : "small-control";
  let bytes = 0;
  let count = 0;
  function* records(): Generator<string> {
    let parentUuid: string | null = null;
    while (large ? bytes <= constants.MAX_STRING_LENGTH : count < 4) {
      const uuid = count === 0 ? firstMessageId : randomUUID();
      const role = count % 2 === 0 ? "user" : "assistant";
      const record = JSON.stringify({
        type: role,
        uuid,
        parentUuid,
        sessionId: sourceSessionId,
        cwd: "/tmp/synthetic-project",
        timestamp: new Date(1_700_000_000_000 + count * 1000).toISOString(),
        isSidechain: false,
        message: { role, content: `entry-${count}: ${payload}` },
      }) + "\n";
      bytes += Buffer.byteLength(record);
      count += 1;
      parentUuid = uuid;
      yield record;
    }
  }
  await pipeline(records(), createWriteStream(sourcePath, { flags: "wx" }));
  const before = await stat(sourcePath);
  assert.equal(before.size, bytes);
  console.log(`${large ? "large" : "small"} fixture: ${bytes} ASCII bytes; ${count} records`);

  if (large) {
    try {
      await readFile(sourcePath, "utf8");
      console.log("direct UTF-8 read: unexpectedly succeeded");
    } catch (error) {
      assert.ok(error instanceof Error);
      console.log(`direct UTF-8 read: ${error.name}: ${error.message}`);
    }
  }

  for (const mode of ["checkpoint", "full"]) {
    const label = `${large ? "large" : "small"} ${mode}`;
    try {
      const forkedSessionId = await forkClaudeSession({
        configDirectory,
        sourceSessionId,
        upToMessageId: mode === "checkpoint" ? firstMessageId : undefined,
      });
      const forkPath = join(projectDirectory, `${forkedSessionId}.jsonl`);
      assert.notEqual(forkedSessionId, sourceSessionId);
      assert.ok((await stat(forkPath)).size > 0);
      if (!large) {
        const forkText = await readFile(forkPath, "utf8");
        assert.ok(forkText.includes("entry-0:"));
        assert.equal(forkText.includes("entry-3:"), mode === "full");
      }
      await rm(forkPath);
      console.log(`${label}: PASS`);
    } catch (error) {
      assert.ok(error instanceof Error);
      console.log(`${label}: ${error.name}: ${error.message.replaceAll(sourceSessionId, "<source-session>")}`);
      failures.push(label);
    }
  }
  assert.equal((await stat(sourcePath)).size, before.size);
  await rm(sourcePath);
}

try {

  await exercise(false);
  await exercise(true);
  const chunk = "p".repeat(256 * 1024);
  const chunks = Array(Math.ceil(constants.MAX_STRING_LENGTH / chunk.length) + 1).fill(chunk);

  assert.deepEqual(failures, [], "Existing transcripts must fork in both modes");
} finally {
  await rm(configDirectory, { recursive: true, force: true });
}

5. Root cause

forkClaudeSession, lines 20–30, supplies bb's custom project transcript store to the real SDK. load, lines 38–47, resolves and parses the source before the SDK can select its checkpoint. Therefore even a checkpoint at the first small message requires reading the entire oversized file.

findTranscript, lines 78–93, calls readFile(path, "utf8") inside a catch-all that continues to the next project. Node raises RangeError: Invalid string length for the synthetic ASCII file above its string cap. The adapter swallows that error, finds no other source, returns null, and the SDK reports the existing session as absent.

try {
  contents = await readFile(
    join(projectDirectory, `${sessionId}.jsonl`),
    "utf8",
  );
} catch {
  continue;
}

append, lines 49–59, creates the entire output string before writing:

entries.map((entry) => `${JSON.stringify(entry)}
`).join("")

A large full fork retains that second limit even with an incremental reader. The primitive-only join probe corroborates this allocation hazard, not a completed execution of the unreachable production writer. The SDK contract also still loads entries into an array; streaming I/O removes the single-string ceiling, not all memory limits.

The bridge caller passes sourceProviderCheckpointId as upToMessageId and forwards the caught error. The introducing commit added the custom store. No SDK-only upgrade can remove the whole-string operations in this bb adapter.

6. Proposed fix

Read and parse JSONL incrementally and serialize/write individual entries with backpressure instead of concatenating the complete transcript. Preserve source-project selection, checkpoint behavior, UTF-8 correctness, exclusive creation, and private file permissions. Ignore genuinely missing candidate files but surface unexpected read failures with their cause. Test a real above-cap file in both modes, checkpoint cut-off, and output/error cleanup. No public protocol, migration, or product decision appears necessary; entry-array memory use remains a separate limit.
