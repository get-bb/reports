#4958 · Codex drops disabled reasoning before session startup

BugPriority: LowEffort: Lowprovidersprovider-codexGitHub issue2026-10-05

Trusted base: be68bf357b3428161bd83f57dda427a9b58094ca

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

BB recognizes a reasoning level named none, but the Codex provider prevents it from reaching a session. Custom Codex models inherit a provider ladder that does not list that level. Even when supplied directly to the real session configuration builder, the level is translated to null and rejected. Two focused tests fail on unchanged trusted main, and the same agent repeated both failures in a second clean checkout. This report verifies BB's rejection, not the behavior of a live third-party model or a particular installed Codex release.

5. Root cause

The provider has two independently meaningful rejection points. Its capabilities and displayed reasoning descriptors both exclude none. The server builds custom-model efforts from those provider capabilities, and its execution validation rejects levels outside that list.

Separately, the outgoing effort mapper treats a valid disabled-reasoning choice the same way as a BB-only unsupported effort:

case "none":
case "ultracode":
  return null;

The real session conversion interprets that null as unsupported and throws before a configuration can be delivered:

const codexEffort = mapBbReasoningLevelToCodex(reasoningLevel);
if (codexEffort == null) {
  throw new Error(
    `Codex does not support the ${reasoningLevel} reasoning level.`,
  );
}

Fixing only the ladder leaves the session failure; fixing only the translation leaves custom-model selection blocked. Neither requires a new SDK field, server/daemon wire schema, persisted field, or command flag. Catalog model lists and the medium default remain authoritative and unchanged.

6. Proposed fix and verification

Add the existing none level to the Codex capability ladder and its matching display descriptor, then return it unchanged from the outgoing mapper. Keep ultracode unsupported. Extend the real session configuration test to expect the value instead of an exception, and the custom-model integration to expect the level while retaining its medium default.

The locally authored fix meets the simple-fix limits: four files, 20 changed text lines (15 additions + 5 deletions), production changes confined to the existing Codex provider, no dependency, migration, generated file, packaging change, protocol change, or new product setting.
