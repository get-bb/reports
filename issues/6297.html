#6297 · Message commands lose content during timeline deferral

Bug Priority: Low Effort: Low threads · 2026-10-26 · Issue

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

Trusted base: 3540a699e29034b53da32bb7efa6f5b4055209eb. Two clean-production checkouts, checked sequentially by the same agent. No linked branch, issue script, or linked regression test was executed.

1. TL;DR

The API removes part of successful inter-thread message commands when deferred content is requested. A long heredoc then fails the parser used by the app to select its message renderer, so the source-level rendering path falls back to a command row. A long quoted argument behaves differently: the parser tolerates its incomplete quote and returns only the surviving prefix of the message. The API regression reproduces both forms on trusted main and passes after a server-only exemption for recognized successful sends. Message delivery was not exercised and no production instance or runtime data was used.

The fix deliberately does not broaden recognition or change ordinary-command deferral; the negative controls assert their existing transport behavior, not an unsupported guarantee about every truncated prefix.

function hasUnpairedSurrogate(value: string): boolean {
  for (let index = 0; index < value.length; index += 1) {
    const code = value.charCodeAt(index);
    if (code >= 0xd800 && code <= 0xdbff) {
      const next = value.charCodeAt(index + 1);
      if (next < 0xdc00 || next > 0xdfff) {
        return true;
      }
      index += 1;
    } else if (code >= 0xdc00 && code <= 0xdfff) {
      return true;
    }
  }
  return false;
}

function findCommandRow(rows: readonly TimelineRow[], command: string) {
  const row = rows.find(
    (candidate) =>
      candidate.kind === "work" &&
      candidate.workKind === "command" &&
      candidate.command === command,
  );
  if (!row || row.kind !== "work" || row.workKind !== "command") {
    throw new Error(`command row ${command} not found`);
  }
  return row;
}

function maybeFindNestedCommandRow(
  rows: readonly TimelineRow[],
  command: string,
): Extract<TimelineRow, { kind: "work"; workKind: "command" }> | null {
  for (const row of rows) {
    if (
      row.kind === "work" &&
      row.workKind === "command" &&
      row.command === command
    ) {
      return row;
    }
    const children =
      row.kind === "turn"
        ? row.children
        : row.kind === "work" && row.workKind === "delegation"
          ? row.childRows
          : null;
    if (children !== null) {
      const match = maybeFindNestedCommandRow(children, command);
      if (match !== null) {
        return match;
      }
    }
  }
  return null;
}

function findNestedCommandRow(
  rows: readonly TimelineRow[],
  command: string,
): Extract<TimelineRow, { kind: "work"; workKind: "command" }> {
  const row = maybeFindNestedCommandRow(rows, command);
  if (row === null) {
    throw new Error(`nested command row ${command} not found`);
  }
  return row;
}

function seedRunningTurnWithCommands(harness: TestAppHarness): {
  threadId: string;
} {
  const { environment, thread } = seedThreadFixture(harness);
  const turn = {
    threadId: thread.id,
    environmentId: environment.id,
    providerThreadId: "p1",
    scope: turnScope("turn-1"),
  } as const;
  seedEvent(harness.deps, {
    ...turn,
    sequence: 1,
    type: "turn/started",
    data: {},
  });
  let sequence = 1;
  for (const [command, output] of [
    ["big", BIG_OUTPUT],
    ["small", SMALL_OUTPUT],
  ] as const) {
    sequence += 1;
    seedEvent(harness.deps, {
      ...turn,
      sequence,
      type: "item/started",
      data: {
        item: {
          type: "commandExecution",
          id: `cmd-${command}`,
          command,
          cwd: "/tmp",
          status: "pending",
          approvalStatus: null,
        },
      },
    });
    sequence += 1;
    seedEvent(harness.deps, {
      ...turn,
      sequence,
      type: "item/completed",
      data: {
        item: {
          type: "commandExecution",
          id: `cmd-${command}`,
          command,
          cwd: "/tmp",
          status: "completed",
          approvalStatus: null,
          exitCode: 0,
          aggregatedOutput: output,
        },
      },
    });
  }
  return { threadId: thread.id };
}

5. Root cause

  1. The server's command deferral branch checks command-plus-output size, then replaces every qualifying settled command with a 300-character prefix and clears output.
  2. Completed-turn grouping identifies successful inter-thread sends using the complete command and keeps them outside the summary fold.
  3. The client renderer re-parses the command it receives. It sees the shortened text rather than the full grouping input.
  4. Heredoc parsing requires the terminator. Successful-send parsing also checks completion/exit status. Losing the terminator makes the heredoc unrecognizable; quoted-token parsing instead tolerates the truncated argument, as demonstrated in the second run.

The underlying defect is inconsistent semantic input: grouping classifies the full command, while presentation classifies a lossy preview of that same command. Deferral treats visible message content as if it were optional expandable command detail.

6. Proposed fix and verified result

Reuse the existing successful-send parser at the server's deferral boundary. Leave recognized successful message commands inline, so the same full input reaches grouping and rendering. Keep the ordinary deferral path for failed, compound, and file-based commands. No public schema, daemon wire field, migration, dependency, or stored-data change is required.

The local repair changes two files in the existing server timeline subsystem: 118 additions and 1 deletion, 119 total changed text lines. The intentional trade-off is that a successful recognized message stays inline; this is the content the special message row actually displays.
