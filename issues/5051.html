#5051 · ACP pre-prompt reconciliation retains launch-time selection

BugHighEffort: Mediumproviders · provider-acpopen on GitHub2026-10-06 · base 6e348ee

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The ACP bridge accepts a different model on a completed-turn follow-up, but sends the next prompt using the startup selection. Two real stdio tests against the trusted repository bridge request strong → default → strong and observe strong → strong → strong, using either supported ACP model interface. A supported effort/tier change also remains low/default instead of high/fast. An environment-triggered rebuild uses the old construction selection. The issue is below the model picker: the shared pre-prompt reconciliation never applies the incoming selection.

5. Root cause

runTurn, lines 2109–2133, invokes reconciliation for each pending input and then dispatches session/prompt. reconcileExecutionSettings, lines 2184–2235, handles environment and permission/write-root state, but omits options.model, options.reasoningLevel and options.serviceTier:

const construction = {
  ...session.construction,
  envVars,
  permissionMode: options.permissionMode,
  workspaceWriteRoots,
};

The spread preserves the original modelSelection. Rebuild therefore also receives the old selection. Session construction, lines 1875–1911, applies native selection at new/load/fork construction, but no live pre-prompt call reaches that selector.

selectAcpNativeModel, lines 1155–1219, compares requested values with current configuration and uses setter responses for dependent options only within the call. AcpThreadSession, lines 160–193, has no retained authoritative model/configuration snapshot. A repair must not reuse stale startup values when returning to the original model.

The queued-input contract is already present on this base: AcpPendingTurnInput includes options, and the per-prompt loop consumes them. No additional wire field is required to carry the reproduction's requested options.

6. Proposed fix and simple-fix gate

  • Compute the effective selection for each pending input at the existing shared pre-prompt boundary. Apply native model selection before its supported dependent settings and before session/prompt.
  • Retain authoritative state from creation, successful setter responses and relevant agent updates. Use current model state for A → B → A and validate dependent values against the resulting model configuration.
  • Update construction selection for recovery. For CLI-owned parameters, compare effective launch arguments and reconcile them through the existing rebuild path rather than silently retaining startup flags.
  • Test failure handling before accepting or dispatching a prompt, plus native round trips, same-model settings changes, and recovery.

No automatic fix PR. The decision-free simple-fix gate is not satisfied for a complete capability-aware repair: a CLI-only agent without usable session/load cannot change launch parameters while retaining in-agent history. The existing resume fallback explicitly starts a fresh session and warns of lost history (lines 1851–1902). Extending that fallback to model-picker changes needs an explicit product decision between rejection and history loss; a native-only setter patch would leave the CLI selection path accepted-but-ignored. No production fix was made, committed, or pushed. The local test-only patch is 109 added text lines in one file; this is not a claimed passing fix.
