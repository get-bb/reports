#5836 · Async isolation misattributes host React insertions

BugPriority: MediumEffort: MediumpluginsGitHub issue2026-10-20

Trusted base: b0bb68655adcc6cd79e495d3484f4011a0640e2e (origin/main fetched from get-bb/bb).

Verdict: REPRODUCED · Root-cause confidence: high · label: confirmed-repro

1. TL;DR

A pending plugin mount can prevent a host-owned React element from entering the document even though the plugin does not touch the DOM. The guard keeps a global plugin-isolation flag active while awaiting the plugin promise. React's unrelated commit then passes through the same patched DOM methods and is incorrectly rejected. Two clean trusted checkouts reproduce this with real React; a settled-promise control succeeds. The full application/browser journey is not claimed as verified.

// @vitest-environment jsdom
import { act } from "@testing-library/react";
import { createRoot } from "react-dom/client";
import { expect, it, vi } from "vitest";
import {
  installForeignDomMutationGuard,
  pluginHostNodeMoveRefusalCount,
  runWithPluginDomIsolationAsync,
  uninstallForeignDomMutationGuardForTest,
} from "./foreign-dom-mutation-guard";

it.each(["pending", "settled"])("allows a host React insertion with a %s plugin mount", async (state) => {
  const warning = vi.spyOn(console, "warn").mockImplementation(() => undefined);
  const container = document.createElement("div");
  document.body.appendChild(container);
  const root = createRoot(container);
  let finishMount = () => {};
  const pendingMount = new Promise<void>((resolve) => {
    finishMount = resolve;
  });
  installForeignDomMutationGuard();
  const mount = runWithPluginDomIsolationAsync(() => pendingMount, "pending-mount");
  try {
    await Promise.resolve();
    if (state === "settled") {
      finishMount();
      await mount;
    }
    act(() => root.render(<div data-bb-plugin-app-overlays="">Overlay content</div>));
    const presentWhilePending = container.querySelector("[data-bb-plugin-app-overlays]") !== null;
    const refused = pluginHostNodeMoveRefusalCount();
    finishMount();
    await mount;
    console.log(JSON.stringify({ state, presentWhilePending, refused, warningCount: warning.mock.calls.length }));
    expect(presentWhilePending).toBe(true);
    expect(refused).toBe(0);
  } finally {
    finishMount();
    await mount;
    act(() => root.unmount());
    uninstallForeignDomMutationGuardForTest();
    container.remove();
    warning.mockRestore();
  }
});

5. Root cause

An app-global isolation depth remains positive across an awaited plugin mount, so the DOM guard attributes unrelated host React commits to that plugin and refuses fresh React nodes inserted into root containers. This is not proof that the plugin executed React's commit; it demonstrates the guard has no execution-owner discriminator during that interval.

Async isolation lifetime:

export async function runWithPluginDomIsolationAsync<T>(
  fn: () => T | Promise<T>,
  label?: string,
  signal?: AbortSignal,
): Promise<T> {
  const previousLabel = enterIsolation(label);
  const work = Promise.resolve().then(fn);
  try {
    if (signal === undefined) return await work;
    const winner = await Promise.race([
      work.then((value) => ({ ok: true as const, value })),
      whenAborted(signal).then(() => ({ ok: false as const })),
    ]);
    if (winner.ok) return winner.value;
  } finally {
    leaveIsolation(previousLabel);
  }
  return await work;
}

Refusal predicate:

function refusePluginReparent(node: Node, newParent: Node): boolean {
  if (isolationDepth === 0) return false;
  if (node.parentNode === newParent) return false;
  if (!isReactHostNode(node)) return false;
  if (node.parentNode === null && isReactHostNode(newParent)) return false;
  recordRefusedMove(node, newParent);
  return true;
}

A freshly created React host node has a React fiber marker but no parent. The external React root container is not a React host node, so the fresh-node exception does not apply. The patched appendChild or insertBefore returns the node without inserting it; React still considers its commit complete. The overlay node can therefore remain detached after the pending mount finishes.

Production linkage: content-script mounting calls the async guard with an abort signal; 10-second default; overlay host element. The test substitutes only a deterministic pending callback; it does not load a third-party plugin or mock React, DOM methods, or the guard.

6. Proposed fix and simple-fix gate

Replace ambient promise-lifetime ownership with execution-scoped attribution, or a carefully specified host-commit exemption, without weakening the existing protection against plugin reparenting after await. This needs a design decision and regression coverage for both invariants.

The existing “keeps isolation across await and event listeners” regression explicitly requires a plugin continuation after await to remain guarded. The implementation wraps timers, listeners, observers, and queueMicrotask, but does not instrument native async/await continuation ownership. Simply shortening the isolation lifetime would remove an existing behavior contract rather than establish correct attribution.

No automatic PR: choosing a replacement execution-ownership mechanism or weakening the post-await guarantee is a design/behavior decision, which fails the rule's simple-fix gate. No production patch was made, no branch was pushed, and no dependency was added. A future design must pass both the new host-commit regression and the existing plugin-reparenting regression.
