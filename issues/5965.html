#5965 · Docs edited-block serializers add avoidable Markdown syntax

Bug Medium priority Medium effort ui · docs

2026-10-21 · Issue · Trusted main 04bdce8111ca3dbdd136c63fad3e36f56e5814c0

Verdict: REPRODUCED · Root-cause confidence: high · Label: confirmed-repro

1. TL;DR

Docs preserves untouched Markdown blocks, but serializes edited blocks using third-party defaults. At that boundary, a lone tilde acquires a backslash, a URL whose label equals its destination acquires angle brackets, and two intentional breaks produce a backslash-only line. Two clean checkouts of trusted main produced the same three failing regression assertions while all ten existing block tests passed. These encodings are valid Markdown, not demonstrated data loss; the defect is unnecessary source normalization. A draft pull request linking the issue appeared during this investigation, so the independently developed local candidate was not committed or pushed.

      Link.configure({ openOnClick: false, autolink: true }),
      Image,
      TaskList,
      TaskItem.configure({ nested: true }),

        html: true,

  const blocks = loadMarkdownBlocks(editor, markdown, (source) => source, false);
  const save = () =>
    saveMarkdownBlocks(editor, blocks, (nodes) =>
      editor.storage.markdown.serializer.serialize(
        editor.schema.topNodeType.create(null, nodes),
      ),
    );
  return { editor, save };
}

function textPosition(editor: Editor, text: string) {
  let position = -1;
  editor.state.doc.descendants((node, pos) => {
    if (position < 0 && node.isText && node.text?.includes(text))
      position = pos + node.text.indexOf(text);
  });
  return position;
}

function topLevelRange(editor: Editor, text: string) {
  let range = { from: 0, to: 0 };
  editor.state.doc.forEach((node, offset) => {
    if (!range.to && node.textContent.includes(text))
      range = { from: offset, to: offset + node.nodeSize };
  });
  return range;
}

5. Root cause

Docs registers standard StarterKit, Link, and Markdown extensions with HTML and linkification enabled, but no Docs-specific text, link, or hard-break serialization policy. The change-handler path serializes changed blocks and forwards the resulting Markdown. Block saving retains original source only when node identities remain unchanged; edited groups call the serializer at line 170.

if (edited.length)
  parts.push({ text: serialize(edited).replace(/\n+$/, "") });

The installed, lockfile-resolved dependency sources explain each observed output:

  • prosemirror-markdown/src/to_markdown.ts:434: esc() escapes all tildes using the same character class as required Markdown punctuation, even a lone tilde that cannot delimit strikethrough.
  • tiptap-markdown/src/extensions/marks/link.js delegates to ProseMirror's link serializer. Its isPlainURL path returns < and > around a URL label equal to the destination.
  • tiptap-markdown/src/extensions/nodes/hard-break.js writes "\\\n" for non-trailing hard breaks outside tables. Two adjacent break nodes therefore naturally yield the backslash-only line. The line is an intentional Markdown encoding of a break, not proof of an extra paragraph or content corruption.

No-edit preservation bypasses these defaults, explaining why changes appear only after editing an affected block.

6. Proposed fix and safety assessment

Customize the existing Docs serializers rather than stripping characters from the completed Markdown string. Preserve lone literal tildes while retaining escapes for repeated tilde delimiters and other syntax. Emit bare URLs only when the configured linkifier would reconstruct the same link and surrounding content is unambiguous; retain explicit syntax otherwise. Represent consecutive or trailing intentional breaks with the already-supported HTML break node, keeping paragraph creation separate from hard-break creation. Verify reopened editor nodes, literal backslashes, strikethrough, code, required escapes, and links beside punctuation.
