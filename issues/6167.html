#6167 · Proactive OAuth rejection disables unexpired pool credentials

BugPriority: Medium Effort: Mediumproviders Issue #61672026-10-23

Trusted base: 1e80ca7b44bccd06c6da75ed9ca6ba497bd380f5.

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

An OAuth refresh failure does not necessarily mean the currently held access token has expired. The request path nevertheless permanently excludes an account after a proactive HTTP 400 refresh rejection, without trying its still-unexpired access token. The background path instead resends the rejected refresh credential on every eligible usage tick, including after access-token expiry, without recording an account error. Both behaviors reproduced through the real Account Pooler hub and provider adapters for Claude and Codex; replacing an errored account’s stored credential also failed to restore it on the next background refresh. The same eight-case reproduction produced six expected regression failures and two passing transient-failure controls in two separate clean checkouts.

6. Proposed repair and automation safety gate

A reviewed repair should model rejected refresh credentials separately from access-token usability. Remember which refresh credential was rejected; do not retry it unchanged; keep non-forced use of a locally unexpired access token possible until expiry or actual upstream rejection. Before committing a terminal error, reread storage and reconcile a changed credential. A normal background tick should record terminal expiry consistently, and should only attempt recovery when storage now contains a different refresh credential. Publish account error transitions through the existing notification path.

Keep forced-refresh behavior and upstream 401/403 handling fail-closed, retain the existing transient backoff, and test refresh single-flight races, changed-secret detection, restart semantics, and event delivery before shipping. A successful fake endpoint does not prove real providers accept an access token after refresh-token rotation.

No automatic fix or pull request: this repair changes OAuth credential rejection and authentication recovery behavior. The rule explicitly excludes authentication changes from its simple-fix allowance. No production files were changed, no fix branch was pushed, and no unverified patch was published. No open pull request was linked to this issue in the checked GitHub connection/cross-reference metadata or open-PR search.
