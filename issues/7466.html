#7466 · Rejected local host credentials prevent launcher recovery

BugHighEffort: MediumhostperfIssue #74662026-11-12 · base 030b1b729f28acedc6f86cd65a71cb3678da8124

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

A local full-stack launcher exits with status 1 whenever its saved host credential is rejected, even though it owns a healthy local server with an existing enrollment mechanism. File existence suppresses the launcher's enrollment-key request, and the daemon always selects the saved credential without a rejection fallback. Two consecutive launches with the same invalid credential both fail at session opening; deleting only the auth file restores readiness. This was reproduced with real packaged server and daemon processes in two clean checkouts, without mocked authentication or a mocked database. An external supervisor that restarts these exits repeats the same startup work; macOS launchd behavior, the reported historical restart count, and CPU magnitude were not measured here.

5. Root cause

  1. Launcher enrollment preparation returns the inherited environment as soon as auth.json exists: 
    if (await pathExists(join(args.dataDir, HOST_AUTH_FILE_NAME))) {
  return args.env;
}
    The full-stack caller at launcher.ts:4310 uses this preparation before spawning the daemon. Existence is treated as sufficient evidence that no enrollment material is needed; credential acceptance is not checked.
  2. Daemon credential selection chooses persistedAuth?.hostKey ?? (await enrollDaemonHost(...)).hostKey. A saved key wins even when enrollment material is separately supplied. State is rewritten only when persisted auth was absent.
  3. HTTP retry policy treats non-5xx errors such as 401 as nonretryable. Session-open HTTP handling turns a non-201 response into ServerResponseError. Connection error classification stores a nonretryable, non-protocol error as fatal. Daemon startup has no credential-recovery branch.
  4. Full-stack supervision catches daemon startup failure, sets process.exitCode = 1, and shuts down the full stack: 
    } catch {
  endStep(red("✗"), "Host daemon failed to start");
  ...
  process.exitCode = 1;
  await args.shutdown("SIGTERM");
  return "stopped";
}
    Because the invalid auth file survives, the next supervisor-triggered launch takes precisely the same branches.
  5. Existing loopback enrollment-key route already supports requesting enrollment material for a specified identity, but checks the loopback/security boundary. Recovery must preserve that boundary; it must not turn arbitrary remote rejections into automatic enrollment.

The deeper mismatch is between persistent local state and server acceptance: a present file is not proof that its credential remains valid. The persistent exit is reproduced; a particular service manager's retry cadence and plugin-by-plugin CPU cost are outside this test.

6. Proposed fix — first principles

For a full-stack launcher that owns its local server, make a narrowly scoped recovery credential available for the existing host identity. On an explicit persisted-credential rejection at session startup, cleanly dispose the failed daemon instance, enroll once through the existing authorized path, replace the saved credential, and retry once. Preserve remote-machine behavior and all loopback and machine-management checks. Do not retry unrelated network, lock, protocol, or permission errors as if they were stale credentials. Verify that a second rejection stops rather than recursively re-enrolling.

No production code was changed. A linked open PR already addresses this issue, and changes to authentication/re-enrollment are outside the autopilot's simple-fix allowance even without that duplicate-PR guard.

10. Appendix — complete reproduction test

All necessary test code and exact retained expected/actual observations are inline. Repository policy excludes raw logs and test artifacts from the public reports checkout; originals remain in the local investigation evidence directory rather than being committed. Logs displayed above are deliberately limited to readiness, failure, shutdown, and the session-open status; no credentials or runtime data are included.

import assert from "node:assert/strict";
import { spawn } from "node:child_process";
import { once } from "node:events";
import { mkdir, mkdtemp, readFile, readdir, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join, resolve } from "node:path";
import { setTimeout as delay } from "node:timers/promises";

const [checkout, serverPort, daemonPort] = process.argv.slice(2);
assert(checkout && serverPort && daemonPort, "Provide checkout, server port, daemon port");
for (const port of [serverPort, daemonPort]) {
  assert(Number(port) >= 40000 && Number(port) <= 60000, "Use isolated high ports");
}
const root = await mkdtemp(join(tmpdir(), "bb-7466-runtime-"));
const dataDir = join(root, "data");
const homeDir = join(root, "home");
await mkdir(dataDir);
await mkdir(homeDir);
const hostId = "00000000-0000-4000-8000-000000007466";
await writeFile(join(dataDir, "host-id"), `${hostId}\n`);
const launcher = resolve(checkout, "packages/bb-app/dist/bb-app.js");
const env = {
  PATH: process.env.PATH,
  HOME: homeDir,
  TMPDIR: root,
  LANG: "C.UTF-8",
  NODE_ENV: "production",
  BB_TELEMETRY: "false",
};
const results = [];

async function launch(name) {
  const child = spawn(process.execPath, [
    launcher,
    "--data-dir", dataDir,
    "--server-bind-host", "127.0.0.1",
    "--server-port", serverPort,
    "--host-daemon-port", daemonPort,
    "--no-in-app-updates",
    "--bundled",
    "start",
  ], { cwd: checkout, env, detached: true, stdio: ["ignore", "pipe", "pipe"] });
  const exited = once(child, "exit");
  let output = "";
  let ready = false;
  let timedOut = false;
  let stopped = false;
  function signalGroup(signal) {
    try {
      process.kill(-child.pid, signal);
    } catch (error) {
      if (error.code !== "ESRCH") throw error;
    }
  }
  function collect(chunk) {
    output += chunk.toString("utf8").replace(/\x1b\[[0-9;]*m/g, "");
    if (!stopped && output.includes("bb is ready")) {
      ready = true;
      stopped = true;
      signalGroup("SIGTERM");
    }
  }
  child.stdout.on("data", collect);
  child.stderr.on("data", collect);
  const timeout = setTimeout(() => {
    timedOut = true;
    signalGroup("SIGTERM");
  }, 120_000);
  const hardTimeout = setTimeout(() => signalGroup("SIGKILL"), 140_000);
  let exitCode;
  let exitSignal;
  try {
    [exitCode, exitSignal] = await exited;
  } finally {
    clearTimeout(timeout);
    clearTimeout(hardTimeout);
    signalGroup("SIGKILL");
  }
  const significant = output.split("\n").filter((line) =>
    /Starting server|Server listening|Starting host daemon|Host daemon failed|Host daemon running|bb is ready|Shutting down/.test(line)
  );
  const result = { name, ready, exitCode, exitSignal, timedOut };
  results.push(result);
  console.log(JSON.stringify(result));
  for (const line of significant) console.log(line);
  assert(!timedOut, `${name}: startup timed out`);
  await delay(400);
  return result;
}

try {
  console.log(`Node ${process.version}; ${process.platform}/${process.arch}; ports ${serverPort}/${daemonPort}`);
  const initial = await launch("fresh-enrollment-control");
  assert(initial.ready, "Fresh enrollment must reach readiness before testing rejected credentials");
  await writeFile(join(dataDir, "auth.json"), `${JSON.stringify({
    hostId,
    hostKey: "synthetic-invalid-host-key",
  })}\n`, { mode: 0o600 });
  const rejectedFirst = await launch("persisted-key-attempt-1");
  const rejectedSecond = await launch("persisted-key-attempt-2");
  const names = await readdir(join(dataDir, "logs"));
  let unauthorized = false;
  for (const name of names.filter((name) => name.endsWith(".log"))) {
    const text = await readFile(join(dataDir, "logs", name), "utf8");
    for (const line of text.split("\n")) {
      if (line.includes("Failed to open session: 401 Unauthorized")) {
        unauthorized = true;
        console.log(`${name}: Failed to open session: 401 Unauthorized`);
      }
    }
  }
  await rm(join(dataDir, "auth.json"));
  const recovered = await launch("auth-file-removed-control");
  assert(recovered.ready, "Removing rejected credentials must restore startup");
  console.log(`Observed session-open 401: ${unauthorized}`);
  console.log(`Stale starts ready: ${rejectedFirst.ready}, ${rejectedSecond.ready}`);
  assert(rejectedFirst.ready && rejectedSecond.ready,
    "REGRESSION: local launcher must recover rejected persisted credentials instead of exiting");
} catch (error) {
  console.error(error.message);
  process.exitCode = 1;
} finally {
  await rm(root, { recursive: true, force: true });
  console.log("Temporary runtime data and isolated home removed; child process groups stopped.");
}
