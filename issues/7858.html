#7858 · Sender identity depends on cached thread metadata

Bug Priority: Low Effort: High threads plugins GitHub issue

November 19, 2026 · trusted main: e6f3032d1898b1404f1facf4baaf75da69e28da3

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high for the sender-title defect.

1. TL;DR

A message can identify its sending thread by ID yet show the generic label “Agent” instead of that thread's title. The timeline obtains sender metadata only from already-populated client caches, and hidden threads normally do not enter list caches. A component-level reproduction demonstrates the fallback with an empty list cache and immediate recovery when the sender detail is cached; it also demonstrates that no sender-detail request is attempted. The same reproduction produces the same expected test failure in a second clean checkout. The other two parts of this bundled issue request new plugin decoration and paste presentation behavior; they are design requests, not independently established regressions. This report does not claim an end-to-end plugin delivery reproduction or a browser screenshot.

// @vitest-environment jsdom

import { writeFileSync } from "node:fs";
import { act, cleanup, render, screen, waitFor } from "@testing-library/react";
import { MemoryRouter } from "react-router-dom";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { afterEach, describe, expect, it, vi } from "vitest";
import { makeThreadWithRuntime } from "@bb/test-helpers/domain-fixtures";
import { threadsQueryKey, threadQueryKey } from "@/hooks/queries/query-keys";
import { conversationRow } from "@/test/fixtures/thread-timeline-rows";
import { sdk } from "@/lib/sdk";
import { ThreadTimelineRows } from "./ThreadTimelineRows";

const sender = makeThreadWithRuntime({
  id: "thr_hidden_repro",
  title: "Hidden QA sender",
  visibility: "hidden",
});

afterEach(() => {
  cleanup();
  vi.restoreAllMocks();
});

function renderMessage() {
  const queryClient = new QueryClient({
    defaultOptions: { queries: { retry: false } },
  });
  queryClient.setQueryData(threadsQueryKey(), []);
  const getSender = vi.spyOn(sdk.threads, "get").mockResolvedValue(sender);
  const view = render(
    <MemoryRouter>
      <QueryClientProvider client={queryClient}>
        <ThreadTimelineRows
          threadId="thr_recipient_repro"
          timelineRows={[
            conversationRow({
              id: "message_hidden_repro",
              role: "user",
              initiator: "agent",
              senderThreadId: sender.id,
              text: "Synthetic delivery for cache-miss verification.",
              sourceSeqStart: 1,
              sourceSeqEnd: 1,
              threadId: "thr_recipient_repro",
            }),
          ]}
          threadRuntimeDisplayStatus="idle"
        />
      </QueryClientProvider>
    </MemoryRouter>,
  );
  return { queryClient, getSender, view };
}

describe("issue 7858 sender title cache miss", () => {
  it("shows the fallback until the sender detail enters the cache", async () => {
    const { queryClient, getSender, view } = renderMessage();
    expect(screen.getByText("Agent")).toBeDefined();
    expect(getSender).not.toHaveBeenCalled();
    writeFileSync("issue-7858-cold.html", view.container.innerHTML);
    act(() => {
      queryClient.setQueryData(threadQueryKey(sender.id), sender);
    });
    await waitFor(() => {
      expect(screen.getByText(sender.title!)).toBeDefined();
    });
    writeFileSync("issue-7858-warm.html", view.container.innerHTML);
    expect(getSender).not.toHaveBeenCalled();
  });

  it("resolves an uncached sender title without opening that sender", async () => {
    renderMessage();
    await waitFor(() => {
      expect(screen.getByText(sender.title!)).toBeDefined();
    });
  });
});

5. Root cause

  1. Ordinary thread-list filtering includes options.includeHidden ? undefined : eq(threads.visibility, "visible"). A hidden sender need not be represented in a list cache.
  2. The sender metadata map is built from sidebar entries, cached individual thread queries, and cached thread lists. There is no authoritative timeline-supplied title in this path.
  3. The per-sender hook only subscribes to this map. A miss returns null and does not initiate a detail read: 
    threadId === null ? null : (store.getSnapshot().get(threadId) ?? null)
  4. The row passes a null title, and the message content chooses the generic source name: 
    sourceName: senderIsPluginSideChat
  ? "side chat"
  : (senderThreadTitle ?? "Agent")

The underlying coupling is cache completeness: presentation assumes unrelated navigation/detail queries have already loaded sender identity. The hidden visibility flag is not itself an authorization finding in this report, and the component reproduction would also affect any otherwise uncached sender. Seeding detail cache without changing the timeline row corrects the title, isolating the failure to metadata availability rather than message delivery.

Other requested surfaces

  • Current public chat props expose no sender-decoration prop. A generalized sender extension would be a new public API, not a small cache fix.
  • The fixed paste threshold and the existing file conversion implement attachment behavior. The public local-file input schema contains path, identity, name, size, and MIME metadata, but no paste-origin discriminator.

6. Proposed fix and autopilot safety check

For the reproduced defect alone, resolve missing sender identity using the existing per-thread read path, deduplicate requests by sender ID, and retain a safe fallback for unavailable/deleted senders. Check error/retry behavior and live renames before shipping; do not make the sidebar list hidden threads merely to fill this cache. The existing thread detail query is a candidate building block, not an implemented or validated patch.

No fix branch or pull request is opened. The complete bundled request includes a new public plugin rendering extension and a persisted prompt-input provenance/schema change, plus product decisions about inline display and settings. Those violate this rule's simple-fix restrictions. A narrow partial cache patch should not silently close the remaining feature requests. An open-PR search for the target issue number and issue timeline linkage found no linked open pull request at investigation time.
