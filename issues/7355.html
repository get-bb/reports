#7355 · CPU profile clock alignment

Bug Priority: Medium Effort: Medium host perf · 2026-11-10 · GitHub issue

Verdict: REPRODUCED (controlled clock-origin mismatch) · Root-cause confidence: high

Trusted base: 7c1353d80729983b86ea1555d18b42407f320406. This verifies the attribution failure through the real profiler worker, not the reporter's macOS environment or its claimed native offset.

1. TL;DR

The diagnostic collector finds a genuine event-loop stall and saves a real CPU profile, but its attribution log can contain no sampled stacks or owners. The collector timestamps stalls using Node's high-resolution clock, while the profiler supplies a separate timestamp domain. The base worker never translates between them. Advancing or retarding only the high-resolution clock's origin by two days makes real sampled work disappear from attribution; leaving the clocks unchanged succeeds. Both results repeat in a second clean trusted checkout. No native macOS run was available, so the platform/version-specific measurement remains unverified.

5. Root cause

The gap observer records milliseconds using Number(process.hrtime.bigint()) / 1e6. The stall collector retains those window timestamps and separately records a wall-clock offset for log presentation.

The sample summarizer initializes its cursor from profile.startTime / 1_000, accumulates sample deltas, and clips directly against the original stall window:

Math.min(end, window.endedAt, profile.endTime / 1_000) -
  Math.max(at, end - MAX_SAMPLE_MS, window.startedAt)

Changing units does not reconcile different origins. With a two-day offset, every overlap is zero; the function consequently records no sample duration, stack, or owner. The wall-clock offset is used only to render log dates and cannot fix this overlap calculation. Profile startup and capture completion pass the raw V8 timeline to the summarizer without measuring a conversion.

The test does not mock profile samples or log output. It changes only the origin of the clock the production collector reads, preserving its rate and durations. This is a controlled demonstration of the clock-domain assumption, not evidence that native Linux clocks have a multi-day discrepancy.

6. Proposed fix and local validation

Read the main thread's high-resolution clock immediately before and after the real console-profiler start and end commands, inside the same inspector evaluation. Each boundary constrains the possible clock offset to an interval. Use an offset from the intersection of both intervals to align a temporary attribution-only profile; keep the saved CPU profile's original V8 timestamps. If the intervals do not overlap, or their shared uncertainty exceeds the existing 10 ms sampling interval, retain the stall as unattributed rather than assigning a misleading owner. Profile rotation retains the correct start reading for each capture.

The local candidate changes only the existing profiling worker and its existing diagnostics regression test: two files, 233 changed text lines (161 additions + 72 deletions), no dependencies, lockfiles, committed generated output, public protocol, schema, persisted-data format, permissions, or release changes.

7. Verification

The same agent repeated the investigation in a second newly created detached worktree at the recorded base, with a separate frozen dependency install and fresh test-generated temporary directories. Production files remained byte-identical to trusted main; only the investigator-authored regression test was applied. No workflow or additional agent was used.

The initial three-case test produced 2 failed | 1 passed | 5 skipped (8) in both clean checkouts. The final four-case regression, rerun against unchanged production in the second checkout, produced 2 failed | 2 passed | 5 skipped (9). The failures are the stable positive and negative origin shifts; the zero-offset control succeeds. With the worker fix, all four cases and the relevant existing suites pass.

Correction during validation: V8 can inline the busy-loop function across repeated parameter cases. The final test retains the original named-frame assertion for the unshifted control and checks the stable plugin-owner attribution boundary for the additional offsets. A sampled, correctly owned stack that has an inlined function is not a clock-alignment failure. No native macOS result is claimed.
