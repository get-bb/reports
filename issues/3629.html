1. TL;DR

The client assumes each registered preference exists in every list response. With a key missing, synchronization throws while reading its revision. Two related write paths also mishandle absent entries. Three newly authored regression tests fail on main and pass with three local guards. This verifies the incomplete-response failure, not a production server condition that generates such responses.

5. Root cause

Reconciliation dereferences the indexed entry without testing its presence. Cache merge and write preparation make the same assumption. React effects invoke reconciliation, so its exception escapes the synchronization call.

The current server enumerates all known preference keys. An absent database row normally yields a default entry, not an omitted key. Version skew or malformed responses remain possible explanations, but neither was demonstrated here.

6. Proposed fix

Skip absent entries during reconciliation and writing, retaining the local atom rather than inventing a server revision. Let an acknowledged write fill an absent cached entry, while preserving the existing protection against older revisions. A local implementation passes all 22 focused tests. An edit without a known server entry stays local; automatic later upload is not introduced.
