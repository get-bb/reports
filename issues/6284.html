#6284 · Native Claude installs are missed outside PATH

BugPriority: MediumEffort: Mediumproviders · provider-claude-code · confirmed-repro

Issue · 2026-10-25 · trusted base 3a2c49a267cd2a62a96ebff880068a7c37074251

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

BB can offer Claude installation again even when its native executable is already present. On POSIX, the maintenance path only searches PATH, while session startup already knows the native installation directories. If the native directory is absent from the host environment, the status reports the provider missing and offers installation again. Re-running installation cannot repair this discovery mismatch. Two clean checkouts reproduce the missing-installation result without downloading an installer or accessing an account.

describe.skipIf(process.platform === "win32")(
  "Claude Code executable discovery on an unprivileged POSIX host",
  () => {
    let homeDir: string;
    let pathDir: string;

    beforeEach(async () => {
      homeDir = await mkdtemp(path.join(os.tmpdir(), "claude-discovery-"));
      pathDir = path.join(homeDir, "path");
      await mkdir(pathDir);
      await symlink("/usr/bin/which", path.join(pathDir, "which"));

      vi.stubEnv("PATH", pathDir);
      vi.stubEnv("BB_CLAUDE_CODE_EXECUTABLE", "");
      vi.spyOn(process, "getuid").mockReturnValue(1000);
    });

    afterEach(async () => {
      vi.unstubAllEnvs();
      vi.restoreAllMocks();
      await rm(homeDir, { recursive: true, force: true });
    });

    it.each([
      { nativeInstalled: true, onPath: false },
      { nativeInstalled: true, onPath: true },
      { nativeInstalled: false, onPath: false },
    ])(
      "reports nativeInstalled=$nativeInstalled, onPath=$onPath without reinstalling an existing CLI",
      async ({ nativeInstalled, onPath }) => {
        const nativePath = path.join(homeDir, ".local", "bin", "claude");
        const pathExecutable = path.join(pathDir, "claude");
        const executableContents = `#!${process.execPath}\nprocess.stdout.write("2.1.310 (Claude Code)\\n");\n`;
        if (nativeInstalled) {
          await mkdir(path.dirname(nativePath), { recursive: true });
          await writeFile(nativePath, executableContents, { mode: 0o755 });
        }
        if (onPath) {
          await writeFile(pathExecutable, executableContents, { mode: 0o755 });
        }

        const status = await getClaudeProviderInstallationStatus(false);

        expect(status).toMatchObject({
          installed: nativeInstalled || onPath,
          executablePath: onPath

            : nativeInstalled
              ? nativePath
              : null,
          currentVersion: nativeInstalled || onPath ? "2.1.310" : null,
        });
        expect(status.installAction?.kind ?? null).toBe(
          nativeInstalled || onPath ? null : "install",
        );

5. Root cause

claudeExecutable(), lines 57–72 immediately returns the bare command on non-Windows systems:

if (process.platform !== "win32" ||
    (await resolveExecutablePath("claude")) !== null) {
  return "claude";
}

resolveExecutablePath() resolves a relative command through which on POSIX. getClaudeProviderInstallationStatus() also runs the relative command for --version, so both probes fail if the native location is not in PATH. Its installed flag is the OR of those two results, and the missing state produces an install action.

installationVerificationPassed() requires status.installed for install verification. The post-install verification path therefore changes a successful installer event into a failed verification event. Meanwhile the existing session resolver already checks HOME/.local/bin/claude, HOME/.claude/local/claude, and known Homebrew directories for non-root users. Two different executable discovery paths are the underlying inconsistency.

6. Proposed fix

Keep explicit executable overrides and PATH precedence, then reuse the existing session resolver for the missing-PATH POSIX case. Retain its executable-file validation and existing root guard. Preserve the Windows-specific fallback unchanged. Regression coverage should exercise native off-PATH discovery, PATH precedence, and the genuinely missing installation. No SDK, wire, stored-data, installation-script, or release contract needs to change.
