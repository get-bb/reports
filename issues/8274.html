#8274 · Retryable Codex errors leave silent turns without a terminal boundary

BugHighEffort: Mediumproviders · provider-codexIssue #8274November 27, 2026

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

Trusted base: b0ddaad731565d7e4de68d824120d802fc78f7d5. Scope of verdict: the bridge liveness failure, not the upstream network outage.

1. TL;DR

A Codex turn can remain open after its child process reports retryable failures and then stops sending events. The bridge forwards those failures, but neither synthesizes a terminal boundary nor arms a reconnect deadline. A new boundary-level regression test observed three retry errors and zero terminal events after three simulated hours; a control with a native completion emitted exactly one terminal event. The same agent repeated both cases in a second clean checkout at the same trusted main commit with the same result. No real accounts, hosted provider requests, live user threads, or user databases were accessed.

5. Root cause

The translator's error case returns only a provider.error delta, preserving willRetry. It does not emit turn.boundary. Native completion translation is what normally produces that terminal delta.

The bridge notification handler and its terminal-error handling forward these deltas and reserve recovery hints for nonretryable errors. No reconnect-silence deadline is scheduled for retryable errors in this path.

Open-turn bookkeeping adds a provider turn ID on turn.open and deletes it on turn.boundary. Without that boundary, the active turn remains unsettled. The existing zero-work timer explicitly returns when an open turn exists, so it cannot rescue this already-started turn.

The deeper fault is trusting a retryable error to imply future child activity without bounding that expectation. This explains the observed bridge liveness failure for a still-running but silent child; it does not explain why any particular Codex or pool request stopped retrying.

6. Proposed fix

Add bounded reconnect inactivity handling in the existing Codex session lifecycle. Arm it only after a retryable error on a live turn, reset or cancel it on meaningful progress and normal termination, and cancel it on session replacement or stop. At expiry, emit a visible terminal failure plus the existing failed-boundary shape, and retire the stuck child so later work does not inherit it. Reuse existing lifecycle primitives and delta contracts; do not invent a wire field. Cover timer cleanup, recovered progress, a late child completion, and a subsequent fresh turn. The timeout value is a product policy to validate separately.
