#8212 · Shared close-control geometry and title-bar sizing

BugPriority: LowEffort: Lowuimobile · GitHub issue · November 26, 2026

Trusted origin/main: b0ddaad731565d7e4de68d824120d802fc78f7d5

PARTIALLY REPRODUCED · Root-cause confidence: high

1. TL;DR

The macOS title-bar rule stretches a tab’s close-button hover background into a 16×28px vertical bar that touches the pill’s top and bottom edges. This is a confirmed browser-layout failure, reproduced from two clean checkouts without changing production code. The broad title-bar descendant selector overrides the close button’s normal square height. The compact touch configuration also has a 36×36px close target flush with the pill, but native pure-touch emulation disables hover paint, so the claimed touch hover clipping was not reproduced. Ordinary desktop and palette controls are square and inset, with only 1px around the 14px icon; that small padding is verified, not itself evidence of clipping.

geometry.js (inline evidence)

const page = await browser.getPage("main");

async function measureViewport(viewport) {
  await page.setViewport(viewport);
  const cases = [];
  for (const name of ["desktop", "macos", "mobile", "palette"]) {
    const control = await page.$(`[data-case=${name}] [data-tab-pill-close]`);
    const bounds = await control.boundingBox();
    await page.mouse.move(bounds.x + bounds.width / 2, bounds.y + bounds.height / 2);
    await page.evaluate(() => new Promise(resolve => requestAnimationFrame(() => requestAnimationFrame(resolve))));
    cases.push(await page.evaluate(name => {
      const section = document.querySelector(`[data-case=${name}]`);
      const pill = section.querySelector("[data-tab-pill]");
      const close = section.querySelector("[data-tab-pill-close]");
      const icon = close.querySelector("[data-icon-root]");
      const rect = element => {
        const bounds = element.getBoundingClientRect();
        return { left: bounds.left, top: bounds.top, width: bounds.width, height: bounds.height };
      };
      const pillRect = rect(pill);
      const closeRect = rect(close);
      return {
        name,
        pill: pillRect,
        close: closeRect,
        icon: rect(icon),
        inset: {
          left: closeRect.left - pillRect.left,
          top: closeRect.top - pillRect.top,
          bottom: pillRect.top + pillRect.height - closeRect.top - closeRect.height,
        },
        radius: { pill: getComputedStyle(pill).borderRadius, close: getComputedStyle(close).borderRadius },
        background: getComputedStyle(close).backgroundColor,
        hovered: close.matches(":hover"),
      };
    }, name));
  }
  return {
    viewport,
    media: await page.evaluate(() => ({
      hover: matchMedia("(hover:hover)").matches,
      coarse: matchMedia("(pointer:coarse)").matches,
      fine: matchMedia("(pointer:fine)").matches,
    })),
    cases,
  };
}

5. Root cause

MACOS_TITLE_BAR_CONTROL_SIZE_CLASS applies height to every descendant button. Its button selector is more specific than the close control’s ordinary size utility and assigns the 28px title-bar control height, confirmed by TITLE_BAR_CONTROL_SIZE_PX. Width remains 16px. The parent pill is also 28px high, so vertically centering that 28px-high button leaves exactly zero inset.

[&_button]:h-(--bb-title-bar-control-size) [&_[data-tab-pill]]:h-(--bb-title-bar-control-size)

The shared affordance classes put both square sizing and hover background on the button itself. TabPillCloseButton later enlarges that same element for coarse pointers; compact mode moves it to the pill’s left edge. There is no independently sized visual surface inside the hit target. That coupling explains the confirmed macOS paint shape and the coarse target geometry, but coarse-pointer geometry alone does not prove hover paint on pure touch.

The actual palette chip delegates to the same component via PaletteModeChip. The source callers use noncompact tabs in SecondaryPanelTabStrip and compact enlarged controls in MobilePanelTabPager.

6. Proposed fix

Scope title-bar button sizing so nested close controls retain their own square geometry. Decouple a centered, inset hover/focus visual surface from the coarse-pointer hit target rather than shrinking the touch target. Add a browser geometry assertion covering native hover on macOS, ordinary desktop, and coarse-pointer configurations. Pure-touch and hybrid hover-capable coarse inputs need separate expectations; do not infer a painted surface from hit-target bounds alone.
