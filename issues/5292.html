#5292 · Removed machine PATH masks shell refresh

Bug · Priority: Medium · Effort: Medium · host, providers · October 9, 2026

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high for the deterministic refresh-masking defect.

TL;DR

A failed shell probe can leave child processes unable to find an installed executable. The probe is not strictly one-shot: main already retries on later requests after a ten-second cache TTL. However, after a machine PATH override has been applied and removed, the environment overlay repeatedly reinstates the original startup PATH, even when a later shell probe succeeds. That persistent failure is reproduced twice with real child processes and unmodified production code. Native macOS launchd timing and real provider behavior were not reproduced in this Linux environment.

Expected: after a successful refresh and removal of a managed PATH, the child receives the refreshed shell PATH and prints ready with status 0.

Actual: the fresh shell alone successfully launches the child; applying the machine environment overlay changes its PATH back to the startup capture, yielding spawnSync qa-provider ENOENT. Full reproduction test
import { spawnSync } from "node:child_process";
import fs from "node:fs/promises";
import os from "node:os";
import path from "node:path";
import { afterEach, expect, it } from "vitest";
import { MachineEnvironment } from "./machine-environment.js";
import {
  createUserShellPathResolver,
  prepareRuntimeShellEnv,
} from "./runtime-shell-env.js";

const directories: string[] = [];
const inheritedPath = "/usr/bin:/bin";

afterEach(async () => {
  await Promise.all(
    directories
      .splice(0)
      .map((directory) => fs.rm(directory, { recursive: true, force: true })),
  );
});

async function fixture(failAll: boolean) {
  const directory = await fs.mkdtemp(path.join(os.tmpdir(), "bb-path-repro-"));
  directories.push(directory);
  const tools = path.join(directory, "tools");
  const shell = path.join(directory, "controlled-shell");
  const slow = path.join(directory, "slow");
  await fs.mkdir(tools);
  await fs.writeFile(slow, "slow");
  await fs.writeFile(
    path.join(tools, "qa-provider"),
    "#!/bin/sh\nprintf 'ready\\n'\n",
    { mode: 0o755 },
  );
  await fs.writeFile(
    shell,
    [
      "#!/bin/sh",
      'if [ -f "$QA_SLOW" ] && { [ "$1" = "-ilc" ] || [ "$QA_FAIL_ALL" = "yes" ]; }; then',
      "  exec /bin/sleep 3",
      "fi",
      'if [ "$1" = "-ilc" ]; then',
      '  PATH="$QA_TOOLS:/usr/bin:/bin"',
      "  export PATH",
      "fi",
      'exec /bin/sh -c "$2"',
      "",
    ].join("\n"),
    { mode: 0o755 },
  );
  const env = {
    PATH: inheritedPath,
    SHELL: shell,
    QA_TOOLS: tools,
    QA_SLOW: slow,
    QA_FAIL_ALL: failAll ? "yes" : "no",
  };
  const resolvePath = createUserShellPathResolver({
    env,
    platform: "linux",
    timeoutMs: 100,
  });
  const runtimeEnv = (resolvedPath: string | null) =>
    prepareRuntimeShellEnv({
      bbExecutableDirectory: path.join(directory, "bb-bin"),
      inheritedPath: resolvedPath ?? inheritedPath,
      serverUrl: "http://127.0.0.1:49999",
    });
  const provider = (shellEnv: Record<string, string>) =>
    spawnSync("qa-provider", [], {
      env: shellEnv,
      encoding: "utf8",
    });
  return { env, slow, tools, resolvePath, runtimeEnv, provider };
}

it("cannot discover a child executable when both startup probes time out", async () => {
  const setup = await fixture(true);
  const resolved = await setup.resolvePath();
  expect(resolved).toBeNull();
  const result = setup.provider(setup.runtimeEnv(resolved));
  expect(result.error).toMatchObject({ code: "ENOENT" });
});

it("accepts a successful plain-login probe that omits interactive tools", async () => {
  const setup = await fixture(false);
  const resolved = await setup.resolvePath();
  expect(resolved).toBe(inheritedPath);
  expect(setup.provider(setup.runtimeEnv(resolved)).error).toMatchObject({
    code: "ENOENT",
  });
});

it("recovers on a later probe without restarting the resolver", async () => {
  const setup = await fixture(true);
  expect(await setup.resolvePath()).toBeNull();
  await fs.rm(setup.slow);
  const resolved = await setup.resolvePath();
  expect(resolved).toBe(`${setup.tools}:${inheritedPath}`);
  const result = setup.provider(setup.runtimeEnv(resolved));
  expect(result.status).toBe(0);
  expect(result.stdout).toBe("ready\n");
});

it("discovers tools from a refreshed shell after a managed PATH is removed", async () => {
  const setup = await fixture(true);
  const originalShell = setup.runtimeEnv(await setup.resolvePath());
  const machine = new MachineEnvironment({ ...setup.env }, originalShell);
  const workingPath = `${setup.tools}:${inheritedPath}`;
  machine.replace([
    {
      name: "PATH",
      value: workingPath,
      source: { core: "machine-environment" },
      reason: "qa",
    },
  ]);
  expect(setup.provider(machine.shellEnvironment(originalShell)).status).toBe(
    0,
  );
  machine.replace([]);
  expect(
    setup.provider(machine.shellEnvironment(originalShell)).error,
  ).toMatchObject({ code: "ENOENT" });
  await fs.rm(setup.slow);
  const refreshedShell = setup.runtimeEnv(await setup.resolvePath());
  expect(setup.provider(refreshedShell).status).toBe(0);
  const result = setup.provider(machine.shellEnvironment(refreshedShell));
  expect(
    result.error,
    "the refreshed PATH must reach the provider child",
  ).toBeUndefined();
  expect(result.status).toBe(0);
  expect(result.stdout).toBe("ready\n");
});

Root cause

The default timeout is 3,000 ms. The argument selection tries interactive login mode before plain login mode. The resolver returns the first parsed successful PATH, returns null when no probe succeeds, and retains a prior success when the next interactive probe fails. Startup environment assembly substitutes the process PATH when probing returns null.

The persistent defect is the MachineEnvironment snapshot combined with its overlay algorithm:

this.originalShell = { ...shell };
...
this.managed.add(entry.name);
...
const result = { ...shell };
for (const name of this.managed) {
  const value = this.values[name] ?? this.originalShell[name];
  if (value === undefined) delete result[name];
  else result[name] = value;
}

The managed-name set remembers PATH after settings remove it. With no active value, every subsequent overlay overwrites the current supplied PATH with originalShell.PATH. A later successful probe cannot escape that fallback. In app construction, originalShell comes from startup runtimeShellEnv. RuntimeManager applies the overlay when resolving shell environment values, while refresh replaces its base shell environment separately. This explains why a good refreshed base can coexist with a bad effective provider PATH.

Important correction: the app TTL is ten seconds, and the refresh cache integration permits a later request to re-probe. The cache refresh algorithm does not permanently retain a failed startup resolution. It is request-triggered rather than an unconditional periodic background timer.

Fix proposal and safety gate

Distinguish a degraded startup fallback from a healthy shell capture; specify the retry budget and which shell environment removing a managed override should restore. A healthy refreshed base must not be masked by an obsolete capture if the chosen contract is to track current login-shell state. Then add a native macOS check covering real interactive startup configuration and launchd boot load.

No pull request is opened: repairing the complete startup/fallback behavior and changing removed-variable restoration semantics needs a maintainer policy decision, failing the no-product-decision simple-fix gate. Native macOS behavior is not yet verified. GitHub metadata and open-PR search found no open pull request linked to #5292 at investigation time. No production fix, branch, or push was attempted in the target repository.
