#6376 · Preserve inline-code provenance when copying file references

BugPriority: MediumEffort: Lowui GitHub issue2026-10-27 · base b6743a36bd9eae1408c35cfc2c7ab1d2419dc79d

REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

Copying a rendered message changes automatically linked inline-code file references into Markdown links. Relative file paths also gain Markdown escapes and absolute file URLs, making pasted text longer than the original. The renderer replaces the code element with an anchor and discards its inline-code provenance; the clipboard serializer then treats it as an authored link. Absolute paths benefit from an existing bare-URL exception but still lose their code fences. Four regression cases fail on unchanged trusted main in two clean checkouts, while all 131 selected existing and regression tests pass after a three-line production fix.

5. Root cause

  1. MarkdownCode replaces local inline code with MarkdownAnchor, passing the path as plain text and preserving no source-kind metadata: 
    const localFileHref = resolveInlineCodeFileHref({
  codeText,
  localFileRouting: linkRouting?.localFile,
});
if (localFileHref !== null) {
  return (
    <MarkdownAnchor
      href={localFileHref}
      linkRouting={linkRouting}
      rewriteLocalhostLinks={rewriteLocalhostLinks}
    >
      {codeText}
    </MarkdownAnchor>
  );
}
  2. nodeMarkdown treats CODE and A differently. Ordinary code spans use the existing code-fence formatter, while links recursively escape text and emit [label](href). The generated file reference reaches the link branch because its CODE element was removed.
  3. isBareUrl only recognizes matching visible targets. A relative label does not equal its resolved absolute file path, so it misses this exception. Matching absolute POSIX and Windows paths pass, but they are copied without their original backticks.
  4. The shared document copy handler writes the serializer's result into text/plain and text/html. This directly reproduces ordinary timeline copying; it is not merely a test of a private helper.

6. Proposed fix and verified candidate

Mark only anchors synthesized from inline code with a private data-clipboard-inline-code attribute. Before the bare-URL and authored-link branches, serialize those marked anchors with the existing codeSpan formatter. The serializer already strips non-whitelisted attributes from rich clipboard HTML, so HTML keeps the file href without leaking the marker. Do not infer provenance from the URL scheme: authored file links must remain links.

The candidate changes three files, with 44 added text lines, zero deleted lines: three production lines and 41 regression-test lines. There is no dependency, public API/protocol, schema, migration, packaging, or stored-data change.
