#5852 · Stored credential selection and legacy fallback

Bug Priority: Low Effort: Low providers provider-acp
Issue #5852 · 2026-10-20 · trusted base e0f6fda5a02332bd4eb44183542a57f34f3263d7

PARTIALLY REPRODUCED · Root-cause confidence: medium

1. TL;DR

The usage collector ignores a SQLite credential whose active flag is NULL, even when it is the only stored key. With an older auth file present, the collector sends the file credential; without that file, it reports unauthenticated and sends no request. Both outcomes repeat in two clean trusted checkouts using a real temporary SQLite database and an intercepted network boundary. The existing suite passes because it explicitly treats NULL as inactive. This verifies the collector mechanism, not the full OpenCode upgrade: no external installer, binary, upstream source link, or issue-provided script was used, so the provider's actual migration and version-specific selection rules remain unverified.

import fs from "node:fs/promises";
import os from "node:os";
import path from "node:path";
import { DatabaseSync } from "node:sqlite";
import { afterEach, beforeEach, expect, it, vi } from "vitest";
import { readOpenCodeGoUsage } from "./opencode-usage.js";

let directory: string;
const fetchUsage = vi.fn<typeof fetch>();
const databaseKey = "fixture-database-only";
const obsoleteKey = "fixture-obsolete-file";

beforeEach(async () => {
  directory = await fs.mkdtemp(path.join(os.tmpdir(), "bb-5852-"));
  await fs.mkdir(path.join(directory, "opencode"));
  fetchUsage.mockReset();
  fetchUsage.mockImplementation(
    async () => new Response("{}", { status: 500 }),
  );
  vi.stubGlobal("fetch", fetchUsage);
});

afterEach(async () => {
  vi.unstubAllGlobals();
  await fs.rm(directory, { recursive: true, force: true });
});

async function seedCredential(active: number | null, legacyFile: boolean) {
  const database = new DatabaseSync(
    path.join(directory, "opencode", "opencode.db"),
  );
  try {
    database.exec(
      "CREATE TABLE credential (id TEXT PRIMARY KEY, integration_id TEXT, label TEXT NOT NULL, value TEXT NOT NULL, connector_id TEXT, method_id TEXT, active INTEGER, time_created INTEGER NOT NULL, time_updated INTEGER NOT NULL)",
    );
    database
      .prepare(
        "INSERT INTO credential (id, integration_id, label, value, active, time_created, time_updated) VALUES (?, ?, ?, ?, ?, ?, ?)",
      )
      .run(
        "fixture-row",
        "opencode",
        "fixture",
        JSON.stringify({ type: "key", key: databaseKey }),
        active,
        10,
        10,
      );
  } finally {
    database.close();
  }
  if (legacyFile) {
    await fs.writeFile(
      path.join(directory, "opencode", "auth.json"),
      JSON.stringify({ "opencode-go": { type: "api", key: obsoleteKey } }),
    );
  }
}

it("control: an explicitly active database credential overrides the legacy file", async () => {
  await seedCredential(1, true);
  const result = await readOpenCodeGoUsage({
    HOME: directory,
    XDG_DATA_HOME: directory,
  });
  const headers = new Headers(fetchUsage.mock.calls[0]?.[1]?.headers);
  expect(headers.get("authorization") === "Bearer " + databaseKey).toBe(true);
  expect(result.usage.status).toBe("error");
});

it.each([true, false])(
  "regression: a selectable unflagged database credential remains usable (legacy file: %s)",
  async (legacyFile) => {
    await seedCredential(null, legacyFile);
    const result = await readOpenCodeGoUsage({
      HOME: directory,
      XDG_DATA_HOME: directory,
    });
    const headers = new Headers(fetchUsage.mock.calls[0]?.[1]?.headers);
    const selectedDatabase =
      headers.get("authorization") === "Bearer " + databaseKey;
    const selectedLegacy =
      headers.get("authorization") === "Bearer " + obsoleteKey;

      JSON.stringify({
        legacyFile,
        selectedDatabase,
        selectedLegacy,
        requests: fetchUsage.mock.calls.length,
        status: result.usage.status,
      }),
    );
    expect(selectedDatabase).toBe(true);
  },
);

5. Root cause

readStoredCredential, line 105 requires active = 1. In SQLite, a NULL active value does not satisfy this predicate, so no key is returned. readOpenCodeGoUsage, line 197 then falls back to legacy credentials without distinguishing database generations. If no legacy key exists, lines 202–203 returns unauthenticated. This completely explains the observed fixture outcomes.

SELECT value FROM credential
WHERE integration_id = ? AND active = 1
ORDER BY time_created DESC, id DESC LIMIT 1

apiKey ??= await readLegacyApiKey(env);

Line 185 also resolves a Console account before querying stored credentials. The entry point is getAcpProviderUsage, line 384. No public API or server path needs to be invented to reach this reader.

The stronger underlying issue is the collector's storage-authority assumption. Existing test, lines 285 onward explicitly groups NULL with inactive rows, so the baseline suite enforces the behavior being reported. Git history attributes the stored-credential implementation to a312ed2d6 (#4696). Whether that assumption is wrong for a particular provider version requires upstream evidence outside this run.

6. Proposed fix and safety gate

First establish a reliable, read-only provider-version discriminator from trusted provider evidence, including fresh and upgraded databases. Then match that version's selected credential and authoritative store while preserving older-version behavior. Cover imported NULL rows, empty current stores with leftover files, Console leftovers, explicit active rows, and ordering ties. Do not broaden the predicate for every database merely because this fixture fails.

No automatic production fix or PR: changing which credential is selected changes authentication behavior, which this autopilot rule explicitly excludes from simple fixes. Provider-version semantics are also unverified. Only the authored reproduction file is added locally; no production code, schema, migration, dependency, or stored user data changes.
