#7597 · String user echoes create diagnostic events

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A normal user-prompt echo is converted into a diagnostic event even though it contains no unsupported behavior. The Claude bridge sends user content as a string, but its visibility classifier only discovers content types in block arrays. The translator correctly consumes a text echo without creating timeline content; its outer fallback then mistakes that empty result for an unknown event. A focused test through the real translator and event assembler produces one provider/unhandled event per supplied string echo. The same agent repeated this result in a second clean checkout; no desktop session, user data, or live provider account was used.

5. Root cause

  1. SDK session options explicitly enable user-message replay. pushInput supplies message: { role: "user", content: text }.
  2. getMessageContentTypes returns an empty list for any non-array content: 
    const content = messagePayload?.["content"];
if (!Array.isArray(content)) {
  return [];
}
  3. User parsing passes that list to the descriptor. User classification treats only sdk/user:text as noise and sdk/user:tool_result as normalized. An empty list becomes bare sdk/user, coverage unknown.
  4. translateUserMessage consumes prompt/checkpoint bookkeeping and normally returns no deltas for a text echo. The outer SDK-envelope fallback then calls unhandledDeltas.
  5. unhandledDeltas emits an unhandled delta for coverage unknown. The real assembler turns it into the event observed by the test. The defect is not in replay enabling, prompt delivery, or diagnostics settings.

6. Proposed fix and simple-fix assessment

Recognize a string at the content boundary as text, including an empty string. Preserve array handling and the existing unknown fallback for unsupported shapes. The tested production candidate is:

if (typeof content === "string") {
  return ["text"];
}

With this candidate, the focused regression passes: 3 passed | 55 skipped (58). The local diff is two files, 51 additions and 25 deletions: 76 changed text lines. It contains no binary, dependency, lockfile, protocol, schema, stored-data, or security change; git diff --check passes.

No pull request was opened or branch pushed. The full existing plugin suite fails because the candidate reduces the pinned background-agents transcript's unhandled count from 6 to 0. The existing test generates expected.json when its update flag is enabled, then compares exact projections. Completing the fix therefore requires generated transcript-expectation changes, which this autopilot's simple-fix rules expressly exclude. The generated file was not modified. A follow-up change should regenerate and review all affected transcript projections before opening a PR.
