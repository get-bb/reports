#5847 · Shell intent parsing promotes a trailing output filter

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The timeline can label a general shell command as a search when a later shell segment invokes grep. The command parser skips unrecognized initial executables, then promotes the first recognizable search segment to represent the entire command. A synthetic normalized command event reproduces the incorrect title in both the timeline title builder and the CLI text formatter, without executing any shell payload. Three non-search-first cases fail the expected command-title check in each of two clean trusted checkouts; a search-first control passes. This is a display classification defect, not evidence that the command itself changed or that any deletion occurred during verification.

5. Root cause

classifyShellSegment returns kind: "none" for general executables, while grep and rg produce search intents. In parseShellCommandIntents, only a detected write clears the result and stops iteration. A none segment is silently skipped; a subsequent search becomes the first retained intent:

if (classification.kind === "write") {
  intents = [];
  return false;
}
if (classification.kind === "intent" && intents.length === 0) {
  intents.push(classification.intent);
}
return true;

This is not a malformed grep pattern or provider execution problem. Command lifecycle projection computes these intents from the full normalized shell string. The title builder then prefers a single exploration-intent title over the full command title. Thus an output filter can replace the visible identity of a general command. The underlying command detail remains available; the headline is misleading.

6. Proposed fix

Conservatively refuse to derive an exploratory summary when the first nonempty shell segment has no recognized exploratory intent. Keep the existing scan of later segments for write disqualification after a recognized first segment. This restores the existing generic command label and complete command text for the demonstrated cases, while preserving genuine search-first pipelines. Add a regression table at the real event-to-timeline-title boundary and correct the old parser fixture that currently expects a search title after unrelated initial commands. No protocol, storage, dependency, or new expansion setting is needed.
