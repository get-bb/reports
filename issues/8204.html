#8204 · Git index-copy disposal leaves cleanup promises unobserved

Bug Priority: High Effort: Low plugins confirmed-repro

GitHub issue · November 26, 2026 · trusted main 9caab570e061530a903dbfb98f65f3db11b02952

Verdict: REPRODUCED · Root-cause confidence: high.

1. TL;DR

The Git plugin reads diffs using a temporary copy of the Git index. Disposing the reader returns before that copy is removed, and a failed removal produces an unhandled promise rejection. A new focused test against unchanged main reproduced both failures twice, each time in a separate checkout. This explains how teardown can overlap deletion and why a filesystem permission failure can fail the test process. The native Windows contention event itself was not reproduced on this Linux host.

The table tests successful and denied removal. The spy delays only the actual copy's filesystem deletion; Git setup, copying, and diff reads remain real. The delay exposes completion ordering without requiring Windows contention. It is restored in finally, and the test leaves cleanup to the real filesystem afterward.

import fs from "node:fs/promises";
import path from "node:path";
import { setTimeout as delay } from "node:timers/promises";
import { expect, it, vi } from "vitest";
import { initRepo, makeTempDir } from "@bb/test-helpers";
import { WorkspaceReads } from "./workspace-reads.js";

it.each([false, true])(
  "settles copied-index removal before disposal returns (permission failure: %s)",
  async (denyRemoval) => {
    const repository = await initRepo(await makeTempDir("disposal-repo-"));
    const scratch = await makeTempDir("disposal-scratch-");
    await fs.writeFile(path.join(repository, "README.md"), "changed tracked content\n");
    const reader = new WorkspaceReads(repository, scratch);
    const result = await reader.diffFiles({
      freshness: { work: "edited", refs: "initial" },
      target: { type: "uncommitted" },
      maxFiles: 10,
      ignoreWhitespace: false,
    });
    expect(result.files.map((file) => file.path)).toContain("README.md");
    const copies = await fs.readdir(scratch);
    expect(copies).toHaveLength(1);
    const copyDirectory = path.join(scratch, copies[0]!);
    const remove = fs.rm.bind(fs);
    let removalSettled = false;
    const interception = vi.spyOn(fs, "rm").mockImplementation(async (target, options) => {
      if (target !== copyDirectory) return remove(target, options);
      try {
        await delay(25);
        if (denyRemoval) {
          throw Object.assign(new Error("Simulated cleanup permission failure"), {
            code: "EPERM",
          });
        }
        await remove(target, options);
      } finally {
        removalSettled = true;
      }
    });
    try {
      await reader.dispose();
      expect(removalSettled).toBe(true);
      if (!denyRemoval) expect(await fs.readdir(scratch)).toEqual([]);
    } finally {
      await delay(100);
      interception.mockRestore();
      await remove(copyDirectory, { recursive: true, force: true });
    }
  },
);

Expected: disposal waits for the idle copy's removal attempt to settle; successful removal empties the scratch root; terminal cleanup failures do not leak an unhandled rejection. Both cases pass with zero unhandled errors.

5. Root cause

workspace-reads.ts:238–250 starts deletion in an env.then(success, failure) callback, discards the returned promise, and returns void. The second callback handles rejection of copy.env only. If the success callback returns a rejecting fs.rm promise, that rejection belongs to the new, discarded promise and is unhandled.

function removeIfUnused(copy: IndexCopy): void {
  if (!copy.retired || copy.users > 0) return;
  void copy.env.then(
    (env) =>
      env.GIT_INDEX_FILE === undefined
        ? undefined
        : fs.rm(path.dirname(env.GIT_INDEX_FILE), {
            recursive: true,
            force: true,
          }),
    () => undefined,
  );
}

dispose():603–613 retires the current copy and calls this void-returning helper without waiting. The test helper:7–16 removes its parent directory at test completion, so its removal can overlap the still-running child cleanup. force: true does not turn arbitrary permission failures into success.

The copy's user count deliberately keeps active Git reads alive. Any repair must preserve that behavior: an active read cannot lose its index just because another caller requests disposal.

6. Proposed fix

Return an observed cleanup promise; await it when disposing an unused copy; use bounded retries for transient filesystem contention and contain terminal best-effort cleanup failures. Background release and retirement paths must also retain rejection handling. Preserve the user-count guard and the existing mid-read disposal regression. This is a contained Git host lifecycle repair, not a protocol or schema change.
