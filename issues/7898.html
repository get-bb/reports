#7898 · Launcher spawn failure leaves exit wait unresolved

BugMedium priorityLow effortdesktop · cli · confirmed-repro GitHub issue2026-11-20 · base fab82665a3299fae8910f55d7519a3b034a03b9a

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A launcher configured with an executable override that does not exist returns success without printing anything. Both a version query and a plugin listing reproduce this on the trusted main branch, built from source. The subprocess wrapper observes the spawn error, preventing Node's default unhandled-error crash, but the shared exit waiter only observes normal exit. The failed spawn never emits that exit event, so the launcher never reaches its error reporter or sets its exit status. When no active handles remain, Node leaves with status zero despite the unfinished promise.

Focused regression test

Save this test as packages/config/test/child-process-exit.test.ts. It uses the actual repository process wrapper, not a mock, and tests the exit waiter's failure contract.

import { spawnHostProcess } from "@bb/process-utils";
import { mkdtempSync, rmSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { expect, it } from "vitest";
import { waitForProcessExit } from "../src/child-process-exit.js";

it("rejects when a child process cannot start", async () => {
  const directory = mkdtempSync(join(tmpdir(), "bb-process-start-failure-"));
  try {
    const command = join(directory, "missing-command");
    const childProcess = spawnHostProcess(command, [], { stdio: "ignore" });

    await expect(waitForProcessExit(childProcess)).rejects.toMatchObject({
      code: "ENOENT",
      path: command,
    });
  } finally {
    rmSync(directory, { recursive: true, force: true });
  }
}, 2_000);

5. Root cause

  1. runBundledCliCommand selects the executable override, starts it with inherited stdio, and awaits waitForProcessExit before converting the result into an exit status.
  2. observe installs an error listener for toolchain invalidation. As a result, ENOENT is not an unhandled EventEmitter error.
  3. waitForProcessExit handles an already-exited child or a future exit event only. For a failed spawn, exitCode and signalCode remain null and there is no exit event: 
    return new Promise<ChildProcessExitResult>((resolvePromise) => {
  childProcess.once("exit", (code, signal) => {
    resolvePromise({ code, signal });
  });
});
  4. runLauncherEntry already prints rejected errors and sets process.exitCode to 1. It cannot act here because the awaited promise never rejects or resolves. An unfinished promise alone does not keep Node alive.

The shared exit waiter is the root-cause owner. The launcher's packaging, executable-selection rules, and fallback policy do not need to change.

6. Proposed fix

Reject the existing exit-wait promise with the original child-process error. Remove the alternative event listener when either exit or error settles the wait. Preserve the already-exited fast path and normal code/signal results. This lets the existing launcher error boundary print the native error and return failure without introducing an executable precheck race, a fallback policy, a new dependency, or a packaging change.
