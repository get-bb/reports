#8234 · Nullish DOM insertion references

Bug High Effort: Low plugins confirmed-repro · GitHub issue · 2026-11-26

Verdict: REPRODUCED · Root-cause confidence: high

Trusted base: b0ddaad731565d7e4de68d824120d802fc78f7d5 (origin/main).

1. TL;DR

The app installs a wrapper around the DOM insertion method before rendering. A JavaScript caller that supplies an explicit undefined reference cannot append through that wrapper: it throws before reaching the original DOM implementation. The wrapper excludes only null before reading the reference's parent, although undefined also represents an append reference in the tested DOM implementation. A new regression test compares unwrapped and wrapped insertion and reproduces the failure in two clean source environments. Changing the reference check to exclude both nullish values fixes the failure without changing plugin reparent protection.

describe("foreign DOM mutation guard", () => {
  it("suppresses the removeChild that a foreign reparent turns into a throw", () => {

  function wrapLikeFileReveal(control: HTMLElement): HTMLElement {
    const parent = control.parentNode;
    if (parent === null) throw new Error("control has no parent");
    const group = document.createElement("span");
    const button = document.createElement("button");
    button.type = "button";
    parent.insertBefore(group, control);
    group.append(control, button);
    return group;
  }

  function removeListItemAfterFileRevealWrap(): Error[] {
    const errors: Error[] = [];
    const container = document.createElement("div");

      onUncaughtError: (error) => {
        errors.push(error instanceof Error ? error : new Error(String(error)));

          {items.map((item) => (

            </button>

5. Root cause

Startup imports and installs the guard. Installation captures the original DOM insertion method. The wrapper's reference check executes before that original method:

if (refusePluginReparent(node, this)) return node;
if (child !== null && child.parentNode !== this) {
  recordSuppression("insertBefore", child, this);
  ...
}
...
nativeInsertBefore.call(this, node, child);

For undefined, the first comparison is true and evaluating the second operand throws a JavaScript TypeError. Neither the native method's argument conversion nor its append behavior is reached. This is a wrapper compatibility defect, not a stale-reference suppression and not a pending asynchronous plugin mount. The TypeScript annotation does not constrain values supplied by JavaScript callers.

6. Proposed fix and regression proof

Use child != null before dereferencing the reference, leaving the original reparent check and native call unchanged. This only restores the existing nullish append contract; it changes no plugin authority, protocol, schema, persistence, packaging, or dependency.
