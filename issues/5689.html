#5689 · Expired Codex credentials bypass AI readiness checks

BugPriority: MediumEffort: Mediumprovidersprovider-codexGitHub issue2026-10-17 · base 6a639cfc0d66e0c789a1bd7309266973228d1a80

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The Codex helper service says it is ready even when its saved ChatGPT access token is known to have expired. Its credential parser computes expiration, but neither the credential reader nor the readiness handler rejects that state. The same credential reader supplies transcription and text-completion requests, so these helpers can send the expired credential and then surface an authentication failure. Two clean checkouts reproduce this behavior with entirely synthetic credentials and intercepted HTTP, without Account Pooler or a live BB instance. Real OAuth refresh, user audio, and end-to-end title and commit generation were not exercised.

import { afterEach, beforeEach, expect, it, vi } from "vitest";
import hostEntry from "./host.js";

let temporaryHome: string;
let authPath: string;
const fetchMock = vi.fn<typeof fetch>();
const harness = experimental_createHostEntryHarness(hostEntry);

beforeEach(async () => {
  temporaryHome = await fs.mkdtemp(path.join(os.tmpdir(), "bb-5689-"));
  const codexHome = path.join(temporaryHome, "codex");
  await fs.mkdir(codexHome);
  authPath = path.join(codexHome, "auth.json");
  vi.stubEnv("HOME", temporaryHome);
  vi.stubEnv("USERPROFILE", temporaryHome);
  vi.stubEnv("CODEX_HOME", codexHome);
  fetchMock.mockReset();
  fetchMock.mockImplementation(async () => {
    throw new Error("Unexpected network request blocked by reproduction");
  });
  vi.stubGlobal("fetch", fetchMock);
});

afterEach(async () => {
  vi.unstubAllGlobals();
  vi.unstubAllEnvs();
  await fs.rm(temporaryHome, { recursive: true, force: true });
});

async function writeAuth(expiration: number): Promise<string> {
  const encode = (value: object) =>
    Buffer.from(JSON.stringify(value)).toString("base64url");
  const accessToken = `${encode({ alg: "none" })}.${encode({ exp: expiration })}.synthetic`;
  const contents = JSON.stringify({
    auth_mode: "chatgpt",
    tokens: {
      access_token: accessToken,
      refresh_token: "synthetic-refresh",
      account_id: "synthetic-account",
    },
  });
  await fs.writeFile(authPath, contents, { mode: 0o600 });
  return contents;
}

it("does not report a known-expired credential as ready", async () => {
  await writeAuth(1);
  const status = await harness.experimental_call("codex.ai.status", {});
  console.log("expired readiness:", JSON.stringify(status));
  expect(status.ready).toBe(false);
});

it("reports missing auth unavailable without requesting the network", async () => {
  const status = await harness.experimental_call("codex.ai.status", {});
  expect(status.ready).toBe(false);
  expect(fetchMock).not.toHaveBeenCalled();
  console.log("missing readiness:", JSON.stringify(status));
});

it("keeps valid auth usable for readiness and transcription", async () => {
  await writeAuth(Math.floor(Date.now() / 1000) + 3600);
  fetchMock.mockResolvedValueOnce(
    Response.json({ text: "synthetic transcript" }),
  );
  expect(await harness.experimental_call("codex.ai.status", {})).toEqual({
    ready: true,
  });
  expect(
    await harness.experimental_call("codex.ai.transcribe", {
      model: "gpt-transcribe",
      audioBase64: Buffer.from("synthetic audio").toString("base64"),
      mimeType: "audio/webm",
      filename: "synthetic.webm",
      hint: null,
      timeoutMs: 1000,
    }),
  ).toEqual({ ok: true, text: "synthetic transcript" });
  expect(fetchMock).toHaveBeenCalledTimes(1);
});

it.each(["transcribe", "complete"] as const)(
  "observes an expired %s request with no recovery",
  async (operation) => {
    const original = await writeAuth(1);
    fetchMock.mockResolvedValueOnce(
      Response.json(
        { error: { message: "Synthetic expired access" } },
        { status: 401 },
      ),
    );
    expect(await harness.experimental_call("codex.ai.status", {})).toEqual({
      ready: true,
    });
    const result =
      operation === "transcribe"
        ? await harness.experimental_call("codex.ai.transcribe", {
            model: "gpt-transcribe",
            audioBase64: Buffer.from("synthetic audio").toString("base64"),
            mimeType: "audio/webm",
            filename: "synthetic.webm",
            hint: null,
            timeoutMs: 1000,

            model: "gpt-4.1",
            prompt: "Synthetic request",
            timeoutMs: 1000,

    expect(fetchMock).toHaveBeenCalledTimes(1);
    expect(await fs.readFile(authPath, "utf8")).toBe(original);
    console.log(
      operation,
      JSON.stringify(result),
      "requests=1 authUnchanged=true",
    );
  },
);

5. Root cause

Expiration decoder compares the JWT exp against the current time. Classification still returns state: "ok" and stores that result as credentials.expired:

state: "ok",
credentials: {
  type: "chatgpt",
  ...
  expired: tokenExpired(accessToken),
}

The shared credential reader treats this as usable without checking expiry:

case "ok":
  return auth.credentials;

The host readiness handler only tests whether this reader throws:

await readCodexAuthCredentials();
return { ready: true };

Text completion and transcription obtain credentials from that same reader and issue their requests directly. HTTP 401 maps to auth_required. The server-side registration sends helper calls and service status to the configured primary host, sharing one availability status for the helper service.

Underlying lifecycle constraint: the existing read-only-auth test deliberately preserves direct use of an expired-looking access token and an unchanged auth file. Adding a second refresh writer without coordinating the credential owner could race token rotation. A missing expiry check is directly demonstrated; successful real refresh is not.

6. Proposed fix and safety gate

Make known-expired OAuth credentials unavailable through the shared helper credential boundary, with primary-host recovery guidance. If automatic recovery is supported, perform serialized refresh through the actual credential owner and retry only within the existing request deadline; do not introduce an independent writer of the auth file. Preserve API-key behavior and test valid, missing, expired, and unsuccessful-refresh paths.

No autopilot pull request: the verified defect lies in authentication semantics and credential ownership, explicitly excluded by the simple-fix gate. Selecting refresh ownership versus a read-only rejection also needs a lifecycle/product decision. Work stops before production edits, a branch, or a push.
