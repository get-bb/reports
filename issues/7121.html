#7121 · Terminal pool refresh errors on current main

BugPriority: MediumEffort: Mediumproviders · no-reproGitHub issue2026-11-05 · base fa30b0a7dcdf745f7baf8e41721f754b7d3198fe

Verdict: ALREADY FIXED on trusted main. Root-cause confidence: medium for the reported deployment; high confidence in the tested current-main behavior. Reproduction label: no-repro.

1. TL;DR

The reported silent refresh failure is not reproducible on the trusted main commit: an expired Claude account becomes status: error with the terminal OAuth error, including when its retained quota is 22 hours old. The same result passes in a second clean checkout, and all 390 Account Pooler tests pass. Repository history identifies a matching repair, commit 6e77fce8c7a0a3bd71b66edfd5f223f5f92cc632 (#6661), merged November 2, 2026. The desktop 0.48.1 release points to e003e9510cbfd3bb6c26a28630b46ffb1c242a44 and was published October 30, 2026, before that repair. Static inspection of that release explains the silent-failure mechanism; this investigation did not inspect the reporter's deployed bundle, so the release mismatch is an evidence-backed explanation rather than proof of that host's exact contents.

import { createHash } from "node:crypto";
import fs from "node:fs/promises";
import { tmpdir } from "node:os";
import path from "node:path";
import { createFakePluginHost } from "@get-bb/plugin-sdk/testing";
import { afterEach, describe, expect, it } from "vitest";
import { z } from "zod";
import { accountPoolConfigSchema, type PoolProvider } from "./contracts.js";
import { createHub, type AccountPoolHub } from "./hub.js";
import {
  AccountStore,
  HubTokenStore,
  PoolAffinityStore,
  QUOTA_MIGRATIONS,
  QuotaStore,
} from "./store.js";

const MINUTE = 60_000;
const ROUTE = "/api/v1/plugins/account-pool/http";
const REFRESH_URL = "https://oauth.invalid/token";
const USAGE_URL = "https://usage.invalid/usage";
const UPSTREAM_URL = "https://upstream.invalid";
const REJECTED = "OAuth refresh failed with HTTP 400. invalid_grant.";

const cleanups: Array<() => Promise<void>> = [];

afterEach(async () => {
  while (cleanups.length > 0) await cleanups.pop()?.();
});

async function createPool(provider: PoolProvider, refreshFailureStatus = 400) {
  const dataDir = await fs.mkdtemp(
    path.join(tmpdir(), "bb-account-pool-rejection-"),
  );
  const host = createFakePluginHost({ pluginId: "account-pool", dataDir });
  const database = host.bb.storage.database();
  host.bb.storage.migrate(database, QUOTA_MIGRATIONS);
  const secretsDir = path.join(dataDir, "secrets");
  let time = 1_800_000_000_000;
  const now = () => time;
  const stores = () => ({
    accounts: new AccountStore(host.bb.storage.kv, secretsDir),
    quotas: new QuotaStore(database),
    affinity: new PoolAffinityStore(database),
    hubTokens: new HubTokenStore(secretsDir, now),
  });
  const initial = stores();
  await initial.accounts.initialize();
  const addAccount = (
    name: string,
    priority: number,
    accessToken: string,
    refreshToken: string,
    ttl: number,
  ) =>
    initial.accounts.add(
      {
        provider,
        kind: "oauth",
        label: name,
        email: null,
        accountUuid: null,
        ...(provider === "codex" ? { codexAccountId: name } : {}),
        subscriptionType: null,
        rateLimitTier: null,
        enabled: true,
        priority,
      },
      { kind: "oauth", accessToken, refreshToken, expiresAt: time + ttl },
    );
  const account = await addAccount(
    "synthetic-account",
    100,
    "access-original",
    "refresh-original",
    10 * MINUTE,
  );
  const refreshTokens: string[] = [];
  const authorizations: string[] = [];
  const rejectedAccessTokens = new Set<string>();
  let accountsChanged = 0;
  const transport: typeof fetch = async (input, init) => {
    const url = String(input);
    if (url === REFRESH_URL) {
      const { refresh_token } = z
        .object({ refresh_token: z.string() })
        .parse(JSON.parse(String(init?.body)));
      refreshTokens.push(refresh_token);
      return Response.json(
        {
          error:
            refreshFailureStatus === 400
              ? "invalid_grant"
              : "temporarily_unavailable",
        },
        { status: refreshFailureStatus },
      );
    }
    if (url === USAGE_URL) return Response.json({});
    if (url.startsWith(`${UPSTREAM_URL}/`)) {
      const authorization = new Headers(init?.headers).get("authorization");
      authorizations.push(authorization ?? "");
      return rejectedAccessTokens.has(
        authorization?.replace(/^Bearer /u, "") ?? "",
      )
        ? Response.json(
            { error: { message: "invalid access token" } },
            { status: 401 },
          )
        : Response.json({ id: "synthetic-response" });
    }
    throw new Error(`Unexpected network destination ${url}.`);
  };
  const startHub = async (
    current: ReturnType<typeof stores>,
  ): Promise<{ hub: AccountPoolHub; stop: () => Promise<void> }> => {
    const hub = createHub({
      ...current,
      now,
      fetch: transport,
      getSettings: () =>
        accountPoolConfigSchema.parse({
          anthropicUpstreamBaseUrl: UPSTREAM_URL,
          codexUpstreamBaseUrl: UPSTREAM_URL,
        }),
      refreshUrl: REFRESH_URL,
      codexRefreshUrl: REFRESH_URL,
      usageUrl: USAGE_URL,
      codexUsageUrl: USAGE_URL,
      onAccountsChanged: () => {
        accountsChanged += 1;
      },
    });
    const controller = new AbortController();
    const running = hub.start(controller.signal);
    await hub.refreshUsage();
    return {
      hub,
      stop: async () => {
        controller.abort();
        await running;
      },
    };
  };
  let active = await startHub(initial);
  cleanups.push(async () => {
    await active.stop();
    await host.harness.lifecycle.dispose();
    await fs.rm(dataDir, { recursive: true, force: true });
  });
  const token = await initial.hubTokens.forHost("synthetic-host");
  const route = provider === "claude" ? "/v1/messages" : "/v1/responses";
  return {
    account,
    accounts: initial.accounts,
    quotas: initial.quotas,
    status: () => active.hub.status(),
    kv: host.bb.storage.kv,
    refreshTokens,
    authorizations,
    rejectedAccessTokens,
    accountsChanged: () => accountsChanged,
    advance: (milliseconds: number) => {
      time += milliseconds;
    },
    error: () => initial.quotas.get(account.id).error,
    tick: () => active.hub.refreshUsage(),
    refresh: () => active.hub.refreshUsage(account.id, true),
    restart: async () => {
      await active.stop();
      active = await startHub(stores());
    },
    signInAgain: (accessToken: string, refreshToken: string, ttl: number) =>
      active.hub.replaceSecret(account.id, {
        kind: "oauth",
        accessToken,
        refreshToken,
        expiresAt: time + ttl,
      }),
    addFallbackAccount: (
      accessToken: string,
      refreshToken: string,
      ttl: number,
    ) =>
      addAccount(
        "fallback-synthetic-account",
        200,
        accessToken,
        refreshToken,
        ttl,
      ),
    request: async () => {
      const response = await active.hub.handle(
        new Request(`https://hub.invalid${ROUTE}${route}`, {
          method: "POST",
          headers: {
            authorization: `Bearer ${token}`,
            "content-type": "application/json",
          },
          body: JSON.stringify(
            provider === "claude"
              ? {
                  model: "claude-sonnet-4-5",
                  max_tokens: 1,
                  messages: [{ role: "user", content: "ok" }],
                }
              : { model: "gpt-5", input: "ok" },
          ),
        }),
        provider,
        route,
      );
      await response.text();
      return response.status;
    },
  };
}

5. Root cause

Released-code mechanism, established by static inspection: 0.48.1 background usage error handling only marks the account failed when recover is already true. That flag requires a pre-existing quota error. A ready account starts with no error, so its rejected OAuth refresh is logged and thrown, the usage-level catch swallows it, and no error is persisted. No rejection fingerprint is recorded in that release path, so another scheduled poll repeats the refresh. Retained quota is never refreshed when credential acquisition fails. This explains a silent ready state, repeated failures, stale usage, and an apparently successful refresh operation without alleging a provider outage.

Current-main repair: HTTP 400/401 classification throws OAuthRefreshError. Usage refresh propagates terminal OAuth failure into account error handles that terminal class even when no prior error exists. Rejected refresh handling stores a rejection fingerprint and only keeps a still-unexpired access token usable. Previously rejected token handling prevents automatic replay and surfaces error on expiry. setError persists the error and notifies account observers, and accountStatus gives error precedence over reset windows and utilization. Manual refresh operation uses the same hub path and returns the resulting account.

The old and current behavior were compared from trusted repository history; the old release was not executed. The missing transition was repaired in #6661 on November 2, after desktop 0.48.1 was published October 30. The actual server bundle and the origin of token rejection remain unverified. An unresolved main-only reproduction would require additional deployment or storage-failure evidence, not speculative changes to authentication.
