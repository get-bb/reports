1. TL;DR

The reported symptom is accidental magnification of the native app's embedded web interface. Two clean checkouts confirm that the shell passes no explicit page-zoom restriction to its WebView, the actual app document specifies an initial scale but no maximum scale, and the initialization bridge does not access the document or register a window event listener. These findings support a missing native-shell zoom policy as a probable cause, not a demonstrated WKWebView gesture failure. This Linux host has no iOS simulator or device, so neither pinch nor double-tap was exercised and no screenshot is available. No fix PR is safe under the autopilot requirements because a native behavioral reproduction and failing regression test are still missing.

5. Root cause

Probable configuration cause: the native shell inherits page-scaling behavior rather than applying an explicit shell-only scale policy. The page's initial-scale=1.0 selects its starting scale; it does not by itself specify a maximum. The local wrapper does not add any policy, and the bridge initializer performs no document adjustment. Native gesture recognition and the final scale were not measured, so a complete runtime causal claim remains unverified.

  • ShellWebView props and bridge injection.
  • Wrapper forwards props directly to WebView.
  • Shell URL is based on the active server.
  • Actual app-shell viewport.
  • Actual bridge initialization entry; its initialization was executed, not reimplemented.
  • Control-specific touch-action policy makes broad double-tap claims unsafe.

6. Proposed fix / next experiment

First obtain a native behavioral regression that fails on trusted main. If confirmed, constrain scaling only inside the native shell using the appropriate platform mechanism; do not globally disable user zoom in the shared browser document. Android's built-in-zoom prop does not implement an iOS fix. Verify pinch and double-tap separately, plus keyboard focus, navigation, image pan/zoom, and ordinary-browser accessibility. The final approach requires evidence that it preserves these interactions, not merely a prop or source-string assertion.
