Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Pi system-message boundaries become two full diagnostic events rather than internal noise. A synthetic 51,200-character prompt section passed through the real Pi translator and shared event assembler is retained in both the start and end events. The same failure occurs with and without an active turn, in two clean checkouts of trusted main. The boundary-role classifier does not recognize the system role, so the fallback keeps the raw envelope. The minimal fix recognizes that role using the existing noise policy; no historical data is changed.

5. Root cause

  1. Boundary-role union and role parser recognize assistant, custom, toolResult and user, but not system. The latter therefore becomes unknown.
  2. Boundary visibility classification gives unknown roles unknown coverage; known roles receive noise coverage.
  3. SDK envelope translation recursively translates the boundary; when no normalized deltas result, it calls unhandledDeltas. That function retains the full raw envelope only for unknown coverage.
  4. The shared assembler copies the raw envelope into a provider/unhandled event. Nothing deduplicates these two distinct boundary envelopes.

The storage amplification begins in event classification, not SQLite allocation. Retention documentation gives no cleanup rule for these events. Other diagnostic consumers use model-fallback payloads, so blanket deletion of all unhandled events would be unsafe.

6. Proposed fix

Add system to the local boundary-role union and role parser. The existing known-role noise policy then suppresses both snapshots before the shared assembler creates stored events. Do not add a new persistence format, protocol, schema, byte cap or pruning migration. Preserve unknown-role diagnostics. Existing stored rows are not removed.
