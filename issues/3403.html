#3403 · Service-tier selection has no standalone persistence path

1. TL;DR

The existing thread composer holds tier changes in local state. Its update API cannot accept a standalone tier preference, so wiring the toggle directly to that endpoint would also require a contract change. A separate Codex converter loses the default selection when serialized to JSON. Two focused tests demonstrate the API and serialization findings on current main and again in a clean checkout. This report does not claim a browser or live-provider reproduction.

import { expect, it } from "vitest";
import { toCodexServiceTier } from "./session-params.js";

it("retains an explicit default-tier reset in the serialized request", () => {
  expect(JSON.stringify({ serviceTier: toCodexServiceTier("fast") })).toBe(

  expect(JSON.stringify({ serviceTier: toCodexServiceTier("default") })).toBe(

  );

contract.test.ts

import { expect, it } from "vitest";
import { updateThreadRequestSchema } from "../src/api/threads.js";

it("accepts a standalone service-tier preference update", () => {
  const result = updateThreadRequestSchema.safeParse({ serviceTier: "default" });
  expect(result.success).toBe(true);
  if (result.success) expect(result.data).toEqual({ serviceTier: "default" });
});

5. Root cause

apps/app/src/views/thread-detail/ThreadDetailPromptArea.tsx:1138 assigns onChange: setServiceTier. apps/app/src/hooks/useThreadCreationOptions.ts:803 only updates selections for an existing thread. No persistence request is made there. packages/server-contract/src/api/threads.ts:546 has no serviceTier member and requires at least one supported field; a tier-only update is rejected.

plugins/provider-codex/src/session-params.ts:555 returns tier === "fast" ? "fast" : undefined. JSON serialization drops that property. plugins/provider-codex/src/bridge/bridge.ts:1018 and plugins/provider-codex/src/bridge/bridge.ts:1478 use this converter in provider requests. The existing converter test explicitly expects undefined for default, so the omission is established behavior requiring a regression expectation change.

6. Proposed fix and autopilot decision

Persist tier selection through a supported update contract and synchronize the composer with saved execution options. Verify the provider's omitted-versus-null behavior before implementing the explicit reset. The complete fix crosses UI, public server contract, and provider code. It fails the rule's no-public-schema-change and one-subsystem limits, so no production fix, branch, push, or PR was attempted. No linked open PR was found in issue timeline metadata or the open-PR issue-number search.
