#7790 · ACP command state exceeds the ingest byte budget

BugPriority: MediumEffort: Lowprovidersprovider-acpGitHub issue2026-11-18 · base 502cf5ae9b61f050ac6d2a7a1b9060f18b339828

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

A long command list can disappear before it reaches the composer or CLI. The ACP bridge caps the number of commands, but not the serialized byte size of their descriptions. The server correctly enforces a separate 65,536-byte extension payload limit and replaces the entire oversized state event with a diagnostic. A fresh thread therefore has no provider command state to read. An integration reproduction constructed from trusted main reproduces this in two clean checkouts: 12 commands survive, while 192 commands produce a 155,424-byte state and zero visible commands.

import { groupHostDaemonEvents } from "@bb/host-daemon-contract";
import { threadTimelineResponseSchema } from "@bb/server-contract";
import { describe, expect, it } from "vitest";
import { toThreadProviderCommandsState } from "../../../../packages/provider-bridge-acp/src/session/thread-state.js";
import { internalAuthHeaders } from "../helpers/commands.js";
import { readJson } from "../helpers/json.js";
import {
  seedEnvironment,
  seedHostSession,
  seedProjectWithSource,
  seedThread,
} from "../helpers/seed.js";

describe("issue 7790: ACP command state reaches timeline readers", () => {
  it.each([12, 192])("retains %i advertised commands", async (count) => {
    const harness = await createTestAppHarness();
    try {
      const { host, session } = seedHostSession(harness.deps);
      const { project } = seedProjectWithSource(harness.deps, {
        hostId: host.id,
      });
      const environment = seedEnvironment(harness.deps, {
        hostId: host.id,
        projectId: project.id,
      });
      const thread = seedThread(harness.deps, {
        projectId: project.id,
        environmentId: environment.id,
        providerId: "codex",
        status: "active",
      });
      const advertised = Array.from({ length: count }, (_, index) => ({
        name: `reference-${index}`,
        description: "Detailed command documentation. ".repeat(24),
      }));
      const payload = toThreadProviderCommandsState(advertised);
      const response = await harness.app.request("/internal/session/events", {
        method: "POST",
        headers: internalAuthHeaders(harness),
        body: JSON.stringify({
          sessionId: session.id,
          eventGroups: groupHostDaemonEvents([
            {
              threadId: thread.id,
              event: {
                type: "thread/extensionState/updated",
                threadId: thread.id,
                providerThreadId: "repro-session",
                scope: threadScope(),
                kind: THREAD_PROVIDER_COMMANDS_STATE_KIND,
                payload,
              },
            },
          ]),
        }),
      });
      expect(response.status).toBe(200);
      const timeline = threadTimelineResponseSchema.parse(
        await readJson(
          await harness.app.request(`/api/v1/threads/${thread.id}/timeline`),
        ),
      );
      const rows = harness.db
        .select({ type: events.type, data: events.data })
        .from(events)
        .where(eq(events.threadId, thread.id))
        .all();
      console.log(
        JSON.stringify({
          count,
          payloadBytes: Buffer.byteLength(JSON.stringify(payload)),
          actualCommands: timeline.providerCommands?.length ?? 0,
          storedTypes: rows.map((row) => row.type),
          diagnostics: rows
            .filter((row) => row.type === "provider/unhandled")
            .map((row) => JSON.parse(row.data)),
        }),
      );
      expect(timeline.providerCommands ?? []).toHaveLength(count);
      expect(timeline.providerCommands?.map((command) => command.name)).toEqual(
        advertised.map((command) => command.name),
      );
    } finally {
      await harness.cleanup();
    }
  });
});

5. Root cause

  1. ACP thread-state mapper, lines 14–31 filters blank names, takes up to 500 commands, and retains complete descriptions/input hints. There is no byte-budget step. 
    commands.filter((command) => command.name.trim() !== "")
  .slice(0, MAX_COMMANDS)
  .map((command) => ({ name: command.name, description: command.description, ... }))
  2. Core command schema, lines 33–42 limits the array to 500, but description length is unrestricted. Thus a count-valid payload need not fit the server's independent byte constraint.
  3. Session snapshot publisher, lines 2959–2967 sends this mapped payload as bb/provider-commands. Thread state publication cache, lines 2877–2894 records serialized state and suppresses identical updates.
  4. Server byte budget defines 64 * 1024. Core state validation, lines 134–145 measures Buffer.byteLength(JSON.stringify(site.payload)) and rejects a larger payload, even when its command count is valid.
  5. Ingest replacement, lines 209–241 replaces the event with provider/unhandled; it does not retain a truncated command-state event. Command projection, lines 51–67 looks for a valid command state and returns null if none exists.
  6. The server head-state reader and CLI commands reader use this provider-command projection. The composer input path receives timeline provider commands. Therefore the absent state explains both reported discovery surfaces.

The root defect is a producer/consumer resource-limit mismatch, not malformed ACP command names and not a reason to weaken ingest validation. On a thread that already had a smaller accepted state, rejection can leave stale earlier commands rather than clearing them; the zero-command result here concerns a fresh thread.

6. Proposed fix

Make the ACP command-state producer respect the existing serialized UTF-8 byte budget before it sends an event. Prefer preserving command names and useful input hints, reducing long descriptions with Unicode-safe truncation and JSON-escape-aware byte measurement; bound the final fallback if non-description content alone exceeds the limit. Preserve unchanged payloads that already fit. Keep the server's rejection boundary intact. Cover multi-byte text, JSON escaping, unusually large names/hints, and ordinary small lists. No fix code is included in this investigation because an open linked PR already covers this work.

Test value: existing ingest tests intentionally reject manually oversized inputs and check small valid core states. This regression crosses the actual ACP mapping/ingestion/projection boundary and exposes the missing producer-side budget. It adds no production export, switch, injected path, or database mock.
