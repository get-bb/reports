#5385 · Concurrent path ranking starves daemon timers

BugHighEffort: Mediumhost · perf · partial-reproGitHub issueOctober 12, 2026 · base 0c6882c747f6ee2018682ed1a1ec66ee1310e48c

PARTIALLY REPRODUCED · Root-cause confidence: high

1. TL;DR

Path search runs on the same JavaScript event loop as daemon heartbeat timers. Workspace discovery is asynchronous and shared between simultaneous equivalent requests, but each waiting request then ranks the entire listing synchronously. In two clean checkouts, 48 actual path commands against 150,000 real files delayed a 10 ms timer for 54.316 and 56.310 seconds, beyond the 30-second production lease. A 20-result limit did not bound this work. This confirms a lease-threatening mechanism, not an observed desktop disconnection: no real daemon WebSocket, macOS UI, HTTP timeout, or plugin reload was reproduced.

5. Root cause

  1. The project paths route issues host.list_paths with server exclusion defaults and the caller's query/result limit.
  2. The pending-listing map shares discovery by root/options, not by query. It is deleted when discovery settles; it is not a persistent listing cache.
  3. The recursive walker awaits directory reads but materializes every accepted entry. There is no walk budget.
  4. Each waiting command resumes and calls synchronous finalization on the shared array. Promise continuations run before the event loop can service timers, so concurrent requests amplify the stall even if discovery happened once.
  5. Finalization filters the complete array. Fuzzy matching normalizes all items, ranks and merges the full candidate set, and only afterward slices to the requested limit.
  6. The real daemon heartbeat uses setInterval on that loop. The separate server's liveness checks expire quiet sessions against the 30,000 ms lease. Its silence handler closes and unregisters the daemon session. This explains the reported host-wide impact, but that network sequence remains an inference here.

The problem is event-loop monopolization, not evidence of a defective lease duration. A healthy server is supposed to reject an actually silent daemon. Fixing only repeated identical queries, yielding only during traversal, or making the lease larger would not protect against one sufficiently expensive ranking operation.

6. Proposed fix and simple-fix gate

Make path discovery/ranking interruptible or execute CPU-heavy ranking outside the heartbeat loop, preserving global fuzzy ordering. Coalesce or cancel obsolete searches so a burst does not repeat expensive work. Add a real server/daemon test that exercises search while checking socket liveness and an unrelated host command.
