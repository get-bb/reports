#7910 · Git plugin snapshots unnecessarily require ancestor objects

BugMedium priorityLow effortplugins · perf · confirmed-reproIssue2026-11-20 · base fab82665a3299fae8910f55d7519a3b034a03b9a

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A git plugin is installed as a snapshot, but the installer first copies the repository's history. A plugin whose current snapshot is complete can therefore fail when an older, unused file object is unavailable. A newly authored service-level regression demonstrates this over a real local Git smart-HTTP transport. It fails on unchanged production code in two separate checkouts and passes with a depth-one fetch repair. The reported real-world download sizes and timing were not measured in this environment.

async function serveGitRepository(repoDir: string) {
  const server = createServer((request, response) => {
    const url = new URL(request.url ?? "/", "http://127.0.0.1");
    const child = execFile(
      "git",
      ["http-backend"],
      {
        encoding: "buffer",
        env: {
          ...process.env,
          GIT_PROJECT_ROOT: dirname(repoDir),
          GIT_HTTP_EXPORT_ALL: "1",
          PATH_INFO: url.pathname,
          QUERY_STRING: url.search.slice(1),
          REQUEST_METHOD: request.method ?? "GET",
          CONTENT_TYPE: request.headers["content-type"] ?? "",
        },
      },
      (error, stdout, stderr) => {
        if (error) {
          response.writeHead(500).end(stderr);
          return;
        }
        const headerEnd = stdout.indexOf("\r\n\r\n");
        for (const header of stdout
          .subarray(0, headerEnd)
          .toString()
          .split("\r\n")) {
          const separator = header.indexOf(":");
          const name = header.slice(0, separator);
          const value = header.slice(separator + 1).trim();
          if (name.toLowerCase() === "status")
            response.statusCode = Number.parseInt(value, 10);
          else response.setHeader(name, value);
        }
        response.end(stdout.subarray(headerEnd + 4));
      },
    );
    request.pipe(child.stdin!);
  });
  await new Promise<void>((resolvePromise) =>
    server.listen(0, "127.0.0.1", resolvePromise),
  );
  const address = server.address();
  if (address === null || typeof address === "string")
    throw new Error("missing git server port");
  return {
    url: `http://127.0.0.1:${address.port}/${repoDir.slice(dirname(repoDir).length + 1)}`,
    close: () =>
      new Promise<void>((resolvePromise) =>
        server.close(() => resolvePromise()),
      ),
  };
}

5. Root cause

The shared git artifact materializer performs an unrestricted clone before detaching the selected commit and removing .git, so historical objects outside the selected snapshot are required.

  • cloneGitCommit at the trusted base clones all advertised refs and their reachable history, detaches the requested commit, checks its identity, and deletes .git.
  • Semver installation candidate probe, installation materialization, and update staging all call this materializer.
  • Commit selector validation and direct commit resolution accept abbreviated commit IDs; a direct fetch can reject these even when cloning and checking out succeeds.
  • Command timeout is five minutes per Git command, not a total installation deadline.

6. Proposed fix

Initialize an empty staging repository and fetch the selected commit at depth one without tags. Keep exact checkout verification, .git cleanup, cancellation propagation, and a clean full-clone fallback for unsupported direct fetches and abbreviated commit IDs.

The local implementation remains in the existing materializer and leaves all public interfaces, persistence, package metadata, and CLI behavior unchanged. Fetch errors other than cancellation use the existing clone behavior; consequently unsupported servers and short commit IDs retain full-download cost. A transient fetch failure can also incur a second attempt. This is an explicit compatibility tradeoff, not a promise that every source becomes shallow.
