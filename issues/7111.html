#7111 · ACP question presentation loses field structure

Bug Priority: Medium Effort: Medium providers · ui · provider-acp

GitHub issue #7111 · November 5, 2026 · trusted main fa30b0a7dcdf745f7baf8e41721f754b7d3198fe

PARTIALLY REPRODUCED · root-cause confidence: high · reproduction label: partial-repro

1. TL;DR

The trusted ACP planner repeats the same question when the top-level message and field title match, appends the field description to that prompt, and drops descriptions from individual choices. The real shared QuestionForm, rendered to HTML, receives that flattened prompt and produces one combined prompt block with no separate leading heading and no choice explanations. Both results repeated in a second clean checkout of the same trusted main commit; optional questions and custom-answer response keys still work. This is a partial verdict because the headless browser could not start: this host has no Chrome executable, so browser layout, computed font weights, mobile behavior, and a live OMP-to-Connect session were not verified.

5. Root cause

  1. AcpElicitationChoice only models value and label. readChoices explicitly reconstructs those two properties for titled alternatives, so entry descriptions are discarded before the UI sees them.
  2. questionFor constructs lines from message, an empty separator, field title, then field description, without comparing message and title. It sets shortLabel to the title, not to the short description. Equal context/title therefore duplicate; the short description remains at the end of prompt.
  3. The domain question schema carries prompt and shortLabel but no distinct heading. QuestionInputBlock renders prompt as a single font-medium div; it already forwards option.description to rows. Lost choice metadata cannot be recovered there.
  4. The live ACP request handler calls the generic planner with params and forwards its payload. OMP's dialect supplies command/model presentation, not question presentation. There is currently no OMP-only interpretation of short descriptions in that path.

6. Proposed fix and autopilot gate

Preserve choice descriptions at the schema reader, deduplicate equal context/title text, and introduce deliberate provider-specific question presentation rather than interpreting every generic ACP description as a heading. Carry the separate heading through the domain/host contract and shared form, then render heading before normal-weight prompt. Keep generic field descriptions, optionality, companion folding, and response keys intact. Verify desktop/mobile rendering and generic providers, with compatibility tests or the required host protocol update for changed wire semantics.

No fix PR was safe under this rule. The full correction crosses the provider, shared domain/schema, host payload, and UI boundaries, and needs a presentation contract decision. That fails the one-subsystem/no-schema-change/no-product-decision gate. The incomplete browser verification is an additional limitation. No production patch or fix branch was pushed.
