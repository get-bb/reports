#5621 · Native tool details are discarded before timeline rendering

BugPriority: MediumEffort: Mediumthreadsprovider-claude-codeIssue2026-10-16

Verdict: REPRODUCED at the provider-event and production React component boundaries, in two clean trusted checkouts. Root-cause confidence: high.

Trusted main commit: 01affc197dc621cddc7343e09b1c5c10a5b9efcb. No reporter-supplied code, patch, branch, or linked URL was fetched or executed.

1. TL;DR

Native Claude Code file reads and searches become compact timeline rows with no disclosure control. The provider retains their file path or search query, but drops extra arguments, native tool identity, and result text before the UI receives the events. Shared event and timeline schemas do not provide structured native-tool detail fields for these row kinds. Separately, the shared client explicitly makes file-read and search rows non-expandable. Two fresh checkouts reproduce both defects, while ordinary command output and expansion work in the same tests.

function translateCall(toolName: string, input: object, output: string) {
  const harness = createClaudeDeltaHarness();
  const started = harness.translate({
    type: "assistant",
    message: {
      role: "assistant",
      content: [{ type: "tool_use", id: "native-tool", name: toolName, input }],
    },
    session_id: "synthetic-session",
  });
  const completed = harness.translate({
    type: "user",
    message: {
      role: "user",
      content: [{ type: "tool_result", tool_use_id: "native-tool", content: output }],
    },
    session_id: "synthetic-session",
  });
  return { started, completed };
}

describe("native tool detail availability at the provider event boundary", () => {
  it.each(cases)("retains $toolName input details", ({ toolName, input, output, option }) => {
    const events = translateCall(toolName, input, output);
    console.log(JSON.stringify({ toolName, events }));
    expect(JSON.stringify(events)).toContain(option);
  });

  it.each(cases)("retains $toolName result text", ({ toolName, input, output }) => {
    const events = translateCall(toolName, input, output);
    expect(JSON.stringify(events.completed)).toContain(output);
  });

  it("retains command output as a positive control", () => {
    const events = translateCall("Bash", { command: "printf bridge-control" }, "bridge-control");
    expect(JSON.stringify(events.completed)).toContain("bridge-control");
  });
});

5. Root cause

Native tool classification is lossy

The classifier maps Read to only a path, and Grep/Glob to a mode, query, and optional path. Unlike generic tool items, those shapes do not retain native tool arguments or native tool names.

    case "Grep":
    case "Glob": {

      const query = parsed.success
        ? toOptionalString(parsed.data.pattern)
        : undefined;
      if (!query) {
        return genericTool(toolName, input);
      }
      const mode = toolName === "Grep" ? "content" : "path";
      const path = parsed.success
        ? toOptionalString(parsed.data.path)
        : undefined;
      return {
        shape: {
          type: "search",
          mode,
          query,
          ...(path ? { path } : {}),
        },
        presentation: searchPresentation({ mode, query }),
      };

Terminal translation deliberately omits native result text

The native branches return an empty close payload even when a tool_result contains text. Bash, by contrast, retains aggregatedOutput. Adding a UI chevron alone cannot recover information already discarded here.

Why existing tests miss this

The existing native-tool translation test asserts the reduced fileRead/search event shapes and presentation, without expecting extra options or results: plugins/provider-claude-code/src/delta-translation.tool-calls.test.ts:509. Its focused file still passes all 23 tests, while the new input/result availability assertions fail. The provider regression owns the event-data availability contract; the separate UI regression guards the independently failing disclosure policy.

6. Proposed fix and simple-fix assessment

Preserve a bounded native tool detail payload through classification, terminal translation, assembly, and timeline projection; then let native read/search rows expose an existing shared disclosure body with safe argument/result rendering. Preserve current row kinds, paths, query summaries, and grouping behavior. Validate data at the provider boundary and cap result text consistently with existing tool output handling. Check server/daemon wire compatibility if the payload contract changes.

No autopilot PR is safe under this rule. A faithful repair preserving the existing row kinds crosses the provider, shared event/timeline contracts, and client rendering. It is not a contained one-subsystem change; the straightforward structured-data repair also changes public schemas/protocol fields. Reclassifying native reads/searches as generic tools solely to fit the limit would change semantics and grouping. The simple-fix gate fails before production edits, so no fix branch was created, no production patch was committed or pushed, and no PR was opened.
