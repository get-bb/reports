#7596 · Claude session metadata becomes diagnostic events

BugPriority: LowEffort: Lowprovidersprovider-claude-codeGitHub issue

2026-11-15 · trusted main da3e60b81d560e114a2bec724bb59c997aaaae7f

Verdict: REPRODUCED at the SDK-envelope → timeline-event boundary. Root-cause confidence: high. Reproduction label: confirmed-repro.

1. TL;DR

Two informational Claude system-message families are missing from the provider's explicit visibility classification. Passing either message family through the actual translator and event assembler creates a provider/unhandled event instead of producing no timeline events. Three regression cases reproduce the defect on trusted main, and the same agent repeated all three failures in a second clean checkout. This is a provider classification bug, not a layout or styling defect. Live Claude emission, desktop rendering, and the reporter's operating-system/version claims were not exercised.

5. Root cause

  1. The subtype parser recognizes an explicit list of names and maps everything else to unknown. Both metadata names are absent.
  2. The coverage switch therefore returns { kind: "sdk/system", coverage: "unknown" } instead of recognizing the metadata as noise.
  3. The SDK-envelope fallback runs after system translation returns no deltas. Its coverage gate suppresses known noise but emits an unhandled delta for unknown coverage.
  4. The event assembler converts that delta into the persisted-event shape provider/unhandled, with rawType: "sdk/system". The regression checks this real end-to-end provider path rather than merely testing a lookup.
const description = claudeCodeVisibilityMetadata.describeRawEvent(rawEvent);
if (description.coverage !== "unknown") {
  return [];
}

The deeper maintenance risk is an explicit subtype inventory drifting behind provider releases. This investigation does not justify silencing every future unknown subtype: unknown-event diagnostics are an intentional existing behavior protected by tests.

6. Proposed fix

Add only the two verified informational subtype names to the local subtype union, parser recognition switch, and noise branch in visibility.ts. Keep unknown subtype behavior unchanged. Keep the three regression cases at the actual SDK-envelope → assembled-event boundary; run the owning provider's existing tests, typecheck, lint, and whitespace check. No public protocol, schema, packaging, dependency, or stored-data change is needed.
