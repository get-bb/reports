#5704 · PR detail reads have no shared request budget

BugHighEffort: Mediumhost · perf · github · partial-repro Issue #5704October 17, 2026 · base ee36dfda7815e8c72672ab57e2bdb1b395ada9be

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high for the request-amplification mechanism, not the reporter's exact live allowance consumption.

1. TL;DR

Every uncached environment PR read asks GitHub for detailed PR state, then asks separately about the merge queue for an open, non-draft PR. The existing ten-second server cache shares simultaneous reads only within one environment identity; it does not impose an aggregate request budget. A deterministic test through the real server cache and host lookup produced 7,200 detail commands plus 7,200 queue commands for sixty environments requested every thirty seconds over one simulated hour. The same test also reproduced duplicate reads across environment identities and a retry thirty seconds after a synthetic quota failure. No real GitHub quota was deliberately exhausted: exact point costs, the original process sample, and the original caller responsible for the observed traffic remain unverified.

function createReader() {
  let now = 0;
  const caches = new WorkspaceReadCaches({
    hub: { onChangedMessage: () => () => undefined },
    now: () => now,
  });
  return {
    advance(milliseconds: number) {
      now += milliseconds;
    },
    read(environmentIndex: number, workspaceIndex = environmentIndex) {
      return caches.pullRequest.read({
        environmentId: `environment-${environmentIndex}`,
        hostId: "synthetic-host",
        key: `workspace-${workspaceIndex}`,
        load: async () => {
          const lookup = await getPullRequestForCurrentBranch({
            cwd: `/tmp/synthetic-repository/workspace-${workspaceIndex}`,
            localBranch: `example-${workspaceIndex}`,
          });
          if (lookup.outcome === "found") {
            return { outcome: "available", pullRequest: lookup.pullRequest };
          }
          if (lookup.outcome === "none") return { outcome: "absent" };
          return lookup;
        },
      });
    },
  };
}

5. Root cause

The request path is SDK environment PR read → server environment route → server read cache → daemon workspace RPC → host PR lookup. The route caches by environment and host as well as workspace identity. That prevents duplicate requests for the same cache key, but gives every different environment a separate slot. The ten-second TTL expires before the active-PR thirty-second poll. There is no budget shared across these cache entries.

export function getEnvironmentPullRequestRefetchInterval(
  pullRequest: ThreadPullRequest | null | undefined,
): number | false {
  if (!pullRequest || pullRequest.state !== "open") {
    return false;
  }
  if (
    pullRequest.autoMerge ||
    pullRequest.inMergeQueue === true ||
    pullRequest.checks.state === "pending" ||
    pullRequest.mergeability.state === "unknown"
  ) {
    return ENVIRONMENT_ACTIVE_PULL_REQUEST_REFETCH_MS;
  }
  return false;

The deeper problem is that short-lived per-environment memoization is not aggregate external-service admission control. A larger fixed TTL or removal of the queue query reduces cost but remains proportional to the number of distinct environments, and therefore cannot guarantee a shared reserve.

6. Proposed fix and simple-fix gate

Introduce explicit shared request-budget policy for background GitHub reads, separate from user-triggered PR mutations. Define the reserve, staleness behavior, account/hostname scope, and reset-aware cooldown. Coalesce equivalent PR identities across workspaces; consider conditional lightweight change detection before loading detail and queue state. Preserve correctness for changed checks/reviews, whose updates need not be represented by a naive PR timestamp comparison.

No fix PR opened. No linked open PR was found in the issue timeline or open-PR search. A safe complete fix requires a product decision about background freshness versus a shared user-action reserve, and coordination between server policy and host-local GitHub transport. That fails the autopilot's no-product/architecture-decision condition; an arbitrary TTL increase would not repair the unbounded aggregate mechanism. No production patch, fix branch, dependency, protocol, stored data, or migration was changed.

Next experiment: after choosing that contract, replay this demand model with mixed active/settled PRs, multiple authentication buckets, quota reset responses, and an interleaved user action. Verify a bounded aggregate read count and timely mutation refresh before implementing admission control.
