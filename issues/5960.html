#5960 · Unknown hook cancellation leaves cleanup retrying without progress

Bug Priority: Medium Effort: High workspaces · GitHub issue · October 21, 2026

Trusted main commit: 405592c0b71b1655a6ab2e1cc7498b5beeb78caa

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

An interrupted environment hook can leave a durable record that the current daemon cannot reconcile. Cancellation then returns an ambiguous outcome, and the server refuses deletion without finishing that record. Teardown failure schedules another attempt after 60 seconds, but that attempt receives no new evidence and takes the same path. Explicit cleanup accepts the request without resolving the ambiguity. The defect was reproduced using real migrated SQLite and the actual server lifecycle code in two clean trusted-main checkouts; the affected production machine was not accessed.

import {
  environmentHookOperations,
  environments,
  getEnvironment,
} from "@bb/db";
import { validatePluginEnvironmentProviderDeclaration } from "@get-bb/plugin-sdk/internal/host-policy";
import { eq } from "drizzle-orm";
import { expect, it } from "vitest";
import { cancelPendingEnvironmentHook } from "../../../src/services/environments/environment-hooks.js";
import {
  cleanupEnvironment,
  sweepProviderEnvironment,
} from "../../../src/services/environments/environment-engine.js";
import { setPluginEnvironmentProviderBridge } from "../../../src/services/plugins/plugin-environment-provider-registry.js";
import { registerHostRpcResponder } from "../../helpers/host-rpc.js";
import {
  seedEnvironment,
  seedHostSession,
  seedProjectWithSource,
} from "../../helpers/seed.js";
import { withTestHarness } from "../../helpers/test-app.js";

it.each(["unknown", "terminated"] as const)(
  "does not retry unchanged blocked teardown indefinitely: %s",
  async (cancelStatus) => {
    await withTestHarness(async (harness) => {
      const { host, session } = seedHostSession(harness.deps);
      const { project } = seedProjectWithSource(harness.deps, {
        hostId: host.id,
      });
      let removals = 0;
      const provider = validatePluginEnvironmentProviderDeclaration({
        id: "repro-provider",
        displayName: "Repro",
        description: "Reproduction fixture",
        icon: "Folder",
        policy: { retireGraceMs: 0 },
        create: async () => ({ status: "failed", message: "Not used" }),
        remove: async () => {
          removals += 1;
          return { status: "removed" };
        },
      });
      const record = { pluginId: "repro-plugin", provider };
      setPluginEnvironmentProviderBridge({
        listEnvironmentProviders: () => [record],
        getEnvironmentProvider: (id) =>
          id === provider.id ? record : undefined,
        invokeProvider: async (_pluginId, _label, run) => ({
          ok: true,
          value: await run(),
        }),
        decisionTimeoutMs: 10000,
      });
      const environment = seedEnvironment(harness.deps, {
        hostId: host.id,
        projectId: project.id,
        path: "/tmp/repro-workspace-not-created",
        status: "error",
        environmentProviderId: provider.id,
        environmentProviderPluginId: record.pluginId,
        environmentProviderInstanceKey: "repro-instance",
        providerOwnsPath: true,
      });
      const operationId = `environment:${environment.id}:repro-instance:teardown`;
      harness.db
        .insert(environmentHookOperations)
        .values({
          id: operationId,
          operationId,
          hostId: host.id,
          path: environment.path!,
          kind: "teardown",
          startedAt: 1,
        })
        .run();
      let cancellations = 0;
      registerHostRpcResponder(harness, {
        hostId: host.id,
        sessionId: session.id,
        handle: async (request) => {
          if (request.command.type === "environment.hook.run")
            return {
              ok: false,
              errorCode: "command_failed",
              errorMessage:
                "Environment hook outcome is unknown after daemon restart",
            };
          if (request.command.type === "environment.hook.cancel") {
            cancellations += 1;
            return { ok: true, result: { status: cancelStatus } };
          }
          throw new Error(`Unexpected RPC: ${request.command.type}`);
        },
      });
      const attempts: unknown[] = [];
      try {
        for (let attempt = 0; attempt < 3; attempt += 1) {
          await sweepProviderEnvironment(harness.deps, environment.id);
          const current = getEnvironment(harness.db, environment.id)!;
          const operation = harness.db
            .select()
            .from(environmentHookOperations)
            .where(eq(environmentHookOperations.id, operationId))
            .get()!;
          attempts.push({
            status: current.teardownStatus,
            attempt: current.teardownAttempt,
            finishedAt: operation.finishedAt,
            retryDelayMs:
              current.retireAt === null
                ? null
                : Math.round((current.retireAt - Date.now()) / 1000) * 1000,
          });
          if (current.teardownStatus === "removed") break;
          harness.db
            .update(environments)
            .set({ retireAt: 0 })
            .where(eq(environments.id, environment.id))
            .run();
        }
        const accepted = cleanupEnvironment(harness.deps, environment.id);
        await sweepProviderEnvironment(harness.deps, environment.id);
        console.info(
          JSON.stringify({
            cancelStatus,
            attempts,
            cleanupAccepted: accepted,
            removals,
            cancellations,
          }),
        );
        if (cancelStatus === "terminated") {
          expect(
            getEnvironment(harness.db, environment.id)?.teardownStatus,
          ).toBe("removed");
          expect(removals).toBe(1);
        } else {
          expect(
            getEnvironment(harness.db, environment.id)?.teardownStatus,
          ).toBe("failed");
          expect(removals).toBe(0);
          expect(cancellations).toBeLessThanOrEqual(1);
        }
      } finally {
        setPluginEnvironmentProviderBridge(undefined);
      }
    });
  },
);

    const { host, session } = seedHostSession(harness.deps);
    const operationId = "repro-interrupted-setup";
    harness.db
      .insert(environmentHookOperations)
      .values({

        return { ok: true, result: { status: "unknown" } };

5. Root cause

  1. The daemon tracks hook operations only in a runtime-manager-keyed in-memory map. cancelEnvironmentHook returns the same unknown status for an absent/cancelled operation and for terminationUnverified. The reply cannot distinguish these reasons.
  2. cancelPendingEnvironmentHook throws before setting finishedAt when status is unknown: 
    if (result.status === "unknown")
  throw new Error(
    "Environment hook outcome is unknown after interruption. Automatic cleanup is blocked; inspect the workspace before recovering it.",
  );
    The persisted operation remains pending, so another request cannot make new progress from that record alone.
  3. Cancelled preparation invokes the same setup-hook cancellation guard. That guard can reject before runRemove. Separately, the teardown-hook catch awaits cancellation before continuing removal, so an unknown reply escapes the intended continue-removal path.
  4. runRemove catches failure and schedules retry records failed status and a fixed delay: 
    teardownStatus: "failed",
teardownMessage: message,
retireAt: Date.now() + REMOVE_RETRY_MS
    REMOVE_RETRY_MS is 60,000. Eligible teardown increments the attempt counter and calls the same removal code. There is no progress-dependent stop condition for this ambiguity.
  5. cleanupEnvironment only resets eligibility and asynchronously sweeps; the API returns acceptance rather than completed cleanup. The environment cleanup command has no recovery option. No supported environment action in this path resolves the hook outcome.

Safety boundary: hook processes use detached process groups where supported. A newer in-memory registry does not prove that a former process group exited. The existing daemon memory-loss test exercises a new runtime alongside the old hook; the unverified-stop test exercises the other ambiguous reply reason. Both passed in each checkout.

6. Proposed fix and automation safety

Represent reconciliation evidence separately from the generic unknown outcome, preserve process-liveness safeguards, stop or bound retries that cannot gather new evidence, and provide an explicit inspection-based recovery action through both CLI and SDK. Recovery must not infer that detached descendants exited merely because a daemon restarted. The current cancellation response contract contains only unknown/terminated; safely extending its meaning or fields requires protocol compatibility work. A recovery operation also needs product policy and durable-state semantics.

No automatic production fix: an open linked PR already exists, and a complete root-cause repair exceeds the rule's no-protocol/no-policy-change simple-fix boundary. No fix branch was pushed and no duplicate PR was created. The new reproduction file remains a report artifact only.
