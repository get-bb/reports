#8241 · Selection actions falsely activate modal shortcut gating

Bug Priority: Medium Effort: Low ui · GitHub issue · November 26, 2026

Trusted base: b0ddaad731565d7e4de68d824120d802fc78f7d5 from origin/main.

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro.

1. TL;DR

The floating text-selection actions are not a modal, but their default Radix accessibility role makes the application treat them as one. The real command provider consequently declines both New thread and an app-target plugin command while the actions are visible. A DOM integration regression passes its no-menu control, then fails for both commands with selected text and the real menu mounted. The same result occurs in a second clean checkout of trusted main. Correct the selection actions' semantics locally rather than weakening protection for real modal dialogs.

5. Root cause

TimelineSelectionMenu.tsx:271 mounts an open Radix Popover, does not override its content role, and prevents autofocus. The installed Radix implementation defaults modal to false but still sets content role="dialog"; caller content props are spread afterward.

<PopoverPrimitive.Root open ...>
  ...
  <PopoverPrimitive.Content
    {...portalScopeProps}
    data-touch-selection-passthrough
    ...
    onOpenAutoFocus={(event) => event.preventDefault()}
  >

AppCommandProvider.tsx:103 considers any non-inert open dialog a modal:

'[role="dialog"][data-state="open"]:not([inert]):not([inert] *)'

The provider recomputes modalOpen at dispatch. The plugin binding resolver excludes app commands when modalOpen is true. The core control uses that same context. The floating selection controls are therefore incorrectly gated as modal content.

6. Proposed fix

Give the floating selection controls a named group role, overriding Radix's default dialog role. These are adjacent action buttons, not a focus-trapping dialog or a toolbar implementing arrow-key navigation. Keep the shared modal selector, dismissal behavior, and focus behavior unchanged. Keep the parameterized regression covering core and plugin commands, plus a real-modal negative control.
