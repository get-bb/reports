#5840 · Context wrappers discard typed CLI error metadata

BugMediumEffort: Lowcli Issue2026-10-20 · base b0bb68655adcc6cd79e495d3484f4011a0640e2e

PARTIALLY REPRODUCED · Root-cause confidence: high for typed-error metadata loss; managed-job-specific trigger unverified.

1. TL;DR

The built CLI preserves an SDK refusal code on an unwrapped thread read but reports the generic code error for the same refusal on a contextualized thread archive. The archive catch block replaces the typed error with a plain Error, discarding metadata before the output layer can inspect it. Both commands still fail with exit status 1; this test does not demonstrate an accepted write. The reported managed-job transport guard is not present in the trusted main commit, and its related PR remains open, so this report does not claim to reproduce that exact guard refusal or prove zero transmitted writes.

import assert from 'node:assert/strict';
import { execFile } from 'node:child_process';
import { mkdtemp, rm } from 'node:fs/promises';
import { createServer } from 'node:http';
import { tmpdir } from 'node:os';
import { join, resolve } from 'node:path';
import { promisify } from 'node:util';

const checkout = resolve(process.argv[2] ?? '.');
const dataDir = await mkdtemp(join(tmpdir(), 'bb-error-metadata-'));
const requests = [];
const server = createServer((request, response) => {
  requests.push({ method: request.method, path: request.url });
  response.writeHead(409, { 'content-type': 'application/json' });
  response.end(JSON.stringify({ error: 'Fixture rejects this operation', code: 'fixture_refusal' }));
});
await new Promise((resolveListen) => server.listen(0, '127.0.0.1', resolveListen));
const address = server.address();
assert(address !== null && typeof address !== 'string');
const execFileAsync = promisify(execFile);

async function invoke(args) {
  const env = {
    PATH: process.env.PATH,
    HOME: dataDir,
    TMPDIR: dataDir,
    BB_DATA_DIR: dataDir,
    BB_CLI_ERROR_LOG: '0',
    BB_CLI_REEXEC: '1',
    BB_SERVER_URL: 'http://127.0.0.1:' + address.port,
  };
  let result;
  try {
    result = { ...await execFileAsync(process.execPath, ['apps/cli/dist/index.js', ...args], { cwd: checkout, env, timeout: 15000 }), exitCode: 0 };
  } catch (error) {
    if (typeof error.code !== 'number') throw error;
    result = { exitCode: error.code, stdout: error.stdout, stderr: error.stderr };
  }
  return { exitCode: result.exitCode, envelope: JSON.parse(result.stdout), stderr: result.stderr.trim() };
}

try {
  const unwrapped = await invoke(['thread', 'list', '--json']);
  const wrapped = await invoke(['thread', 'archive', 'thr_metadata_fixture', '--json']);

  assert.equal(unwrapped.exitCode, 1);

5. Root cause

BbHttpError stores the HTTP error code and status; response resolution constructs it from the fixture response.

The archive catch block routes this error through prependErrorContext:

export function prependErrorContext(context: string, err: unknown): Error {
  return new Error(`${context}: ${getErrorMessage(err)}`);
}

The helper preserves only rendered text, not the error subtype, code, hint, exit status, or cause. The action output handler recognizes CliUsageError, CliExitError, and BbHttpError, otherwise selecting error. The newly allocated plain Error fails those checks. The unwrapped thread-list control retains the SDK error and therefore its original code.

6. Proposed fix

Preserve typed error metadata when adding context, rather than reducing the error to text. Preserve the contextual message, original code and hint, and any explicit exit status; keep arbitrary non-Error inputs supported. Before proposing a fix for the exact managed-job issue, land its prerequisite on trusted main and add a regression that exercises a wrapped mutation, asserting the specific refusal code, nonzero exit, and zero transmitted mutations. No fix branch or PR was created: this report only partially reproduces the reported scenario, and the exact refusal path is not yet on the authorized base.
