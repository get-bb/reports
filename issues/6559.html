#6559 · Git index-copy fallback rejects non-directory index paths

BugPriority: MediumEffort: Lowworkspaces GitHub issue2026-10-29 · base 3bacfac9ed69d42392076e5b3da2815bec822cd8

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro.

1. TL;DR

The Git plugin fails an otherwise valid workspace status read when Git reports an index path beneath a regular file. The optional index-copy optimization checks that path using a real filesystem stat, but handles only missing entries, not a non-directory ancestor. The resulting ENOTDIR escapes before Git can produce its diff. A focused regression reaches the production WorkspaceReads status method with a real repository and real filesystem, reproduces the error in two clean trusted checkouts, and succeeds after a narrow fallback change. This verifies the shared host-layer failure, not the third-party machine integration or its downstream cleanup UI.

import { execFileSync } from "node:child_process";
import { tmpdir } from "node:os";
import fs from "node:fs/promises";
import path from "node:path";
import { afterEach, describe, expect, it, vi } from "vitest";
import { initRepo, makeTempDir } from "@bb/test-helpers";
import { runGit } from "bb-environment-provider-host/workspace-git";
import { WorkspaceReads } from "./workspace-reads.js";

let freshReads = 0;
function fresh() {
  freshReads += 1;
  return { work: `copy-work-${freshReads}`, refs: `copy-refs-${freshReads}` };
}

const UNCOMMITTED = { type: "uncommitted" } as const;
const STATUS_BUDGET = {
  maxUntrackedLineStatFiles: 50,
  maxUntrackedLineStatBytes: 1024 * 1024,
};

function changedFiles(reads: WorkspaceReads) {
  return reads
    .diffFiles({
      freshness: fresh(),
      target: UNCOMMITTED,
      maxFiles: 50,
      ignoreWhitespace: false,
    })
    .then((result) =>
      result.files.map((file) => `${file.statusLetter} ${file.path}`),
    );
}

async function startOfSecond(): Promise<void> {
  const remainder = 1_000 - (Date.now() % 1_000);
  await new Promise((resolve) => setTimeout(resolve, remainder + 20));
}

afterEach(() => {
  vi.restoreAllMocks();
  vi.unstubAllEnvs();
});

describe.skipIf(process.platform === "win32")("WorkspaceReads index copy", () => {
  it("reads status and diffs when the resolved index is below a marker file", async () => {
    const repo = await initRepo(await makeTempDir("bb-index-copy-marker-"));
    const storage = await makeTempDir("bb-index-copy-storage-");
    const gitDir = path.join(storage, "git-dir");
    await fs.rename(path.join(repo, ".git"), gitDir);
    await fs.writeFile(path.join(repo, ".git"), `gitdir: ${gitDir}\n`);
    await fs.writeFile(path.join(repo, "README.md"), "edited\n");
    const realGit = execFileSync("which", ["git"], { encoding: "utf8" }).trim();
    const shimDir = await makeTempDir("bb-git-marker-index-");
    await fs.writeFile(
      path.join(shimDir, "git"),
      `#!/bin/sh\ncase " $* " in *" rev-parse --git-path index "*) printf '.git/index\\n'; exit 0;; esac\nexec "${realGit}" "$@"\n`,
      { mode: 0o755 },
    );
    vi.stubEnv("PATH", `${shimDir}${path.delimiter}${process.env.PATH ?? ""}`);
    const reads = new WorkspaceReads(repo, tmpdir());

    try {
      expect(
        await reads.getStatus({ freshness: fresh(), ...STATUS_BUDGET }),

    } finally {
      await reads.dispose();
    }
  });

      const stats = await realLstat(target, options);
      if (target !== file) return stats;

    const untracked = async () =>
      (
        await reads.getStatus({ freshness: fresh(), ...STATUS_BUDGET })
      ).workingTree.files.find((entry) => entry.path === "notes.txt");

    expect(await untracked()).toMatchObject({ insertions: 1 });
    await fs.writeFile(file, "a\nb\n");
    expect(await untracked()).toMatchObject({ insertions: 2 });
  });

5. Root cause

The host status handler calls WorkspaceReads.getStatus. Status enrichment runs Git diff through withIndexEnv and acquireIndexCopy. The index location is resolved by rev-parse; acquireIndexCopy stats it and returns null for ENOENT, which already means run the diff without a replacement GIT_INDEX_FILE. POSIX reports ENOTDIR, rather than ENOENT, when a non-final path component is a regular file. Because that code is not recognized, the optional optimization becomes a hard failure of the workspace read.

  private async acquireIndexCopy(): Promise<IndexCopy | null> {
    const realPath = await this.realIndexPath();
    const stats = await fs.stat(realPath).catch((error: unknown) => {
      if (error instanceof Error && "code" in error && error.code === "ENOENT") {
        return null;
      }
      throw error;
    });
    if (stats === null) return null;

This is not a general inability of Git to operate through a marker file: the fixture has valid backing metadata and real Git can read it. The incompatible assumption is that the advertised index must be traversable through the host filesystem.

6. Proposed fix

Handle ENOTDIR alongside ENOENT at the index stat boundary. Reuse the existing null fallback so Git reads its own index without a copied GIT_INDEX_FILE. Do not catch every filesystem error: permission failures and unexpected I/O failures should retain their existing error reporting. No public SDK, CLI, wire contract, packaging, data, or authentication changes are needed.

The implemented candidate changes two files in the existing Git subsystem: 36 additions plus one deletion, 37 total changed text lines. No binary, dependency, generated, migration, or lockfile changes.
