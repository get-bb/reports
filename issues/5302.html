#5302 · Recording export in the native shell

Bug High priority Medium effort mobile, ui · Issue · October 9, 2026

Trusted base: 6d3e82f35dfb10dbf0e05dc87e71c876d2e8759c

PARTIALLY REPRODUCED · Root-cause confidence: medium · Reproduction label: partial-repro

1. TL;DR

The reported symptom is an audio recovery action that produces no saved recording in the native iOS app. A direct source-level probe confirms that export creates a page-local object URL and clicks a download anchor, even with a usable iOS bridge installed; it neither calls native sharing nor Web Share. However, the proposed explanation that the shell always rejects blob navigation is incorrect: the real URL policy allows same-origin blob URLs for root-mounted servers, while prefixed mounts reject them. The existing native share validator rejects both blob and data URLs. This Linux investigation does not reproduce the iOS user-visible failure, toast-dismissal loss, or reload loss on hardware; the verdict deliberately remains partial.

5. Root cause and limits

Verified gap: Failed-audio export only clicks a blob download anchor; there is no native file handoff. Same-origin blob navigation is allowed on root mounts, so the reported universal navigation rejection is not the cause. The native WebView screen has no file-download callback in this path. Which WKWebView callback fires for this action, and whether the native download implementation loses the bytes, remain unmeasured. Missing native handoff is a plausible explanation of the reported iOS symptom, not a fully proven device-level root cause.

  • Voice hook: local File and error-toast callbacks. The toast callback captures audioFile; there is no durable save in this branch.
  • Export helper: complete implementation.
  • Native navigation handler and debug setting.
  • URL policy. A same-origin blob URL retains the embedded HTTPS origin; with no server path prefix, the early return admits it. Blob pathname is not /bb, so a prefixed mount fails that check.
  • Share boundary validation: only HTTP(S) URL payloads, text, and title; no recording byte/file payload.
  • Native share handler forwards accepted share payloads to Share.share.
const OBJECT_URL_REVOKE_DELAY_MS = 60_000;

export function downloadBlob(blob: Blob, fileName: string): void {
  const url = URL.createObjectURL(blob);
  const anchor = document.createElement("a");
  anchor.href = url;
  anchor.download = fileName;
  document.body.append(anchor);
  anchor.click();
  anchor.remove();
  setTimeout(() => URL.revokeObjectURL(url), OBJECT_URL_REVOKE_DELAY_MS);
}

6. Proposed fix and safety check

First instrument the native iOS WebView download delegate with synthetic audio. Then implement a bounded, capability-negotiated file export with native temporary-file cleanup, completion/error feedback, and retention on failure; do not merely allow more URL schemes. Test native export success, cancellation, failure, and page reload, as well as older shells without the new capability. Retain the recording until export has completed; keep the desktop fallback.

No pull request: the actual iOS download failure is not fully reproduced, and a native byte-transfer repair crosses the app/native bridge protocol, outside this rule's single-subsystem, no-protocol-change simple-fix conditions. No production fix, branch, or pull request was created. No open linked pull request was found in issue timeline metadata or the issue-number search at investigation time.
