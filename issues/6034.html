import json
import runpy
from pathlib import Path

root = Path.cwd()
skill = Path('.bb/skills/verify-bb')
test_module = runpy.run_path(str(root / skill / 'scripts/test_inventory.py'))
fixture = test_module['InventoryTest']()
fixture.setUp()
try:
    browser_path = 'apps/cli/src/commands/browser.ts'
    fixture.write(browser_path, (root / browser_path).read_text())
    result = fixture.run_check('--write')
    print(f'Fixture baseline exit: {result.returncode}')
    print(result.stdout + result.stderr, end='')
    assert result.returncode == 0, result.stderr
    snapshot = json.loads((fixture.repo / skill / 'inventory.json').read_text())
    browser = snapshot['groups']['cli:browser']
    assert browser['recipes'] == ['features/desktop.md']
    assert any(entry.endswith(': instances') for entry in browser['declarations'])
    checked = fixture.run_check()
    print(f'Fixture check exit: {checked.returncode}')
    print(checked.stdout + checked.stderr, end='')
    assert checked.returncode == 0, checked.stderr
finally:
    fixture.doCleanups()

5. Root cause

CLI_OWNERS at the trusted base is a deliberate allowlist without a browser entry. Family discovery and owner resolution enumerate command source filenames and fail closed for an absent owner:

for family, paths in sorted(families.items()):
    owner = CLI_OWNERS.get(family)
    if owner is None:
        raise ValueError(f'Unmapped CLI family: {family}; add recipes and an explicit owner')

browser.ts registers the browser family and delegates to the desktop browser SDK. Consequently collection raises before main compares the saved fingerprints or writes either inventory file. The symptom cannot be explained by stale digests, application login or runtime availability.

The original fixtures introduce project.ts but no browser.ts, so they validate the scanner's generic rules without detecting this missing production owner. The existing desktop recipe page also has no dedicated browser CLI recipes. Assigning ownership needs corresponding recipe documentation, not a broad allowlist relaxation.

6. Proposed fix and verification

The implemented candidate adds browser → desktop to the existing table, four browser CLI/SDK recipe rows and an index link outside the historical audit. It preserves unknown-family rejection, source fingerprints, missing-recipe checks, historical verification results and all recorded baselines. It changes 81 text lines, all additions, across four files in the existing verification-skill subsystem; no dependency, protocol, generated file or stored-data change is involved.

Two focused regressions were added before the owner entry:
