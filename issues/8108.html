#8108 · Pi manual-compaction settlement recovery

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium

1. TL;DR

A deterministic adapter-level replay reproduces an interruption error after a successful manual compaction even though a subsequent agent run completes. The real BB PiRpcSession and delta translator generate the error; the test does not substitute their settlement logic. Successful manual compaction emits its own completed boundary, but does not identify the preceding aborted run as intentional recovery. The settlement path consequently retains the abort error before or during the continuation. This was repeated in a second clean trusted checkout, but the original third-party extension, Pi 1.6.0, model, and live workload were not exercised; their exact causal ordering remains unverified.

5. Root cause

Verified conditional mechanism: the classifier maps an explicit aborted settlement or the last assistant's aborted stop reason to the interruption diagnostic, without consulting successful manual compaction or continuation intent. Native overflow recovery has special handling, but manual compaction is tracked for input queuing and delivery rather than marking the interrupted run as recovered.

if (event.aborted === true || last?.stopReason === "aborted") {
  return "Pi run interrupted unexpectedly; no automatic resume was attempted";
}
  1. compaction_end(reason: manual) becomes context.compacted followed by its own completed turn boundary when successful. This completion is not evidence that the interrupted agent run succeeded.
  2. If the continuation starts before the final settlement, reportSupersededRunFailure still classifies the old aborted assistant as failure. Its suppressions cover native retry/overflow recovery, not a successful manual compaction plus extension continuation.
  3. If the old settlement arrives first, deliverSettlement immediately computes its abort error and retires that run. A later successful run does not retroactively retract the earlier error.
  4. The translator turns the retained settlement error into provider.error. Thus a compaction completion and an error can coexist with a subsequently successful continuation.

  • Continuation delivery — plugins/provider-pi/src/bridge/rpc-session.ts:741

Confidence limit: this explains the diagnostic for the tested event streams with high confidence. Confidence that it is the exact live extension cause is medium: the replay chooses event ordering and valid channel identities rather than obtaining them from that extension and runtime. The pinned Pi runtime source supports manual compaction events with willRetry: false, and emits authoritative settlement after asynchronous extension handlers, but that alone does not establish the reported Pi 1.6.0 sequence.

6. Proposed fix and safety decision

No product pull request was opened. Only the adapter replay is reproduced; the live extension settlement chain remains unverified. Removing abort errors unconditionally, or treating every successful manual compaction as recovery, would hide the missing-continuation failure protected by the negative control. Suppressing errors only in the superseded-run path would miss the after-settlement case.

The next experiment is a trusted local extension fixture running through an actual Pi process, capturing bridge-channel settlement identities alongside RPC events while exercising successful compaction, compaction failure, cancellation, and absent/delayed continuation. First establish a reliable way to correlate an intentional extension recovery with the interrupted run. Then add recovery-aware handling at the session owner while retaining real abort and failed-compaction errors; do not infer intent from proximity or prose.

Safe-fix gate: the investigative patch is one test file, 75 additions and zero deletions, and passes git diff --check. It is not a fix: its two recovery assertions deliberately remain red, no safe production correction is proven, and live integration coverage is missing. Consequently it was not pushed to the product repository. No dependency, protocol, schema, stored data, packaging, or release behavior was changed.
