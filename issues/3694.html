PARTIALLY REPRODUCED · Root-cause confidence: high for the pagination defect

1. TL;DR

The paginator can discard every supplied row while claiming older history exists without a continuation cursor. A synthetic two-row reproduction demonstrates this on current main. Moving the ownership boundary past the first row causes the failure, even though a later row lies inside the owned range. The live event-selection chain and server performance were not reproduced.

5. Root cause

Segment construction uses the first row as its cursor when no message anchor exists. Ownership filtering and empty return then reject the entire group based on that cursor, without considering that another row belongs to the owned range. The empty return preserves knownHasOlderSegments but hard-codes a null cursor. This explains the synthetic failure precisely; it does not establish how the reported production event window arose.

Current main also restores missing request context in the event-selection path, so absence of a particular old profiling stage does not prove request restoration was removed.

6. Proposed fix

First add an event-backed regression covering selection, projection, and a complete older-page walk. Recover ownership of the actual group at window selection, then verify that older cursors make progress. A blanket inclusion of overlapping groups is unsafe: an existing pagination test deliberately excludes older context groups whose source end overlaps the window. Do not synthesize an arbitrary cursor without validating it through the cursor decoder.

No PR: required installation/build and existing regression suites could not run because the pnpm executable is missing. No production code was changed or pushed.
