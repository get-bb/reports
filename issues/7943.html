#7943 · Sequential daemon-message validation

BugPriority: LowEffort: Lowhost · perf · confirmed-reproGitHub issue2026-11-20

Trusted base: 89f1e507d62d0fcd94bd319c61ba2e9cd18f607c, fetched from get-bb/bb origin/main and checked again after reproduction.

Verdict: REPRODUCED · Root-cause confidence: high.

1. TL;DR

Routine daemon messages spend avoidable CPU time rejecting unrelated message formats before validating their own format. The exported daemon-to-server validator is an ordered union with 18 members; a terminal-output message reaches member 14, while a failed RPC also crosses a nested success/failure union. On this machine a 32-byte terminal payload took 9.57–9.71 µs per parse with the current validator versus 0.83–0.90 µs with an experimental discriminator-based validator. The normal daemon send and server receive paths both call the current validator. This is a schema-level performance reproduction, not a measurement of user-visible lag, fleet CPU consumption, or end-to-end WebSocket throughput.

Complete reproduction script

import assert from "node:assert/strict";
import { performance } from "node:perf_hooks";
import { z } from "zod";
import {
  hostDaemonDaemonWsMessageSchema,
  hostDaemonOnlineRpcResponseMessageSchema,
  type HostDaemonDaemonWsMessage,
} from "./src/session.js";

const original = hostDaemonDaemonWsMessageSchema;
const dispatched = z.discriminatedUnion("type", [
  ...original.options.slice(0, -1),
  z.discriminatedUnion("ok", hostDaemonOnlineRpcResponseMessageSchema.options),
]);

function countTypeReads(schema: z.ZodType, message: HostDaemonDaemonWsMessage) {
  let reads = 0;
  const observed = new Proxy(message, {
    get(target, property, receiver) {
      if (property === "type") reads += 1;
      return Reflect.get(target, property, receiver);
    },
  });
  schema.parse(observed);
  return reads;
}

function measure(schema: z.ZodType, message: HostDaemonDaemonWsMessage, iterations: number) {
  for (let warmup = 0; warmup < 1500; warmup += 1) schema.parse(message);
  const samples: number[] = [];
  for (let repeat = 0; repeat < 5; repeat += 1) {
    const started = performance.now();
    for (let iteration = 0; iteration < iterations; iteration += 1) schema.parse(message);
    samples.push(((performance.now() - started) * 1000) / iterations);
  }
  return Number(Math.min(...samples).toFixed(3));
}

const terminalMessage = (bytes: number): HostDaemonDaemonWsMessage => ({
  type: "terminal.output",
  terminalId: "fixture-terminal",
  chunk: { seq: 7, dataBase64: Buffer.alloc(bytes, 65).toString("base64") },
});
const samples: Array<{ name: string; message: HostDaemonDaemonWsMessage; iterations: number }> = [
  { name: "heartbeat", message: { type: "heartbeat" }, iterations: 20000 },
  { name: "terminal-32B", message: terminalMessage(32), iterations: 20000 },
  { name: "terminal-4096B", message: terminalMessage(4096), iterations: 6000 },
  { name: "terminal-65536B", message: terminalMessage(65536), iterations: 1000 },
  {
    name: "rpc-failure",
    message: {
      type: "host-rpc.response",
      requestId: "fixture-request",
      commandType: "host.list_files",
      ok: false,
      errorCode: "fixture-error",
      errorMessage: "Fixture operation did not complete",
    },
    iterations: 20000,
  },
];

console.log(JSON.stringify({ node: process.version, zod: z.core.version, options: original.options.length }));
for (const sample of samples) {
  assert.deepEqual(original.parse(sample.message), dispatched.parse(sample.message));
  const originalReads = countTypeReads(original, sample.message);
  const dispatchedReads = countTypeReads(dispatched, sample.message);
  const originalUs = measure(original, sample.message, sample.iterations);
  const dispatchedUs = measure(dispatched, sample.message, sample.iterations);
  console.log(JSON.stringify({ name: sample.name, originalReads, dispatchedReads, originalUs, dispatchedUs }));
}

const malformedMessages = [
  { type: "fixture-unsupported" },
  { type: "terminal.output", terminalId: "fixture-terminal", chunk: { seq: -1, dataBase64: "@@" } },
];
for (const message of malformedMessages) {
  const originalResult = original.safeParse(message);
  const dispatchedResult = dispatched.safeParse(message);
  assert.equal(originalResult.success, false);
  assert.equal(dispatchedResult.success, false);
  console.log(JSON.stringify({
    invalidType: message.type,
    originalIssues: originalResult.error?.issues.map(({ code, path }) => ({ code, path })),
    dispatchedIssues: dispatchedResult.error?.issues.map(({ code, path }) => ({ code, path })),
  }));
}
console.log("PASS: valid payload outputs match; invalid payloads remain rejected.");

5. Root cause

The validator uses ordered alternatives rather than indexing the explicit message discriminator. Rejecting earlier alternatives incurs field validation and issue construction before the correct message object is reached. For RPC failures the outer union also enters a plain nested union and first rejects its success branch. The runtime read counts agree with the source member order; they are measured separately from the timing loops so proxy overhead does not contaminate timings.

Outer union, session.ts:846:

export const hostDaemonDaemonWsMessageSchema = z.union([
  desktopBrowserChangedSchema,
  hostDaemonMachineShutdownAckMessageSchema,
  hostDaemonHeartbeatMessageSchema,
  ...
  hostDaemonTerminalOpenedMessageSchema,
  hostDaemonTerminalOutputMessageSchema,
  ...
  hostDaemonOnlineRpcResponseMessageSchema,
]);

Nested RPC union, session.ts:522:

export const hostDaemonOnlineRpcResponseMessageSchema = z.union([
  hostDaemonOnlineRpcResponseSuccessSchema,
  hostDaemonOnlineRpcResponseFailureSchema,
]);
  • Daemon send boundary: const parsed = hostDaemonDaemonWsMessageSchema.parse(message).
  • Server receive boundary: passes the same exported schema to parseSocketValue.
  • Server parser: const result = schema.safeParse(value).
  • Base64 validation remains a separate payload-size-dependent cost.
  • The package entry point publicly re-exports the session schemas.

6. Proposed fix and safety decision

A contained follow-up can dispatch the outer message validator by type and its RPC success/failure validator by ok, while retaining every member's field validation. The script demonstrates the performance opportunity without dropping validation. Cover valid and malformed messages across all variants, especially RPC success command dispatch, unknown types, and strict object-key rejection.

No automatic fix PR: the repair modifies exported daemon protocol validation schemas. This automation's simple-fix policy excludes public protocol/schema changes, even when valid wire fields appear unchanged. The observed unknown-type error-path change also means diagnostic compatibility should not be assumed. No production patch, fix branch, or fix push was made.
