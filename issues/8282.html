#8282 · ACP child-session negotiation and routing gaps

BugPriority: MediumEffort: Highproviders · provider-acp · partial-repro Issue #82822026-11-27 · base b0ddaad731565d7e4de68d824120d802fc78f7d5

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high for the bridge gaps tested here; live Cursor background behavior is unverified.

1. TL;DR

BB's Cursor ACP path currently has no negotiated child-session support. A local diagnostic peer demonstrates that BB sends no subagent capability and discards child-session text while successfully displaying parent-session text. Lifecycle-shaped notifications alone also do not create a delegation item. A deliberately unanswered prompt remains pending during a one-second observation and stops when the user explicitly cancels it. These results confirm bridge-side gaps, but do not reproduce a real Cursor background task ending early or a real provider hanging during its completion drain.

5. Root cause

Negotiation does not offer or retain child-session capability

The initialize builder has no dialect-specific subagent feature. Enabling the parameterized picker only affects picker metadata; it does not enable child sessions. The decoder also has no subagent capability field.

Routing and translation only understand the current parent session

After startup and load handling, a session ID mismatch returns before updates reach the model or translator. Thus an associated child message cannot reach the user-facing delta stream. Recognizing the association requires an explicit child-session registry and lifecycle handling; merely removing this filter could mix unrelated sessions into the parent thread.

6. Proposed fix and automation safety

First verify the actual provider extension contract against a trusted protocol source and a controlled live Cursor session. Then implement typed lifecycle decoding, child-to-parent correlation, nested event translation, and background-state handling before advertising support. Preserve the current session isolation rather than accepting every session ID. Timeout design needs a defined progress signal, idle and overall limits, cancellation grace, and cleanup for unresponsive peers; choose these deliberately so normal long-running work is not cancelled arbitrarily.

No automatic fix PR: the complete repair requires ACP wire-schema/capability changes and a product decision about timeout policy, both forbidden by this rule's simple-fix gate. No production fix, branch, commit, or push to the target repository was attempted. The diagnostic assertions are intentionally still failing on unchanged production code.

No linked or matching open PR was found through the issue timeline and an open-PR search for the issue number at investigation time. No PR branch was checked out or executed.
