#7181 · Plugin credential values bypass diagnostic masking

BugUrgentEffort: Mediumsecurity, providers Issue #71812026-11-06 · trusted main 14b3293254da0a3b4c858a01c5415d91f17aa7b5

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

Provider credentials are correctly supplied to their provider but also copied into diagnostic entries without masking. The environment resolver masks core contributions, not plugin contributions such as Account Pooler credentials. A focused test using only synthetic values fails for all three credential names in two clean worktrees of trusted main; an equivalent core-source control passes. The persistence, raw-event API, CLI JSON and diagnostic-display paths preserve those strings according to source inspection. This establishes an avoidable persistence and secondary-disclosure path, not additional agent authority beyond credentials already intentionally supplied to it.

5. Root cause

  1. Account Pooler emits plain-string provider and parent-marker credentials: provider credential contributions; parent-marker contributions. The server attaches plugin provenance without sensitivity metadata: plugin contribution resolution.
  2. The runtime resolver constructs a real environment and diagnostic entries separately but masks diagnostic contributions only by core ownership: environment resolver.
envVars[contribution.name] = value;
...
entries.push({
  name: contribution.name,
  source: contribution.source,
  value: "core" in contribution.source ? { masked: true } : value,
  reason: contribution.reason,
});

The plugin-source branch stores the same plaintext in both outputs, regardless of name. The core-source branch uses a masked object. The test demonstrates this distinction without reading any real credentials.

  1. The runtime forwards the resolved entries into provider.env-resolved without another redaction pass: event emission. The public event schema accepts raw strings as well as masked objects.
  2. The server serializes the event remainder using data: JSON.stringify(data), and database insertion forwards input.data: event serialization; database event write.
  3. The raw-event route returns stored rows and CLI JSON stringifies them unchanged: raw event API; CLI JSON output. The diagnostic renderer displays raw strings verbatim and substitutes bullets only for masked objects: diagnostic renderer.

History: source blame attributes the core-only masking branch to f8142f54d21. The plugin authoring documentation describes the current disclosure behavior. A final fetch found no newer main commit affecting the inspected resolver or serialization path.

Proof boundary: production of plaintext diagnostic entries was executed twice. Event emission, storage, API transport, CLI and display were traced statically rather than exercised with a live provider. Exact retention, a packaged release and actual account compromise are not established by this report.

6. Proposed fix and automation safety gate

Keep provider values in the execution environment, but establish a separate confidentiality policy for diagnostic entries before event emission. Decide a compatible masking default for plugin contributions and whether sensitivity metadata is needed. Preserve useful name/source/reason information, ensure all output surfaces consume the redacted representation, and address historical stored plaintext separately.

No automatic PR: changing the documented public diagnostic contract and its security disclosure policy is outside the rule's simple-fix limits. A field's permitted type need not change for its public meaning to change. No production patch or fix branch was started or pushed.
