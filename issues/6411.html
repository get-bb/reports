#6411 · Runtime probe errors discard termination signals

BugHighEffort: MediumpluginsGitHub issue2026-10-27 · base c6c23be71

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium overall; high for signal loss. Reproduction label: partial-repro.

1. TL;DR

Browser Automation verifies a downloaded runtime by executing it with --version before launching a browser. When that process terminates with SIGILL, the current installer reports exit null and loses the useful signal name. A local, checksum-matching test fixture reproduces this diagnostic failure through the real installer in two clean checkouts of trusted main. The current release pin also selects just one Linux x64 artifact using operating system and architecture, not CPU features. This host supports BMI2 and AVX2, so the reported pre-BMI2 processor crash and its exact native instruction were not reproduced; the fixture is not a CPU emulator.

5. Root cause

The process utility returns a real child process (host-process.ts). The installer then listens to close with only its first argument and returns only the nullable code, stdout, and stderr (installer.ts):

child.once("close", (code) => {
  …
  else resolve({ code, stdout, stderr });
});

As demonstrated by the control, a signal-terminated child has a null exit code and a non-null signal. Because the latter is discarded, the version probe cannot report it. The error directly interpolates the null code (version-probe error):

`${asset} did not report version ${release.version} on this host (exit ${probe.code}). ${tail(probe.stderr || probe.stdout)}`

Separately, runtime-pin.ts records version 1.0.0-rc.4 and only one Linux x64 digest. Platform selection ignores CPU features, and artifact naming is simply package plus platform. This explains why current selection cannot distinguish older from newer x64 processors, but source inspection alone does not prove that the shipped executable requires BMI2.

6. Proposed fix and safety gate

Preserve both the child exit code and termination signal in the installer's command result, and include the signal in probe failures while retaining normal exit diagnostics and cancellation/timeout semantics. The focused regression above protects that observable diagnostic contract.

The broader compatibility fix first needs an upstream artifact with verified CPU requirements and a successful run on affected hardware, followed by an explicit selection policy that preserves digest/provenance checks and correct cache identity. Do not bypass validation or infer that any generic SIGILL proves a particular missing CPU feature.
