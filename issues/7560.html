#7560 · ACP completion totals are emitted as context occupancy

BugPriority: MediumEffort: Mediumprovidersprovider-acpGitHub issue

2026-11-14 · trusted origin/main: da3e60b81d560e114a2bec724bb59c997aaaae7f

PARTIALLY REPRODUCED · root-cause confidence: high for the bb mapping; live Grok behavior unverified

1. TL;DR

The Grok-specific ACP adapter treats prompt-completion token totals as the number of tokens currently occupying the context window. A new regression probe against unchanged production code emits an exact, non-estimated context event containing 750,000 used tokens against a 500,000-token capacity. The same result occurs in a second clean checkout with the same test and fresh temporary test resources. This proves the bb conversion and event path, not what a real Grok CLI sends: Grok is not installed in this environment and no live provider or user runtime data was accessed. The literal claim that the visible percentage exceeds 100% is not supported: bb's percentage helper clamps it to 100%, while the raw counts can exceed capacity.

5. Root cause

The Grok prompt-result converter selects inputTokens, falling back to totalTokens, from completion metadata and returns it under the name used:

export function grokContextUsageFromPromptResult(
  result: unknown,
): { used: number } | undefined {
  const parsed = grokPromptResultSchema.safeParse(result);
  if (!parsed.success) {
    return undefined;
  }
  const meta = parsed.data._meta;
  const used =
    meta?.usage?.inputTokens ??
    meta?.inputTokens ??
    meta?.usage?.totalTokens ??
    meta?.totalTokens;
  return used === undefined ? undefined : { used };
}

The Grok emitter pairs that number with the remembered model capacity and marks it estimated:false:

function emitGrokContextWindow(session: AcpThreadSession, used: number): void {
  if (
    session.dialect.id !== "grok" ||
    session.grokContextWindowSize === undefined
  ) {
    return;
  }
  const cost = session.model.snapshot().usage?.cost ?? undefined;
  sendThreadDeltas(session.bbThreadId, [
    {
      kind: "contextWindow",
      used,
      size: session.grokContextWindowSize,
      estimated: false,
      attach: "open",
      ...(cost === undefined ? {} : { cost }),
    },
  ]);
}

Both normal turn completion and compact completion call this converter. There is no measurement of retained context occupancy in these paths. The shared assembler copies used into usedTokens and size into modelContextWindow. The runtime probe passes through that assembler and prints the resulting product event.

The deeper problem is conflating two quantities: a sum of tokens processed across model calls need not equal the tokens retained in the current window. Simply clamping the count to capacity would still invent occupancy, including when a billing sum is below capacity. Existing tests currently encode this conflation: the owner-boundary test expects the fixture's completion input total as occupancy, and the helper test explicitly describes that assumption. The new negative regression is not already covered by those positive expectations.

The visible percentage calculation independently clamps the ratio to [0,1]. This explains the correction to the report's literal percentage claim: an over-capacity raw numerator is proven, a percentage label above 100 is not.

6. Proposed fix and simple-fix gate

Obtain and validate an explicit live context-occupancy signal from Grok/ACP, preferably the existing ACP usage_update used/size path, and keep completion billing totals separate. Cover ordinary turns and compaction. If upstream does not supply that signal, product behavior for an unavailable meter must be decided rather than substituting a total or clamping it.

No fix PR opened. The live Grok field semantics and availability could not be verified here. Choosing between suppressing unavailable measurements and introducing a new provider-specific telemetry source requires a provider/product contract decision, which fails the rule's no-decision simple-fix gate. No production patch, branch, commit, or push was made for bb. The test-only investigation patch is 42 added/deleted text lines across two files in one subsystem; it is evidence, not a proposed complete fix.

Next experiment: capture a sanitized ACP exchange from an isolated authenticated Grok session while varying tool-call count and compaction, comparing a separately measured live window with completion totals. Establish the upstream live-occupancy contract before choosing a replacement implementation.
