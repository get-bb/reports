1. TL;DR

The reported symptom is a native console host surviving a completed terminal command. BB already invokes PTY disposal before announcing terminal exit, so simply adding another call to dispose is not supported by the current source. Inspection of the pinned dependency reveals a more specific candidate: its Windows shell-exit callback removes the native resource record before JavaScript can call the native close routine. Both clean runs exercised the real BB terminal manager and real Linux PTY successfully, but neither executed that Windows code. A Windows native-resource test is supplied below; its Windows branch is explicitly unexecuted.

Test source

import { execFile } from "node:child_process";
import os from "node:os";
import { promisify } from "node:util";
import type { HostDaemonDaemonWsMessage } from "@bb/host-daemon-contract";
import { expect, it, vi } from "vitest";
import { RuntimeManager } from "../runtime-manager.js";
import { TerminalManager } from "./terminal-manager.js";

const execFileAsync = promisify(execFile);

async function countOwnedNativeHosts(): Promise<number> {
  const result = await execFileAsync("powershell.exe", [
    "-NoProfile",
    "-NonInteractive",
    "-Command",
    `@(Get-CimInstance -ClassName Win32_Process -Filter 'ParentProcessId = ${process.pid}' | Where-Object Name -EQ 'conhost.exe').Length`,
  ]);
  const count = Number(result.stdout.trim());
  if (!Number.isSafeInteger(count) || count < 0) {
    throw new Error("Invalid native-host count");
  }
  return count;
}

it("releases a native terminal host after a short command exits", async () => {
  const nativeAuditAvailable = process.platform === "win32";
  const before = nativeAuditAvailable ? await countOwnedNativeHosts() : null;
  const messages: HostDaemonDaemonWsMessage[] = [];
  const logger = {
    debug: vi.fn(),
    error: vi.fn(),
    info: vi.fn(),
    warn: vi.fn(),
  };
  const manager = new TerminalManager({
    logger,
    resolveShell: async () => (nativeAuditAvailable ? "cmd.exe" : "/bin/sh"),
    runtimeManager: new RuntimeManager(),
    sendMessage: (message) => {
      messages.push(message);
      return true;
    },
  });
  try {
    await manager.handleMessage({
      type: "terminal.open",
      contributedEnv: [],
      requestId: "open-lifecycle",
      terminalId: "term-lifecycle",
      target: { kind: "host_path", cwd: os.tmpdir() },
      cols: 80,
      rows: 24,
      start: { mode: "command", command: "exit 0" },
    });
    await vi.waitFor(
      () =>
        expect(messages).toContainEqual({
          type: "terminal.exited",
          terminalId: "term-lifecycle",
          exitCode: 0,
          closeReason: "process-exit",
        }),
      { timeout: 8_000 },
    );
    await manager.handleMessage({
      type: "terminal.close",
      terminalId: "term-lifecycle",
      reason: "user",
    });
    expect(logger.warn).not.toHaveBeenCalled();
    expect(logger.error).not.toHaveBeenCalled();
    if (nativeAuditAvailable) {
      await vi.waitFor(
        async () => expect(await countOwnedNativeHosts()).toBe(before),
        { timeout: 5_000, interval: 500 },
      );
      console.info("native-process-audit=PASS");
    } else {
      console.info(
        `native-process-audit=UNAVAILABLE platform=${process.platform}`,
      );
    }
    console.info("terminal-process-exit=PASS close-after-exit=PASS");
  } finally {
    await manager.shutdownAll();
    manager.dispose();
  }
}, 20_000);

5. Root cause: a native ownership candidate

  1. The trusted lockfile pins node-pty 1.2.0-beta.15 for the host daemon.
  2. BB's default adapter wraps the real node-pty object. Its dispose helper calls that object's destroy method.
  3. The exit listener routes normal process exit to finishTerminalSession, which disposes the PTY before emitting terminal.exited.
  4. In the dependency's distributed lib/windowsTerminal.js, destroy delegates through the readiness queue to kill. Kill calls the Windows agent's kill method, which delegates to its native binding. This is a real disposal path, not an absent BB call.
  5. However, the distributed src/win/conpty.cc shell-exit watcher removes the pty_baton from ptyHandles before notifying JavaScript. The baton owns raw handles and has no destructor that invokes the native pseudoconsole closer.
  6. Its PtyKill routine closes the pseudoconsole only when get_pty_baton still returns a record. A later JS destroy/kill can therefore find no record and do nothing. Calling BB disposal again after exit cannot restore the erased native handle.

These snippets are dependency-source inspection, not a native debugger trace. The installed Windows binary was not executed, so whether it exhibits exactly this source's behavior remains unverified. There is also a readiness-deferred destroy path for terminals that produce no output; the native record-loss mechanism does not require that additional condition.

Account for output draining, active kill, double close, shell-exit/kill races, and both ConPTY modes.
