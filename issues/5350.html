#5350 · Pi worker restart and temporary extension paths

BugHighEffort: Mediumproviders · provider-pi · no-repro open on GitHubOctober 11, 2026 · base 3912f4aaefb7dff55c7e0cb5003b26b5cf1457dc

Verdict: NOT REPRODUCED · Root-cause confidence: low for the reported incident. Confidence is high in the narrower finding that ordinary worker restart, resume, and fork succeed in the tested environment.

1. TL;DR

The report describes Pi failing at startup while loading an extension that tries to read a missing temporary tools file. On current trusted main, a new worker computes its own extension and tools paths rather than accepting an old extension path from persisted session data. A direct process-level check started real Pi, released its session, exited the worker, verified that the old temporary root was gone, and successfully resumed and forked that saved session in a new worker. The same check passed in a second clean checkout. The original macOS incident is not disproved, but its proposed stale-session-path mechanism is not demonstrated by these results, so no production patch is justified.

import { spawn } from "node:child_process";
import { once } from "node:events";
import {
  existsSync,
  mkdirSync,
  mkdtempSync,
  readdirSync,
  readFileSync,
  rmSync,
  writeFileSync,
} from "node:fs";
import { tmpdir } from "node:os";
import { dirname, join, resolve } from "node:path";
import { createInterface } from "node:readline";
import { fileURLToPath } from "node:url";
import { expect, it } from "vitest";
import { z } from "zod";
import { FULL_PERMISSION_OPTIONS } from "./test-support.js";

const responseSchema = z
  .object({
    id: z.number().optional(),
    result: z.unknown().optional(),
    error: z.unknown().optional(),
  })
  .passthrough();
const identitySchema = z.object({ providerThreadId: z.string() });

it("resumes and forks with a fresh worker after the previous scratch root is removed", async () => {
  const root = mkdtempSync(join(tmpdir(), "bb-5350-check-"));
  const workspace = join(root, "workspace");
  const sessions = join(root, "sessions");
  const workerTemps = join(root, "worker-temps");
  for (const directory of [workspace, sessions, workerTemps])
    mkdirSync(directory);
  const repository = resolve(
    fileURLToPath(new URL("../../../../", import.meta.url)),
  );
  const cli = join(
    dirname(
      fileURLToPath(import.meta.resolve("@earendil-works/pi-coding-agent")),
    ),
    "cli.js",
  );
  const workers: ReturnType<typeof startWorker>[] = [];

  function startWorker() {
    const child = spawn(
      process.execPath,
      [
        "--conditions=source",
        "--import",
        "tsx",
        join(
          repository,
          "packages/provider-bridge-protocol/src/bridge-worker-entry.ts",
        ),
        join(repository, "plugins/provider-pi/src/host.ts"),
        "provider-pi",
        join(root, "plugin-data"),
      ],
      {
        cwd: repository,
        env: {
          PATH: process.env.PATH,
          HOME: root,
          TMPDIR: workerTemps,
          PI_CODING_AGENT_DIR: join(root, "agent"),
          BB_PI_BRIDGE_SESSION_DIR: sessions,
          BB_PI_BRIDGE_COMMAND: process.execPath,
          BB_PI_BRIDGE_ARGS: JSON.stringify([cli]),
          ANTHROPIC_API_KEY: "unused-local-rpc-test-key",
        },
        stdio: ["pipe", "pipe", "pipe"],
      },
    );
    const messages: z.infer<typeof responseSchema>[] = [];
    let stderr = "";
    let nextId = 0;
    const exited = once(child, "exit");
    const lines = createInterface({ input: child.stdout });
    lines.on("line", (line) =>
      messages.push(responseSchema.parse(JSON.parse(line))),
    );
    child.stderr.on("data", (chunk: Buffer) => {
      stderr += chunk.toString();
    });
    const worker = {
      async request(method: string, params: Record<string, unknown>) {
        const id = ++nextId;
        child.stdin.write(
          `${JSON.stringify({ jsonrpc: "2.0", id, method, params })}\n`,
        );
        const deadline = Date.now() + 60_000;
        while (Date.now() < deadline) {
          const response = messages.find((message) => message.id === id);
          if (response) return response;
          if (child.exitCode !== null || child.signalCode !== null)
            throw new Error(`worker exited: ${stderr}`);
          await new Promise((resolve) => setTimeout(resolve, 20));
        }
        throw new Error(`request timed out: ${method}; ${stderr}`);
      },
      async close() {
        if (child.exitCode === null && child.signalCode === null)
          child.stdin.end();
        await exited;
        lines.close();
      },
    };
    workers.push(worker);
    return worker;
  }

  async function initialize(worker: ReturnType<typeof startWorker>) {
    const response = await worker.request("initialize", {
      protocolVersion: 2,
      client: { name: "local-restart-check", version: "0" },
      grammarVersions: [3, 3],
    });
    expect(response.error).toBeUndefined();
  }

  function scratchRoot() {
    const roots = readdirSync(workerTemps).filter((name) =>
      name.startsWith("bb-provider-bridge-"),
    );
    expect(roots).toHaveLength(1);
    return join(workerTemps, roots[0]!, "pi");
  }

  const threadParams = {
    threadId: "thr_local_restart_check",
    cwd: workspace,
    instructionMode: "append",
    options: FULL_PERMISSION_OPTIONS,
  };
  try {
    const first = startWorker();
    await initialize(first);
    const started = await first.request("thread/start", threadParams);
    expect(started.error).toBeUndefined();
    const { providerThreadId } = identitySchema.parse(started.result);
    const oldScratch = scratchRoot();
    expect(existsSync(join(oldScratch, "bb-pi-extension.mjs"))).toBe(true);
    expect(
      readdirSync(oldScratch).some((name) => name.startsWith("pi-tools-")),
    ).toBe(true);
    const released = await first.request("thread/stop", {
      threadId: threadParams.threadId,
      providerThreadId,
      intent: "release",
      activeTurnId: null,
    });
    expect(released.error).toBeUndefined();
    const sessionFile = join(sessions, `${providerThreadId}.jsonl`);
    if (!existsSync(sessionFile)) {
      const timestamp = "2026-10-11T00:00:00.000Z";
      writeFileSync(
        sessionFile,
        [
          JSON.stringify({
            type: "session",
            version: 3,
            id: "local-restart-check",
            timestamp,
            cwd: workspace,
          }),
          JSON.stringify({
            type: "message",
            id: "user1",
            parentId: null,
            timestamp,
            message: {
              role: "user",
              content: "Local saved history",
              timestamp: 1,
            },
          }),
        ].join("\n") + "\n",
      );
    }
    const history = readFileSync(sessionFile, "utf8");
    await first.close();
    expect(existsSync(oldScratch)).toBe(false);
    console.log("first worker exited; previous scratch root and tools removed");

    const second = startWorker();
    await initialize(second);
    const resumed = await second.request("thread/resume", {
      ...threadParams,
      providerThreadId,
    });
    expect(resumed.error).toBeUndefined();
    expect(identitySchema.parse(resumed.result).providerThreadId).toBe(
      providerThreadId,
    );
    const newScratch = scratchRoot();
    expect(newScratch).not.toBe(oldScratch);
    expect(existsSync(join(newScratch, "bb-pi-extension.mjs"))).toBe(true);
    expect(
      readdirSync(newScratch).some((name) => name.startsWith("pi-tools-")),
    ).toBe(true);
    expect(readFileSync(sessionFile, "utf8").startsWith(history)).toBe(true);
    console.log("real Pi resumed successfully using a new worker scratch root");
    const forked = await second.request("thread/fork", {
      ...threadParams,
      threadId: "thr_local_fork_check",
      sourceProviderThreadId: providerThreadId,
    });
    expect(forked.error).toBeUndefined();
    expect(identitySchema.parse(forked.result).providerThreadId).not.toBe(
      providerThreadId,
    );
    console.log(
      "real Pi forked successfully after the previous worker root was removed",
    );
  } finally {
    await Promise.all(workers.map((worker) => worker.close()));
    rmSync(root, { recursive: true, force: true });
  }
}, 180_000);

5. Root-cause analysis

The cause of the original incident is not established. Current source does confirm that reading a missing tools file inside the extension would throw. However, a missing tools file is not proof that an extension path was persisted across workers: the extension reads the tools path from its process environment at load time, and the two paths describe different resources.

  • bridge-worker-entry.ts:36–49 allocates a per-worker temporary root and removes it at process exit; lines 91–116 calls start before consuming requests and removes the root on input closure.
  • bridge.ts:224–247 holds scratch/extension state in module-local memory. The cache starts empty in a new worker process. lines 1241–1247 sets that worker's current scratch directory before requests.
  • bridge.ts:563–569 sends resume into session construction. lines 600–610 selects construction inputs explicitly, and lines 710–744 builds fresh runtime options:
    scratchDir: requireScratchDir(),
extensionPath: requireExtensionPath(),
    No persisted extension path is consumed on this route.
  • bridge.ts:916–928 supplies those same local path helpers to the fork helper.
  • rpc-session.ts:195–223 writes the per-child tools file before launch and passes the extension argument. lines 240–255 overrides PI_BB_TOOLS_FILE with the freshly written path and removes scratch files on child exit.
  • bb-pi-extension.ts:168–170 reads that environment path synchronously:
    const toolsFile = process.env.PI_BB_TOOLS_FILE;
const tools = toolsFile ? JSON.parse(readFileSync(toolsFile, "utf8")) : [];

Ordinary cross-process restart cannot carry this module-local extension cache into a fresh worker. A packaging discrepancy, an extra extension/catalog launch, or a teardown-versus-load race would require additional runtime evidence; none is established here. The check covers graceful worker exit, not macOS temporary cleanup during an in-flight child startup, abrupt worker death, or historical packaged execution.

6. Proposed fix / next experiment

No production change is proposed without a failing regression at the actual boundary. On the failing packaged macOS configuration, capture sanitized child launch arguments, whether the referenced tools file exists immediately before extension load, which process initiated that load, and ordering of worker/child exit and cleanup. Compare the installed artifact with this trusted source. This would distinguish stale inherited environment, additional extension loading, a cleanup race, and an artifact mismatch without changing user Pi configuration.

Simple-fix gate: not met because trusted main did not reproduce the defect and no focused regression fails for the reported reason. No branch, production patch, or pull request was created. GitHub metadata and issue timeline showed no linked open pull request at investigation time.
