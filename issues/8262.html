#8262 · Queue admission bypasses thread lifecycle

Bug Priority: Medium Effort: Low threads confirmed-repro

Issue #8262 · 2026-11-26 · trusted main b0ddaad731565d7e4de68d824120d802fc78f7d5

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The shared database queue API accepts a new message after its thread has been archived or soft-deleted. A deterministic test obtains a thread snapshot, retires the persisted thread, then attempts queue admission using the retained identifier. Both retired states produce one new queue row and a queue-change notification instead of refusing the write. The insertion transaction does not enforce current thread lifecycle state. Physical removal is different: an absent parent is already refused on this base. This report proves the database invariant violation, not an end-to-end HTTP or provider race.

import { expect, it } from "vitest";
import { createProject } from "../../src/data/projects.js";
import { upsertHost } from "../../src/data/hosts.js";
import {
  archiveThread,
  createThread,
  deleteThread,
  getThread,
  markThreadDeleted,
} from "../../src/data/threads.js";
import {
  createQueuedThreadMessage,
  listQueuedThreadMessages,
} from "../../src/data/queued-thread-messages.js";
import { noopNotifier } from "../../src/notifier.js";
import { createMigratedConnection } from "../../src/testing.js";

it.each(["live", "archived", "soft-deleted", "removed"] as const)(
  "queue admission respects the %s lifecycle",
  (lifecycle) => {
    const db = createMigratedConnection();
    try {
      const host = upsertHost(db, noopNotifier, { name: "queue-repro-host" });
      const { project } = createProject(db, noopNotifier, {
        name: "queue-repro-project",
        source: { type: "local_path", hostId: host.id, path: "/tmp/queue-repro" },
      });
      const snapshot = createThread(db, noopNotifier, {
        projectId: project.id,
        providerId: "codex",
      });
      if (lifecycle === "archived") archiveThread(db, noopNotifier, snapshot.id);
      if (lifecycle === "soft-deleted") {
        markThreadDeleted(db, noopNotifier, { threadId: snapshot.id });
      }
      if (lifecycle === "removed") deleteThread(db, noopNotifier, snapshot.id);

      const current = getThread(db, snapshot.id);
      expect(snapshot.archivedAt).toBeNull();
      expect(snapshot.deletedAt).toBeNull();
      if (lifecycle === "archived") expect(current?.archivedAt).toEqual(expect.any(Number));
      if (lifecycle === "soft-deleted") expect(current?.deletedAt).toEqual(expect.any(Number));
      if (lifecycle === "removed") expect(current).toBeNull();

      const notifications: string[] = [];
      let accepted = false;
      let refusal = "none";
      try {
        createQueuedThreadMessage(db, {
          ...noopNotifier,
          notifyThread: (_threadId, changes) => notifications.push(...changes),
        }, {
          threadId: snapshot.id,
          content: [{ type: "text", text: "lifecycle probe", mentions: [] }],
          model: "repro-model",
          reasoningLevel: "medium",
          permissionMode: "full",
          serviceTier: "default",
          waitingOn: { kind: "thread-busy" },
          sendAt: null,
          payload: { kind: "inline" },
          systemNotice: null,
        });
        accepted = true;
      } catch (error) {
        refusal = error instanceof Error ? error.message : String(error);
      }

      const actual = {
        accepted,
        rows: listQueuedThreadMessages(db, snapshot.id).length,
        notifications,
      };
      console.log(JSON.stringify({ lifecycle, ...actual, refusal }));
      expect(actual).toEqual(lifecycle === "live"
        ? { accepted: true, rows: 1, notifications: ["queue-changed"] }
        : { accepted: false, rows: 0, notifications: [] });
    } finally {
      db.$client.close();
    }
  },
);

5. Root cause

The shared insertion function computes attachment ownership, queue order, and message state before performing the insert. It never loads or predicates on the target thread's archivedAt or deletedAt.

export function createQueuedThreadMessageInTransaction(
  tx: DbTransaction,
  input: CreateQueuedThreadMessageInput,
) {
  const now = Date.now();
  acquireProjectAttachmentOwnership(
    tx,
    input.threadId,
    projectAttachmentPaths(input.content),
  );

The public wrapper does use an immediate transaction, but serialization alone cannot enforce a condition that is never checked. After the transaction succeeds, the wrapper emits queue-changed.

const row = db.transaction(
  (tx) => createQueuedThreadMessageInTransaction(tx, input),
  { behavior: "immediate" },
);
notifier.notifyThread(input.threadId, ["queue-changed"]);

Archival leaves the thread row present and sets archivedAt. Soft deletion likewise sets deletedAt. Neither makes a foreign-key reference invalid. Conversely, deleteThread physically removes the parent, so that case is not equivalent to soft deletion.

Delayed admission calls the shared insert while retaining args.thread. Explicit queue admission separately reloads the thread in its transaction; that local defense does not establish the shared write invariant.

Root cause: lifecycle policy exists at selected callers rather than at the common transactional insertion boundary. This is a persisted-state admission bug, not evidence of a provider failure or a broken transaction implementation.

6. Proposed fix

At the start of the common insertion function, read the target thread's current lifecycle fields in the insertion transaction. Refuse archived, soft-deleted, and missing threads before attachment ownership changes or message insertion. Keep admission serialized with retirement, and emit no queue notification for a refusal. Surface a typed lifecycle error through the server's conflict response rather than the generic error path. The base error handler has no lifecycle-specific mapping.

Retain the live-thread control and explicitly test markThreadDeleted, not only physical removal. Separately verify the HTTP mapping and delayed API send path. No production changes were made in this investigation.
