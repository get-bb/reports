#7666 · System prompt reconstruction retains SDK snapshot defaults

BugPriority: MediumEffort: Lowprovidersprovider-claude-codeGitHub issue2026-11-17 · base ad0f4f4e8cf2f61cfad629d87f9b7e096fb59f19

Verdict: PARTIALLY REPRODUCED · root-cause confidence: high (SDK contract); live model symptom unverified

1. TL;DR

The bridge reconstructs its system-prompt options from the supplied instructions, but leaves Claude Code's persisted-prompt behavior enabled. The installed SDK documents that this default can reuse a session's original prompt even when a later launch supplies different instructions. A focused executable test at the actual option-builder boundary fails for both append and replace modes, in two trusted checkouts. This verifies the incompatible option selection, not a live model returning stale instructions: no real account, user data, or provider session was accessed. The verdict is deliberately partial because prompt recording is account/backend dependent and a live cold-resume experiment was not performed.

import { describe, expect, it } from "vitest";
import { buildSessionOptions } from "../session-options.js";

describe("system prompt reconstruction contract", () => {
  it.each(["append", "replace"] as const)(
    "%s instructions are not superseded by a persisted SDK snapshot",
    (instructionMode) => {
      const instructions = [
        "Use concise responses.",
        "Use detailed responses.",
        "Use detailed responses.",
      ];
      const prompts = instructions.map((baseInstructions) =>
        buildSessionOptions(
          {
            baseInstructions,
            instructionMode,
            cwd: "/tmp/isolated-instruction-contract",
            permissionMode: "default",
            permissionScope: "workspace",
            serviceTier: "default",
            workflowsEnabled: false,
            chromeEnabled: false,
            disable1MContext: false,
            artifactsEnabled: false,
            sandboxEnabled: true,
          },
          {},
        ).systemPrompt,
      );

      console.log(JSON.stringify({ instructionMode, prompts }));

      for (const [index, prompt] of prompts.entries()) {
        expect(prompt).toEqual(
          instructionMode === "append"
            ? {
                type: "preset",
                preset: "claude_code",
                append: instructions[index],
                snapshot: false,
              }
            : {
                type: "custom",
                prompt: instructions[index],
                snapshot: false,
              },
        );
      }
    },

5. Root cause

The owning subsystem is the Claude Code provider's SDK-option adapter. The provider contract freezes instructions within a session but applies updates at its next construction. The option builder uses the following shapes:

replace: baseInstructions ?? "You are a helpful coding assistant."
append: { type: "preset", preset: "claude_code", append: baseInstructions }

The installed SDK declaration, sdk.d.ts:2468–2522, documents that omitted or true snapshot settings retain the first recorded prompt across requests and resumes until compaction; a bare string follows the same default. It also documents an explicit false value and a custom object representation for opting out. Recording is rolling out and is not effective on every backend, which limits what a local option test can establish.

The trusted path is consistent with the report's mechanism: the server resume context includes instructions; the daemon forwards those instructions; session attachment rebuilds options; and the SDK adapter passes the prompt through. These are static trace findings, not an executed full server/daemon lifecycle.

6. Proposed fix

At every construction, use the SDK's explicit snapshot opt-out for both preset and custom prompts. Keep the existing fallback instruction text and instruction-mode selection. The custom object representation is necessary because bare strings cannot carry this opt-out. Test changed and unchanged resumes in a recording-enabled account, including an existing session with an older record. Also measure cache and extended-thinking consequences rather than assuming a cost-free change.
