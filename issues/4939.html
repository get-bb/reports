#4939 · ACP bridge loses recovery state when its agent exits

BugHighEffort: Mediumproviders · host · provider-acpIssueOctober 5, 2026 · base 53e06758f2c3fdf712f29b3a715787d351e51900

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A local ACP agent really exits after an external signal, but its BB bridge stays alive. The bridge deletes the thread’s session, so submitting another turn in an idle thread returns No active ACP session instead of relaunching the agent. A second defect appears when the agent exits during a pending prompt: the bridge clears its active-prompt flag before emitting the exit error, leaving the runtime’s turn active. Both failures reproduce using the repository’s own ACP fixture, without external agents or account credentials. Retaining the session construction state, completing interrupted turns, and invoking the existing resume path restores subsequent turns.

5. Root cause

  1. The child exit handler rejects pending requests first, then asynchronously stops the process tree before invoking onExit.
  2. The prompt rejection handler clears activePromptKind. By the time onExit calls emitSessionError, the error emitter sees no active prompt and emits no failed-turn delta. The runtime adapter maps the remaining error notification to a warning, which does not end the turn.
  3. The agent onExit callback unconditionally calls removeSession, deleting the saved construction and provider-session mapping even for unexpected exits of established sessions.
  4. turn/start looks up that deleted session and returns -32000 before any restart logic runs.
  5. The existing rebuild mechanism already resumes using saved construction state. Session initialization already uses session/load and warns when it must fall back to session/new. This mechanism is not missing globally; unexpected exits discard the state needed to reach it.
onExit: cancelPendingPermissions(session);
        removeSession(session);
        ... emitSessionError(session, ...);

runTurn catch: ... session.activePromptKind = null;

turn/start: liveSessionForThread(threadId) === undefined
            → sendError(id, -32000, "No active ACP session")

The host unexpected-provider-exit event builder is a separate outer-process boundary. Editing that event builder alone cannot restore an agent child whose still-running ACP bridge deleted its session.

6. Proposed fix and validation

Keep construction state for an unexpectedly exited, established ACP session; continue deleting it for explicit stops, releases, stale callbacks, and failed construction. Preserve the active-prompt marker until the exit callback emits the failed completion, then clear it. Treat an exited connection as a reason for the existing execution-settings reconciliation to rebuild the session before the next turn. Reject dynamic-tool calls against retained but dead connections. Reuse existing session/load, fresh-session fallback, identity, and session/replaced notifications; no new public protocol or dependency is needed.

The implemented candidate changes two ACP bridge files, 126 added-plus-deleted text lines (119 additions and 7 deletions). Seven focused cases pass after the candidate fix. The complete ACP suite passes 373 tests with 4 existing skips; the complete agent-runtime suite passes 307 tests. Both packages’ typechecks and lints pass, as does git diff --check. Real runtime checks pass for idle and active child exits and retain the original provider session ID.

The local fixture confirms correct use of session/load and session identity; it does not prove persisted conversation history for the external agent. If the external implementation refuses restoration, existing fallback deliberately reports context loss.
