#8306 · Claude per-model usage normalization drops fallback windows

Bug Priority: Medium Effort: Low providers provider-claude-code

2026-11-28 · GitHub issue · base b0ddaad731565d7e4de68d824120d802fc78f7d5

Verdict: REPRODUCED at the provider normalization boundary · Root-cause confidence: high · reproduction label: confirmed-repro.

1. TL;DR

The Claude provider can return successful usage containing only the session and overall weekly windows even when its input contains valid per-model weekly data. The normalizer reads model windows exclusively from limits and never consumes the SDK's model_scoped field. A focused regression reproduces this data loss in two clean trusted-base checkouts when limits is absent, empty, or contains only aggregate rows. This is a data-normalization defect, not a rendering defect; no live account, throttling request, or browser was used. The specific claim that newer CLI releases generate this input after throttling remains unverified here.

5. Root cause

The initialization probe returns the SDK usage response without normalizing the model windows. The usage schema explicitly validates aggregates and limits but has no model-scoped parser. Its passthrough retains the raw property without making it a consumed typed input.

The sole model-window normalization path enumerates weekly-scoped limits, deduplicates names, and emits normalized windows. The caller invokes it only on limits:

const windows = [
  usageWindow(parsed.data.five_hour, "Current session", "five-hour"),
  usageWindow(parsed.data.seven_day, "Weekly limit", "weekly"),
  ...scopedWindows(parsed.data.limits),
].filter((window): window is ProviderUsageWindow => window !== null);

If no weekly-scoped limits exist, this call yields no model windows. Successful aggregate parsing still produces status: "ok", so nothing reports a provider-usage error. The downstream usage label builder can label weekly model windows, but cannot recover a window the provider discarded.

6. Proposed fix

Validate model-scoped entries at the external usage boundary. When the canonical limits produce no usable model windows, translate the alternate entries to the existing scoped-limit representation and reuse its normalization. Preserve the canonical limits whenever they produce windows; do not merge conflicting alternative data. This shares name deduplication, percentage clamping, and reset-date handling, adds no public contract, and affects only the existing Claude provider subsystem.

The local candidate changes two files, 82 total text lines (81 additions, 1 deletion). Its focused regression passes after the repair.
