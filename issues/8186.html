#8186 · Deleted workspace misreported as a missing provider executable

BugMedium priorityMedium efforthostworkspaces

Issue #8186 · November 25, 2026 · base fb045a046653cc127656ca3c7243d44ae4c94f3f

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

Deleting the directory behind a cached environment makes the next provider bridge launch fail even though its executable exists. The daemon reports missing_executable because the spawn error names the executable, not the missing working directory. Archiving follows the same workspace-bound launch path and fails before the provider receives its archive request. A cold archive instead fails with path_not_found; neither case falls back to the existing provider maintenance workspace. Three focused command-level regressions reproduce these failures twice on unchanged production code.

5. Root cause

  1. Workspace resolution checks cached path identity but does not revalidate existence. Environment reuse can return a compatible cached entry without reprovisioning.
  2. Provider spawn passes the workspace to spawnManagedProcess as the working directory:
    const managed = spawnManagedProcess({
  command: processConfig.command,
  args: processConfig.args,
  cwd: this.args.workspacePath,
  env,
});
    The operating-system launch fails when that directory is gone. The reported spawn path is still the existing Node executable.
  3. Startup error handling wraps the error message. Error classification recognizes spawn/ENOENT as missing_executable without checking its working directory. Command router places that classification in the RPC failure response.
  4. Archive/unarchive handlers uses a workspace-bound runtime for archive, while unarchive invokes withProviderMaintenanceRuntime. Maintenance runtime creation explicitly creates its own working directory before launch. An uncached missing workspace already produces the correct path error, but archive still cannot proceed.

6. Proposed fix

Disambiguate a workspace-bearing command's missing-executable launch failure against its actual working directory. Preserve genuine executable failures when that directory exists, and do not relabel unrelated provider errors. For archive only, recover from a verified missing workspace by routing the same provider-thread archive request through the existing maintenance runtime, as unarchive already does. Keep live workspace-bound archival unchanged so thread detachment behavior remains intact. Cover both cached and cold archive paths and the structured submit error. No new dependency, protocol field, stored state, or packaging change is necessary.
