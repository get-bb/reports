#5010 · Pending admission loses dispatch author

BugPriority: MediumEffort: Mediumthreadsconfirmed-reproGitHub issue2026-10-06 · base fd31b75fb9c7f40e68747089c911b098763aa851

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A message sent by another agent is recorded as user-authored when it admits a pending destination thread. The dispatch hook sees the correct agent sender, but the persisted first turn loses both the sender ID and the agent envelope. The same service call into an idle, already-started thread preserves attribution. A captured startup command also requests permission escalation as ask, whereas an agent send into an idle thread uses deny in the tested accept-edits mode. Both clean trusted checkouts reproduce the defect; fixing attribution without resolving startup permission policy would leave an inconsistent contract.

6. Proposed fix and autopilot safety decision

Carry the resolved per-message author through pending admission and event creation, and construct the same agent envelope as the started-thread send path. Keep creation ancestry and retry identity separate from this sender. Then resolve startup permission escalation from the accepted author's identity, including restart/recovery behavior; identity can be persisted explicitly or recovered from the canonical startup request event, but either option needs intentional compatibility and policy review.

No automated production fix or pull request: the faithful end-to-end repair changes permission policy, and an attribution-only patch knowingly leaves agent-authored startup using user escalation. Permission/security-boundary changes are excluded by this rule's simple-fix gate. No production branch was pushed. No open pull request linked to #5010 was found through issue cross-reference metadata or the open-PR search; no external prototype code was fetched or executed.
