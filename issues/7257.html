#7257 · Plugin selector ancestor filtering

BugMedium priorityMedium effortplugins · perfGitHub issue2026-11-07

Verdict: REPRODUCED · Root-cause confidence: high. This verdict covers isolated selector overhead on trusted main, not the reported desktop interaction timings.

Trusted base: 55135d1e5045d6c5d3c24f5a4d5556ed3e11cb00.

1. TL;DR

Plugin utility styles impose substantial work even on inserted host elements that are outside every plugin root. Two clean source checkouts generate CSS that takes about 24 ms to style and lay out a synthetic subtree; equivalent separately scoped rules take about 4 ms. The matching roots themselves are not the problem: combining alternatives inside an ancestor :where() prevents Chromium's ancestor filter from extracting a required attribute. Requiring the root-marker attribute is faster but is not behavior-preserving: a built-in toast uses only the named attribute. Separating entire rules by root alternative preserves that case, anonymous portals, zero scope specificity, and nested selector-list specificity.

Matching contract

Computed --probe-0 is 1 on the root and descendant for current and separated forms, whether the root is named-only, named-plus-marker, or anonymous. An unrelated named plugin matches neither. Marker-required output loses both matches on a named-only root; owned-only output loses the anonymous matches.

5. Root cause

pluginScopeRoots returns a union of named roots and unnamed marker roots. scopePluginUtilities puts that union inside one zero-specificity :where(). scopeStatements emits descendant and self rules and preserves nested selector-list specificity. Common utility classes cause these nonmatching descendant rules to be considered on host elements.

The exact browser revision's ancestor identifier collector only traverses :where()/:is() when its selector list has one alternative. Its separate subject-filter implementation can intersect alternatives; that does not provide the missing ancestor attribute here. The timings and engine implementation support the reported ancestor-filter mechanism. No CSS selector-statistics trace was captured.

loadPluginAppBundle previously kept full-scope CSS unchanged when loading served assets, so already-built plugin sheets retained the slow form. Its owned-root negotiation removes the anonymous arm only for eligible bundles and capable clients; it does not repair full-scope requests.

Compatibility counterexample: StarToast sets a named attribute without a root marker. Requiring a marker therefore changes an existing rendered contract, not merely hypothetical third-party markup.

6. Proposed fix and tested patch

At asset loading, split compiler-generated utility rules into one complete rule per root alternative, keeping each :where() single-argument. Duplicate each original selector list and body as a unit rather than splitting list members into independently specific rules. Keep authored non-utility CSS, unmatched lists, declaration strings, and keyframes intact. Derive owned-root variants before splitting full-scope variants, then hash and compress the final served bytes. This preserves current roots without requiring a new marker contract, protocol, dependency, or rebuild of installed plugins.

The patch touches five existing files in the plugin CSS subsystem. The actual patched helper, not just the experimental separated control, was benchmarked: current 24.5 ms versus fixed 4.5 ms. The browser's four-root self/descendant matching matrix was identical before and after. Splitting duplicates declarations and can increase full-scope stylesheet size; normal asset compression remains in use. Exact UI latency benefits remain unmeasured.

7. Verification

The same agent repeated the reproduction from a second clean temporary worktree at 55135d1e5045d6c5d3c24f5a4d5556ed3e11cb00, with a separate frozen install/build, independently generated fixture bytes, and a new empty browser session. Both generated fixture files had the same SHA-256 (3d8f2203dc6584b6a57b8468f2e8d166af9e05ca1c103237d06288bf696fd7f5), and both runs showed the same slowdown and compatibility counterexample. The second compiler test execution bypassed Turbo's result cache and passed 33 tests. No claim of a separate reviewer or independent agent is made.

Report correction after checking source and browser behavior: named roots do not universally carry a marker. The safe patch uses separate alternatives instead of imposing that prerequisite.
