1. TL;DR

The reporter describes intermittent whole-window blanking in macOS desktop 0.49.0 and correlates it with provider model-discovery logs. A server-side diagnostic using 61 synthetic models and a six-second pending refresh does not empty the catalog: cached reads complete while discovery is still pending, and an unchanged result emits no catalog invalidation. The packaged desktop launches its runtime in another OS process; the server then sends model discovery to the host daemon over RPC. These findings do not establish why a macOS window blanks or why native trust evaluation is observed. No macOS GUI, native trust fault, ACP provider binary, or visible blanking was reproduced on this Linux host, so a production fix would be speculative.

5. Root cause

The root cause of the reported visible symptom is unknown. The reported timing is a useful lead but is not enough to identify a blocking thread or a renderer-remount trigger. Source inspection establishes the following boundaries, rather than a UI failure:

  • spawnOwnedRuntime calls startBbAppProcess; startBbAppProcess calls spawn with separate stdio/IPC. createBbAppProcessEnv enables Electron's Node mode for the packaged child, not an in-process server.
  • startFullStackServerProcess and startDaemonProcess start distinct managed processes.
  • startRefresh calls callHostOnlineRpc with provider.list_models. Its elapsed duration includes time awaiting another process; the settlement log is not a measurement of Electron main-thread CPU time.
  • evaluate serves a usable stale catalog during background refresh. settlement change detection compares the picker view before scheduling a change notification.
  • client catalog-change handling invalidates host execution-option queries. That code does not itself request a global window reload.

Separate OS processes weaken the proposed direct JavaScript-thread explanation; they do not disprove native OS contention, proxy-related work elsewhere in Electron, memory pressure, GPU issues, or another invalidation path. None of those alternatives is asserted as a finding.

6. Proposed fix / next experiment

No production patch is justified yet. On a disposable macOS arm64 desktop instance, collect a PID-qualified Electron main/renderer/GPU trace spanning an affected refresh, record renderer navigation, process exits and DOM-remount events, and compare the built-in and remote-server cases. Repeat with a controlled provider discovery delay and independently vary system trust/proxy settings. Only move or change work after identifying the process and stack that causes the blank. A failing regression for that observed mechanism is required before a simple fix.
