#6670 · Path-installed plugins lose source during workspace retirement

BugHigh Effort: Mediumpluginsworkspaces IssueOctober 30, 2026

Trusted base: 9662c45478f4a74f33f11b70187657d97f1e14a7 · Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro.

1. TL;DR

A local plugin installation records the original source directory, even when that directory belongs to a disposable personal workspace. The server recognizes this risk but emits only a logger warning and returns a successful running plugin without that warning. The real personal-workspace deletion handler recursively deletes the directory without consulting installed-plugin registrations. Restarting the plugin runtime then marks the managed-source plugin missing; an otherwise identical plugin installed outside the workspace remains running. A focused reproduction exercised these real installation, filesystem deletion, persistence, and runtime-loading paths twice, including a second clean checkout.

This is an in-process lifecycle reproduction, not a Windows desktop or browser recording. The connection from thread archiving to workspace removal is source-traced below; the reproduction directly invokes the same host removal entry after installation.

import { existsSync } from "node:fs";
import { mkdir, mkdtemp, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { getInstalledPlugin } from "@bb/db";
import { createMigratedConnection } from "@bb/db/testing";
import { experimental_createHostEntryHarness } from "@get-bb/plugin-sdk/testing/host";
import { expect, it, vi } from "vitest";
import { createPersonalWorkspaceHostEntry } from "../../../../../plugins/environment-personal-workspace/host.js";
import { createAiServiceRegistry } from "../../../src/services/ai/ai-service-registry.js";
import { createPluginService } from "../../../src/services/plugins/plugin-service.js";
import { createNoopTelemetryService } from "../../../src/services/system/telemetry.js";
import { testLogger } from "../../helpers/test-app.js";

it("keeps installed plugin sources available after personal workspace retirement", async () => {
  const root = await mkdtemp(join(tmpdir(), "bb-6670-repro-"));
  const dataDir = join(root, "data");
  const db = createMigratedConnection();
  const warnSpy = vi.spyOn(testLogger, "warn");
  const host = experimental_createHostEntryHarness(
    createPersonalWorkspaceHostEntry(),
    {
      experimental_paths: {
        dataDir: join(
          dataDir,
          "plugins",
          "environment-personal-workspace",
          "host-data",
        ),
        tempDir: join(root, "tmp"),
      },
    },
  );
  const createService = () =>
    createPluginService({
      db,
      dataDir,
      appVersion: "0.48.1",
      aiServices: createAiServiceRegistry(),
      telemetry: createNoopTelemetryService(),
      logger: testLogger,
      bundledPlugins: [],
      loadTimeoutMs: 2000,
      hub: {
        getDaemonSessionIdForHost: () => null,
        notifyPluginChanged: () => {},
        onWatchedTargets: () => () => {},
        notifyPluginSignal: () => 0,
        notifySystem: () => {},
      },
    });
  let service = createService();
  try {
    const workspace = await host.experimental_call("createWorkspace", {
      pathKey: "thr_retention_repro",
    });
    const managedRoot = join(workspace.path, "bb-plugin-retention-managed");
    const stableRoot = join(root, "stable", "bb-plugin-retention-stable");
    for (const [sourceRoot, name] of [
      [managedRoot, "bb-plugin-retention-managed"],
      [stableRoot, "bb-plugin-retention-stable"],
    ]) {
      await mkdir(sourceRoot, { recursive: true });
      await writeFile(
        join(sourceRoot, "package.json"),
        JSON.stringify({
          name,
          version: "0.1.0",
          bb: {
            name: "Retention fixture",
            description: "Personal workspace source retention reproduction.",
            branding: { icon: "Zap" },
            server: "./server.ts",
          },
        }),
      );
      await writeFile(
        join(sourceRoot, "server.ts"),
        "export default function plugin() {}\n",
      );
    }
    const installed = await service.installPath(managedRoot);
    expect(installed.status).toBe("running");
    expect(getInstalledPlugin(db, installed.id)?.rootDir).toBe(managedRoot);
    expect(warnSpy).toHaveBeenCalledWith(
      expect.stringContaining("bb-managed workspace"),
    );
    expect((await service.installPath(stableRoot)).status).toBe("running");
    console.log(
      "install:",
      JSON.stringify({
        status: installed.status,
        sourceRetainedInWorkspace:
          getInstalledPlugin(db, installed.id)?.rootDir === managedRoot,
        warningInResult: JSON.stringify(installed).includes(
          "bb-managed workspace",
        ),
      }),
    );
    expect(
      await host.experimental_call("removeWorkspace", {
        pathKey: "thr_retention_repro",
        path: workspace.path,
      }),
    ).toEqual({ removed: true });
    console.log(
      "retirement:",
      JSON.stringify({
        managedSourceExists: existsSync(managedRoot),
        stableSourceExists: existsSync(stableRoot),
      }),
    );
    await service.stop();
    service = createService();
    await service.start();
    const statuses = {
      managed: service.list().find((plugin) => plugin.id === installed.id)
        ?.status,
      stable: service.list().find((plugin) => plugin.id === "retention-stable")
        ?.status,
    };
    console.log("restart:", JSON.stringify(statuses));
    expect(statuses).toEqual({ managed: "running", stable: "running" });
  } finally {
    await service.stop();
    db.$client.close();
    warnSpy.mockRestore();
    await rm(root, { recursive: true, force: true });
  }
});

5. Root cause

Path installation does not promote source to a durable location

installPathSource: detection, logger warning, and registration detects a managed root, calls logger.warn, then registers that same rootDir and path: source. It neither copies the source nor changes its ownership or lifecycle. The test confirms the database retains the ephemeral root and the successful return value contains no warning.

return registerInstalled({
  rootDir,
  source: `path:${rootDir}`,
  provenance: { kind: "direct" },
  sourceIntent: { kind: "path", canonicalPath: rootDir },
  exactResolution: { kind: "path" },
  refuseEngineMismatch: false,
  validated: false,
});

The archive/removal lifecycle does not retain installed path roots

Thread archive schedules sweepProviderEnvironment. Environment sweep considers live threads and retirement state; runRemove invokes the provider removal operation. The personal-workspace provider calls the host removeWorkspace method.

The tested host entry validates the removable directory, kills processes beneath it, and executes:

await rm(target, { recursive: true, force: true });

None of these removal steps checks installed-plugin references. Installing a plugin does not create a live thread or extend the environment's lifetime. The default environment policy has a 300,000 ms retirement grace; this delays deletion but does not protect plugin source.

A runtime restart reveals the stale registration

loadOne stats the persisted root. If it is gone, it reports missing and asks for reinstallation. This is why a restart can expose earlier source deletion without the update itself having removed the files.

The warning does not reach the user-facing success path

The install route returns the successful installation job. CLI plugin printing prints the plugin status, optional status detail, and source, not server logger output. The app success toast displays the plugin name after success. This is a missing warning-delivery contract as well as a source-ownership/lifetime mismatch.

6. Proposed fix and safe-fix gate

Make the source lifetime explicit at the installation boundary and preserve that contract across retirement. Candidate policies are promoting managed-workspace source to durable storage, refusing an unsafe path install with a clear error, or retaining the environment while installed plugins reference it. An explicit warning must be carried to both CLI and UI rather than logged only server-side.

No automatic fix PR: these alternatives change the established mutable local-path development contract or environment-retention policy and require a product decision. The warning-only alternative needs a public installation-result/progress contract delivered through SDK, CLI, and UI. This is outside the rule's no-public-schema/no-product-decision simple-fix gate. No production patch, branch, commit, or push was made. The focused failing test is retained inline as evidence, not presented as a completed fix.

After choosing a policy, test managed personal workspaces and provider-owned worktrees, an attached non-owned directory, stable external paths, and installation/retirement races. For a warning-based repair, explicitly test visibility in the actual CLI and app success paths; do not treat a logger spy as sufficient regression coverage.
