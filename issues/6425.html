#6425 · Codex goal-clear acknowledgements violate the existing host contract

Bug Medium Effort: Low providers, provider-codex, confirmed-repro open on GitHub 2026-10-28 · base 33b8f913e8fadc815b329eb0b13d2612faa4495e

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A goal-clear operation can succeed inside Codex while BB rejects its acknowledgement. The Codex bridge routes this operation through a generic maintenance handler that throws away the native response and emits {ok:true}. The existing host contract accepts only an object containing a boolean cleared. A new process-boundary regression reproduces the wrong result on trusted main in two separate clean checkouts. This is a source-level reproduction, not verification of the reporter's installed Windows build or a live Codex goal.

5. Root cause

Goal-clear dispatch calls the generic maintenance path. That handler awaits the child operation with an ignored result schema, discards the returned native value, and sends {ok:true}. This also loses an explicit native false value. Native errors do not reach the success branch.

await withChildForThread(params.threadId, (connection) =>
  sendMaintenanceRequestWithRetries(connection, request),
);
await settle();

// settle emits:
sendResult(id, { ok: true });

The independently defined host result schema is z.object({ cleared: z.boolean() }).strict(). The clearThreadGoal operation supplies that schema to sendCommand. A missing cleared field and extra ok field therefore explain the reported validation failure without requiring a version mismatch.

Existing archive/conformance coverage checks the generic acknowledgement but does not cover the goal-clear result contract. The regression owns that response at the actual bridge/native-process boundary, verifies the provider thread ID and exactly one native request, and needs no production test seam.

6. Proposed fix

Give goal-clear a dedicated handler using the existing child lifecycle and error forwarding. Parse the native result at the connection boundary, preserve explicit booleans, normalize empty/null successful acknowledgements once, and emit exactly the established host result. Leave generic maintenance replies unchanged. An explicitly malformed cleared field becomes an error rather than false success. This restores an existing contract; no public protocol definition or host-daemon wire schema changes.
