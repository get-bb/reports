#7985 · Inherited shell argv override survives child environment sanitation

BugMedium priorityLow effortdesktopworkspacesGitHub issue2026-11-21

Trusted base: 35a03bbbb3f4d8dc814c1a152db5a463102b4250.

Verdict: REPRODUCED at the child-environment boundary. Root-cause confidence: high. Reproduction label: confirmed-repro.

1. TL;DR

An inherited shell argument-zero override reaches user child processes even after bb sanitizes their environment. The shared sanitizer removes bb runtime variables and Node mode, but not ARGV0; the terminal manager uses that sanitizer when constructing its shell environment. A real subprocess launched with the sanitizer's output sees the unwanted override in two clean checkouts of trusted main. This verifies the environment-leak defect, not an end-to-end packaged desktop launch: this machine has no zsh, rustup, or AppImage fixture. Removing just the inherited override makes the reproduction and focused regression pass without discarding the AppImage metadata.

Complete reproduction artifact

import assert from "node:assert/strict";
import { spawnSync } from "node:child_process";
import { resolve } from "node:path";
import { pathToFileURL } from "node:url";

const { sanitizeInheritedChildProcessEnv } = await import(
  pathToFileURL(resolve("packages/process-utils/src/environment.ts"))
);
const parentEnv = {
  ARGV0: "/opt/bb-fixture.AppImage",
  APPIMAGE: "/opt/bb-fixture.AppImage",
  APPDIR: "/tmp/bb-fixture-mount",
  PATH: "/usr/bin:/bin",
};
const childEnv = sanitizeInheritedChildProcessEnv({ env: parentEnv });
const child = spawnSync(
  process.execPath,
  ["-e", "console.log(JSON.stringify({ARGV0:process.env.ARGV0 ?? null,APPIMAGE:process.env.APPIMAGE,APPDIR:process.env.APPDIR}))"],
  { env: childEnv, encoding: "utf8" },
);
assert.equal(child.status, 0, child.stderr);
console.log(child.stdout.trim());
assert.equal(parentEnv.ARGV0, "/opt/bb-fixture.AppImage");
assert.equal(JSON.parse(child.stdout).ARGV0, null, "inherited argv override must not reach a user child process");

5. Root cause

The desktop environment builder preserves its input environment in the packaged Electron-Node case:

if (args.runtimeMode === "electron-node") {
  return { ...args.env, ELECTRON_RUN_AS_NODE: "1" };
}

The shared child-environment sanitizer only filters undefined values, NODE_ENV, and BB-prefixed keys:

if (normalizedKey === "NODE_ENV" || normalizedKey.startsWith("BB_")) {
  continue;
}
sanitizedEnv[normalizedKey === "PATH" ? "PATH" : key] = value;

Therefore ARGV0 survives. The terminal environment builder uses that result directly before applying terminal-specific values:

return {
  ...sanitizeInheritedChildProcessEnv({ env: process.env }),
  ...args.shellEnv,
  BB_TERMINAL_SESSION_ID: args.terminalId,
  ...
};

The ordinary runtime shell overlay builds PATH and bb-specific variables, rather than clearing the override. The PTY spawn receives the composed environment. The reported downstream shell behavior is consistent with this retained override, but the shell/proxy-dispatch portion was not run here.

6. Proposed fix and regression

Filter inherited ARGV0 in the existing process-utils sanitizer, the shared owner used by terminals and other user child processes. Retain APPIMAGE and APPDIR: they are unrelated metadata, and removing every AppImage variable would broaden the change unnecessarily. Do not alter packaging, desktop runtime selection, protocols, or user configuration.

The tested patch changes two files in process-utils: 11 additions and 2 deletions, 13 total changed text lines. It extends the existing sanitizer contract test instead of introducing a duplicate test or test-only production export. The extended test fails against unchanged production because ARGV0 remains in the received object; after the fix it passes and still verifies that AppImage metadata remains present.
