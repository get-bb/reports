#6279 · Observed child model is dropped before timeline projection

BugPriority: LowEffort: Lowproviders · provider-claude-codeopen on GitHub2026-10-25 · base 3a2c49a267cd2a62a96ebff880068a7c37074251

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

A native background agent can deliver its text successfully while its model remains null in the timeline. A source-level reproduction feeds a concrete, public model identifier through the real Claude translator, delta assembler, and timeline builder; child text arrives under the correct parent, but the active background task still has no model. Replaying a later progress message does not repair it. The same agent repeated both cases in a second clean trusted checkout and observed the same model-only assertion failures. This is not a live macOS/provider-session replay; the reporter’s private session, precise model identifier, and UI appearance were not inspected.

5. Root cause

  1. Assistant translation parses the child assistant and emits text/thinking with the parent reference. It does not turn the assistant’s actual model into task metadata.
  2. Task snapshots contain lifecycle, usage, and summary data, but no observed model. The provider delta background-task schema and persistable background-task event schema also have no model field. Merely adding an object property inside the provider would not establish an end-to-end typed transport contract.
  3. Delta assembly copies known background-task fields into the event. It cannot currently carry an observed task model.
  4. Task updates do not apply a model, and task creation initializes it to null.
  5. Model enrichment only consults the spawning delegation’s model and task-family fallback. No path obtains the actual child response model; an inherited request supplies no requested model to fall back to. Thus real child activity and a null task model coexist.

The bug crosses the provider-translation, shared event/bridge, and timeline-projection boundaries. It is deeper than a missing UI label or one omitted provider assignment. The server’s timeline service uses this same timeline builder.

6. Proposed fix and safety decision

Parse the observed model at the Claude boundary, associate it only with the matching child Agent task, and carry it in explicit typed task metadata through delta assembly, persisted events, and projection. Preserve a known concrete model across progress and completion; ignore absent or synthetic metadata and unrelated parent/sibling activity. Ensure observed metadata takes precedence over a requested-model fallback. Add regression coverage for ordering, task generations, completion, synthetic responses, and sibling isolation.

No automated fix or pull request: this needs changes to public provider/event schemas and multiple existing subsystems. Both are explicit exclusions from the simple-fix rule, regardless of possible line count. A proper implementation also needs the repository’s host-daemon wire-compatibility assessment and protocol-version handling. No production patch, fix branch, or stopped fix was pushed.
