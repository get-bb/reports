#7498 · Panel width inheritance invalidation

BugPriority: LowEffort: Lowui · perf · confirmed-reproGitHub issue2026-11-13

Trusted base: 070bf3df0aae0f009488f29d8941f5fec8532a93. Verdict: REPRODUCED · Root-cause confidence: high.

1. TL;DR

The right panel has a width custom property that is intended for the panel itself, but that value also propagates into its entire content tree. A focused Chrome trace with 2,400 descendants shows every one of those descendants restyled after each width write: 2,401 elements including the panel. An otherwise identical non-inherited control changes the same panel width while restyling just one element. This happens in both clean trusted checkouts. The reproduction verifies the style-invalidation mechanism, not the full app's reported toggle frame times.

5. Root cause

The panel writes an unregistered custom property on its aside, so the value inherits into every descendant and each write invalidates their computed styles.

  • apps/app/src/components/secondary-panel/useSecondaryPanelResize.ts:39 assigns the property directly on the panel element.
  • apps/app/src/components/secondary-panel/ThreadSecondaryPanel.tsx:956 reads that property in the aside's width expression. There is no intended descendant consumer.
  • apps/app/src/components/ui/theme.css:959 registers the analogous sidebar width as non-inherited, but does not register this secondary-panel property. The trusted theme contains only that one @property declaration.
  • apps/app/src/components/secondary-panel/useSecondaryPanelResize.ts:52 writes at drag completion; apps/app/src/components/secondary-panel/useSecondaryPanelResize.ts:99 still writes for non-drag resizes. Reducing write frequency does not change inheritance invalidation per remaining write.
secondaryPanelRef.current?.style.setProperty(
  "--secondary-swipe-width",
  `${size}cqw`,
);

width: `var(--secondary-swipe-width, ${persistedWidthPercent}cqw)`

Changing the width can still require descendant layout even when style invalidation is contained. A registration removes this measured style-inheritance overhead; it does not guarantee zero layout or a particular frame budget.

6. Proposed fix

Register the panel-only width property as non-inherited, leaving its unset state without a concrete initial value so the existing container-width fallback remains effective. The separate control demonstrates both unchanged sizing and the removal of inherited invalidation. Test actual descendant computed values and invalidation in a real browser, and retain fallback coverage. No production fix branch was created because an open linked PR already owns this issue.
