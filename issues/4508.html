#4508 · Hidden split pane timeline refetch

BugMedium priorityMedium effortthreads · perfGitHub issue2026-09-29 · base ea49535e06e83a0df0b11b56b8280cc2e1f5addd

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A maximized split pane keeps sibling thread panes mounted. Their timeline observers continue to be enabled even though the sibling content is hidden. A focused React Query reproduction shows a hidden sibling fetch again when its query is invalidated. This proves avoidable query work in the split-pane path; production network frequency and CPU impact were not measured.

5. Root cause

SplitThreadArea sets visual hiding on the sibling while preserving its mounted content. ThreadDetailView calls the timeline controller without a visibility input. The controller defaults enabled to true, and the timeline hook passes that state to React Query. The invalidation path sees an active timeline query and can refetch it. Document visibility is a separate condition and remains true during pane maximization.

6. Proposed fix

Pass split-pane visibility to the thread detail timeline controller. Disable only the hidden pane's observer, retaining the mounted pane and cached rows. Let the observer refetch on reveal. A separate visible observer for the same thread should continue fetching.
