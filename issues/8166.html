1. TL;DR

The stock mobile connect flow references a subflow that is not present in the repository. A dependency-resolution regression check fails at that exact reference in two clean checkouts of trusted main. This establishes a broken on-disk flow dependency without starting the app, pairing a device, or contacting a server. The existing mobile flow-boundary tests still pass because they do not check that included files exist. This Linux environment has neither Maestro nor an iOS simulator, so the reported Maestro diagnostic and complete native journey were not executed here; the verdict deliberately remains partial.

import assert from "node:assert/strict";
import { readdirSync, readFileSync, statSync } from "node:fs";
import { dirname, join, relative, resolve } from "node:path";

const root = resolve(process.argv[2] ?? ".");
const flowRoot = join(root, "apps/mobile/e2e");

function yamlFiles(directory) {
  return readdirSync(directory, { withFileTypes: true }).flatMap((entry) => {
    const path = join(directory, entry.name);
    if (entry.isDirectory()) return yamlFiles(path);
    return /\.ya?ml$/u.test(entry.name) ? [path] : [];
  });
}

const missing = [];
let checked = 0;
for (const path of yamlFiles(flowRoot)) {
  const source = readFileSync(path, "utf8");
  for (const match of source.matchAll(/^\s*- runFlow:\s+(\.\.?\/[^\s#]+)\s*$/gmu)) {
    const target = resolve(dirname(path), match[1]);
    checked += 1;
    if (!statSync(target, { throwIfNoEntry: false })?.isFile()) {
      const line = source.slice(0, match.index).trimEnd().split("\n").length + 1;
      missing.push(`${relative(root, path)}:${line} -> ${relative(root, target)}`);
    }
  }
}

console.log(`Checked ${checked} relative scalar runFlow includes.`);
try {
  assert.deepEqual(missing, [], "Every relative scalar runFlow include must resolve to a file");
  console.log("PASS: all checked flow dependencies exist.");
} catch (error) {
  console.error(error.message);
  process.exitCode = 1;
}

5. Root cause

The connect flow at lines 135–146 still contains an external settings helper invocation:

- runFlow: ../subflows/open-settings.yaml

Relative to the containing flow, the resolved path is apps/mobile/e2e/subflows/open-settings.yaml. The committed subflows tree does not contain it. Its entire file list is:

clear-open-confirmation.yaml
launch-app.yaml
open-bb-link.yaml
pair-direct-server.yaml

The consumer therefore cannot load that dependency as shipped. This is a source-content defect, not a simulator certificate, account, network, or stub-service failure. History associates the current flow with the WebView-shell replacement commit 15e87df425; that is context, not proof that every later UI step works.

The existing test owner checks link conventions and a direct-pairing helper but never validates the existence of external flow dependencies. Its two tests pass on the broken base. The native shell route prefixes already include server settings, offering an existing navigation boundary rather than requiring a fabricated missing helper.

6. Proposed fix

Replace the stale settings-helper invocation with navigation through the existing link helper to the supported server-settings route, and validate the following selectors against the current native screen. Extend the existing mobile E2E test owner with a file-resolution contract for both scalar and object-form external flow references. Validate actual iOS loading first, then pairing, session renewal, and repair; removing a file error alone does not prove those later behaviors. No source patch is made in this investigation because an open pull request already closes this issue.
