1. TL;DR

Moving Claude's configuration directory leaves skills from the default home directory in BB's discovered skill list. The Claude resolver correctly returns the configured directory, but the provider also declares the default directory as a static user root. BB intentionally scans both sets. A filesystem integration test reproduced the extra skill twice at the trusted main commit; no provider CLI, login, or live BB instance was involved.

import { mkdir, mkdtemp, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import path from "node:path";
import { expect, it, vi } from "vitest";
import { pipeline } from "./pipeline.js";

it("lists only the configured Claude user skills directory", async () => {
  const homeDir = await mkdtemp(path.join(tmpdir(), "bb-relocated-skills-"));
  try {
    const configuredDir = path.join(homeDir, "configured");
    for (const [directory, name] of [
      [path.join(homeDir, ".claude"), "default-root-skill"],
      [configuredDir, "configured-root-skill"],
    ] as const) {
      const skillDir = path.join(directory, "skills", name);
      await mkdir(skillDir, { recursive: true });
      await writeFile(
        path.join(skillDir, "SKILL.md"),
        `---\nname: ${name}\ndescription: Test skill\n---\nTest content.\n`,
      );
    }
    vi.stubEnv("CLAUDE_CONFIG_DIR", configuredDir);
    const relocated = await pipeline({
      providerId: "claude-code",
      cwd: null,
      homeDir,
    });
    expect(relocated.skills.map((skill) => skill.name).sort()).toEqual([
      "configured-root-skill",
    ]);
    vi.stubEnv("CLAUDE_CONFIG_DIR", "");
    const defaults = await pipeline({
      providerId: "claude-code",
      cwd: null,
      homeDir,
    });
    expect(defaults.skills.map((skill) => skill.name)).toEqual([
      "default-root-skill",
    ]);
  } finally {
    vi.unstubAllEnvs();
    await rm(homeDir, { recursive: true, force: true });
  }
});

5. Root cause

plugins/provider-claude-code/src/native-roots.ts:17 declares .claude/skills as a home-relative user root. Its resolver at line 43 creates a second user root from the selected configuration directory. apps/server/src/services/providers/native-roots.ts:210 retains both declaration and resolver output. apps/host-daemon/src/command-handlers/list-commands.ts:361 appends declared and resolved scan roots; the two absolute paths are distinct, so deduplication cannot remove the stale one.

packages/plugin-sdk/src/backend-contract.ts:1556 says directories whose location is host-configured should be resolved rather than declared. packages/plugin-sdk/src/native-roots-contract.ts:1 explicitly documents additive resolution. The contained root cause is therefore the Claude declaration, not generic resolver precedence.

6. Proposed fix and automation limit

Remove the static Claude user skill declaration; keep project roots and resolve user skills through the existing resolver. The local three-line removal makes the focused regression pass, including default-directory fallback. All 364 Claude provider tests and its typecheck pass.

The full native-root suite reports 22 passing tests and one failing existing test: claude-code (config-dir) explicitly expects home-claude-skill and linked-home-skill. tests/integration/native-roots-golden/fixtures.ts:406 includes those names, and the generated goldens/claude-code.config-dir.json records them in both commands and skills. tests/integration/native-roots-golden/capture.ts:23 generates these golden files.

No PR was opened. Completing the fix requires correcting fixture expectations and the generated golden file, which violates this automation's prohibition on generated-file changes. The local fix was stopped and not pushed. A follow-up should update those expectations and regenerate the relevant golden, then rerun the suite. Resolver failure continues to be a separate fallback concern: without a static declaration, a failed resolver supplies no user roots, consistent with the existing command-root behavior.
