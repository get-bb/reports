1. TL;DR

The core home-directory failure is already fixed on current main: a contributed CODEX_HOME reaches the real child process used by the bridge test fixture. That repair merged in #6887 on November 3, 2026, before this issue was filed on November 6. The secondary claim remains observable: contributed app-server executable and argument overrides do not override the host launcher. A five-test existing home-selection suite passes, while two new launch-override hypothesis tests fail for the same assertions in two clean checkouts. No new fix PR is safe under the simple-fix rule: home forwarding is already repaired, and exposing a host executable selector through thread environment contributions requires a launch-policy decision.

5. Root cause

The bridge intentionally separates the thread command environment from its app-server launch environment. The launch-name allowlist contains pool routing and home selection, but not executable or argument selectors:

const APP_SERVER_LAUNCH_ENV_NAMES = [
  CODEX_POOL_BASE_URL_ENV,
  CODEX_POOL_AUTH_TOKEN_ENV,
  CODEX_HOME_ENV,
] as const;

appServerLaunchEnv starts with the inherited host process environment and overlays only those listed thread values. Consequently CODEX_HOME is available in the child, while thread executable overrides are ignored.

resolveAppServerLaunch reads the launcher command and arguments from its input. At the actual spawn boundary, that input is the unsanitized result of appServerLaunchEnv, not the sanitized child environment. Existing host-level selectors therefore work, as the trusted test fixture demonstrates. Simply allowing BB-prefixed names through the general sanitizer would not fix the missing thread overlay and would unnecessarily broaden internal-variable inheritance.

The primary home repair is 7e58e30c1eb082748d194a62e4ac456cb27b5417, merged November 3, 2026. Its existing process-boundary coverage is exercised without modification. This report does not establish which published release first contains that commit.

6. Proposed fix and simple-fix decision

No additional home-forwarding patch is necessary on this base. To address the remaining limitation, maintainers first need to decide whether executable selection is a supported thread-scoped capability or a host-only launch control. If thread-scoped selection is intended, narrowly overlay only the explicit launcher selectors before resolution, preserve child-environment sanitization, and define how changes affect existing sessions and model listing. Do not indiscriminately merge every contributed variable into host launch controls.

No fix branch or PR: the reported home bug does not reproduce on trusted main, and enabling executable/argument replacement requires a product and launch-boundary decision. Those fail the simple-fix criteria even though the eventual code edit may be short. The only source additions made for investigation are uncommitted local hypothesis tests; there are zero production changes and nothing is pushed to the target code repository.
