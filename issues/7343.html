#7343 · Running ACP command metadata is not refreshed

BugPriority: LowEffort: Lowprovidersprovider-acp GitHub issue · November 10, 2026 · base 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

A running ACP command can retain its announcement text after the provider supplies the real command. The translator saves the richer input internally but emits no item refresh, so timeline consumers cannot update the running row. The reproduction exercises the real translator and shared delta assembler, without an agent account, shell command execution, database, or live app. One detail differs from the report: this base uses the announcement title as the initial command, so the value is Terminal, not an empty string.

5. Root cause

packages/provider-bridge-acp/src/delta-translation.ts:728–805 merges each update with the stored announcement and reclassifies it, but uses only the resulting type for routing. It does not publish changed command metadata on non-terminal paths. For running commands it returns an output snapshot when available, otherwise a suppressed fallback. A terminal update instead builds an item close from the merged event, explaining why final data can be correct.

packages/provider-bridge-protocol/src/assembler/delta-assembler.ts:1364–1414 already supports another item.open with the same provider key: it reuses the BB item ID and emits updated item/started data. packages/provider-bridge-acp/src/presentation.ts:16–24 derives the headline from the classified command. No new protocol field or consumer API is needed.

6. Proposed fix and checked implementation

Compare the old and merged command classification on non-terminal updates. When the command or presentation title changes, emit a same-key item refresh before streamed output. Preserve no-turn fallback behavior, unchanged-update suppression, other tool kinds, and the existing close path.

The checked implementation changes two existing files in the ACP bridge: 75 test additions and 38 production additions plus 12 deletions, 125 total changed text lines. It adds no dependency, generated file, migration, stored data, public schema, or wire field.
