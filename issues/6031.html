#6031 · ACP choice and companion fields remain separate questions

BugPriority: MediumEffort: Lowproviders · provider-acp · partial-repro Issue #6031October 21, 2026 · base b143a22860944a96bf183605dfb0ffe58b1de283

Verdict: PARTIALLY REPRODUCED. Root-cause confidence: high for the planner mechanism; the actual provider and live UI are unverified.

1. TL;DR

A deterministic test of the production ACP planner produces two question cards from a string enum property and a companion text property. Answering only the enum declines the whole form, even when the text property is not listed in the schema's required array. The planner treats every schema property as a separate question and never interprets companion relationships. The same result occurs in two newly cloned, clean main checkouts without changing production code. A live omp request, its consumer's expected response, and macOS UI behavior were not tested, so this is a partial reproduction rather than an end-to-end confirmation.

import { describe, expect, it } from "vitest";
import { planAcpElicitation } from "./elicitation.js";

function planFormatQuestion() {
  const plan = planAcpElicitation({
    mode: "form",
    message: "Choose the response format",
    requestedSchema: {
      type: "object",
      required: ["format"],
      properties: {
        format: {
          type: "string",
          title: "Response format",
          enum: ["brief", "detailed"],
        },
        format__other: { type: "string", title: "Custom format" },
      },
    },
  });
  if (plan.kind !== "questions") {
    throw new Error(JSON.stringify(plan));
  }
  return plan;
}

describe("issue 6031 trusted-base reproduction", () => {
  it("records the split and refusal when the optional text property is omitted", () => {
    const plan = planFormatQuestion();
    const withoutCompanion = plan.toResponse({
      kind: "user_answer",
      answers: { format: { selected: ["brief"] } },
    });
    const withCompanion = plan.toResponse({
      kind: "user_answer",
      answers: {
        format: { selected: ["brief"] },
        format__other: { selected: [], freeText: "outline" },
      },
    });
    const observed = {
      questions: plan.payload.questions.map((question) => ({
        id: question.id,
        allowFreeText: question.allowFreeText,
        options: question.options?.map((option) => option.value) ?? [],
      })),
      withoutCompanion,
      withCompanion,
    };
    console.log(JSON.stringify(observed, null, 2));
    expect(observed).toEqual({
      questions: [
        { id: "format", allowFreeText: false, options: ["brief", "detailed"] },
        { id: "format__other", allowFreeText: true, options: [] },
      ],
      withoutCompanion: { action: "decline" },
      withCompanion: {
        action: "accept",
        content: { format: "brief", format__other: "outline" },
      },
    });
  });

  it("regression: presents the choice and companion as one free-text-capable question", () => {
    const plan = planFormatQuestion();
    expect(plan.payload.questions).toHaveLength(1);
    expect(plan.payload.questions[0]).toMatchObject({
      id: "format",
      allowFreeText: true,
    });
  });

  it("keeps a standalone text property as its own question", () => {
    const plan = planAcpElicitation({
      mode: "form",
      requestedSchema: {
        type: "object",
        properties: { notes__other: { type: "string" } },
      },
    });
    expect(plan.kind).toBe("questions");
    if (plan.kind !== "questions") {
      throw new Error(JSON.stringify(plan));
    }
    expect(plan.payload.questions).toHaveLength(1);
    expect(

        kind: "user_answer",
        answers: { notes__other: { selected: [], freeText: "follow up" } },
      }),
    ).toEqual({ action: "accept", content: { notes__other: "follow up" } });

5. Root cause

The ACP planner creates one question per schema property, disables free text for enum choices, and declines the whole form when any property has no decodable answer.

  1. elicitation.ts:135–151: ordinary string choices and multi-choices explicitly disable free text.
  2. elicitation.ts:265–297: properties become entries, and every entry becomes a separate planned question. The schema's required array is not consulted. The property count limit is also applied before planning.
  3. elicitation.ts:170–185: an enum decodes only a selected enum value; arbitrary typed text is not an enum answer.
  4. elicitation.ts:309–324: any undecodable property causes the whole form to decline, not just omission of that property.
  5. bridge.ts:1883–1926: the real elicitation handler forwards this payload to the runtime and passes the resolution through this same planner's response decoder.
planned.push({
  name,
  field,
  question: questionFor(name, fieldSchema, field, ...),
});
...
if (!decoded) {
  return { action: "decline" };
}

The excerpt is abbreviated for readability. The links point to the recorded unchanged production source. A repository-wide source search found no existing __other mapping. The first result alone establishes the split; the second explains why users must fill both cards.

6. Proposed fix and simple-fix gate

Capture the installed provider request and accepted responses first; then implement provider-scoped companion folding with enum-safe response encoding, required-field handling, and controls for unrelated similarly named fields.

No production fix or PR was created. The simple-fix gate requires no product or public-contract decision. Trusted main does not establish when a suffix-named field is a companion rather than an independent field, or what a provider accepts when the enum is required and only custom text is supplied. A global suffix heuristic could silently combine unrelated fields, while returning custom text as an enum value would violate that schema. Choosing either behavior without a verified provider contract is not a safe contained fix.

The failing test is retained as a report artifact, not committed into the product with a known failure. No dependency, protocol, stored data, or production source was changed. No stopped fix was pushed.
