Bug Priority: Medium Effort: Low mobile inline-vis partial-repro

1. TL;DR

The report describes an empty embedded HTML area in the native mobile shell. Trusted main creates inline HTML with an iframe srcDoc, but supplies no explicit WebView origin whitelist. The installed WebView library filters local-document URLs before invoking the app's navigation policy, even though that policy accepts local subframes. An executable reproduction against the real installed gate confirms that about:srcdoc, blob:, and data: are rejected with zero app-callback calls in two separate clean checkouts. The full existing mobile test suite passes, explaining why helper-only coverage did not catch the integration gap.

import { afterEach, describe, expect, it, vi } from "vitest";
import {
  createOnShouldStartLoadWithRequest,
  defaultOriginWhitelist,
} from "react-native-webview/src/WebViewShared";
import { allowsSubframeLoad } from "./shell-save-file";
import { isShellNavigation } from "./shell-url";

vi.mock("react-native", () => ({
  Linking: {
    canOpenURL: vi.fn(async () => false),
    openURL: vi.fn(async () => undefined),
  },
  StyleSheet: { create: (styles: object) => styles },
}));

afterEach(() => {
  vi.restoreAllMocks();
});

const serverUrl = "https://shell.example";

function dispatchNavigation(
  url: string,
  isTopFrame: boolean,
  originWhitelist: readonly string[] = defaultOriginWhitelist,
) {
  const policy = vi.fn((request: { url: string; isTopFrame: boolean }) => {
    if (
      request.isTopFrame === false &&
      allowsSubframeLoad(request.url, serverUrl)
    ) {
      return true;
    }
    return isShellNavigation(request.url, serverUrl);
  });
  const loadRequest = vi.fn();
  const onNavigation = createOnShouldStartLoadWithRequest(
    loadRequest,
    originWhitelist,
    policy,
  );
  const nativeEvent = {
    url,
    isTopFrame,
    lockIdentifier: 5986,
    navigationType: "other",
    mainDocumentURL: serverUrl,
    loading: false,
    title: "Navigation gate reproduction",
    canGoBack: false,
    canGoForward: false,
  };
  onNavigation({ nativeEvent } as Parameters<typeof onNavigation>[0]);
  return { policy, loadRequest };
}

describe("shell navigation through the installed WebView gate", () => {
  it.each([
    "about:srcdoc",
    "blob:https://shell.example/inline-document",
    "data:text/html,%3Cp%3Elocal-document%3C%2Fp%3E",
  ])("permits the shell-approved local subframe %s", async (url) => {
    const warning = vi.spyOn(console, "warn").mockImplementation(() => {});
    expect(allowsSubframeLoad(url, serverUrl)).toBe(true);
    const { policy, loadRequest } = dispatchNavigation(url, false);
    await Promise.resolve();
    console.log(
      JSON.stringify({
        url,
        appPolicyCalls: policy.mock.calls.length,
        nativeLoadDecision: loadRequest.mock.calls[0]?.[0],
        warningCount: warning.mock.calls.length,
      }),
    );
    expect(policy).toHaveBeenCalledOnce();
    expect(loadRequest).toHaveBeenCalledWith(true, url, 5986);
  });

  it.each(["about:blank", `${serverUrl}/api/v1/files/document`])(
    "delivers the allowed control subframe %s",
    (url) => {
      const { policy, loadRequest } = dispatchNavigation(url, false);
      expect(policy).toHaveBeenCalledOnce();
      expect(loadRequest).toHaveBeenCalledWith(true, url, 5986);
    },
  );

  it("preserves the top-frame rejection of a foreign HTTPS document", () => {
    const url = "https://outside.example/document";
    const { policy, loadRequest } = dispatchNavigation(url, true);
    expect(policy).toHaveBeenCalledOnce();
    expect(loadRequest).toHaveBeenCalledWith(false, url, 5986);
  });

  it("records the top-frame consequence of widening the blob gate", async () => {
    vi.spyOn(console, "warn").mockImplementation(() => {});
    const url = `blob:${serverUrl}/local-document`;
    expect(isShellNavigation(url, serverUrl)).toBe(true);
    const baseline = dispatchNavigation(url, true);
    expect(baseline.policy).not.toHaveBeenCalled();
    expect(baseline.loadRequest).toHaveBeenCalledWith(false, url, 5986);
    const experiment = dispatchNavigation(url, true, [
      ...defaultOriginWhitelist,
      "blob:*",
    ]);
    expect(experiment.policy).toHaveBeenCalledOnce();
    expect(experiment.loadRequest).toHaveBeenCalledWith(true, url, 5986);
    await Promise.resolve();
    console.log(
      JSON.stringify({
        topFrameBlob: true,
        defaultGate: baseline.loadRequest.mock.calls[0]?.[0],
        widenedGate: experiment.loadRequest.mock.calls[0]?.[0],
      }),
    );
  });
});

5. Root cause

  1. The inline HTML renderer creates a srcdoc iframe, retaining the scripts/forms sandbox. No production iframe change is needed to explain this failure.
  2. The shell configures its app callback but not originWhitelist; the wrapper does not supply one either.
  3. The installed dependency's src/WebView.ios.tsx:56 defaults that prop to defaultOriginWhitelist. Its src/WebViewShared.tsx:20 defines HTTP(S) defaults, and :36-38 additionally accepts about:blank.
  4. In the installed src/WebViewShared.tsx:40-72, a whitelist miss sets the native decision to false and attempts Linking fallback. The application's callback is in the alternate branch and is never reached for that miss.
  5. The app's helper allows the local protocols, but its acceptance is downstream of the earlier library gate.
const SUBFRAME_LOCAL_PROTOCOLS = new Set(["about:", "blob:", "data:"]);

if (SUBFRAME_LOCAL_PROTOCOLS.has(target.protocol)) return true;

The expected 224px symptom follows from the frame's initial constant and height fallback. A document canceled before loading cannot run its height reporter. This is a source-supported explanation, not a measured native screen result.

The deeper coverage gap is the boundary between the app's URL predicate and the WebView's earlier predicate: testing only the app helper does not test whether it can be reached.

6. Proposed fix and automation decision

Make the WebView's preliminary gate compatible with the local subframes the shell intentionally supports, while keeping the final app policy authoritative. Preserve iframe sandboxing and explicitly distinguish local subframes from top-frame navigation. A root-profile same-origin blob deserves a negative top-frame regression before broadening scheme admission.

No new fix branch or pull request was created. An open linked PR already exists (#5988), and duplicating it is forbidden by this rule. Additionally, native rendering was not reproduced here and gate changes touch a navigation boundary; neither a small diff nor helper-only passing tests satisfies the autopilot's safety criteria. No proposed production change or linked PR patch was run.

7. Static review of linked PR #5988

Metadata and diff were read as untrusted data only. Reviewed head: 6c04f81b701c3df8acb540aa47aabfcd820dfdf4, four files, 38 additions and no deletions. The diff supplies a whitelist to the shell and derives local schemes from its existing allow-set, so it addresses the specific preliminary-gate mismatch identified by the trusted-main reproduction.

Medium-priority review concern: apps/mobile/src/screens/webview/ProfileWebViewScreen.tsx:333 in that diff widens the gate for top frames as well as subframes. On trusted main, isShellNavigation checks origin and returns true for any matching-origin URL when the configured server has no path prefix. A same-origin blob: URL has that origin. Therefore, broadening the blob gate can admit a top-frame blob that the default gate rejects. This is a verified change in JavaScript navigation decisions, not a demonstrated exploit or a native-device result.

The additional parameter experiment in the embedded test passes: with all production code untouched, the default factory decision is false, and the same factory given only an extra blob pattern yields true through the real shell predicate. This experiment was authored from trusted-main code; it does not execute the PR branch or patch.

The PR's added tests duplicate the dependency's matching algorithm, rather than importing the real callback factory, and do not exercise top-frame distinction. Recommendation: add owner-boundary callback tests using the installed factory and check same-origin blob top-frame rejection explicitly. Verdict: statically addresses the reported mismatch; native behavior and navigation-boundary safety are not approved by this report. No PR review comment was posted.
