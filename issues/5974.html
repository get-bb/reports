#5974 · Missing properties extension in editor language routing

Bug · Priority: Low · Effort: Low · plugins · 2026-10-21 · GitHub issue

Verdict: REPRODUCED · Root-cause confidence: high

1. Summary

The File Editor chooses its Monaco language from an explicit extension map. The properties extension is absent, so a properties path resolves to plaintext and is absent from the editor's claimed extensions. Two clean checkouts of trusted main reproduced these failures with an original regression test. Adding one map entry fixes both outcomes. The existing ini entry must remain: this editor passes an explicit language rather than relying on Monaco's native extension detection.

5. Root cause

The configuration-extension map contains ini, toml, cfg, and conf but not properties. The language selector and extension claims derive from that same map:

export const CLAIMED_EXTENSIONS: readonly string[] = Object.keys(
  LANGUAGE_BY_EXTENSION,
).filter((extension) => !PREVIEW_RENDERED_EXTENSIONS.has(extension));

const extension = name.slice(dotIndex + 1).toLowerCase();
return LANGUAGE_BY_EXTENSION[extension] ?? "plaintext";

The editor creation path supplies that result as an explicit language, and the file-opener registration supplies the derived claims. Monaco's own extension registration does not override the explicit plaintext choice. A direct investigation build of the repository's Monaco staging script succeeds, including its language-registration checks.

6. Proposed fix and test evidence

Add properties: "ini", beside the existing ini mapping. Do not replace or remove ini. The change uses the already bundled grammar, introduces no dependency or public contract, and changes only language routing within the existing File Editor subsystem.
