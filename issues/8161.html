#8161 · ACP instruction text retains command examples

Bug Priority: Medium Effort: Medium providers provider-acp partial-repro

GitHub issue · November 25, 2026 · trusted base fb045a046653cc127656ca3c7243d44ae4c94f3f

PARTIALLY REPRODUCED · Root-cause confidence: medium overall; high for the BB-side transport mechanism.

1. TL;DR

BB sends skill descriptions inside an ordinary ACP text block on a session's first prompt. Its description sanitizer removes angle brackets and normalizes whitespace, but leaves slash-command examples unchanged. A focused transport test demonstrates that an invented command example reaches the repository's ACP agent fixture even though the user's message contains only a greeting; the second prompt contains no injected skill description. The same failing safety assertion was repeated in a second clean checkout. The fixture does not expand slash commands, and Antigravity is unavailable here, so automatic command execution, command metadata, and the exact desktop symptom remain unverified.

5. Root cause

The BB-side mechanism has three parts, all verified at the recorded commit:

  1. Description sanitization normalizes whitespace and strips angle brackets. It does not distinguish prose command examples from executable slash syntax: 
    const sanitized = description
  .replace(/[\r\n]+/gu, " ")
  .replace(/\s+/gu, " ")
  .replace(/[<>]/gu, "")
  .trim();
  2. Catalog construction interpolates that description into session instructions together with the skill's readable path.
  3. Prompt construction consumes pending instructions once and appends the user's text as a separate text block: 
    const instructions = session.pendingInstructions;
if (instructions) {
  session.pendingInstructions = undefined;
  blocks.push({
    type: "text",
    text: `${SYSTEM_INSTRUCTIONS_OPEN_TAG}\n${instructions}\n</system_instructions>`,
  });
}

The existing BB skill-command rewriting operates on user-input mention metadata, not on the pending instruction block. Consequently it does not neutralize examples embedded in catalog descriptions.

The fixture's prompt logger joins text blocks with a newline and logs the resulting string. It does not invent commands or command metadata. The observed exposure therefore establishes BB's contribution to the reported mechanism, but it does not establish what Antigravity does with that text. The fixture's joining separator also means this report does not verify the reporter's exact block-boundary concatenation.

6. Proposed fix / next experiment

First capture a minimal prompt with the affected provider and confirm which forms of command references its parser treats as inert prose. Then consider neutralizing command-like examples only in generated skill descriptions, while preserving ordinary file paths, URLs and intentional user commands. An escape should not be assumed safe until it is tested against the real parser. A transport-level alternative would require checking ACP capability and compatibility rather than simply labeling an ordinary text block as system text.

No fix branch or pull request was opened. The rule permits fixes only for bugs reproduced on trusted main. The provider-specific command expansion was not reproduced, so changing serialization based solely on this partial result would not meet that gate. No public protocol, stored data, or provider behavior was changed. No open PR linked to issue 8161 was found through timeline metadata and open-PR searches at investigation time.
