#5451 · Windows startup registration and antivirus compatibility

BugPriority: Medium Effort: Mediumhost Issue October 13, 2026 · base 164648c69595

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium · Reproduction label: partial-repro

1. TL;DR

The Windows installer constructs a hidden PowerShell command and registers it as a per-user sign-in startup entry. Two clean checkouts generated that command directly from the trusted production module. Source inspection also shows that registration happens after enrollment and daemon startup, and a registry-command failure escapes to the installer's error handler. These findings establish the reported operation and a plausible failure path, not Bitdefender's reason for detecting it. This investigation ran on Linux without Windows or Bitdefender; no actual antivirus alert, blocked registry write, or Windows enrollment failure was reproduced.

5. Root cause and error propagation

Verified implementation mechanism: the installer uses a per-user registry startup value containing an inline hidden-PowerShell invocation. Candidate compatibility cause: this operation is what the issue attributes to the antivirus block, but attributing the detection to these flags rather than another operation, reputation, policy, or detector state requires a native detector trace.

  • Run-key constant, line 31: HKCU\Software\Microsoft\Windows\CurrentVersion\Run.
  • Command generation, lines 176–188: quoted Node and installer paths followed by --start; the wrapper uses powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -Command.
  • Registration, lines 828–848: execFileAsync runs reg.exe add with REG_SZ, the generated command, and overwrite enabled. windowsHide: true hides the registry subprocess; it is separate from the login command's -WindowStyle Hidden.
  • Install ordering, lines 985–1041: CLI enrollment, server join, service-file persistence, installer copy, daemon startup, then registry registration. A late registration failure does not imply all earlier steps failed or were rolled back.
  • Outer error handler, lines 1069–1079: rejection prints an error and assigns process.exitCode = 1.
  • Existing command-generation test intentionally expects hidden PowerShell; it does not test antivirus compatibility or a blocked registry write.

The relevant installer implementation was introduced by commit 450954cb11 on October 2, 2026. A second fetch of trusted origin/main still resolved to the recorded base; no later installer fix was present during this investigation.
