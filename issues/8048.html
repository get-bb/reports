#8048 · Global Git helper reset suppresses unrelated HTTPS credentials

BugPriority: MediumEffort: Lowworkspaceshostconfirmed-reproGitHub issue2026-11-23

Trusted base: a89f5d7e010ff3fb94253fbabd65b17236dde5d4. Verdict: REPRODUCED · Root-cause confidence: high.

1. TL;DR

The machine Git environment replaces Git's credential helper list for every host, even though the replacement helper only answers HTTPS requests for github.com. An unrelated HTTPS repository therefore loses access to its configured machine helper. This is a command-environment override; it does not delete the machine's saved configuration. An offline reproduction imports the actual production configuration function, passes its returned environment directly to Git, and demonstrates the failure twice at the same trusted main commit. GitHub still resolves a synthetic forwarded credential, while a working unrelated local helper stops resolving credentials.

Self-contained regression program

import assert from "node:assert/strict";
import { spawnSync } from "node:child_process";
import { mkdtemp, rm } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { pathToFileURL } from "node:url";

const { githubGitConfiguration } = await import(
  pathToFileURL(join(process.cwd(), "apps/server/src/services/machines/git-credentials.ts"))
);
const scratch = await mkdtemp(join(tmpdir(), "bb-8048-credentials-"));
const environment = {
  PATH: process.env.PATH,
  HOME: scratch,
  GIT_CONFIG_NOSYSTEM: "1",
  GIT_CONFIG_GLOBAL: join(scratch, "gitconfig"),
  GIT_TERMINAL_PROMPT: "0",
  GIT_ASKPASS: "/bin/false",
  GH_TOKEN: "synthetic-forwarded-value",
};
const helper = '!printf "%s\\n" "username=machine-user" "password=synthetic-machine-value"';
const contributions = Object.fromEntries(
  githubGitConfiguration().map(({ name, value }) => {
    assert.equal(typeof value, "string");
    return [name, value];
  }),
);

function git(argumentsList, env, input) {
  const result = spawnSync("git", argumentsList, {
    cwd: scratch,
    env,
    input,
    encoding: "utf8",
    timeout: 5000,
  });
  if (result.error) throw result.error;
  return result;
}

function probe(label, protocol, host, forwarded, expectedPassword) {
  const result = git(
    ["credential", "fill"],
    forwarded ? { ...environment, ...contributions } : environment,
    `protocol=${protocol}\nhost=${host}\n\n`,
  );
  const resolved = result.status === 0 && result.stdout.includes(`password=${expectedPassword}\n`);
  console.log(`${label}: exit=${result.status}, expectedCredentialResolved=${resolved}`);
  if (result.status !== 0) console.log(result.stderr.trim());
  return { status: result.status, resolved, output: result.stdout };
}

try {
  for (const host of ["forge.invalid", "github.com"]) {
    assert.equal(git(["config", "--global", `credential.https://${host}.helper`, helper], environment).status, 0);
  }
  const control = probe("control / unrelated HTTPS", "https", "forge.invalid", false, "synthetic-machine-value");
  const forwarded = probe("bb / unrelated HTTPS", "https", "forge.invalid", true, "synthetic-machine-value");
  const github = probe("bb / GitHub HTTPS", "https", "github.com", true, "synthetic-forwarded-value");
  const lookalike = probe("bb / lookalike HTTPS", "https", "github.com.forge.invalid", true, "synthetic-forwarded-value");
  const insecure = probe("bb / GitHub HTTP", "http", "github.com", true, "synthetic-forwarded-value");
  assert.equal(control.resolved, true, "Local credential control must work without contributions");
  assert.equal(github.resolved, true, "GitHub must use the forwarded synthetic credential");
  assert.notEqual(lookalike.status, 0, "Lookalike hosts must not receive the forwarded credential");
  assert.notEqual(insecure.status, 0, "Plain HTTP must not receive the forwarded credential");
  assert.equal(lookalike.output.includes(environment.GH_TOKEN), false);
  assert.equal(insecure.output.includes(environment.GH_TOKEN), false);
  assert.equal(forwarded.resolved, true, "Unrelated HTTPS must retain its configured local credential helper");
  console.log("Regression assertion: PASS");
} catch (error) {
  console.log(`Regression assertion: FAIL — ${error.message.split("\n")[0]}`);
  process.exitCode = 1;
} finally {
  await rm(scratch, { recursive: true, force: true });
}

5. Root cause

The production configuration list and helper contain an empty, unscoped credential helper followed by a helper that only serves HTTPS github.com:

const githubCredentialHelper =
  '!f() { test "$1" = get || exit 0; protocol=; host=; while IFS= read -r line && test -n "$line"; do case "$line" in protocol=*) protocol=${line#protocol=} ;; host=*) host=${line#host=} ;; esac; done; if test "$protocol" = https && test "$host" = github.com && test -n "$GH_TOKEN"; then printf "username=x-access-token\\npassword=%s\\n" "$GH_TOKEN"; fi; }; f';

const gitConfig = [
  ["credential.helper", ""],
  ["credential.helper", githubCredentialHelper],
  ["url.https://github.com/.insteadOf", "git@github.com:"],
  ["url.https://github.com/.insteadOf", "ssh://git@github.com/"],
] as const;

githubGitConfiguration serializes that list as command-scope GIT_CONFIG_COUNT, GIT_CONFIG_KEY_*, and GIT_CONFIG_VALUE_* environment entries. Git applies the empty helper as a reset after reading the local configuration. Because the reset has no URL restriction, it discards the accumulated helper list for the unrelated host too. The sole remaining helper deliberately returns nothing for that host, so Git reaches its noninteractive username failure. The fixture uses the returned environment entries directly, rather than rebuilding a guessed approximation of bb's configuration.

The host environment resolver includes these entries for enabled non-primary machines. Environment synchronization sends the resolved entries to the host, and MachineEnvironment applies the managed values to process and shell environments. Those wiring paths were inspected, not exercised through a live enrollment.

Existing helper coverage verifies that forwarded values are limited to HTTPS github.com and not sent to lookalike hosts or plain HTTP. That does not assert preservation of another host's pre-existing helper list. The reproduction adds this missing behavioral invariant without creating a production test seam.

6. Proposed fix and autofix safety

A maintainer-reviewed repair should URL-scope the helper-list reset and forwarded helper to the HTTPS GitHub context, preserving their ordering. Unrelated host helper chains should remain intact. Keep the existing SSH URL rewrite behavior and the helper's exact host/protocol checks. Extend the owning credential test with the local-helper preservation scenario and retain coverage for stale GitHub helpers, lookalike hosts, plain HTTP, and SSH rewrite behavior.

No autofix PR: this changes credential selection and authentication behavior, which the rule explicitly excludes from simple fixes. The exclusion is decisive even if the eventual patch is small. No production patch, fix branch, commit, or push was made to get-bb/bb. The proposed repair is derived from the trusted configuration and observed Git behavior; it has not been executed or declared verified here.
