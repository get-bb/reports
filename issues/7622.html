#7622 · Palette capture consumes printable search keystrokes

BugPriority: MediumEffort: Lowui GitHub issue2026-11-16 · base da3e60b81d560e114a2bec724bb59c997aaaae7f

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

The shared palette dialog treats a printable search keystroke as a command shortcut when a plugin command uses that key. A new regression at the real React component boundary fails in both Quick palette and Search threads. The dialog capture handler cancels the native editing event before the search input can use it. Both lowercase and Shift-uppercase bindings reproduce this on two clean trusted-main checkouts. The contained repair preserves printable editing events while leaving modified shortcuts and normal command selection intact.

5. Root cause

CommandPalette.tsx:258–279 installs a capture handler on the entire dialog. After checking that the event belongs to the open dialog, it asks for a matching shortcut. Every match is immediately prevented and stopped, and a matching palette action is chosen. There is no distinction between a text-editing event and a command invocation.

AppCommandProvider.tsx:318–342 matches shortcut keys and client platform; it rejects repeats and composition but does not reject printable keys from editable targets. This is appropriate for a matching helper but insufficient as the palette's entire input policy.

Choosing an action queues its callback and closes the dialog. Thus the capture handler can both suppress text entry and close the search UI. The window path separately evaluates binding context and uses dispatch. Plugin defaults exclude modal context, so ordinary window routing does not require this dialog-local shortcut behavior.

Plugin availability is also evaluated while building the action list. A broader redesign of availability/context semantics is not required to prevent the reproduced editing interception; applying all normal modal exclusions to the palette would disable existing intentional in-dialog shortcuts.

6. Proposed fix and tested result

Before shortcut matching in the palette capture handler, return for a one-character key without Ctrl, Meta, or Alt when the event target is editable. Reuse the existing editable-target predicate. Shift remains allowed so uppercase typing is protected too. Do not alter global matching, public APIs, shortcut persistence, or command-selection semantics.
