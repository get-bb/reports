#5364 · Pi discovery stops before nested skills

BugPriority: MediumEffort: Lowproviders · provider-piGitHub issue2026-10-11 · base 3aa5ef327093f2834f800370881ac0bed8f2d811

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. TL;DR

BB omits skills stored more than one directory below Pi skill roots from both skill and command discovery. The omission reproduces on the current trusted main commit, in two fresh checkouts with isolated temporary files. Repository-pinned Pi loads the same nested and linked-bundle fixtures, keeps them manual-only, and excludes them from its automatic prompt. A top-level link makes BB discover the unchanged skill. Simply enabling recursive root declarations is not a safe complete fix: it recovers real nested directories but still misses linked bundles and removes previously working top-level user links.

5. Root cause

plugins/provider-pi/src/native-roots.ts (L14-L18) declares all four Pi roots as strings. packages/domain/src/native-roots.ts (L174-L184) normalizes strings to recursive: false. The configured/relocated resolver in plugins/provider-pi/src/native-roots.ts (L83-L94) also omits a recursive flag, which defaults false in the resolved-root contract.

user: [".pi/agent/skills", ".agents/skills"]
project: [".pi/skills", ".agents/skills"]
return { path: entry, recursive: false, ancestors: false, namePrefix: "" };

packages/domain/src/native-roots.ts (L315-L323) fills the resolved root's missing recursive value with false. apps/host-daemon/src/command-handlers/list-commands.ts (L142-L151) chooses a shallow skill root when recursion is false. apps/host-daemon/src/command-discovery.ts (L252-L280) only tests each immediate child directory for SKILL.md; it does not descend into a bundle. The shared native-root pipeline drives both skill records and command records, explaining the matching omissions.

A second mechanism makes a provider-only repair insufficient: apps/host-daemon/src/command-discovery.ts (L283-L309) skips every symlink while walking recursively. The shallow path deliberately follows user-origin skill links, unlike project-origin links. apps/host-daemon/src/command-discovery.ts (L313-L329) separately enforces the project boundary for recursive roots. These distinct trust rules must not be silently replaced while repairing Pi discovery.

6. Proposed fix and simple-fix check

Enable recursion for Pi's declared and resolved skill roots only together with a deliberate shared-scanner repair that preserves supported user links, canonical-file deduplication, cycle/entry/depth limits, and existing project containment. Keep manual-only prompt behavior unchanged; the comparison confirms that Pi itself handles it correctly, but no BB model turn was tested.

The smallest provider-only experiment changed one production file (9 additions + 2 deletions) and was tested after the regression's expected pre-fix failures. It produced 2 failed | 6 passed (8): real nested roots became discoverable, but the linked bundle remained absent and the previously passing top-level user-link control regressed. The existing 22 native-root golden tests still passed, demonstrating why they alone are insufficient.

The simple fix was stopped and reverted. No fix commit, push, or pull request was created. It cannot pass the focused regression, and completing the repair requires changing shared, security-sensitive symlink traversal rather than a contained provider declaration. That exceeds this rule's no-security-boundary-change safety constraint. The rejected experiment is included only as evidence, not as a recommended patch:
