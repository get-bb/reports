#5822 · Cancelled hooks are misclassified as daemon failures

BugPriority: MediumEffort: LowhostGitHub issue2026-10-20 · base 7e4232ef241b5cdfb7d272cee044fe6f82702c70

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

A cancellation that reaches the daemon before its hook-run request leaves a cancellation marker. When the delayed request arrives, the handler safely refuses to run the script, but throws an ordinary Error. The RPC router mistakes this expected outcome for a host failure and warns with the Error object; the production logger serializes that object with its stack. Repeating the same request repeats the warning. This report reproduces that mechanism deterministically, not the original production log volume or the upstream reason for repeated requests.

Complete regression test
import { readFile, writeFile } from "node:fs/promises";
import { join } from "node:path";
import { makeTempDir } from "@bb/test-helpers";
import { expect, it, vi } from "vitest";
import { CommandRouter } from "../../src/command-router.js";
import { createHarness } from "./dispatch-helpers.js";

it.each([false, true])(
  "reports pre-dispatch hook cancellation without warnings (resumeOnly: %s)",
  async (resumeOnly) => {
    const path = await makeTempDir("bb-hook-rpc-cancel-");
    await writeFile(join(path, ".bb-env-setup.sh"), "echo unsafe > marker\n");
    const logger = { debug: vi.fn(), warn: vi.fn() };
    const router = new CommandRouter({
      ...createHarness().dispatchOptions({ dataDir: path }),
      logger,
    });

    await expect(
      router.handleOnlineRpcRequest({
        type: "host-rpc.request",
        requestId: "cancel-before-dispatch",
        command: { type: "environment.hook.cancel", operationId: "cancelled" },
      }),
    ).resolves.toMatchObject({ ok: true, result: { status: "unknown" } });

    for (const requestId of ["delayed-run", "repeated-run"]) {
      await expect(
        router.handleOnlineRpcRequest({
          type: "host-rpc.request",
          requestId,
          command: {
            type: "environment.hook.run",
            operationId: "cancelled",
            path,
            kind: "setup",
            contributedEnv: [],
            resumeOnly,
            timeoutMs: 5000,
          },
        }),
      ).resolves.toMatchObject({
        ok: false,
        errorCode: "command_failed",
        errorMessage: "Environment hook cancelled before dispatch",
      });
    }

    await expect(readFile(join(path, "marker"))).rejects.toMatchObject({
      code: "ENOENT",
    });
    expect(logger.warn).not.toHaveBeenCalled();
    expect(logger.debug).toHaveBeenCalledTimes(2);
    expect(logger.debug).toHaveBeenCalledWith(
      {
        commandType: "environment.hook.run",
        errorCode: "command_failed",
        handlerMs: expect.any(Number),
        ok: false,
      },
      "Online host RPC",
    );
  },
);

it("still warns when hook recovery has an unknown outcome", async () => {
  const path = await makeTempDir("bb-hook-rpc-unknown-");
  const logger = { debug: vi.fn(), warn: vi.fn() };
  const router = new CommandRouter({
    ...createHarness().dispatchOptions({ dataDir: path }),
    logger,
  });

  await expect(
    router.handleOnlineRpcRequest({
      type: "host-rpc.request",
      requestId: "unknown-recovery",
      command: {
        type: "environment.hook.run",
        operationId: "unknown",
        path,
        kind: "teardown",
        contributedEnv: [],
        resumeOnly: true,
        timeoutMs: 5000,
      },
    }),
  ).resolves.toMatchObject({
    ok: false,
    errorCode: "command_failed",
    errorMessage: "Environment hook outcome is unknown after daemon restart",
  });
  expect(logger.warn).toHaveBeenCalledExactlyOnceWith(
    { type: "environment.hook.run", err: expect.any(Error) },
    "online host RPC failed",
  );
});

5. Root cause

  1. Cancellation handler stores "cancelled" for a not-yet-dispatched operation.
  2. Run handler sees that marker and throws a generic Error:
    if (existing === "cancelled")
  throw new Error("Environment hook cancelled before dispatch");
    The marker remains, so another run request takes the same path.
  3. Expected-failure classification suppresses warnings only for the existing expected-error class or specific recognized codes. This generic Error has command_failed, which is not globally expected.
  4. RPC failure handling therefore warns with err: error. Production error serializer includes the Error stack.
  5. Existing lifecycle debug logger already records compact failure metadata, without an Error object. Correctly marking just this known cancellation as expected is sufficient; no global warning filter or new wire code is needed.

The generic throw has existed since commit 5f558957aa (September 8, 2026). This explains warning severity and stack amplification. It does not establish the root cause of the server's production retry volume; the command descriptor marks hook runs non-retryable at the transport layer.

6. Proposed fix

Use the existing ExpectedCommandDispatchError at the cancelled-marker branch. Preserve command_failed, the exact message, failed-response shape, marker retention, and non-execution behavior. The existing router then emits its compact debug record without a warning stack. Do not classify every command_failed or every hook failure as expected; unknown recovery and other faults must remain visible. No protocol version change is needed because the existing wire behavior is deliberately unchanged and asserted in the regression.
