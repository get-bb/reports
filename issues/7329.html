1. TL;DR

The report describes new Claude models missing from the picker while Account Pooler is enabled. The bb-side preconditions are confirmed: model discovery receives plugin-contributed routing environment, the pool deliberately marks Claude Code as host-managed, and the Claude provider builds its model list only from CLI initialization. Existing behavioral tests pass in two clean trusted checkouts and demonstrate that reported models are preserved and the bridge memo can refresh. Those tests do not establish that an authenticated, current Claude CLI skips its served catalog or that any particular newly released model is available to pooled accounts. No live login, customer configuration, or real pooled account was accessed, so the end-to-end symptom and upstream authentication gate remain unverified.

import { describe, expect, it, vi } from "vitest";
import { createClaudeCodeBridgeModelListMemo } from "../model-list.js";

function catalog(model: string) {
  return {
    models: [
      {
        id: model,
        model,
        displayName: model,
        description: "",
        reasoningDiscovery: "known" as const,
        supportedReasoningEfforts: [],
        defaultReasoningEffort: "medium" as const,
        isDefault: true,
      },
    ],
    selectedOnlyModels: [],
  };
}

describe("createClaudeCodeBridgeModelListMemo", () => {
  it("shares one probe between concurrent asks and reuses it until the window ends", async () => {
    let currentTime = 0;
    let resolveProbe: (value: ReturnType<typeof catalog>) => void = () => {};
    const list = vi.fn(
      () =>
        new Promise<ReturnType<typeof catalog>>((resolve) => {
          resolveProbe = resolve;
        }),
    );
    const listModels = createClaudeCodeBridgeModelListMemo({
      list,
      now: () => currentTime,
      ttlMs: 1_000,
    });

    const first = listModels();
    const second = listModels();
    expect(list).toHaveBeenCalledTimes(1);
    resolveProbe(catalog("opus"));
    await expect(first).resolves.toEqual(catalog("opus"));
    await expect(second).resolves.toEqual(catalog("opus"));

    currentTime = 999;
    await expect(listModels()).resolves.toEqual(catalog("opus"));
    expect(list).toHaveBeenCalledTimes(1);

    currentTime = 1_000;
    const refreshed = listModels();
    expect(list).toHaveBeenCalledTimes(2);
    resolveProbe(catalog("sonnet"));
    await expect(refreshed).resolves.toEqual(catalog("sonnet"));
  });
});

5. Root cause

Verified bb mechanism: bb has no independent pooled-Claude catalog source in the inspected discovery path. It transforms the CLI initialization models, so it cannot introduce a newly available model that initialization omits. The pool's host-managed environment is intentional credential isolation, not an accidental missing-login assignment.

  1. Server catalog launch resolves plugin-contributed environment with a null thread/project context and a concrete host. The discovery request includes that environment.
  2. Account Pooler contributes the hub route and host-managed mode:
    ANTHROPIC_BASE_URL = Account Pooler HTTP route
ANTHROPIC_AUTH_TOKEN = synthetic per-machine hub token in the test
CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST = 1
    The source explicitly explains that host-managed mode prevents refreshing and consuming the host login's single-use refresh token. Repository history attributes this behavior to the login-isolation change.
  3. The SDK initialization probe forwards its environment and returns session.initializationResult(). Model discovery returns buildClaudeCodeModels(initialization.models).
  4. The model builder iterates only the discovered records. It normalizes and deduplicates them; it does not fetch a second catalog.
  5. The bridge TTL is two minutes. The memo implementation discards an expired result and probes again. This rules out an infinite bridge-memo lifetime, not upstream staleness.

Unproven causal link: whether the current external Claude CLI specifically disables served-catalog discovery in this routing mode. That mechanism is plausible but is outside the exercised code. Confidence is medium because the entire bb-side dependency chain is visible, while the upstream authentication gate, real cache mutation, and current account entitlements were not observed.

6. Proposed fix or next experiment

First obtain a sanitized initialization/catalog trace using an isolated test login and empty temporary home in the supported current CLI. Compare pooled routing against a direct-login control, capture requests and model IDs, and repeat after memo expiry. This experiment must keep the operator's own login untouched.

If that confirms the gate, evaluate an authenticated, read-only model-discovery operation owned by the pool, with explicit account-selection, entitlement, multi-host, and credential-isolation semantics. Do not remove host-managed mode or impersonate a personal login as a quick fix; that would undermine the protection the existing routing code intentionally provides. Hardcoding a newly reported model would not solve recurring catalog freshness.
