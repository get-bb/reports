#8154 · Chromium discovery and nonstandard Keychain metadata

BugPriority: MediumEffort: Lowdesktoppartial-reproIssue2026-11-25

Trusted base: 562cbc3972838a75f37c38c0dee322b4030eedbc

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: medium

1. TL;DR

The importer can discover an unlisted Chromium profile and count its cookies without knowing how that browser names its macOS encryption key. If no catalog metadata matches, it guesses the Keychain service and account from the storage directory name. A controlled service-level test lists a synthetic profile successfully, then fails with keychainItemMissing when the key is stored under a different service. Reading the same database with explicit metadata decrypts its synthetic cookie. This reproduces the proposed mechanism, not an actual installation of the reported browser: its macOS storage location, native Keychain identifiers, and real two-profile import remain unverified on this Linux host.

import { createCipheriv } from "node:crypto";
import { mkdir, mkdtemp, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { DatabaseSync } from "node:sqlite";
import { expect, it, vi } from "vitest";
import { createBrowserImportService } from "../src/browser-import/browser-import.js";
import { readChromiumCookies } from "../src/browser-import/chromium-cookies.js";
import {
  deriveChromiumKey,
  type SecretCommandRunner,
} from "../src/browser-import/chromium-keys.js";

it("imports a discovered Chromium profile whose key uses a nonstandard service", async () => {
  const home = await mkdtemp(join(tmpdir(), "bb-8154-fixture-"));
  try {
    const root = join(home, "Library", "Application Support", "Unlisted", "User Data");
    const profile = join(root, "Default", "Network");
    await mkdir(profile, { recursive: true });
    await writeFile(join(root, "Local State"), JSON.stringify({
      profile: { info_cache: { Default: { name: "Personal" } } },
    }));
    const cookieDatabasePath = join(profile, "Cookies");
    const cipher = createCipheriv(
      "aes-128-cbc",
      deriveChromiumKey("test-key", 1003),
      Buffer.alloc(16, 0x20),
    );
    const encrypted = Buffer.concat([
      Buffer.from("v10"), cipher.update("synthetic-value"), cipher.final(),
    ]);
    const database = new DatabaseSync(cookieDatabasePath);
    try {
      database.exec(`
        create table meta (key text primary key, value text);
        insert into meta values ('version', '14');
        create table cookies (
          host_key text, name text, value text, encrypted_value blob,
          path text, expires_utc integer, is_secure integer,
          is_httponly integer, samesite integer
        );
      `);
      database.prepare("insert into cookies values (?, ?, ?, ?, '/', 0, 1, 1, 1)")
        .run(".example.test", "session", "", encrypted);
    } finally {
      database.close();
    }
    const requestedItems: string[][] = [];
    const run: SecretCommandRunner = async (command, args) => {
      expect(command).toBe("/usr/bin/security");
      requestedItems.push([...args]);
      if (args[3] === "Unlisted Storage Key" && args[5] === "Unlisted") {
        return { stdout: "test-key\n", stderr: "", exitCode: 0 };
      }
      return { stdout: "", stderr: "item not found", exitCode: 44 };
    };
    const service = createBrowserImportService({
      context: { platform: "darwin", home },
      listBrowserStorageNames: async () => new Set(["unlisted"]),
      runSecretCommand: run,
    });
    const source = (await service.listSources()).find((item) => item.id.startsWith("storage-"));
    expect(source).toMatchObject({
      name: "Unlisted (Chromium)",
      profiles: [{ directory: "Default", name: "Personal", cookieCount: 1 }],
    });
    if (!source) throw new Error("synthetic source missing");
    const set = vi.fn(async () => undefined);
    const outcome = await service.importCookies({
      sourceId: source.id, sourceProfileDirectory: "Default",
    }, { cookies: { set, flushStore: vi.fn(async () => undefined) } });
    console.log("import outcome:", JSON.stringify(outcome));
    console.log("requested item:", JSON.stringify(requestedItems));
    const control = await readChromiumCookies({
      cookieDatabasePath,
      keychainService: "Unlisted Storage Key",
      keychainAccount: "Unlisted",
      linuxSecretApplication: undefined,
      platform: "darwin",
    }, run);
    expect(control.cookies).toEqual([
      expect.objectContaining({ name: "session", value: "synthetic-value" }),
    ]);
    console.log("explicit-metadata control: decrypted 1 synthetic cookie");
    expect(outcome).toEqual({ ok: true, imported: 1, skipped: 0, skippedDomains: [] });
    expect(set).toHaveBeenCalledOnce();
  } finally {
    await rm(home, { recursive: true, force: true });
  }
});

5. Root cause

Discovery consults the known-source catalog by root suffix. When nothing matches, it builds the Keychain fields from the detected directory name:

keychainService: known?.keychainService ?? `${name} Safe Storage`,
keychainAccount: known?.keychainAccount ?? name,

Cookie counts depend on SQLite storage, not on acquiring a decryption secret, so successful listing does not validate those identifiers. The import service forwards them unchanged to the Chromium reader. The Keychain reader performs an exact service/account query and translates a missing item or exit code 44 to keychainItemMissing. It does not derive another service from a profile or retry with application-specific aliases.

The two synthetic runs establish this mechanism with high confidence. Overall root-cause confidence remains medium because the actual browser's native identifiers have not been verified. The guessed-item limitation explains the reported symptom only if those supplied identifiers are accurate.

6. Proposed fix and automatic-fix decision

First verify the browser's storage root and exact service/account using an isolated macOS installation without exposing its secret. Then follow the existing known-Chromium-source pattern, supply explicit metadata, and extend the real import-service regression to exercise that browser's selected profiles and cookie locations.

No automatic pull request is safe under this rule. The native browser-specific claim is only partially reproduced. In addition, adding a dedicated known-source ID requires updating the shared source-ID schema, which the simple-fix gate explicitly excludes. A discovery-only special case would avoid the ID change but would not deliver the requested known-source behavior and would still rest on unverified native metadata. No production code, fix branch, commit, or pull request was created.
