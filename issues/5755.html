#5755 · Native-memory instructions target the provider-management page

Bug Priority: Low Effort: Low documentation memory · GitHub issue · October 19, 2026

Trusted base: bc0ef30134e0633c1b6a1adbc1a22fb18a7f9aa0

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

BB's Memory documentation and settings banner tell users to disable provider-native memory in the Providers settings section. The native-memory switches are actually boolean settings owned by the Claude Code and Codex plugins, whose configuration pages appear under Plugins. Five guidance surfaces on trusted main contain the stale destination. A source-level reproduction verifies the disagreement in two clean checkouts; it does not start BB, change user preferences, or invoke a provider. This is a copy/navigation defect, not evidence that the underlying memory switches are broken.

5. Root cause

Instructions use the provider-management category as a shorthand for provider-specific configuration. That is not the app's navigation model: provider plugin settings are registered through bb.settings.define, and the sidebar links plugin entries under a distinct Plugins heading. Thus the requested switch exists, but following the instruction takes the reader to a different screen.

  • Memory README, lines 6–8: stale destination.
  • Memory overview, lines 17–19: repeats the stale destination.
  • Bundled agent skill, lines 8–10: gives the same incorrect navigation advice to agents.
  • Memory settings banner, lines 185–191: identical user-facing mismatch.
  • Provider guide, lines 80–84: incorrectly places provider-specific pages under Providers.
  • Sidebar, lines 430–449: actual plugin configuration links under Plugins.
  • Plugin settings renderer, lines 135–149: boolean fields render as switches.
  • Providers settings component: provider management, not the plugin settings form.
  • Claude setting registration and Codex setting registration: the existing controls.
  • Claude native flag mapping and Codex native config mappings.
  • CLI plugin settings parsing and update boundary.
Stale instruction: Settings → Providers
Existing UI ownership: Settings → Plugins → provider plugin configuration
Claude setting label: Claude Code memory
Codex setting label: Codex memory

6. Proposed fix

Correct the five stale guidance surfaces to describe the existing provider plugin settings, with concise cross-references to one explanation of the native-memory controls. Make the provider guide agree with the same navigation. Do not move or duplicate the switches: the defect is copy drift, not a missing control. Keep lifecycle claims separate from the verified navigation fix unless they are checked at the provider boundary.

No fix branch or new pull request was created because an open PR already links to this issue. In particular, no production change, package version change, new dependency, or permanent test was introduced by this investigation.
