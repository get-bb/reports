#4880 · Move freeze incorrectly clears the live connect account

Bug High Effort: Low remote · connect · confirmed-repro open on GitHub 2026-10-05 · base 300a08b859f7786452c4fcab4e3a2bef56b823bb

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

During a server move, the source server pauses public writes but deliberately keeps its account and connect plugins running. Those plugins still communicate through POST RPCs, so the freeze rejects their account reads with HTTP 503 and code server_moving. Connect collapses that temporary response into an account-unavailable error, clears its last known account, and closes the live tunnel. A local test with the real account and connect plugins reproduces the disconnect after the real 25-second long-poll expires; a separate real freeze-middleware and SDK test verifies the HTTP-to-error translation. Both failures repeat in a second clean checkout of the same trusted main commit.

5. Root cause

The write freeze classifies all non-move POST routes as writes, including plugin RPCs that only read account state. The SDK preserves the freeze's distinct error code, but the account client throws that information away when it translates every 503 into account unavailable. AccountLink reserves that error for situations in which it must clear the account, so it calls the connect tunnel with null. Connect's existing identity-change path then tears down the current tunnel. The retry path cannot restore the account while status RPCs continue returning the freeze response.

): MiddlewareHandler {

6. Proposed fix

In connect's existing account RPC error boundary, retain the original error specifically when its status is 503 and its code is server_moving. AccountLink already logs and retries non-unavailable failures without clearing the last known account. Keep normal missing/stopped-plugin responses, actual sign-out, and credential rejection behavior unchanged. This changes neither the freeze allowlist nor any authentication or authorization rule, protocol, package, data schema, or stored data.

The proposed local fix changes only the connect client and its existing integration test. It addresses this account-poll-induced teardown, not every remaining failure in a full server move. In particular, a blocked move-time grant is a separate concern.
