1. TL;DR

The issue reports a package typecheck failure at a test assertion using Node's Buffer global. Two fresh worktrees of trusted main, each installed with the frozen lockfile, successfully ran the actual package typecheck. An additional forced compiler run listed Node declaration files, including the Buffer declarations, despite the package's types: [] setting. All 22 existing package tests also passed. The reported failure's environmental prerequisite remains unknown, so no fix pull request is justified by this investigation.

5. Root cause analysis

The reported failure's root cause is not established. Source inspection does verify the two reported ingredients: the Buffer assertion at line 230 and types: [] at line 8. Neither file was modified for these runs.

expect(Buffer.compare(Buffer.from(total), Buffer.from(data))).toBe(0);

However, types: [] does not erase declarations reached through imported modules and their explicit references. The test imports Vitest. The installed Vitest entry declaration imports its reporter declarations and Node modules such as node:stream; the reporter declarations also import Node modules. Direct compiler instrumentation confirms that the resulting program includes Node's index and Buffer declarations.

pnpm exec turbo run typecheck --filter=@bb/tunnel-contract --force -- --listFiles
pnpm exec turbo run typecheck --filter=@bb/tunnel-contract --force -- --explainFiles

Both diagnostic runs exit 0. Relevant compiler inputs, with checkout-specific prefixes omitted:

@types+node@22.19.10/node_modules/@types/node/buffer.d.ts
@types+node@22.19.10/node_modules/@types/node/index.d.ts
@types+node@24.12.4/node_modules/@types/node/buffer.d.ts
@types+node@24.12.4/node_modules/@types/node/index.d.ts

This explains why the global is available here. It does not prove why the reporter's earlier environment differed. The package typecheck script invokes the installed compiler normally.
