#7755 · Provider updater labels lose executable identity

BugPriority: LowEffort: Lowuiprovider-claude-codeGitHub issue2026-11-18 · base ab7ad23bacb822445a1d7639d10318af86258148

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The Updates settings show which tool will perform each provider update. When a provider identifies its own executable by an absolute path, its self-updater is not labeled “Built-in updater.” The label instead shows the executable basename, or a fragment of a shell-quoted path. Two runs of the real React component at the same trusted main commit produce four matching failures while a bare executable control passes. This is a label-formatting defect; no provider update was executed.

5. Root cause

The label helper at the trusted base splits the display command on whitespace before extracting its last path segment. It strips executable extensions only on that extracted command token, then compares it against the entire status.executableName.

export function providerCliUpdaterName(
  status: ProviderCliStatusEntry["status"],
): string | null {
  const command = status.installAction?.command.trim().split(/\s+/u)[0];
  if (command === undefined || command.length === 0) {
    return null;
  }
  const executable = (command.split(/[\\/]/u).pop() ?? command).replace(
    /\.(?:exe|cmd|bat)$/iu,
    "",
  );
  if (executable === status.executableName) {
    return "Built-in updater";
  }
  return UPDATER_NAMES[executable] ?? executable;
}

For an absolute path, this compares claude with /opt/tools/claude, so the built-in branch cannot match. For a quoted path with spaces, the first whitespace-separated token is not the executable at all. An apostrophe escaped as a shell quote boundary further survives as label punctuation.

Claude executable resolution can return an absolute path. The bridge response returns it as executableName and formats the update command from the same executable. The shared formatter single-quotes parts with spaces or backslashes and escapes embedded apostrophes. These contracts explain both failure modes without executing the provider.

The provider row calls this helper only for display; the label and tooltip retain the original action command separately. This investigation does not test updater execution.

6. Proposed fix

Recognize the executable as one shell-formatted word, including the quote/escape form produced by the shared formatter. Normalize both that executable and the reported identity to basenames with the same extension handling before comparing them. Preserve existing package-manager labels and the original command. Keep the regression at the rendered component boundary; no protocol or installation-policy change is needed.
