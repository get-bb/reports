1. TL;DR

The issue describes a side-chat fork timing out and attributes it to Unicode separators splitting a valid provider response. On unchanged trusted main, the actual connection successfully receives both U+2028 and U+2029, including responses with 10,000,000 padding characters and a separator's UTF-8 bytes split across writes. A direct Node readline probe also returns exactly one record per response, not three fragments. The same agent repeated the checks in a second clean checkout with caching bypassed; all ten investigation cases and seven existing connection tests passed. This does not disprove the reported installed-macOS timeout: that environment and its original provider traffic were unavailable.

Complete authored test
import { createInterface } from "node:readline";
import { Readable } from "node:stream";
import { describe, expect, it } from "vitest";
import { z } from "zod";
import { createCodexAppServerConnection } from "./app-server-connection.js";

const cases = [0x2028, 0x2029].flatMap((codePoint) =>
  [false, true].flatMap((fragmented) =>
    [0, 10_000_000].map((padding) => ({ codePoint, fragmented, padding })),
  ),
);

describe("provider stdout separator investigation", () => {
  it.each([0x2028, 0x2029])(
    "keeps U+%i inside a single JSON record",
    async (codePoint) => {
      const text = `before${String.fromCodePoint(codePoint)}middle${String.fromCodePoint(codePoint)}after`;
      const response = { id: 7, result: { text } };
      const lines: string[] = [];
      for await (const line of createInterface({
        input: Readable.from([Buffer.from(`${JSON.stringify(response)}\n`)]),
        terminal: false,
      })) {
        lines.push(line);
      }
      expect(lines).toHaveLength(1);
      expect(JSON.parse(lines[0]!)).toEqual(response);
    },
  );

  it.each(cases)(
    "resolves a response with $codePoint, fragmented=$fragmented, padding=$padding",
    async ({ codePoint, fragmented, padding }) => {
      const text = `before${String.fromCodePoint(codePoint)}middle${String.fromCodePoint(codePoint)}after${"x".repeat(padding)}`;
      const childScript = [
        `const text = "before" + String.fromCodePoint(${codePoint}) + "middle" + String.fromCodePoint(${codePoint}) + "after" + "x".repeat(${padding});`,
        'process.stdin.once("data", (chunk) => {',
        "const request = JSON.parse(chunk.toString());",
        'const wire = Buffer.from(JSON.stringify({jsonrpc:"2.0", id:request.id, result:{text}}) + "\\n");',
        `if (${fragmented}) {`,
        `const boundary = wire.indexOf(Buffer.from(String.fromCodePoint(${codePoint}))) + 1;`,
        "process.stdout.write(wire.subarray(0, boundary));",
        "setTimeout(() => process.stdout.write(wire.subarray(boundary)), 25);",
        "} else { process.stdout.write(wire); }",
        "});",
      ].join("");
      const connection = createCodexAppServerConnection({
        command: process.execPath,
        args: ["-e", childScript],
        cwd: process.cwd(),
        env: process.env,
        recordThreadId: null,
        onNotification: () => undefined,
        onRequest: () => undefined,
        onExit: () => undefined,
      });
      try {
        const response = await connection.request({
          method: "fixture/response",
          params: {},
          resultSchema: z.object({ text: z.string() }),
          timeoutMs: 2_000,
        });
        expect(response.text).toBe(text);
      } finally {
        await connection.kill();
      }
    },
  );
});

5. Root cause assessment

No cause of the reported installed fork timeout has been established. The hypothesized separator-framing mechanism does not occur in the tested source/runtime. The loaded Node implementation uses this line-ending expression, which does not match either Unicode separator:

const lineEnding = /\r?\n|\r(?!\n)/g;

The real connection reads stdout through readline at lines 257–265. It does ignore JSON parse failures, but that fact alone does not demonstrate malformed framing. An unfulfilled request eventually produces the generic request deadline error; that error is not diagnostic of a Unicode cause.

A replay-helper comment also asserts Unicode splitting. It is not runtime evidence and was not treated as proof. The tests above exercise the production connection directly.
