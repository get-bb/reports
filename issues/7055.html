#7055 · Tasks list settlement stalls on cached route changes

BugPriority: MediumEffort: Lowplugins · tasks Issue · 2026-11-04 · base 82e14ef0d485403ed5c7f1406127a29ee3253ba6

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The real Tasks panel can keep showing placeholder rows after navigation to an already cached list. React reuses one unkeyed list component across All, Active, and project routes; its route-settlement effect deliberately skips the first route-change render. When the new query is already settled, nothing must change the dependencies that would run that effect again. A frontend integration regression using the actual panel registration and SDK query cache fails on trusted main in both checkouts. Keying list instances by route scope and deleting the redundant settlement gate fixes the regression while retaining genuine loading and error states.

5. Root cause

RouteOutlet returns the same ListView component type without a route key for all three list route kinds. Thus component-local state and the previous-task fallback survive scope changes.

The settlement effect writes the current route to a ref but updates settledRouteScope only if the route did not just change and the query is not loading. The body gate then renders LoadingRows whenever settledRouteScope disagrees with the new route, even with usable query data.

The effect depends only on routeScope, tasksQuery.isLoading and tasksQuery.data. Cached navigation can leave all three dependencies stable after that skipped effect. An unrelated rerender alone does not rerun it. The same gate excludes the error branch during a route mismatch.

useListTasks retains the previous scope's data while loading. Simply removing the gate without isolating list instances could expose old-scope rows on an uncached destination. The repair addresses both lifetime and settlement rather than relaxing the gate in isolation.

The route guard dates to commit b61ec88de2f (confirmed by blame); it is still present at the recorded trusted base. No backend or daemon wire change is needed.

6. Proposed fix and measured result

Give All, Active, and project ListView instances distinct React keys in RouteOutlet. Remove the now-obsolete cross-route settlement state and its render gate. A remount starts previous-data fallback state empty for an uncached scope, while the shared SDK cache still serves cached data. Existing preference and scroll stores remain scope-addressed.

The implemented candidate changes only three existing Tasks files: 84 additions and 20 deletions, 104 changed text lines total. Production accounts for five additions and twenty deletions; regression coverage adds 79 lines. It adds no API, dependency, schema, protocol, migration, stored-data change, or release change.
