#8060 · Ladle replaces its core plugin runtime with a test runtime

BugHighEffort: Mediumui · pluginsIssue

November 23, 2026 · trusted origin/main 02239e9e373fe8a74a75f91afbfb06016ed5a1ef

REPRODUCED · root-cause confidence: high · reproduction label: confirmed-repro

TL;DR

The sidebar fixture renders a crash fallback instead of thread rows. Its story installs the SDK's unit-test runtime even though Ladle has already installed the real app runtime. The thread-list plugin consequently looks for the test-only slot context, which the real core host does not provide. An independently authored story-render test reproduces the exact exception in two clean checkouts of the recorded main commit. A separate missing Vite resolver also prevents a Ladle production build. An open PR already addresses this issue, so this run does not create another fix PR.

Expected: a successful static story build. Actual, twice:

[vite]: Rollup failed to resolve import "virtual:bb-plugin-zod" from "CHECKOUT/apps/app/src/lib/plugin-zod-runtime.ts".

CHECKOUT replaces only the temporary directory prefix. Ladle subsequently also reports missing build/meta.json while handling its failed build; that is secondary, not the cause.

Root cause

  1. Ladle global components imports the real runtime initializer and overrides only the story composer search hooks.
  2. The sidebar story then calls the test runtime installer at module scope. The same call appears in the question, Codex elicitation, interaction-state, and workflow story modules.
  3. installTestPluginRuntime replaces the global runtime object and sets pluginSdkApp: testPluginSdkApp. In contrast, installPluginRuntime uses host.__bbPluginRuntime ??= { ... }, so an existing fake runtime is not repaired by calling it.
  4. SDK hook forwarders select functions from the currently installed global runtime on each call. The thread-list plugin calls useBbContext. The selected test hook asks useSlotEnv for its private context and throws when absent.
  5. The story mounts through SidebarThreadListContent, not the testing renderer. Core's PluginSlotMount supplies PluginContext, not the testing SlotEnvContext, so the throw reaches the slot crash boundary.

The workflow case has a second installer entry: its loadPluginApp call reaches the test registration helper, which also installs the fake runtime. Removing only the workflow's explicit installer would therefore leave that path broken.

The separate build defect is confined to Ladle configuration: the runtime Zod import references a virtual module, while the Ladle plugin array omits pluginZodRuntime, which resolves it. Both clean builds corroborate that boundary failure.

Proposed fix

Keep core-hosted Ladle stories on the real runtime. Remove the five story-level test installer calls and replace the workflow's test registration helper with the existing core registration collector. Retain an end-to-end story-render regression at the real host boundary. Add the existing virtual-Zod resolver to Ladle's Vite configuration as a separate correction. Do not change the public testing SDK or make the core initializer silently overwrite arbitrary runtimes.
