#5201 · Selected skills lose provider invocation semantics

Bug Priority: Medium Effort: Low providers · provider-codex · GitHub issue

October 8, 2026 · trusted origin/main f135a001e72942cee9118d2693208ec0725e2f18

Verdict: REPRODUCED at the provider conversion boundary · Root-cause confidence: high · reproduction label: confirmed-repro.

1. TL;DR

BB records a selected skill as text plus structured mention metadata. Selecting it through the slash menu retains a slash in the text, while selecting it through the dollar menu retains a dollar sign. The Codex input converter discards the metadata and forwards that text unchanged. A newly written regression test reproduces this difference on unchanged trusted main in two separate clean checkouts. This report verifies the outgoing input defect, not a fresh live model response or native skill-content injection.

5. Root cause

The composer inserts the active trigger into serialized text while its resource constructor preserves skill metadata. The command resource contract records identity and source but has no native skill path.

At the provider boundary, the converter does not inspect mentions at all:

case "text":
  return { type: "text", text: chunk.text, text_elements: [] };

Consequently a selected slash skill is indistinguishable from literal slash text in the emitted Codex input. The turn/start request and turn/steer request both consume the same converter result. This directly explains the outgoing payload defect. The reported native skill-block behavior remains a downstream claim, not freshly executed evidence.

6. Proposed fix

Within the existing Codex converter, translate only exact, valid ranges whose resource is a slash-triggered skill into dollar invocation text. Preserve the displayed BB input, dollar selections, ordinary commands, unselected text, and unrelated input variants. Reject stale, overlapping, or out-of-bounds ranges instead of rewriting arbitrary text. A native skill item would additionally require a skill path that the current mention contract does not carry; the contained text translation avoids a discovery or public-contract change.

No fix branch or duplicate pull request was created: an open ready PR already explicitly closes this issue.

7. Existing PR: #5202

PR #5202 was OPEN and non-draft, and GitHub closing-issue metadata linked it to #5201. Its diff was read only after designing and running the trusted-base regression. No PR code was checked out or executed.

The static diff updates the existing converter to sort mention ranges, select slash skill resources, require an exact text match, reject out-of-bounds or previously consumed ranges, and reconstruct only the provider text. Its tests cover selected skills, plain text, repeated names and stale ranges. Static verdict: the proposed approach targets the reproduced root cause; no blocking finding in the inspected diff. This is not a runtime approval of the PR: only the unchanged main converter and the independently authored report test were executed.
