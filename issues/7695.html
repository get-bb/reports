#7695 · Plain Markdown takes the full-document renderer during streaming

BugMedium priorityLow effortui · perf · confirmed-repro GitHub issue2026-11-17 · base 1320c88e8abdd3f145bc9a5c305eace269fb2f28

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Streaming assistant messages are intended to reuse already-rendered Markdown blocks. A literal less-than sign in inline code, a code fence, escaped text, or comparison prose instead sends the preview through the whole-document HTML renderer. In a direct component reproduction, each of eight paragraph appends reparses the settled prefix in all four cases; a plain-text control reparses that prefix zero times. The real Markdown parser and HTML pipeline execute in these tests: instrumentation records their source inputs without replacing their results. This establishes repeated parsing work, not an end-user frame-time measurement or a claim about the frequency of affected answers.

// @vitest-environment jsdom

import { cleanup, render } from "@testing-library/react";
import { afterEach, beforeAll, describe, expect, it, vi } from "vitest";
import { LazyMarkdownHtml } from "./lazy-markdown-html";
import { MarkdownPreview } from "./markdown-preview";

const parsedSources = vi.hoisted(() => [] as string[]);

vi.mock("react-markdown", async (importOriginal) => {
  const actual = await importOriginal<typeof import("react-markdown")>();
  return {
    ...actual,
    default: (props: Parameters<typeof actual.default>[0]) => {
      parsedSources.push(props.children ?? "");
      return actual.default(props);
    },
  };
});

beforeAll(() => LazyMarkdownHtml.preload());

afterEach(() => {
  cleanup();
  parsedSources.length = 0;
});

describe("issue 7695 settled Markdown parsing", () => {
  it.each([
    ["plain control", "A collection of items."],
    ["inline code", "Use `ReadonlySet<Item>` here."],
    ["fenced code", "```js\nif (size < limit) return count;\n```"],
    ["comparison prose", "Progress < target means keep working."],
    ["escaped angle", "Display \\<button\\> literally."],
  ])("does not reparse settled content: %s", (label, sample) => {
    let content = `Settled marker.\n\n${sample}\n\nSettled ending.\n\n`;
    const view = render(
      <MarkdownPreview content={content} allowHtml incrementalBlocks />,
    );
    expect(view.container.textContent).toContain("Settled marker.");
    parsedSources.length = 0;

    for (let index = 1; index <= 8; index += 1) {
      content += `Additional paragraph ${index}.\n\n`;
      view.rerender(
        <MarkdownPreview content={content} allowHtml incrementalBlocks />,
      );
    }

    const reparsedSettledSources = parsedSources.filter((source) =>
      source.includes("Settled marker."),
    );
    console.log(
      JSON.stringify({
        label,
        updates: 8,
        reparsedSettledCalls: reparsedSettledSources.length,
        reparsedDocumentLengths: reparsedSettledSources.map(
          (source) => source.length,
        ),
        parsedCharacters: parsedSources.reduce(
          (total, source) => total + source.length,
          0,
        ),
      }),
    );
    expect(view.container.textContent).toContain("Additional paragraph 8.");
    expect(reparsedSettledSources).toHaveLength(0);
  });

  it("keeps real cross-block HTML on the sanitized document path", () => {
    const initial =
      '<details>\n<summary>Settled marker.</summary>\n\nInside.\n\n</details>\n\nTail.';
    const view = render(
      <MarkdownPreview content={initial} allowHtml incrementalBlocks />,
    );
    parsedSources.length = 0;
    view.rerender(
      <MarkdownPreview
        content={`${initial}\n\nAdditional paragraph.`}
        allowHtml
        incrementalBlocks
      />,
    );
    expect(view.container.querySelector("details summary")?.textContent).toBe(
      "Settled marker.",
    );
    expect(view.container.querySelector("details")?.textContent).toContain(
      "Inside.",
    );
    expect(parsedSources.some((source) => source.includes(initial))).toBe(true);
  });
});

5. Root cause

The assistant-message caller enables both HTML and incremental blocks in ConversationMessageContent.tsx:580–603. The preview makes its renderer decision from the unparsed source, before resolving cached pieces:

const rendersHtml = allowHtml && content.includes("<");
const usesIncrementalBlocks =
  incrementalBlocks && !rendersHtml && promptMentions === undefined;

Source: markdown-preview.tsx:1778–1781. This lexical test cannot distinguish an actual HTML node from code or literal prose. When it is true, markdown-preview.tsx:1960–1976 skips resolveMarkdownPieces, selects LazyMarkdownHtml, and passes the complete normalized body to it. The loaded HTML implementation combines rehypeRaw and sanitization before invoking ReactMarkdown: markdown-html.tsx:77–87.

The alternative incremental implementation already summarizes each Markdown syntax tree and reuses unchanged piece entries. The gate bypasses this mechanism entirely. Thus, for fixed-size appended blocks, the sum of full-document input lengths grows quadratically with the number of updates. This is a statement about accumulated parser input, not a measured CPU-time bound. Other global Markdown constructs may independently require whole-document parsing; the reproduction deliberately contains none.

6. Proposed fix

Record whether a parsed piece actually contains an HTML node in its existing summary, retain that information with cached entries, and use the aggregated result to select whole-document sanitized rendering. Non-HTML angles should retain the existing incremental path. Do not remove HTML sanitization or render genuine HTML independently per piece: markup can span piece boundaries. Keep the existing conservative behavior when incremental processing is disabled or unavailable. The regression above should become green, while the genuine-HTML control and existing incremental/cold-HTML suites remain green.
