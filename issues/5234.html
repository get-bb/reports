#5234 · Latest-state lookup is already linear on main

BugHighEffort: Lowthreads, perf, no-reproIssue #5234October 8, 2026 · base ff94848832b22c3281ffc4b5b9069d2490ddea36

Verdict: ALREADY FIXED · Root-cause confidence: high

1. TL;DR

The report describes long server pauses during thread-list loading when threads have unrelated extension history but no goals. The earlier database query correlated a latest-state search with every state-event row, allowing repeated parsing of the same history. Trusted main already replaces that outer event scan with one descending candidate search per requested thread. The repair is commit ef570298ef45b39d837da0fcab0fb94ea086783b, merged in #4931 on October 5, 2026 at 21:04:53 UTC, before this issue was created on October 8. Two fresh checkouts of current main inspect each synthetic unrelated payload once and return no goals, so another patch would duplicate an existing fix.

Complete reproduction test (save as packages/db/test/issue-5234-repro.test.ts):

import { performance } from "node:perf_hooks";
import { expect, it } from "vitest";
import { threadScope } from "@bb/domain";
import { createConnection } from "../src/connection.js";
import { migrate } from "../src/migrate.js";
import { noopNotifier } from "../src/notifier.js";
import { createProject } from "../src/data/projects.js";
import { upsertHost } from "../src/data/hosts.js";
import { createThread } from "../src/data/threads.js";
import {
  insertEvents,
  listLatestThreadStateEventRowsByThreadIds,
} from "../src/data/events.js";

it.each([96, 384])(
  "inspects unrelated extension payloads at most once with %i events per thread",
  (historyLength) => {
    const db = createConnection(":memory:");
    const delegate = createConnection(":memory:");
    try {
      migrate(db);
      migrate(delegate);
      const host = upsertHost(db, noopNotifier, { name: "synthetic-host" });
      const { project } = createProject(db, noopNotifier, {
        name: "synthetic-project",
        source: { type: "local_path", hostId: host.id, path: "/tmp/synthetic" },
      });
      const threads = Array.from({ length: 8 }, () =>
        createThread(db, noopNotifier, {
          projectId: project.id,
          providerId: "codex",
        }),
      );
      const payload = JSON.stringify({
        kind: "synthetic/state",
        payload: { text: "z".repeat(8192) },
      });
      insertEvents(
        db,
        noopNotifier,
        threads.flatMap((thread) =>
          Array.from({ length: historyLength }, (_, index) => ({
            data: payload,
            itemId: null,
            itemKind: null,
            parentToolCallId: null,
            scope: threadScope(),
            sequence: index + 1,
            threadId: thread.id,
            type: "thread/extensionState/updated" as const,
          })),
        ),
      );
      const threadIds = threads.map((thread) => thread.id);
      const started = performance.now();
      expect(
        listLatestThreadStateEventRowsByThreadIds(db, {
          threadIds,
          kind: "provider-codex/goal",
        }),
      ).toEqual([]);
      const elapsedMs = performance.now() - started;
      const builtinJsonExtract = delegate.$client.prepare<
        [string, string],
        { value: string | null }
      >("SELECT json_extract(?, ?) AS value");
      let jsonExtractions = 0;
      db.$client.function(
        "json_extract",
        { deterministic: true },
        (data: string, path: string) => {
          jsonExtractions += 1;
          const result = builtinJsonExtract.get(data, path);
          if (!result) throw new Error("Missing SQLite JSON result");
          return result.value;
        },
      );
      expect(
        listLatestThreadStateEventRowsByThreadIds(db, {
          threadIds: [...threadIds, threadIds[0]!],
          kind: "provider-codex/goal",
        }),
      ).toEqual([]);
      const maximumExtractions = threads.length * historyLength;
      console.log(
        JSON.stringify({
          historyLength,
          threads: threads.length,
          rows: 0,
          nativeQueryMs: Number(elapsedMs.toFixed(3)),
          jsonExtractions,
          maximumExtractions,
          sqlite: delegate.$client
            .prepare("SELECT sqlite_version()")
            .pluck()
            .get(),
        }),
      );
      expect(jsonExtractions).toBeGreaterThan(0);
      expect(jsonExtractions).toBeLessThanOrEqual(maximumExtractions);
    } finally {
      db.$client.close();
      delegate.$client.close();
    }
  },
);

5. Root cause

The old implementation searched outer state-event rows and evaluated a correlated MAX(candidate.sequence) against each row's thread. A missing goal forces the kind predicate to parse unrelated state history; correlating this work to each outer event amplifies it. That historical mechanism is visible in the trusted merged source diff, not inferred from the issue's executable snippet.

The repair changes the correlation domain to a VALUES list of requested thread IDs, selects one candidate row in descending sequence order with LIMIT 1, and uses the existing partial state index. Missing goals still require one history pass per requested thread, but not a history pass per state event.

  • Current latest-state query and batching.
  • Thread-list prompt-banner candidate lookup calls the function for requested threads.
  • Existing semantics: legacy goals, clear events, extension kinds, missing state, duplicate/empty IDs, and SQLite-variable-limit batching.
  • Existing multi-thread query-plan regression.
  • Trusted merged repair; local ancestry check confirms it is an ancestor of the tested base.
