#6516 · Detached touch targets leave scroll corrections pending

BugPriority: MediumEffort: LowmobilethreadsIssue

2026-10-29 · trusted origin/main 24a5b76866621c2e093787219c7e605bcb0cefc1

PARTIALLY REPRODUCED · Root-cause confidence: high at the scroll-keeper boundary

1. TL;DR

The component can leave newly inserted older rows above the reachable scroll range when its touch-start element disappears before the touch ends. A new test drives the real ScrollPositionKeeper with the repository's existing deterministic DOM layout harness. With an attached target, the correction flushes to scrollTop 320; with a detached target, scrollTop remains 0 and the content retains a negative 320px transform. The same agent repeated this result in a second clean checkout of the same trusted main commit. Native WKWebView gestures, real pagination, and the reported persistence until reopening were not exercised, so this is a partial reproduction of the device report rather than a claim of complete iOS verification.

Complete reproduction test
// @vitest-environment jsdom

import { afterEach, expect, it, vi } from "vitest";
import { installFakeFlowLayout, setFakeHeight } from "@/test/fake-flow-layout";
import { ScrollPositionKeeper } from "./scroll-position-keeper";

let cleanup = () => {};

afterEach(() => {
  cleanup();
  vi.useRealTimers();
  document.body.replaceChildren();
});

it.each([false, true])("releases a prepended-page correction after touch completion (removed target: %s)", (removed) => {
  vi.useFakeTimers({ toFake: ["setTimeout", "clearTimeout", "performance"] });
  const viewport = document.createElement("div");
  const content = document.createElement("div");
  const target = document.createElement("button");
  const items = document.createElement("div");
  content.append(target, items);
  viewport.append(content);
  document.body.append(viewport);
  const layout = installFakeFlowLayout({ scrollElement: viewport, viewportHeight: 500 });
  const makeRow = (index: number) => {
    const row = document.createElement("div");
    row.dataset.timelineRowId = `entry-${index}`;
    setFakeHeight(row, 160);
    return row;
  };
  items.append(...Array.from({ length: 12 }, (_, index) => makeRow(index)));
  const keeper = new ScrollPositionKeeper({
    bottomThresholdPx: 4,
    deferWritesWhileScrolling: true,
    getContentElement: () => content,
    getFloorElement: () => null,
    getFooterElement: () => null,
    getScrollElement: () => viewport,
    getTopLevelRows: () => items.querySelectorAll<HTMLElement>("[data-timeline-row-id]"),
    initiallyAttached: false,
  });
  const disconnect = keeper.connect(viewport);
  cleanup = () => { disconnect(); layout.restore(); };
  layout.userScrollTo(40);
  layout.userScrollTo(0);
  vi.advanceTimersByTime(500);
  target.dispatchEvent(new TouchEvent("touchstart", { bubbles: true }));
  if (removed) target.remove();
  items.prepend(makeRow(-2), makeRow(-1));
  keeper.reconcile();
  expect(content.style.transform).not.toBe("");
  target.dispatchEvent(new TouchEvent("touchend", { bubbles: true }));
  vi.advanceTimersByTime(1000);
  console.log(JSON.stringify({ removed, scrollTop: viewport.scrollTop, transform: content.style.transform }));
  expect(viewport.scrollTop).toBe(320);
  expect(content.style.transform).toBe("");
});

5. Root cause

apps/app/src/components/ui/scroll-position-keeper.ts:205 sets touching on touchstart and clears it in endTouch. The touch-end and cancellation listeners are registered only on the scroll element (apps/app/src/components/ui/scroll-position-keeper.ts:281). Once a descendant is detached, an event dispatched to that descendant no longer traverses the former scroll ancestor. The new test exercises precisely that DOM event-delivery difference, while all production source remains unchanged.

    const onTouchStart = () => {
      if (!this.touching) {
        this.gestureScrolled = false;
        this.touchStartScrollTop = scrollElement.scrollTop;
      }
      this.touching = true;
    };
    const activeTouchPointers = new Set<number>();
    const endTouch = () => {
      if (!this.touching) return;
      activeTouchPointers.clear();
      this.touching = false;
      if (Math.abs(scrollElement.scrollTop - this.touchStartScrollTop) >= 1) {
        this.gestureScrolled = true;
        this.scrollMovedAt = window.performance.now();
      }
      if (this.gestureScrolled) {
        this.extendInput(MOMENTUM_SESSION_MS);
        this.handleScroll();
      }
      this.scheduleDeferredWrite();
    };
    const onTouchEnd = (event: TouchEvent) => {
      if (event.touches.length > 0) return;
      endTouch();
    };

The fallback for touch pointers only accepts pointerup, not pointercancel (apps/app/src/components/ui/scroll-position-keeper.ts:243). The deferral gate then remains closed because touching is still true, and every settle timer schedules another timer instead of flushing (apps/app/src/components/ui/scroll-position-keeper.ts:886):

  private shouldDefer(scrollTop: number, max: number): boolean {
    if (!this.options.deferWritesWhileScrolling) return false;
    if (this.touching) return true;
    if (window.performance.now() - this.scrollMovedAt < SCROLL_SETTLE_MS) {
      return true;
    }
    return scrollTop < 0 || scrollTop > max;
  }

  private scheduleDeferredWrite(): void {
    if (this.deferred === 0 || this.settleTimeout !== null) return;
    this.settleTimeout = window.setTimeout(() => {
      this.settleTimeout = null;
      const scrollElement = this.options.getScrollElement();
      if (scrollElement === null || this.deferred === 0) return;
      const scrollTop = scrollElement.scrollTop;
      if (this.shouldDefer(scrollTop, this.maxScrollTop)) {
        this.scheduleDeferredWrite();
        return;
      }
      this.flushDeferred();
      this.reconcile();
    }, SCROLL_SETTLE_MS);

apps/app/src/components/ui/scroll-position-keeper.ts:1003 renders the deferred correction as a negative content transform. With native scrollTop already at zero, those translated rows cannot be reached by reducing scrollTop further. This explains the inaccessible older-row symptom under the test's event sequence, but does not establish the precise native iOS sequence or duration.

The production path enables this mode for iOS WebKit in apps/app/src/components/ui/bottom-anchored-scroll-body.tsx:125. apps/app/src/components/thread/timeline/ThreadTimelineSurface.tsx:204 conditionally mounts the older-message status, so its removal is a plausible real target-loss trigger. The component reproduction deliberately does not require server pagination or a specific production thread.

6. Proposed fix

Observe terminal touch events on the actual start target as well as the scroll ancestor, so removing that target cannot suppress completion. Keep the existing rule that active remaining touches prevent completion. Remove any extra listeners when the gesture finishes and when the keeper disconnects. Preserve the existing momentum/settle policy rather than unconditionally writing scrollTop during a live iOS gesture.

No production fix was applied: an open pull request already links to this issue. A duplicate PR would violate the automation's safety rules.
