1. TL;DR

The report concerns two device-settings labels becoming unreadable with large iOS accessibility text. The trusted source defaults every grouped-row title to one line, and the settings links do not override that limit. Running the actual grouped-row component with an injected iOS environment returns a title line limit of one in both tested viewport configurations. That constraint prevents wrapping, but this Linux environment cannot establish the exact native ellipsis, row height, or maximum Dynamic Type behavior. A linked open pull request already exists, so no duplicate fix was attempted.

import { Children, isValidElement, type ReactNode } from "react";
import { afterAll, expect, it, vi } from "vitest";

const dimensions = vi.hoisted(() => ({
  width: 440,
  height: 956,
  scale: 3,
  fontScale: 3,

vi.mock("react-native", () => ({
  Pressable: "NativePressable",
  View: "NativeView",

}));
vi.mock("@/theme/ThemeProvider", () => ({
  useTheme: () => ({ tokens: { foreground: "black", primary: "blue" } }),
}));
vi.mock("./Text", () => ({ Text: "TitleTextBoundary" }));
vi.mock("./Icon", () => ({
  Icon: "IconBoundary",
  isIconName: () => false,
}));
vi.mock("./ListRow", () => ({
  DisclosureChevron: "ChevronBoundary",
  SelectedCheck: "CheckBoundary",
  LIST_ROW_ICON_SIZE: 20,
}));
vi.mock("./Separator", () => ({ Separator: "SeparatorBoundary" }));

vi.stubEnv("EXPO_OS", "ios");
const { GroupedRow } = await import("./Grouped");
afterAll(() => vi.unstubAllEnvs());

function findTitle(
  node: ReactNode,
  title: string,
): { numberOfLines?: number } | undefined {
  for (const child of Children.toArray(node)) {
    if (
      !isValidElement<{ children?: ReactNode; numberOfLines?: number }>(child)
    ) {
      continue;
    }
    if (child.type === "TitleTextBoundary" && child.props.children === title) {
      return child.props;
    }
    const nested = findTitle(child.props.children, title);
    if (nested !== undefined) return nested;
  }
  return undefined;
}

it.each([
  { title: "Appearance", width: 440 },
  { title: "Notifications", width: 440 },
  { title: "Appearance", width: 390 },
  { title: "Notifications", width: 390 },
])("allows scaled title wrapping: $title at $width", ({ title, width }) => {
  dimensions.width = width;
  const rendered = GroupedRow({ title, trailing: "chevron", onPress: vi.fn() });
  const titleProps = findTitle(rendered, title);
  expect(titleProps).toBeDefined();
  const numberOfLines = titleProps?.numberOfLines;
  console.log(
    JSON.stringify({
      title,
      width,
      fontScale: dimensions.fontScale,
      numberOfLines,
    }),
  );
  expect([undefined, 0]).toContain(numberOfLines);
});

5. Root cause

DeviceSettingsScreen creates the Appearance and Notifications LinkRows without titleLines overrides. LinkRow forwards these props into GroupedRow.

GroupedRow defaults titleLines to 1, and the title Text receives numberOfLines unchanged. The shared Text component forwards remaining props to RNText. The row uses a minimum height rather than a fixed height; removing a title line cap is the relevant starting point, not hardcoding a taller row. Larger glyphs competing with the leading icon and trailing chevron then have no multiline escape path. Exact native truncation and the accessibility threshold still need simulator verification.

titleLines = 1
...
<Text numberOfLines={titleLines}>{title}</Text>

6. Proposed fix

Make the existing grouped-row title policy permit wrapping for enlarged iOS text without reducing font scaling or fixing the row height. Preserve intentional caller limits unless the accessibility policy explicitly supersedes them. Validate ordinary text, enlarged accessibility text, explicit titleLines, Android behavior, and dynamic scale changes on native devices. No production change or patched test run was made in this investigation.
