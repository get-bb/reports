#5092 · Literal environment paths are saved without explaining expansion semantics

BugPriority: MediumEffort: Lowhostcliconfirmed-repro Issue on GitHubOctober 7, 2026 · base 68a1e8b7aa84fbd836eb8825e4d042ae0c52e74a

Verdict: REPRODUCED · Root-cause confidence: high, for literal propagation and missing CLI guidance.

1. TL;DR

Machine environment values are stored and delivered as literal strings, not as shell expressions. Three home-relative spellings survive a real CLI save, HTTP API validation, encrypted SQLite storage, daemon environment assembly, and execution in a child shell unchanged. The CLI emits no notice, and listing metadata deliberately hides saved values. A generic child that uses such a value as a directory path creates a relative directory inside its working tree; an absolute-path control creates its directory outside the working tree. This confirms the configuration/feedback defect without running Claude Code or accessing any real credentials.

Literal string preservation is appropriate for opaque secrets; the defect is the undisclosed path interpretation, not proof that all environment values should undergo interpolation.

import { fileURLToPath } from "node:url";
import { getAppSettings, setAppSettings } from "@bb/db";
import { expect, it } from "vitest";

import { resolveUserMachineEnvironment } from "../../src/services/machines/environment-settings.js";

function childOutput(
  file: string,
  args: string[],
  options: { cwd: string; env: NodeJS.ProcessEnv; input?: string },
): Promise<{ stdout: string; stderr: string }> {
  return new Promise((resolveOutput, reject) => {
    const child = spawn(file, args, options);
    let stdout = "";
    let stderr = "";
    child.stdout.on("data", (chunk: Buffer) => {
      stdout += chunk.toString();
    });
    child.stderr.on("data", (chunk: Buffer) => {
      stderr += chunk.toString();
    });
    child.on("error", reject);
    child.on("close", (code) => {
      if (code !== 0) reject(new Error(`Child exited ${code}: ${stderr}`));
      else resolveOutput({ stdout, stderr });
    });
    child.stdin.end(options.input);
  });
}

5. Root cause

Input processing does not invoke a shell. apps/cli/src/commands/machine-environment.ts:21 limits stdin and removes one trailing newline, but otherwise preserves its content. apps/cli/src/commands/machine-environment.ts:78 sends the value through the SDK and prints masked metadata; it does not issue a semantic notice.

  return Buffer.concat(chunks)
    .toString("utf8")
    .replace(/\r?\n$/u, "");

The boundary schema packages/server-contract/src/api/machine-environment.ts:7 checks type, length, and NUL bytes, not shell/path semantics. The server's apps/server/src/services/machines/environment-storage.ts:182 encrypts the exact supplied value, and apps/server/src/services/machines/environment-settings.ts:10 decrypts it into a contributed environment entry without interpolation.

The final decisive assignment is apps/host-daemon/src/operation-environment.ts:4:

  for (const entry of entries) {
    if (typeof entry.value === "string") env[entry.name] = entry.value;
    else {
      if (!base.BB_SERVER_URL)
        throw new Error("Host environment requires BB_SERVER_URL");
      env[entry.name] = `${base.BB_SERVER_URL}${entry.value.serverPath}`;
    }

Both apps/host-daemon/src/terminals/terminal-manager.ts:608 and apps/host-daemon/src/plugin-host-manager.ts:294 use this helper. A child shell expanding the variable once does not recursively evaluate dollar signs or tildes inside its value. A path consumer therefore receives an ordinary relative string; directory resolution uses its current working directory, not HOME.

The editor's apps/app/src/components/settings/MachineEnvironmentSettings.tsx:270 describes global/project scope but not literal interpretation. Its apps/app/src/components/settings/MachineEnvironmentSettings.tsx:628 defaults to a concealed input, receives no saved plaintext, and disables saved-value reveal. The API's apps/server/src/services/machines/environment-settings.ts:34 deliberately replaces saved values with null. This is sensible secret protection but makes missing save-time guidance consequential.

Underlying cause: a general-purpose secret-preserving string setting lacks discoverable interpretation guidance for users entering path syntax. The daemon's literal assignment alone is not evidence of an unsafe expansion bug that should be fixed by indiscriminately interpreting all secret strings.

6. Proposed fix and autopilot decision

Preserve all bytes of submitted secrets. Add clear literal-value guidance at the editing boundary, CLI save feedback/help, and discoverable configuration documentation; recommend an absolute path for directory-valued settings. A non-blocking notice should not echo the submitted value or reveal saved plaintext. Keep SDK behavior documented and consistent without changing stored values.

No pull request is opened. A complete warning-only repair spans the app and CLI, so it fails this autopilot's requirement that a fix stay in one existing subsystem. Interpolation is not a safe one-subsystem substitute: it changes the interpretation of general-purpose secret values and requires a product-policy decision. The investigator-authored focused test demonstrates the missing-notice failure before any production edits; no speculative production fix, branch, commit, or push was made to get-bb/bb.

No open linked pull request was present in the issue timeline, and an open-PR search for the numeric issue reference also found none. This does not justify relaxing the simple-fix gate.
