Width measurements trigger unnecessary message-action commits

Type: Bug · Priority: Medium · Effort: Low · Areas: ui, perf
Trusted main: 55135d1e5045d6c5d3c24f5a4d5556ed3e11cb00

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high · Reproduction label: partial-repro

1. Summary

The message-action component schedules React updates whenever its measured integer width changes, even when exactly the same actions remain visible. An added regression test on unchanged production code measured 32 commits for one mounted action bar, and 384 summed per-bar commits for 12 bars, across 32 width changes. Repeating an identical width 32 times produced no commits. The same agent repeated the result in a second clean checkout of the same trusted main commit.

This establishes the unnecessary React work, not the subjective stutter, actual animation frame rate, or the number of mounted rows in a real conversation. No running desktop app, macOS frame recording, browser screenshot, or end-to-end panel toggle was captured. The verdict is therefore deliberately partial.

5. Root cause

useMeasuredWidth stores raw integer width in React state. Its observer callback does this on every delivery:

const inlineSize =
  entry.contentBoxSize?.[0]?.inlineSize ?? entry.contentRect.width;
setWidth(Math.floor(inlineSize));

MessageActionBar calls the hook for each mounted bar. The width enters the discrete action-fit computation, and is also applied as inline maxWidth. React therefore observes every different pixel value, rather than only a change in the visible action set. Equal widths bail out, explaining the negative control.

SecondaryPanelLayout transitions the main panel's layout dimensions, with a 220ms transition token. This is a source-supported route by which width observations can arrive repeatedly; the test deliberately delivers individual measurements, not simulated browser animation frames.

TimelineRowsList also measures its width and uses it to construct a context-provider value. A project-wide search for MessageColumnWidthContext found only its declaration, import, and provider open/close tags; there is no consumer. This adds a needless state subscription at the list owner, but this report does not claim to have counted commits for every timeline descendant.

6. Proposed repair and limits

Keep only the discrete fitted-action result in React state. Maintain any necessary continuously varying width limit without a React state update, preserving responsive overflow behavior. Remove the unused top-level width subscription and context. Existing threshold-crossing tests must continue to verify actions moving into the menu, including touch behavior. Then measure a genuine panel toggle with a long conversation in a browser/desktop performance trace; layout and painting can still be expensive after React work is reduced.

The new test protects an externally measurable rendering-work invariant, exercises the real component, needs no new production export, and includes an equal-width control plus visible-action assertions. Existing tests cover responsive action placement but did not assert commit counts.
