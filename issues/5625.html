#5625 · Local path links bypass preview routing

BugPriority: MediumEffort: Mediumuipartial-repro GitHub issue · October 16, 2026

Trusted base: 01affc197dc621cddc7343e09b1c5c10a5b9efcb, fetched from get-bb/bb origin/main.

PARTIALLY REPRODUCED · Root-cause confidence: high

1. TL;DR

The real Markdown renderer leaves bare absolute paths with extensionless basenames as ordinary browser links rather than local preview links. A DOM click on an extensionless path never invokes the local-file callback, while an explicit file URL for the identical path does. The parser requires a dotted basename for bare trusted-host absolute paths and rejects trailing directory separators in all modes. There is also no directory outcome in the thread link resolver: an accepted explicit directory-shaped URL is dispatched to the file-preview route. These findings repeat in two clean trusted source checkouts; the final macOS Electron/system-browser navigation and not-found page are not reproduced here.

// @vitest-environment jsdom

import { cleanup, fireEvent, render, screen } from "@testing-library/react";
import { afterEach, beforeAll, expect, it } from "vitest";
import { LazyMarkdownHtml } from "./lazy-markdown-html";
import { MarkdownPreview } from "./markdown-preview";
import { buildMarkdownMessageLinkRouting } from "./markdown-message-link-routing";
import { parseLocalFileHref } from "./markdown-local-file-link";
import { resolveThreadLocalFileLink } from "@/lib/thread-local-file-links";

beforeAll(() => LazyMarkdownHtml.preload());
afterEach(cleanup);

const fixtures = [
  { label: "dotted", href: "/tmp/local-route-proof/manual.md" },
  { label: "extensionless", href: "/tmp/local-route-proof/Buildfile" },
  { label: "directory", href: "/tmp/local-route-proof/assets" },
  { label: "directory-slash", href: "/tmp/local-route-proof/assets/" },
  { label: "explicit-file", href: "file:///tmp/local-route-proof/Buildfile" },
  { label: "explicit-directory", href: "file:///tmp/local-route-proof/assets" },
  {
    label: "explicit-directory-slash",
    href: "file:///tmp/local-route-proof/assets/",
  },
  { label: "home-relative", href: "~/local-route-proof.md" },
];

it("records actual rendered hrefs and path resolutions", () => {
  const linkRouting = buildMarkdownMessageLinkRouting({
    onOpenLocalFileLink: () => true,
    workspaceRootPath: "/workspace",
  });
  render(
    <MarkdownPreview
      content={fixtures
        .map(({ label, href }) => `[${label}](${href})`)
        .join("\n\n")}
      linkRouting={linkRouting}
    />,
  );
  const observations = fixtures.map(({ label, href }) => {
    const parsed = parseLocalFileHref({
      absoluteLinks: { kind: "trusted-host" },
      href,
    });
    const renderedHref =
      screen.queryByRole("link", { name: label })?.getAttribute("href") ?? null;
    const resolution =
      parsed === null
        ? null
        : resolveThreadLocalFileLink({
            fileOpenTargetIds: [],
            hostFileLinksAvailable: true,
            link: parsed,
            threadStorageRootPath: "/thread-storage",
            workspaceRootPath: "/workspace",
          }).kind;
    return { label, parsed: parsed !== null, renderedHref, resolution };
  });
  console.log(JSON.stringify(observations, null, 2));
  expect(observations.find(({ label }) => label === "dotted")?.resolution).toBe(
    "open-host-path",
  );
  expect(
    observations.find(({ label }) => label === "extensionless")?.renderedHref,
  ).toBe("/tmp/local-route-proof/Buildfile");
  expect(
    observations.find(({ label }) => label === "directory-slash")?.parsed,
  ).toBe(false);
  expect(
    observations.find(({ label }) => label === "explicit-directory")
      ?.resolution,
  ).toBe("open-host-path");
});

it("opens an extensionless absolute file through the same host preview route as explicit file URLs", () => {
  const resolutions: ReturnType<typeof resolveThreadLocalFileLink>[] = [];
  const linkRouting = buildMarkdownMessageLinkRouting({
    onOpenLocalFileLink: (link) => {
      resolutions.push(
        resolveThreadLocalFileLink({
          fileOpenTargetIds: [],
          hostFileLinksAvailable: true,
          link,
          threadStorageRootPath: "/thread-storage",
          workspaceRootPath: "/workspace",
        }),
      );
      return true;
    },
    workspaceRootPath: "/workspace",
  });
  render(
    <MarkdownPreview
      content="[control](file:///tmp/local-route-proof/Buildfile)\n\n[subject](/tmp/local-route-proof/Buildfile)"
      linkRouting={linkRouting}
    />,
  );
  const expectedResolution = {
    kind: "open-host-path",
    request: { lineRange: null, path: "/tmp/local-route-proof/Buildfile" },
  };
  expect(fireEvent.click(screen.getByRole("link", { name: "control" }))).toBe(
    false,
  );
  expect(resolutions).toEqual([expectedResolution]);
  resolutions.length = 0;
  fireEvent.click(screen.getByRole("link", { name: "subject" }));
  expect(resolutions).toEqual([expectedResolution]);
});

5. Root cause

Message routing enables trusted-host absolute local links. That policy selects requireLikelyFileBasename for non-URL absolute hrefs in parseLocalFileHref.

  }
  const parts = parseAbsoluteLocalFileHref(
    urlParts?.path ?? href,

  );
  const link =
    parts === null

The filename heuristic and trailing-separator validation reject extensionless basenames and slash-terminated paths:

function hasLikelyFileBasename(path: string): boolean {
  const segments = isWindowsDriveLocalFilePath(path)
    ? path.split(/[\\/]/u)
    : path.split("/");
  const basename = segments[segments.length - 1] ?? "";
  return basename.startsWith(".") || basename.includes(".");
}

function isValidAbsoluteLocalFilePath({
  path,
  requireLikelyFileBasename,
}: LocalFilePathValidationArgs): boolean {
  return (
    isAbsoluteLocalFilePathStart(path) &&
    path !== "/" &&
    !path.endsWith("/") &&
    !(isWindowsDriveLocalFilePath(path) && path.endsWith("\\")) &&
    !path.includes("\n") &&
    !path.includes("\r") &&
    !path.includes("?") &&
    !path.includes("#") &&
    !hasControlCharacter(path) &&
    (!requireLikelyFileBasename || hasLikelyFileBasename(path))
  );

When classification fails, the URL transform falls back to defaultUrlTransform; the rendered DOM confirms that bare paths survive unchanged, whereas the rejected file URL becomes plain text. MarkdownAnchor only consumes recognized local links prevents the default navigation only when an applicable callback handles the link. Otherwise the raw anchor has target="_blank".

Home-relative paths are excluded from relative resolution, with no replacement home expansion in this path.

A second defect prevents a parser-only directory fix: the resolution union has no directory result, and the resolver routes accepted paths only to file-oriented destinations. The main thread handler opens workspace, storage, or host file previews consumes these outcomes. Accepting more strings would not implement directory opening.

For the desktop symptom, the ordinary browser preference handler only accepts HTTP(S) strings, while the Electron new-window handler forwards resolvable external URLs. This supports, but does not replace, a live desktop verification of the final navigation.

6. Proposed fix and simple-fix gate

Separate local-path recognition from file-versus-directory resolution. Preserve existing app-route handling, contained-root restrictions, and unsupported URL-host rejection. Use trusted host metadata when a path's type is ambiguous; route a directory through the existing appropriate folder/storage browsing action rather than a file reader. Define how unresolved and home-relative paths should behave before enabling a broader set of local targets. Add renderer click and directory-resolution regressions, plus desktop end-to-end verification.

No automatic fix PR: a complete fix needs a directory-aware routing contract and a policy decision about ambiguous absolute paths; the current contract is file-only. A one-line relaxation would leave directories broken and change an explicitly tested classification policy. This fails the “no product or architecture decision” simple-fix condition.
