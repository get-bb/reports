#5834 · File opener registration rejects separator-containing extensions

Bug Priority: Medium Effort: Low plugins · GitHub issue · 2026-10-20

Trusted main: b0bb68655adcc6cd79e495d3484f4011a0640e2e

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A plugin cannot register a file viewer for extensions containing an underscore or hyphen. Its setup fails before a file can be opened, even though the downstream file resolver can preserve and match these extension characters. The collector applies an alphanumeric-only check to each extension. A registration-to-resolution regression test fails at that exact check in two separate clean checkouts of the same trusted main commit.

5. Root cause

The SDK collector validates extensions before adding the file opener:

if (typeof extension !== "string" || !/^[a-z0-9]+$/.test(extension)) {
  throw new Error(...);
}

That character class excludes both separators. In contrast, extension extraction returns the suffix unchanged apart from lowercase normalization. File-opener selection checks whether that suffix is in the registered extension list.

The exception propagates out of the complete plugin setup. The frontend failure handler then deactivates the committed generation and stores failed status. This explains why an overly strict file-extension check can remove more than the individual opener. No daemon or filesystem behavior is involved in the observed failure.

The alphanumeric-only check dates to commit 564090dfb1 according to blame; it is still present in the recorded main commit.

6. Proposed fix

Permit lowercase alphanumeric segments joined by an underscore or hyphen at the existing registration boundary. Keep dots, uppercase letters, whitespace, path separators, and empty segments invalid. Document the same grammar in the SDK declaration and Plugin Guide. Cover both registration and subsequent case-normalized file matching with the focused table, while retaining malformed-input tests. No change to the resolver, wire types, stored data, or dependencies is needed.
