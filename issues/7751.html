#7751 · ACP compaction updates are not normalized

Bug · Priority: Low · Effort: Medium · providers · provider-acp

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. Summary

The ACP bridge does not advertise support for session compaction notifications. If compaction notifications nevertheless reach the translator, they become unhandled provider events instead of timeline compaction items. A two-test regression fixture demonstrates both missing behaviors on trusted main in two clean checkouts. The existing translation suite passes, which explains why its current manual-compaction coverage has not caught the automatic path. This is a provider-event normalization reproduction, not a live desktop or browser rendering reproduction.

Full reproduction source
import { describe, expect, it } from "vitest";
import { createDeltaAssembler } from "@bb/provider-bridge-protocol/assembler";
import {
  ACP_TURN_STARTED_METHOD,
  ACP_UPDATE_METHOD,
} from "./bridge-protocol.js";
import {
  requestAcpInitialize,
  type AcpAgentConnection,
} from "./bridge/agent-connection.js";
import { createAcpDeltaTranslator } from "./delta-translation.js";

describe("automatic ACP compaction contracts", () => {
  it("advertises compaction support during initialization", async () => {
    const requests: { method: string; params: unknown }[] = [];
    const connection: AcpAgentConnection = {
      async request(request) {
        requests.push({ method: request.method, params: request.params });
        return request.resultSchema.parse({
          protocolVersion: 1,
          agentCapabilities: {},
        });
      },
      notify() {},
      async kill() {},
      exited: false,
    };

    await requestAcpInitialize(connection, {
      parameterizedModelPicker: false,
      fsAccess: false,
    });

    expect(requests).toContainEqual({
      method: "initialize",
      params: expect.objectContaining({
        clientCapabilities: expect.objectContaining({
          session: expect.objectContaining({ compaction: {} }),
        }),
      }),
    });
  });

  it("keeps agent compaction in the current turn and records completion", () => {
    const threadId = "compaction-contract-thread";
    const translator = createAcpDeltaTranslator({ cwd: "/workspace" });
    const assembler = createDeltaAssembler({
      providerId: "acp",
      entropyPrefix: "compaction-contract",
      textDeltaFlushMs: 0,
    });
    assembler.assemble({
      threadId,
      deltas: translator.translateAcpEvent(
        {
          jsonrpc: "2.0",
          method: ACP_TURN_STARTED_METHOD,
          params: { threadId },
        },
        { threadId },
      ),
    });
    const turnId = assembler.getOpenTurnId(threadId);
    expect(turnId).toBeTruthy();

    for (const status of ["in_progress", "completed"]) {
      const deltas = translator.translateAcpEvent(
        {
          jsonrpc: "2.0",
          method: ACP_UPDATE_METHOD,
          params: {
            threadId,
            update: {
              sessionUpdate: "compaction_update",
              compactionId: "automatic-cycle",
              status,
            },
          },
        },
        { threadId },
      );
      const events = assembler.assemble({ threadId, deltas });
      console.log(JSON.stringify({ status, events }));
      const itemEventType =
        status === "in_progress" ? "item/started" : "item/completed";
      expect.soft(events).toContainEqual(
        expect.objectContaining({
          type: itemEventType,
          item: expect.objectContaining({ type: "contextCompaction" }),
        }),
      );
      expect.soft(assembler.getOpenTurnId(threadId)).toBe(turnId);
      if (status === "completed") {
        expect.soft(events).toContainEqual(
          expect.objectContaining({ type: "thread/compacted" }),
        );
      }
      expect.soft(events.some((event) => event.type === "provider/unhandled"))
        .toBe(false);
    }
  });
});

5. Root cause

  1. Initialization capability builder advertises filesystem, terminal, auth and selected optional capabilities, but never session compaction. The request test captures that omission at the transport boundary.
  2. Generic update parsing accepts an unfamiliar update via a pass-through object with a string sessionUpdate. The automatic event is not rejected for malformed shape.
  3. Translator fallback has no automatic compaction branch, so the parsed update reaches unhandledDeltas(rawEvent). The visibility inventory also omits compaction updates. Neither required timeline lifecycle events nor compaction completion are produced.
  4. Manual compaction is different: startCompaction sends a /compact prompt and synthetic lifecycle methods. Their translator handlers deliberately open/end a compaction turn. Reusing that handler for automatic compaction would risk interrupting the running turn.
function acpClientCapabilities(parameterizedModelPicker, fsAccess, elicitation) {
  return {
    fs: { readTextFile: fsAccess, writeTextFile: fsAccess },
    terminal: false,
    auth: { terminal: true },
    ...(elicitation ? { elicitation: { form: {} } } : {}),
    ...(parameterizedModelPicker === true
      ? { _meta: { parameterizedModelPicker: true } }
      : {}),
  };
}

default:
  return unhandledDeltas(rawEvent);

The excerpt above omits TypeScript parameter annotations only. The pinned SDK's schema/schema.json describes ClientSessionCapabilities.compaction as a complete-contract opt-in, with omission meaning unsupported. Its CompactionUpdate is an ID-addressed upsert with nullable patch fields; its summary-chunk notification can introduce an in-progress compaction. No issue-supplied URL was fetched.

ClientSessionCapabilities.compaction:
"Support for ID-addressed context compaction updates. Omitted or `null`
means unsupported; `{}` advertises the complete compaction contract."

CompactionUpdate required fields: compactionId, status
CompactionSummaryChunk required fields: compactionId, content

6. Fix proposal and automation safety

Implement the complete negotiated ACP compaction contract before advertising it: validate updates at ingress; track session-scoped compaction IDs; handle upserts, summary chunks and terminal failures/cancellation; emit the existing compaction item/compacted deltas inside the active turn without flushing unrelated work; and add visibility coverage. Only then advertise the capability.

No automated fix or pull request. A complete repair changes the externally advertised ACP initialization capability contract and its accepted notification schema/semantics. Public-protocol/schema changes are excluded from this rule's simple-fix scope. Enabling the capability alone would advertise behavior the translator does not implement. No production change, fix branch, commit or push was made in get-bb/bb.

No open pull request was linked through issue timeline metadata, and an open-PR search for the issue number returned none at investigation time. Other compaction-related open PRs were not checked out or run.
