#5671 · Completed replies rejected by terminal-turn projection

Bug Priority: Medium Effort: Low threads confirmed-repro

GitHub issue · 2026-10-17 · trusted base 6a639cfc0d66e0c789a1bd7309266973228d1a80

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

The shared timeline projector discards a completed assistant reply if its first accepted text arrives after the turn is stopped. The Stop event marks the turn closed, and the text projector then rejects both streaming deltas and authoritative completed messages. A fresh regression test on current trusted main returns no assistant message where one completed reply is expected. The same agent repeated that failure in a second clean checkout. This establishes a deterministic projection defect; the original live provider timing and saved provider history were not accessed or reproduced.

import { describe, expect, it } from "vitest";
import type { ThreadEventRow } from "@bb/domain";
import type { TimelineRow } from "@bb/server-contract";
import {
  createTimelineEventFactory,
  flattenTimelineRows,
  renderTimelineFixture,
} from "./timeline-test-harness.js";

type TimelineWorkRow = Extract<TimelineRow, { kind: "work" }>;
type TimelineSystemRow = Extract<TimelineRow, { kind: "system" }>;

function getOnlyWorkRowByCallId(
  rows: readonly TimelineRow[],
  callId: string,
): TimelineWorkRow {
  const matches = flattenTimelineRows(rows).filter(
    (row): row is TimelineWorkRow =>
      row.kind === "work" && "callId" in row && row.callId === callId,
  );
  expect(matches).toHaveLength(1);
  const row = matches[0];
  if (!row) {
    throw new Error(`Expected work row for ${callId}`);
  }
  return row;
}

function getTopLevelSystemRows(
  rows: readonly TimelineRow[],
): TimelineSystemRow[] {
  return rows.filter((row): row is TimelineSystemRow => row.kind === "system");
}

function renderIdleTimeline(events: ThreadEventRow[]) {
  return renderTimelineFixture({
    events,
    projectionOptions: {
      threadStatus: "idle",
      turnMessageDetail: "full",
    },
  });
}

describe("timeline interruption projection", () => {
  it("renders a completed reply after Stop without accepting late deltas", () => {
    const event = createTimelineEventFactory({ threadId: "thread-1" });
    const stoppedEvents = [
      event.turnStarted({ createdAt: 0 }),
      event.systemThreadInterrupted({ createdAt: 1_000 }),
      event.assistantDelta({
        itemId: "reply-after-stop",
        delta: "Discard this unfinished text.",
        createdAt: 2_000,
      }),
    ];

    expect(
      renderIdleTimeline(stoppedEvents).messages.filter(
        (message) => message.kind === "assistant-text",
      ),
    ).toEqual([]);

    const timeline = renderIdleTimeline([
      ...stoppedEvents,
      event.assistantCompleted({
        itemId: "reply-after-stop",
        text: "Persisted reply.",
        createdAt: 3_000,
      }),
      event.assistantDelta({
        itemId: "another-late-reply",
        delta: "This must not reopen the stopped turn.",
        createdAt: 4_000,
      }),
      event.assistantCompleted({
        itemId: "reply-after-stop",
        text: "Duplicate completion must not replace the reply.",
        createdAt: 5_000,

        text: "Persisted reply.",

5. Root cause

The terminal-event handling in build-event-projection.ts:670–693 calls onThreadInterrupted for the thread interruption event. That handler calls closeOpenTurns, adding active turn IDs to closedTurnIds and clearing openTurnIds (event-projection-state.ts:126–173).

The shared assistant text resolver then rejects any item from a closed turn before creating a message. Its argument type even omits mode, so it cannot distinguish a transient delta from an authoritative final update (buffered-text-projection.ts:46–83):

const messageKey = createBufferedTextInstanceKey(args.identity);
if (args.state.closedTurnIds.has(args.identity.turnId)) {
  return null;
}
if (args.refs.finalizedKeys.has(messageKey)) {
  return null;
}

Both assistant delta and completed-item paths use that resolver, passing different modes (assistant-event-projection.ts:87–137). Thus the final text never reaches projection storage or the timeline renderer. The guard is shared rather than Codex-specific; this test does not establish how frequently any provider produces this event order.

6. Proposed fix and focused validation

Pass the existing update mode to the resolver. For a closed turn, reject deltas but allow a not-yet-finalized completed item. Keep the turn closed; do not add it back to the open-turn set. Keep the item-level finalized-key check so duplicate completions remain ignored. No provider protocol, API, schema, persisted data, dependency, or packaging change is required.

A local implementation passes the regression and all 486 tests in the 31-file thread-view suite; the package typecheck also passes. The initial full trusted-base build passed. Formatting and git diff --check pass. The package has no lint script, so its Turbo lint invocation executes no tasks and is not claimed as a lint pass.
