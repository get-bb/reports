#5705 · Read-only runtime trees reject completed host artifacts

BugPriority: MediumEffort: Lowdesktop · hostIssueOctober 17, 2026

Verdict: REPRODUCED · Root-cause confidence: high.

Trusted base: ee36dfda7815e8c72672ab57e2bdb1b395ada9be from the public repository's main branch.

1. TL;DR

The enrolled-host artifact service rejects an otherwise successful build when its installed runtime has read-only directories. Its recursive copy preserves the chunk directory modes, so the temporary copy contains directories that its non-root owner cannot clean up. Real npm packing succeeds and the final tarball is present, but the awaited cleanup throws EACCES and overrides the return value. A retry rebuilds the package and leaves another temporary directory. This was reproduced at the real service boundary in two clean checkouts; the HTTP 500 consequence follows from the verified route mapping, not from a live enrollment test.

5. Root cause

materializePackagedHostPackage makes fresh writable parent directories but uses a recursive fs.cp for the chunk subtree without normalizing the copied directory write bits:

await cp(
  join(hostDaemonSource, "bb-chunks"),
  join(hostDaemonTarget, "bb-chunks"),
  { recursive: true },
);

For a 0555 source, the copied directories are also 0555. Deleting children requires write permission on their parent directories; owning the copied files is not enough. Depending on which recursive deletion reports first, Node exposes EACCES during unlink or rmdir. This variation does not change the cause.

buildArtifact packs and renames the completed artifact, then awaits removal of the temporary package in a finally block:

return { digest, path: artifactPath, size: artifactStats.size };
} finally {
  if (temporaryHostPackageRoot !== undefined) {
    await rm(temporaryHostPackageRoot, { force: true, recursive: true });
  }
}

That rejection overrides the pending return. The service catch clears artifactPromise, so the next call starts another build instead of using the existing tarball. The download route converts the propagated permission error into HTTP 500 with code host_package_unavailable. force does not bypass operating-system permission checks.

6. Proposed fix and automation safety

Ensure that the service-owned temporary copy has owner-writable directories before its cleanup runs, without modifying the installed source or broadening permissions outside that temporary tree. Walk nested directories, not just the top-level chunk directory. Decide deliberately whether to normalize before packing or only before removal, because that affects packaged modes. Cleanup policy should not silently hide failed builds or create unbounded leftovers.

No automatic fix or PR: this rule excludes fixes that change permission handling or packaging. This defect concerns both copied permission modes and host-package preparation, so the simple-fix safety gate fails even though the likely edit is small. No production change, branch, commit, or push was made in get-bb/bb. The regression above is suitable evidence for a maintainer-authorized fix; a post-fix pass is not claimed.
