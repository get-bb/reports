1. TL;DR

The app maintains a shared sidebar query plus thread-list queries, including related-thread lists. Eleven kinds of realtime thread changes bypass the existing one-second active-refetch throttle. A deterministic test delivers four events spaced 200 ms apart: the sidebar query executes four times instead of once within that burst. Both clean checkouts produce the same failure; the test also observes real TanStack Query list observers rather than mocking the cache. This reproduces the request-amplification mechanism, not the reporter's production request rates, server timings, or CPU share.

it.each([

  "thread-deleted",
  "history-rewritten",
  "title-changed",
  "queue-changed",
  "archived-changed",
  "pin-state-changed",
  "parent-changed",
  "environment-changed",
  "read-state-changed",
  "events-appended",

  vi.useFakeTimers();
  const queryClient = new QueryClient({
    defaultOptions: { queries: { gcTime: Infinity, retry: false } },
  });
  const effects = createRealtimeCacheEffects({ queryClient });
  let revision = 0;
  const keys = [
    sidebarNavigationQueryKey(),
    threadListQueryKey({ archived: false }),
    threadListQueryKey({ archived: false, projectId: "project-1" }),
    threadListQueryKey({
      archived: false,
      projectId: "project-1",
      sourceThreadId: "thr_parent",
      originKind: "fork",

        queryKey,
        queryFn: reads[index],

  const inactiveKey = threadListQueryKey({

    projectId: "project-1",

    }
    for (const observer of observers) {

      id: "thr_child",

5. Root cause

Thread changes are dispatched through a registry. The short scheduler debounce coalesces changes within a small window, but not a stream spaced 200 ms apart. Structural changes call dirtyThreadListQueries; title, queue, read state, environment and background activity call dirtyActiveThreadListQueries. Both directly refetch active queries. Only the metadata-less status fallback uses dirtyActiveThreadListQueriesWithThrottledRefetch.

  queryClient,
}: ThreadRealtimeDirtyContext): QueryKey[] {
  if (projectId) {

      queryClient,

      invalidateQueryKeyWithoutCancelingActiveFetch({

        queryKey,

}

function dirtyActiveThreadListQueries({
  projectId,
  queryClient,
}: ThreadRealtimeDirtyContext): QueryKey[] {
  const listQueryKeys = projectId
    ? [
        ...getCachedProjectThreadListInvalidationQueryKeys({
          projectId,
          queryClient,
        }),
        ...getCachedGlobalThreadListInvalidationQueryKeys({ queryClient }),
      ]
    : getCachedThreadListQueryKeys(queryClient);
  for (const queryKey of listQueryKeys) {
    if (isArchivedThreadListQueryKey(queryKey)) {
      queryClient.invalidateQueries({
        exact: true,
        queryKey,
        refetchType: "none",
      });
      continue;
    }
    invalidateQueryKeyWithoutCancelingActiveFetch({
      exact: true,
      queryClient,
      queryKey,
    });
  }
  return [sidebarNavigationQueryKey(), threadSearchQueryKeyPrefix()];
}

function dirtyActiveThreadListQueriesWithThrottledRefetch({
  projectId,
  queryClient,
}: ThreadRealtimeDirtyContext): void {
  const listQueryKeys = projectId
    ? [
        ...getCachedProjectThreadListInvalidationQueryKeys({
          projectId,
          queryClient,
        }),
        ...getCachedGlobalThreadListInvalidationQueryKeys({ queryClient }),
      ]
    : getCachedThreadListQueryKeys(queryClient);
  for (const queryKey of listQueryKeys) {
    if (isArchivedThreadListQueryKey(queryKey)) {
      queryClient.invalidateQueries({
        exact: true,
        queryKey,
        refetchType: "none",
      });
      continue;
    }
    invalidateQueryKeyWithThrottledActiveRefetch({
      exact: true,
      minIntervalMs: THREAD_LIST_STATUS_FALLBACK_REFETCH_MIN_INTERVAL_MS,
      queryClient,
      queryKey,
    });
  }
  for (const queryKey of [
    sidebarNavigationQueryKey(),
    threadSearchQueryKeyPrefix(),
  ]) {
    invalidateQueryKeyWithThrottledActiveRefetch({
      exact: false,
      minIntervalMs: THREAD_LIST_STATUS_FALLBACK_REFETCH_MIN_INTERVAL_MS,
      queryClient,
      queryKey,
    });
  }
}

The shared key group includes sidebarNavigationQueryKey; its query function calls the bootstrap endpoint. Related-thread lists use the same cached thread-list key family, so the active-list loop also invalidates them. Refetches now avoid cancelling an active fetch (a prior livelock fix), but that protection does not rate-limit quick completed reads.

6. Proposed fix

Route both structural and active-only thread-list invalidations through the existing per-QueryClient, per-key one-second leading/trailing refetch scheduler. Preserve archived-list invalidation rules, immediate stale marking, non-cancelling in-flight behavior and disposal cleanup. Share the same buckets with the status fallback so mixed event types cannot bypass the bound. Do not alter HTTP protocols, server policy, compression or dependencies.
