1. TL;DR

An unset organization preference previously inherited the global Custom default after an upgrade, so the sidebar selected the thread-only rendering path. This explains missing project headings without requiring deleted projects. Trusted main now contains an installation fallback migration and reads that fallback at revision zero. The report validates this mechanism with isolated database, API, and client tests; it does not claim a desktop visual reproduction or verify the reporter’s personal data.

import { describe, expect, it } from "vitest";
import { PERSONAL_PROJECT_ID } from "@bb/domain";
import {
  createConnection,
  migrate,
  createProject,
  createThread,
  upsertHost,
  noopNotifier,
} from "../src/index.js";

const SIDEBAR_INSTALLATION_DEFAULTS_MIGRATION_TIMESTAMP = 1790009314673;

it("leaves a fresh migrated database without an installation override", () => {
  const db = createConnection(":memory:");
  try {
    migrate(db);
    expect(
      db.$client.prepare("SELECT * FROM ui_preference_defaults").all(),
    ).toEqual([]);
    expect(db.$client.prepare("SELECT * FROM ui_preferences").all()).toEqual(
      [],
    );
    db.$client.exec(
      `INSERT INTO ui_preferences VALUES ('sidebar.chronologicalSort', '"alpha"', 1, 1)`,
    );
    migrate(db);
    expect(
      db.$client.prepare("SELECT * FROM ui_preference_defaults").all(),
    ).toEqual([]);
  } finally {
    db.$client.close();
  }
});

describe.each(["project", "thread", "preference"] as const)(
  "existing installation with %s",
  (kind) => {
    it.each([null, "chronological", "machine", "project"])(
      "keeps saved choice %s separate from the fallback",
      (choice) => {
        const db = createConnection(":memory:");
        try {
          migrate(db);
          if (kind === "preference") {
            db.$client.exec(
              `INSERT INTO ui_preferences VALUES ('sidebar.chronologicalSort', '"alpha"', 1, 1)`,
            );
          } else if (kind === "thread") {
            createThread(db, noopNotifier, {
              projectId: PERSONAL_PROJECT_ID,
              providerId: "test-provider",
            });
          } else {
            const host = upsertHost(db, noopNotifier, {
              id: "host-sidebar",
              name: "Sidebar test",
            });
            createProject(db, noopNotifier, {
              name: "Existing project",
              source: {
                type: "local_path",
                hostId: host.id,
                path: "/tmp/sidebar-installation-defaults",
              },
            });
          }
          if (choice !== null) {
            db.$client
              .prepare(
                "INSERT INTO ui_preferences VALUES ('sidebar.organizationMode', ?, 4, 123)",
              )
              .run(JSON.stringify(choice));
          }
          const before = db.$client
            .prepare("SELECT * FROM ui_preferences")
            .all();
          const projects = db.$client.prepare("SELECT * FROM projects").all();
          const threads = db.$client.prepare("SELECT * FROM threads").all();
          db.$client.exec("DROP TABLE ui_preference_defaults");
          db.$client
            .prepare("DELETE FROM __drizzle_migrations WHERE created_at >= ?")
            .run(SIDEBAR_INSTALLATION_DEFAULTS_MIGRATION_TIMESTAMP);
          migrate(db);
          expect(
            db.$client.prepare("SELECT * FROM ui_preference_defaults").all(),
          ).toEqual([
            { key: "sidebar.organizationMode", value_json: '"project"' },
          ]);
          expect(
            db.$client.prepare("SELECT * FROM ui_preferences").all(),
          ).toEqual(before);
          expect(db.$client.prepare("SELECT * FROM projects").all()).toEqual(
            projects,
          );
          expect(db.$client.prepare("SELECT * FROM threads").all()).toEqual(
            threads,
          );
          migrate(db);
          expect(
            db.$client.prepare("SELECT * FROM ui_preferences").all(),
          ).toEqual(before);
        } finally {
          db.$client.close();
        }
      },
    );
  },
);

5. Root cause

The absent preference was treated as permission to use a newly changed global default. An upgrade therefore changed behavior even without an explicit user selection. The prior read path returned getUiPreferenceDefault(key) whenever the stored row was missing. This is source inspection only; historical code was not executed.

On current main, migration 0129 sets a separate project fallback when existing preferences, non-personal projects, or threads establish an existing installation. The server preference resolver selects saved choice, then installation fallback, then global default. The client reconciliation path accepts a revision-zero fallback while allowing legacy browser choices to migrate. The sidebar mode switch selects project rendering only outside machine/chronological modes.
