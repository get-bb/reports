#5844 · Host plugin toolchain bootstrap lacks its npm runtime

BugPriority: MediumEffort: Mediumpluginscliconfirmed-reproGitHub issue

October 20, 2026 · trusted origin/main bd93d18896bab97c950c4fa3451b621c1e0569c1

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

A newly built enrolled-host runtime cannot bootstrap the plugin compiler on an empty cache. The packaged CLI reports that it is downloading the toolchain, then exits with Cannot find module 'npm/package.json' before starting a download. The compiler deliberately resolves npm relative to its own bundle, but the enrolled-host package does not declare npm. Both the source host-package builder and the server-side artifact generator omit it. The actual bundled CLI reproduced the same failure from two clean trusted checkouts; a control using the repository's already-locked npm proved that it can resolve and run once npm is made available beside the bundle.

5. Root cause

  1. apps/cli/src/commands/plugin.ts:1635 runs plugin manifest/layout handling and then requests the compiler toolchain before building.
  2. packages/plugin-build/src/toolchain.ts:136 first tries a locally resolvable compiler and then a valid cached compiler. On a fresh packaged host neither exists. It announces fetching and evaluates resolveBundledNpmCli() while constructing the subprocess arguments.
  3. packages/plugin-build/src/npm-cli.ts:1 requires npm relative to import.meta.url:
function bundledNpmBin(fileName: string): string {
  const require = createRequire(import.meta.url);
  return join(dirname(require.resolve("npm/package.json")), "bin", fileName);
}

That module resolution throws synchronously before the subprocess starts. A working npm executable on PATH is not a substitute for a package resolvable from the CLI chunk.

The mismatch is at the packaging boundary: packages/bb-app/scripts/build-host.mjs:23 generates the host package using a six-item allowlist without npm. The server artifact service independently uses the same six-item allowlist in apps/server/src/services/install/bb-app-artifact.ts:24, then constructs the installed host manifest from it at apps/server/src/services/install/bb-app-artifact.ts:162. The full application package, unlike those host-only projections, declares npm. Development-local toolchains and warm caches bypass the broken bootstrap path, explaining why source-level compiler tests do not detect it.

6. Proposed fix and autopilot safety

Preserve the existing bundled-package-manager policy by ensuring both enrolled-host package generators carry the already-pinned npm runtime, then test a pristine extracted host package with empty compiler cache and no global module fallback. A useful regression contract is that npm resolves from the shipped CLI and its version command works even with PATH empty. An owner should also exercise the first toolchain download and plugin build on supported host platforms.
