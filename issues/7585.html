#7585 · ACP running presentation misses delayed arguments

BugPriority: LowEffort: Lowproviders · provider-acp

2026-11-15 · Issue · trusted base da3e60b81d560e114a2bec724bb59c997aaaae7f

Verdict: REPRODUCED · Root-cause confidence: high · reproduction label: confirmed-repro

1. Summary

ACP tools may announce a read or search before they supply its arguments. bb correctly classifies the later arguments, but it does not publish the changed presentation for the running item. Consumers therefore retain the announcement title until completion. Six focused cases reproduce this at the real ACP translator and shared event assembler boundary, with and without simultaneous output. The same agent repeated the failure in a second clean checkout of trusted main.

import { describe, expect, it } from "vitest";
import { createDeltaAssembler } from "@bb/provider-bridge-protocol/assembler";
import {
  ACP_TURN_STARTED_METHOD,
  ACP_UPDATE_METHOD,
} from "./bridge-protocol.js";
import { createAcpDeltaTranslator } from "./delta-translation.js";

describe.each([
  {
    name: "file read",
    kind: "read",
    input: { path: "lib/entry.ts" },
    title: "entry.ts",
    nextInput: { path: "lib/other.ts" },
    nextTitle: "other.ts",
    completedType: "fileRead",
  },
  {
    name: "path search",
    kind: "search",
    input: { glob: "**/*.spec.ts", path: "/workspace/lib" },
    title: "**/*.spec.ts",
    nextInput: { glob: "**/*.json", path: "/workspace/lib" },
    nextTitle: "**/*.json",
    completedType: "search",
  },
  {
    name: "content search",
    kind: "search",
    input: { pattern: "needle", path: "/workspace/lib" },
    title: "needle",
    nextInput: { pattern: "another needle", path: "/workspace/lib" },
    nextTitle: "another needle",
    completedType: "search",
  },
])("ACP late input: $name", (sample) => {
  it.each([undefined, "partial result"])(
    "refreshes presentation without replacing the running shape (output=%s)",
    (output) => {
      const translator = createAcpDeltaTranslator({ cwd: "/workspace" });
      const assembler = createDeltaAssembler({
        providerId: "acp",
        progressThrottleMs: 0,
      });
      const translate = (update: Record<string, unknown>) =>
        assembler.assemble({
          threadId: "late-input-thread",
          deltas: translator.translateAcpEvent(
            {
              jsonrpc: "2.0",
              method: ACP_UPDATE_METHOD,
              params: { threadId: "late-input-thread", update },
            },
            { threadId: "late-input-thread" },
          ),
        });
      assembler.assemble({
        threadId: "late-input-thread",
        deltas: translator.translateAcpEvent({
          jsonrpc: "2.0",
          method: ACP_TURN_STARTED_METHOD,
          params: { threadId: "late-input-thread" },
        }),
      });
      const initial = translate({
        sessionUpdate: "tool_call",
        toolCallId: "late-input-call",
        kind: sample.kind,
        title: sample.kind,
        status: "pending",
      }).find((event) => event.type === "item/started");
      expect(initial?.item.type).toBe("toolCall");

      const update = {
        sessionUpdate: "tool_call_update",
        toolCallId: "late-input-call",
        status: "in_progress",
        rawInput: sample.input,
      };
      const refreshed = translate({ ...update, rawOutput: output });
      expect(
        refreshed.find((event) => event.type === "item/started"),
      ).toMatchObject({
        item: {
          ...initial?.item,
          presentation: expect.objectContaining({ title: sample.title }),
        },
      });
      if (output !== undefined) {
        expect(refreshed).toContainEqual(
          expect.objectContaining({
            type: "item/toolCall/progress",
            itemId: initial?.item.id,
            message: output,
          }),
        );
      }
      expect(translate(update)).toEqual([]);

      expect(
        translate({ ...update, rawInput: sample.nextInput }).find(
          (event) => event.type === "item/started",
        ),
      ).toMatchObject({
        item: {
          ...initial?.item,
          presentation: expect.objectContaining({ title: sample.nextTitle }),
        },
      });
      const completed = translate({
        sessionUpdate: "tool_call_update",
        toolCallId: "late-input-call",
        status: "completed",
      });
      expect(completed).toEqual(
        ["toolCall", sample.completedType].map((type) =>
          expect.objectContaining({
            type: "item/completed",
            item: expect.objectContaining({
              id: initial?.item.id,
              type,
              presentation: expect.objectContaining({
                title: sample.nextTitle,
              }),
            }),
          }),
        ),
      );
    },
  );
});

5. Root cause

The translator merges the update into the previously announced event, then reclassifies it. However, the running refresh branch requires both classifications to be commands:

previous?.item.type === "command" &&
classified.item.type === "command"

A read or search with no arguments initially falls back to a generic tool. Once its path or query arrives, the existing classifiers can build fileRead/search presentation, but no item.open publishes it. The stored merged arguments are not enough to update event consumers.

Simply reopening with the newly classified semantic shape would introduce a different bug. The assembler's two-shape close path settles the original running shape before emitting the specialized completion. Changing the running shape prematurely would suppress that original completion. The repair must retain the announcement's shape while updating presentation.

There is also a routing detail in the progress return: updates that include non-command output must return the presentation refresh alongside progress rather than discard it.

6. Focused repair

Remember the original DeltaItemShape instead of only its type. When a running read/search presentation changes, reopen the existing provider item key using that original shape and the refined presentation. Continue to classify merged input for completion. Return the refresh before any progress. Keep the command refresh behavior, duplicate-update suppression, and all existing public event shapes unchanged.

The local repair changes two files in the existing ACP subsystem: 21 production additions + 7 production deletions + 132 regression lines = 160 changed text lines. It adds no dependency, generated file, lockfile, migration, stored-data change, or public protocol/schema field. Existing SDK and CLI event consumers use the same event path.
