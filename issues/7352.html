#7352 · Nested model menu leaks keyboard navigation

Bug Priority: Medium Effort: Low ui GitHub issue
2026-11-10 · trusted base 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The desktop model picker has a nested menu for additional models. Pressing ArrowRight on a focused row in that nested menu incorrectly requests a reasoning change from medium to high. The nested menu does not consume that key, so React delivers it to the enclosing picker's reasoning shortcut handler even though the nested content is rendered through a portal. A focused React DOM regression test reproduces the real component path in two clean trusted checkouts. The minimal repair makes the submenu own its horizontal navigation keys without closing it on ArrowRight.

5. Root cause

The nested content handler only recognizes two keys:

if (event.key === "Escape" || event.key === "ArrowLeft") {
  event.preventDefault();
  onOpenChange(false);
  triggerRef.current?.focus();
}

The shared desktop popover renders through a Radix portal. React's component ancestry still carries synthetic key events to the outer popover's key handler. Its reasoning shortcut returns for prevented events, but otherwise advances one option on ArrowRight:

const next =
  activeReasoningOptions[index + (event.key === "ArrowRight" ? 1 : -1)];
if (next) handleReasoningSelect(next.value);

The focused button is not an editable input, so the editable-target guard does not block this path. The parent is behaving as designed for its own model rows; the defect is that the nested menu fails to own its navigation key. Trusted-base blame dates the content handler to commit ebd8150661d; no linked PR was available at investigation time.

6. Proposed fix and verification

Keep Escape, ArrowLeft, and ArrowRight inside the submenu. Prevent their defaults and propagation. Return without dismissing on ArrowRight; retain the existing dismiss-and-refocus behavior for Escape and ArrowLeft. Leave the outer picker's intentional reasoning shortcuts unchanged.

The implemented candidate touches only the menu and its existing picker test file: 27 additions + 1 deletion = 28 total text lines across 2 files. It changes no dependencies, protocol, schema, permissions, stored data, packaging, or release behavior.
