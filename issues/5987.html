#5987 · Native skill paths are omitted from server dispatch

BugPriority: Medium Effort: Mediumprovidersthreads Issue #5987

Verdict: REPRODUCED · Root-cause confidence: high for the server dispatch omission. Trusted base: d1627a473684d29920567b3cf9c05bd68edb2d97.

1. TL;DR

A selected native skill reaches the outgoing host command as a name-only mention, without server-resolved instructions telling the agent where its file is. Both new-thread and follow-up-turn builders reproduce this omission. The existing skill-listing service can ask the host to discover native skill files, but these two builders do not connect that result to the prompt. This report proves the missing context at the real server command boundary, not an actual agent's subsequent filesystem search. Providers may independently understand their own slash commands, so universal failure across every provider is not established.

Complete reproduction test

import { describe, expect, it } from "vitest";
import { encodeClientTurnRequestIdNumber, type PromptInput } from "@bb/domain";
import {
  buildExecutionOptions,
  buildThreadStartCommand,
  prepareTurnSubmitCommandPayload,
} from "../../src/services/threads/thread-commands.js";
import {
  EMPTY_WORKSPACE_AGENT_CONTEXT,
  registerHostRpcResponder,
} from "../helpers/host-rpc.js";
import { configuredAcpProvider } from "../helpers/provider-registry.js";
import { skillInput } from "../helpers/prompt-input.js";
import {
  seedEnvironment,
  seedHostSession,
  seedProjectWithSource,
  seedThread,
  seedThreadRuntimeState,
} from "../helpers/seed.js";
import { withTestHarness } from "../helpers/test-app.js";

describe("native skill mention dispatch", () => {
  it.each(["start", "submit"] as const)(
    "includes the host-resolved skill path in agent-only %s input",
    async (entryPoint) => {
      const provider = await configuredAcpProvider({
        id: "native-repro",
        displayName: "Native repro",
        command: "native-repro-agent",
        args: [],
      });
      await withTestHarness(
        {
          extraProviders: [
            {
              ...provider,
              declaration: {
                ...provider.declaration,
                experimental_nativeSkillRoots: {
                  user: [".native-repro/skills"],
                  project: [],
                },
              },
            },
          ],
        },
        async (harness) => {
          const { host, session } = seedHostSession(harness.deps, {
            id: "host-native-skill-repro",
          });
          const workspacePath = "/workspace/native-skill-repro";
          const skillPath = "/provider-home/.native-repro/skills/audit-fixture/SKILL.md";
          const responder = registerHostRpcResponder(harness, {
            hostId: host.id,
            sessionId: session.id,
            handle: ({ command }) => {
              if (command.type === "host.read_workspace_agent_context") {
                return { ok: true, result: EMPTY_WORKSPACE_AGENT_CONTEXT };
              }
              if (command.type === "host.list_skills") {
                return {
                  ok: true,
                  result: {
                    skills: [{
                      id: `skill_${"a".repeat(64)}`,
                      name: "audit-fixture",
                      description: "A native skill fixture",
                      filePath: skillPath,
                      rootKind: "provider-user",
                      linked: false,
                    }],
                  },
                };
              }
              throw new Error(`Unexpected RPC ${command.type}`);
            },
          });
          try {
            const { project } = seedProjectWithSource(harness.deps, {
              hostId: host.id,
              path: workspacePath,
            });
            const environment = seedEnvironment(harness.deps, {
              hostId: host.id,
              projectId: project.id,
              path: workspacePath,
            });
            const thread = seedThread(harness.deps, {
              projectId: project.id,
              environmentId: environment.id,
              providerId: "acp-native-repro",
            });
            seedThreadRuntimeState(harness.deps, {
              environmentId: environment.id,
              providerThreadId: "provider-native-repro",
              threadId: thread.id,
            });
            const execution = await buildExecutionOptions(
              harness.deps,
              { model: "fixture-model" },
              { threadId: thread.id },
            );
            const input = skillInput("audit-fixture");
            const originalInput = structuredClone(input);
            const command = entryPoint === "start"
              ? await buildThreadStartCommand(harness.deps, {
                  environment, execution, fork: null,
                  permissionEscalation: "ask", input,
                  projectId: project.id, providerId: thread.providerId,
                  requestId: encodeClientTurnRequestIdNumber({ value: 5987 }),
                  syncGeneratedTitle: false, thread,
                })
              : await prepareTurnSubmitCommandPayload(harness.deps, {
                  environment, execution, permissionEscalation: "ask",
                  input, target: { mode: "start" }, thread,
                });
            const context: PromptInput | undefined = command.input.find(
              (item) => item.type === "text" && item.visibility === "agent-only",
            );
            expect(context).toMatchObject({
              type: "text", visibility: "agent-only", mentions: [],
              text: expect.stringContaining(skillPath),
            });
            expect(input).toEqual(originalInput);
          } finally {
            responder.unregister();
          }
        },
      );
    },
  );
});

5. Root cause

apps/server/src/services/threads/thread-commands.ts:270–306 builds the start command with the original input and inputGroups. apps/server/src/services/threads/thread-commands.ts:362–391 similarly forwards unchanged prompt data into the submit command. Neither path resolves mentioned native skill names or appends a fallback instruction.

The discovery mechanism already exists: apps/server/src/services/skills/skill-listing.ts:212–238 calls apps/server/src/services/providers/native-roots.ts:244–275 with the active host and workspace. The host implementation, apps/host-daemon/src/command-handlers/list-skills.ts:135–150, resolves roots and returns discovered skill file paths. The failure is the missing server prompt-enrichment step, not an absent host discovery capability.

The resolver also uses the server's providerNativeRoots cache, as declared in apps/server/src/services/providers/native-roots.ts:110–111 and consumed at apps/server/src/services/providers/native-roots.ts:190–207. That dependency is not currently part of the work-session dependency bundle used by the command builders.

6. Proposed fix and simple-fix gate

Add shared server-side prompt enrichment after runtime resolution and before command dispatch. Use the active provider's existing host-discovery service, leave staged BB skills on their existing path, and append non-pill, agent-only context to the last effective input group. If native discovery is unavailable or unsuccessful, direct the agent to the existing skill-listing command instead of guessing filesystem layout. Keep caller-owned inputs unchanged and cover missing skills, scan errors, absent roots, grouped inputs, and prompts without skill mentions.

No pull request: a local candidate made the focused regression pass and 84 relevant tests passed, but it failed typecheck because cached native-root resolution needs additional dependency wiring. Propagating that dependency surfaced changes in interactions, skill installation, server startup, and test harnesses, exceeding this rule's five-file/simple-subsystem limit. The attempt was stopped; no candidate commit or branch was pushed.

The stopped candidate was 348 added/deleted text lines across four initially changed files; the remaining required wiring would increase that scope. This is not a completed or shippable fix.
