#7496 · Responsive context layout commits after resize delivery

BugPriority: LowEffort: LowuiGitHub issueNovember 13, 2026 · base 070bf3df0aae0f009488f29d8941f5fec8532a93

Verdict: PARTIALLY REPRODUCED · Root-cause confidence: high for deferred DOM commitment; native-browser frame timing remains unverified.

1. TL;DR

The context card and transcript inset are supposed to choose their layout from the current pane width. A focused component reproduction shows that the actual production component still exposes the previous card/inset state immediately after its resize callback returns. All four tested band crossings retain the previous state until React commits the scheduled update; two same-band controls pass. The existing component suite also passes. The result repeats in a second clean checkout, but this host has no available Chrome executable, so no claim is made about an exact one-frame delay, the animated right-panel journey, or desktop rendering.

// @vitest-environment jsdom
import { act, cleanup, render, screen } from "@testing-library/react";
import { createStore, Provider } from "jotai";
import { MemoryRouter } from "react-router-dom";
import { afterEach, expect, it, vi } from "vitest";
import { TooltipProvider } from "@bb/shared-ui/tooltip";
import {
  ThreadContextCard,
  ThreadContextCardProvider,
  useThreadContextCardContentInset,
} from "./PluginThreadContextCard";

function Transcript() {
  const inset = useThreadContextCardContentInset();
  return <main aria-label="Transcript" style={{ paddingInlineEnd: inset }} />;
}

function Content() {
  return <p>Repository information</p>;
}

afterEach(() => {
  cleanup();
  vi.restoreAllMocks();
  vi.unstubAllGlobals();
});

it.each([
  { start: 1600, end: 1200, initialInset: "0px", inset: "312px", card: "visible" },
  { start: 1200, end: 900, initialInset: "312px", inset: "0px", card: "absent" },
  { start: 900, end: 1200, initialInset: "0px", inset: "312px", card: "visible" },
  { start: 1200, end: 1600, initialInset: "312px", inset: "0px", card: "visible" },
  { start: 1600, end: 1700, initialInset: "0px", inset: "0px", card: "visible" },
  { start: 1200, end: 1250, initialInset: "312px", inset: "312px", card: "visible" },
])("commits card and transcript before resize delivery returns: $start -> $end", (scenario) => {
  const deliveries = new Map<ResizeObserver, () => void>();
  vi.stubGlobal("ResizeObserver", class implements ResizeObserver {
    constructor(private callback: ResizeObserverCallback) {}
    observe(target: Element) {
      if (target.hasAttribute("data-scroll-overlay")) {
        deliveries.set(this, () => this.callback([], this));
      }
    }
    disconnect() {
      deliveries.delete(this);
    }
    unobserve() {}
  });
  const width = vi.spyOn(HTMLElement.prototype, "clientWidth", "get");
  width.mockReturnValue(scenario.start);
  render(
    <Provider store={createStore()}>
      <TooltipProvider>
        <MemoryRouter>
          <ThreadContextCardProvider
            enabled
            threadId="resize-repro-thread"
            projectId="resize-repro-project"
            environment={null}
            coreRows={[{ id: "info", group: "info", order: 1, component: Content }]}
            coreSections={[]}
          >
            <Transcript />
            <div data-scroll-overlay=""><ThreadContextCard /></div>
          </ThreadContextCardProvider>
        </MemoryRouter>
      </TooltipProvider>
    </Provider>,
  );
  const transcript = screen.getByRole("main", { name: "Transcript" });
  const readDom = () => {
    const card = document.querySelector<HTMLElement>("[data-thread-context-card]");
    return {
      inset: transcript.style.paddingInlineEnd,
      card: card === null ? "absent" : card.hidden ? "hidden" : "visible",
    };
  };
  expect(transcript.style.paddingInlineEnd).toBe(scenario.initialInset);
  expect(deliveries.size).toBe(1);
  let delivered = readDom();
  act(() => {
    width.mockReturnValue(scenario.end);
    for (const notify of [...deliveries.values()]) notify();
    delivered = readDom();
  });
  const expected = { inset: scenario.inset, card: scenario.card };
  expect(readDom()).toEqual(expected);
  console.info(JSON.stringify({ start: scenario.start, end: scenario.end, delivered, settled: readDom() }));
  expect(delivered).toEqual(expected);
});

5. Root cause

The production layout effect finds the scroll overlay, reads its width, and calls a React state setter from the ResizeObserver callback. That update does not require a synchronous DOM commit before callback return:

  useLayoutEffect(() => {
    const overlay = probeRef.current?.closest<HTMLElement>(
      "[data-scroll-overlay]",
    );
    if (!overlay || !setLayout) return;
    const measure = () =>
      setLayout(resolveThreadContextCardLayout(overlay.clientWidth));
    measure();
    const observer = new ResizeObserver(measure);
    observer.observe(overlay);
    return () => observer.disconnect();
  }, [setLayout]);

The width resolver selects three discrete bands using a 760px transcript maximum and 312px reserved card width. The inset hook derives the transcript reserve from React layout state; the card branch also depends on that state. When the DOM width changes but the state commit is deferred, both consumers still describe the previous band. The measured observations match this mechanism exactly.

The real transcript path reads the inset in ThreadScreen, passes it to the scroll surface at the thread view, and renders it as paddingInlineEnd. No daemon, database, or protocol behavior is involved.

6. Proposed fix

Ensure a changed width band is committed synchronously when native resize delivery occurs, while keeping the initial layout-effect measurement separate and avoiding redundant synchronous commits within a band. React DOM already supplies the required synchronous-commit primitive, so no dependency is needed. Validate the native right-panel animation and controls in a browser before claiming exact-frame correctness. No production fix was attempted here: an existing open pull request already links this issue, and the visual reproduction remains partial.
