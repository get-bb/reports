#8176 · Repeated quote-offset scans stall composer edits

BugPriority: MediumEffort: Lowuiperfconfirmed-reproGitHub issue

November 25, 2026 · trusted main fb045a046653cc127656ca3c7243d44ae4c94f3f

Verdict: REPRODUCED · Root-cause confidence: high

1. TL;DR

Typing a response after a long quote does substantially more work than typing after equivalent unquoted content. The serializer re-scans earlier quote lines and reconstructs cumulative prefix lengths for every text and mention endpoint. In two clean checkouts, increasing the fixture from 800 to 3,200 quoted lines increased serialization time by about 21×, while the equivalent unquoted control stayed below one millisecond. A real Tiptap editor with the composer extensions and an update callback measured about 537–538 ms per edit at 3,200 lines. This is a synchronous CPU-cost defect; no provider, database, network request, or running BB app is needed to reproduce it.

// @vitest-environment jsdom
import { performance } from "node:perf_hooks";
import { Editor, getSchema } from "@tiptap/core";
import type { Node as ProseMirrorNode } from "@tiptap/pm/model";
import { expect, it } from "vitest";
import { promptEditorExtensions } from "./prompt-editor-extensions";
import {
  promptEditorSerializationFromDoc,
  promptEditorValueFromDoc,
} from "./prompt-editor-serialization";

const schema = getSchema(promptEditorExtensions({ getPlaceholder: () => "" }));

function documentWithLines(lineCount: number, quoted: boolean): ProseMirrorNode {
  const paragraphs = Array.from({ length: lineCount }, (_, index) =>
    schema.nodes.paragraph!.create(null, [
      schema.text(`passage ${index} `),
      schema.nodes.mention!.create({
        mention: { kind: "project", projectId: `project_${index}`, label: `@p${index}` },
        serializedText: `@p${index}`,
      }),
    ]),
  );
  const reply = schema.nodes.paragraph!.create(null, schema.text("response"));
  return schema.nodes.doc!.create(
    null,
    quoted ? [schema.nodes.blockquote!.create(null, paragraphs), reply] : [...paragraphs, reply],
  );
}

function medianDuration(action: () => void): number {
  action();
  action();
  const durations = Array.from({ length: 9 }, () => {
    const start = performance.now();
    action();
    return performance.now() - start;
  }).sort((left, right) => left - right);
  return durations[4]!;
}

      console.log(JSON.stringify({ scenario: "serialize", quoted, lineCount, docSize: doc.content.size, medianMs: duration }));
      if (quoted) quoteTimes.push(duration);

      extensions: promptEditorExtensions({
        getPlaceholder: () => "",

5. Root cause

The quote serializer first serializes the inner nodes, then prefixes each serialized line. For each mapped offset it starts searching at the first line, copies all earlier prefixed lines with slice, and reduces their length differences. This repeated prefix computation is the avoidable work:

const prefixedOffset = (offset: number): number => {
  let lineIndex = lines.length - 1;
  for (let index = 0; index < lines.length; index += 1) {
    if (offset <= lineGlobalStarts[index]! + lines[index]!.length) {
      lineIndex = index;
      break;
    }
  }
  const prefixDelta = prefixedLines
    .slice(0, lineIndex + 1)
    .reduce(
      (sum, prefixedLine, index) =>
        sum + (prefixedLine.length - lines[index]!.length),
      0,
    );
  return offset + prefixDelta;
};

With one text segment and one mention per nonempty line, the quote translation makes six endpoint lookups per line: four for the two offset-mapping segments, and two for the mention. Each lookup on line i revisits roughly i lines. Summing over the quote gives Θ(N²) work for this fixed-width-line fixture, with extra temporary-array allocation. More generally the quote mapping is O((segments + mentions) × lines), in addition to inner serialization; line count alone is not a bound for arbitrary node fragmentation.

Decoration building serializes the entire document. Its transaction apply path rebuilds on the measured document changes. Separately, the composer update handler serializes the whole document again. Editing only the response does not bypass the unchanged quote.

The deeper triggering condition is whole-document serialization on ordinary edits, not a provider or a mention-rendering failure. Removing duplicate serialization alone would reduce the constant factor but leave the quadratic endpoint mapping. Repository history attributes the repeated prefix computation to the pre-plugin serializer; the later composer extraction retained it.

6. Proposed fix

Compute original line-end positions and cumulative prefix deltas once per quote. Locate each endpoint with binary search and add its cached delta, preserving the current “offset at line end belongs to that line” boundary rule and the one-character prefix for empty lines. This bounds quote endpoint translation to O(lines + endpoints × log(lines)) rather than repeated prefix scans and copies. A carefully implemented monotonic cursor is another option, but must handle separate mapping and mention passes. Retain correctness coverage for empty lines, nested quotes, mentions, line boundaries, and the response separator.
