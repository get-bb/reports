1. TL;DR

The report describes a timeline that ignores wheel and trackpad input while keyboard and scrollbar input still work. Native browser wheel input scrolled both timeline panes in two clean checkouts of current main. Large and small pixel deltas both worked with the right panel closed. No root cause was established, and no production change or pull request is justified by this evidence. This result does not rule out a client-specific or persisted-state-dependent defect.

Repeatable browser assertion

const p = await browser.getPage("main");
const state = () => p.evaluate(() => [...document.querySelectorAll(".thread-scrollbar")].map(e => ({top:e.scrollTop, height:e.clientHeight, total:e.scrollHeight})));
const settle = () => p.evaluate(() => new Promise(resolve => setTimeout(resolve, 500)));
const samples = [];
for (const [pane,x] of [[0,300],[1,900]]) {
  await p.mouse.move(x,250);
  for (const deltaY of [-120,48,-7,7]) {
    const before = await state();
    await p.mouse.wheel({deltaY});
    await settle();
    const after = await state();
    const movement = after[pane].top - before[pane].top;
    samples.push({pane,deltaY,before:before[pane].top,after:after[pane].top,movement});
    if (Math.sign(movement) !== Math.sign(deltaY)) throw new Error(JSON.stringify(samples));
  }
}
console.log(JSON.stringify({userAgent:await p.evaluate(() => navigator.userAgent),samples},null,2));
await p.shot({type:"jpeg",maxEdge:1280,quality:85});

5. Root cause

Unknown. The inspected implementation does not support assigning blame to the timeline wheel listener: the listener is passive, and its handler records intent without canceling the event. The timeline is an overflow-y-auto scroll container. The inactive-pane scrim has pointer-events-none. The native browser tests demonstrate that these paths permit wheel scrolling in this configuration. They cannot exclude a different overlay, extension, browser, or persisted UI state in the affected client.

6. Next experiment

Obtain the affected client product/version and compare an empty client profile with its existing profile. In the failing timeline record the wheel event target, defaultPrevented value, element under the pointer and scrollTop before/after input, with right panel open and closed. Reproduce that state in a trusted isolated app before choosing a fix. No source patch was made; no failing regression test exists.
