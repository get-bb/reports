#7534 · Cleanup retries against a retired desktop generation

Bug Priority: Medium Effort: Medium desktop partial-repro · GitHub issue · 2026-11-13

Trusted origin/main: f024a372f0e1e0670f6fd7452ebcd1341f639c95

PARTIALLY REPRODUCED · Root-cause confidence: high

1. TL;DR

The server-side retry loop is reproduced in two clean checkouts: closing an old desktop session twice targets its saved generation both times, fails both times, and keeps telling the caller to retry. A replacement session using the new generation opens and closes successfully in the same fixture. The real host-broker test suite separately confirms that refreshed instances reject old generations. This is a partial reproduction because desktop RPCs in the plugin reproduction are simulated; no live Electron reconnect, original incident resources, or HTTP transport was exercised.

No production fix or pull request is included. A generation change revokes leases without necessarily removing the old tabs, so blindly rebinding cleanup or silently treating a stale generation as successful cleanup would choose ownership/retirement policy without enough evidence.

5. Root cause

  1. releaseDesktop, lines 96–129, builds every cleanup request from the saved desktop target, including its old generation. It does not rediscover an instance or classify retirement separately: 
    const scope = {
  hostId: target.hostId,
  instanceId: target.instanceId,
  generation: target.generation,
  threadId: target.threadId,
};
  2. Host broker, lines 282–294, correctly requires a matching instance and generation for scoped commands. A request carrying the retired generation is rejected before dispatch. Its existing refreshed-generation test exercises this behavior against the real broker and passes.
  3. finish, lines 130–205, records the session as closed but leaves cleanup pending after any rejected cleanup operation. Every failure receives the same retry instruction: 
    record.cleanupPending = failures.length > 0;
await save(record);
...
throw new Error(
  `Browser session ${state}, but cleanup on host ${session.hostId} failed: ${reasons}. Run close to retry.`,
);
    The next close reloads the persisted record and repeats the same unreachable generation. Local host-close success does not remove the desktop cleanup failure.
  4. The safety constraint is deeper than the retry text. Desktop generation rotation, lines 323–342, revokes leases and can clear thread association. revoke, lines 132–148, removes lease state and unmarks leased tabs; it is not tab cleanup. release_control, lines 510–520, rejects an unavailable lease. Merely substituting the new generation would not recreate the original lease and is not a proven ownership-safe repair.

Confidence: high for this saved-generation/retry mechanism, supported by two executed plugin reproductions, actual broker tests, and the recorded source. Confidence does not extend to the original desktop's tab state or the precise reconnect trigger.

6. Proposed fix and simple-fix gate

Define an explicit terminal disposition for retired desktop generations and communicate whether cleanup was completed, the resource is known gone, or cleanup cannot safely continue. Preserve strict thread, generation, lease, and owned-tab boundaries. Treat temporary host disconnection separately from confirmed retirement. Do not convert stale-generation failures into silent cleanup success or replay the old tab IDs against a replacement generation.

No production repair was attempted: choosing when ownership may transfer or when an owned-resource obligation may be retired needs a product/lifecycle decision that the available evidence does not resolve. That fails the automation's no-product-decision/no-security-boundary simple-fix gate. The reproduction patch adds 91 text lines in one existing test file and changes no production source; it is retained locally only. There was no fix branch, commit, push, or pull request. No open pull request linked to issue 7534 was found by search or issue timeline metadata.

Next test after that policy is chosen: drive the actual desktop broker through generation rotation while an owned tab and an attached shared tab coexist; verify that only resources with provable ownership can be closed and that the caller receives a final cleanup disposition. Re-run the focused failing contract against that implementation.
