Root cause and existing fix

The historical mechanism is unowned eager allocation: every host construction calls mkdtempSync, while only disposal requests with cleanupStorage true remove that directory. Tests that omit dispose therefore create resources without helper-local teardown. Current code still has this behavior:

packages/plugin-sdk/src/testing/fake-plugin-host.ts:692

  const persistentState =
    sharedState ??
    ({
      kvRows: new Map<string, string>(),
      storageRoot: mkdtempSync(join(tmpdir(), "bb-fake-plugin-host-")),
      storedSettings: new Map<string, PluginSettingValue>(
        Object.entries(options.settings ?? {}),
      ),
    } satisfies FakePluginPersistentState);

The crucial missing part of the report's current-main analysis is the outer owner. packages/plugin-sdk/vitest.config.ts:1 uses defineWorkspaceTestConfig, whose vitest.shared.ts:325 registers vitest.global-tmpdir.ts. The runner creates one shared temporary root, switches TMPDIR before workers start, reference-counts project setup/teardown, restores the previous TMPDIR and recursively removes the root after the final project. The deletion occurs outside worker lifetime:

vitest.global-tmpdir.ts:16

export default function setup(): () => Promise<void> {
  const holder = globalThis as SandboxHolder;
  let sandbox = holder[ACTIVE];
  if (sandbox === undefined) {
    const previous = process.env.TMPDIR;
    sandbox = {
      root: mkdtempSync(join(tmpdir(), "bb-vt-")),
      previous,
      references: 0,
    };
    holder[ACTIVE] = sandbox;
    process.env.TMPDIR = sandbox.root;
  }
  sandbox.references += 1;
  return async () => {
    const active = holder[ACTIVE];
    if (active === undefined) return;
    active.references -= 1;
    if (active.references > 0) return;
    delete holder[ACTIVE];
    if (active.previous === undefined) delete process.env.TMPDIR;
    else process.env.TMPDIR = active.previous;
    await killProcessesReferencingPath(active.root);
    rmSync(active.root, {
      recursive: true,
      force: true,
      maxRetries: 10,
      retryDelay: 100,
    });
  };

The cited revision b629714e31487bde8af5574639422a9b5c97cbb5 dates to August 27, 2026; git ancestry and the merged-PR metadata establish the ordering. Historical failure was not executed because this investigation runs only trusted current-main code. Current runner-level cleanup, rather than a helper-level fix, explains the zero-leftover measurements.

Proposed fix

No new change for the normal repository test-run leak is justified: the current shared runner already owns cleanup. Standalone consumers or nonstandard runners still need explicit harness.dispose(), and interrupted runner processes can bypass global teardown; neither scenario was exercised here. If a current-main macOS reproduction remains, first record the actual worker TMPDIR and whether the parent global teardown completed, then compare it with the shared setup path before adding another cleanup owner.
