#5821 · Unbounded append-only service capture files

BugPriority: MediumEffort: MediumhostGitHub issue2026-10-20

Trusted base: 7e4232ef241b5cdfb7d272cee044fe6f82702c70

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

The launcher captures each service's stdout and stderr in a separate append-only file. Unlike the structured application logs, these capture files have no size check, rotation, or restart retention limit. Using the exact production helper, a real child grew each service capture to 48 MiB while running and 64 MiB after one restart, with no backup files created. A second clean checkout produced identical results. The issue affects both server and host-daemon captures and does not require multiple servers or a particular warning message.

Expected storage property: an explicitly bounded retention policy should eventually stop one active capture from retaining every byte indefinitely, while preserving useful recent diagnostics. This report does not invent a new numeric product limit.

Actual: every batch is appended intact, the same capture remains after restarting, and no retention machinery runs. Each capture retained all 67,108,864 bytes. Finite execution alone cannot prove infinite growth; the absence of any limiting branch in the actual write path explains why these observations continue.

Complete repeatable evidence script

import assert from "node:assert/strict";
import { once } from "node:events";
import { mkdtempSync, readdirSync, renameSync, rmSync, statSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join, resolve } from "node:path";
import { pathToFileURL } from "node:url";

const checkout = resolve(process.argv[2] ?? ".");
const { spawnLoggedProcess } = await import(pathToFileURL(join(checkout, "packages/bb-app/src/logged-process.ts")));
const scratch = mkdtempSync(join(tmpdir(), "bb-capture-growth-"));
const children = new Set();
const batchBytes = 16 * 1024 * 1024;
const childSource = `
  const assert = require("node:assert/strict");
  const { fstatSync, writeSync } = require("node:fs");
  assert(fstatSync(1).isFile());
  assert(fstatSync(2).isFile());
  const chunk = Buffer.alloc(1024 * 1024, 120);
  process.on("message", (message) => {
    if (message === "stop") {
      process.disconnect();
      return;
    }
    for (const descriptor of [1, 2]) {
      for (let index = 0; index < 8; index++) {
        let offset = 0;
        while (offset < chunk.length) {
          offset += writeSync(descriptor, chunk, offset, chunk.length - offset);
        }
      }
    }
    process.send("written");
  });
  process.send("ready");
`;

async function start(logDir, logName) {
  const child = spawnLoggedProcess({
    command: process.execPath,
    args: ["-e", childSource],
    env: {},
    ipc: true,
    logDir,
    logName,
  });
  children.add(child);
  assert.deepEqual(await once(child, "message"), ["ready", undefined]);
  return child;
}

async function writeBatch(child) {
  const message = once(child, "message");
  child.send("write");
  assert.equal((await message)[0], "written");
}

async function stop(child) {
  const closed = once(child, "close");
  child.send("stop");
  assert.deepEqual(await closed, [0, null]);
  children.delete(child);
}

const timeout = setTimeout(() => {
  for (const child of children) child.kill("SIGKILL");
  process.exitCode = 1;
}, 30_000);

try {
  console.log(`environment: ${process.platform} ${process.arch} node ${process.version}`);
  for (const logName of ["host-daemon", "server"]) {
    const logDir = join(scratch, logName);
    const logPath = join(logDir, `${logName}-stdio.log`);
    const child = await start(logDir, logName);
    for (let batch = 1; batch <= 3; batch++) {
      await writeBatch(child);
      const size = statSync(logPath).size;
      assert.equal(size, batch * batchBytes);
      console.log(`${logName} running batch ${batch}: ${size} bytes`);
    }
    await stop(child);
    const restarted = await start(logDir, logName);
    await writeBatch(restarted);
    await stop(restarted);
    assert.equal(statSync(logPath).size, 4 * batchBytes);
    assert.deepEqual(readdirSync(logDir), [`${logName}-stdio.log`]);
    console.log(`${logName} after restart: ${statSync(logPath).size} bytes; files: ${readdirSync(logDir).join(", ")}`);
  }

  const logDir = join(scratch, "rename-probe");
  const logPath = join(logDir, "host-daemon-stdio.log");
  const child = await start(logDir, "host-daemon");
  await writeBatch(child);
  renameSync(logPath, `${logPath}.1`);
  writeFileSync(logPath, "");
  await writeBatch(child);
  await stop(child);
  assert.equal(statSync(`${logPath}.1`).size, 2 * batchBytes);
  assert.equal(statSync(logPath).size, 0);
  console.log(`rename probe: renamed file ${statSync(`${logPath}.1`).size} bytes; replacement ${statSync(logPath).size} bytes`);
  console.log("RESULT: both capture files grow without rotation while running and across restarts; rename alone does not redirect the child descriptors.");
} finally {
  clearTimeout(timeout);
  for (const child of children) {
    const closed = once(child, "close");
    child.kill("SIGKILL");
    await closed;
  }
  rmSync(scratch, { recursive: true, force: true });
}

5. Root cause

The service launcher calls spawnLoggedProcess for managed services. That helper opens one capture path in append mode and hands the descriptor directly to the child's two output streams:

const fd = openSync(
  join(args.logDir, `${args.logName}-stdio.log`),
  "a",
  0o600,
);
try {
  return spawn(args.command, args.args, {
    cwd: process.cwd(),
    env: args.env,
    stdio: args.ipc === true ? ["ignore", fd, fd, "ipc"] : ["ignore", fd, fd],
  });
} finally {
  closeSync(fd);
}

Complete helper at the trusted base. The parent closes its copy after spawning; the child's copies remain open. There is no size check before opening, no live accounting, and no reopen or rotation hook. Restarting opens the same pathname with append semantics.

Structured logging is a separate sink: pino-roll receives the application file while pino-pretty also emits console output. Rotation in that transport does not rotate the launcher's stdout/stderr descriptor.

The direct-file design was intentional: the earlier backpressure repair removed parent/terminal forwarding to prevent service freezes. The current capture tests protect direct regular-file descriptors and output retention across restarts; they do not check a storage bound. Debugging guidance accurately documents the append-across-restarts behavior.

6. Proposed fix and simple-fix gate

Introduce bounded capture retention for the shared helper, with explicit handling of a continuously running child, restart retention, diagnostics on capture failure, and shutdown. Preserve the property that terminal or parent-output backpressure cannot block a service. Add a failing-before/passing-after regression at the real-child boundary once the retention contract is selected.

A rename at startup cannot bound a long-lived writer. A periodic rename and fresh pathname also cannot redirect the already-open child descriptors: the probe leaves the new file at zero bytes while the renamed file grows to 32 MiB. Routing through a parent stream would remove the direct-file protection; truncating in place discards retained diagnostics and needs an explicit loss/retention policy. These are design choices, not a safe mechanical patch.
