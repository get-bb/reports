#7346 · Plugin wait ownership is replaced by hook order

BugMedium priorityLow effort threadspluginsGitHub issue 2026-11-10 · base 7c1353d80729983b86ea1555d18b42407f320406

Verdict: REPRODUCED · Root-cause confidence: high · Reproduction label: confirmed-repro

1. TL;DR

Queued messages have one plugin holder, even when several plugins ask to wait. A plugin that submits a held message, or already holds a durable queued message, can lose that attribution to a different plugin merely because the other hook runs first. The dispatch pass collects all wait decisions but selects the first without considering either source of ownership. Two clean checkouts reproduce the wrong plugin and wrong leading reason using the actual send/recheck entry points and migrated SQLite. The repair preserves an owning plugin when it is still waiting, while retaining first-hook fallback for unowned messages or an owner that has stopped waiting.

5. Root cause

The hook pass appends wait decisions in registration order, then chooses the holder solely by array position:

const waiter = waits[0];
return { kind: "wait", waiter, additionalWaiters: waits.slice(1) };

The request already exposes queued rows and ephemeral submission metadata through the context builder. The SDK contract explains that queued rows retain their durable state, whereas submission metadata is null on retries. Ignoring both allows an unrelated earlier waiter to replace the existing holder.

Dispatch-attempt persistence takes the selected plugin and combined reason. waitHolderFor derives the persisted holder index from that plugin. Plugin unregistration clears rows by this index; orphan recovery also interprets it as the holding plugin. These are consequences of incorrect selection, not separate database or recovery defects.

History: git blame attributes positional selection to commit 49dadc363ab on September 1, 2026. No later trusted-main fix was present when the fix branch was created.

6. Proposed fix and verification

Resolve the preferred plugin from the first queued row's plugin wait, or otherwise the submitting plugin. Extract that plugin's first wait decision when present, falling back to the first wait if it is absent. Keep all remaining decisions in their original order. An owner that no longer waits must not suppress another plugin's wait. Remove the obsolete comment asserting that the first registered waiter always owns the row.

The local repair touches only server dispatch selection and its existing regression suite: 95 changed text lines (88 additions, 7 deletions), two files, no dependency, lockfile, generated file, migration, public schema, protocol, or stored-data migration.
