1. TL;DR

The ACP bridge sends the same instruction block again after successfully loading an existing provider session. A focused test proves that ordinary consecutive prompts do not repeat the block, while stop/resume with the same provider session ID does. A second test confirms that personal workspaces inherit a Git root and synthetic AGENTS.md in the surrounding data directory. These tests exercise BB code with a repository fake ACP agent and an isolated filesystem; they do not measure actual model context, native CLI loading, compaction, or token costs.

5. Root cause

Session construction always assigns pendingInstructions: params.instructions. Successful session/load restores the original session ID without clearing that field. Prompt construction consumes the field once per bridge session and prepends a text block. The delivery lifetime is the in-memory bridge session, which is shorter than a restorable provider conversation. A failed load takes the fresh-session fallback, where sending instructions is necessary.

pendingInstructions: params.instructions,

const instructions = session.pendingInstructions;
if (instructions) {
  session.pendingInstructions = undefined;
  blocks.push({
    type: "text",
    text: `<system_instructions>\n${instructions}\n</system_instructions>`,
  });
}

The server reads global AGENTS.md and adds it to the instruction bundle. Thus a global file included there is subject to the same bridge resend mechanism tested with the small marker.

Separately, plugin data directory construction nests host data below the daemon data directory. The workspace resolver appends workspaces and the path key, and the host handler only creates the directory. It establishes no new Git root. Native instruction discovery can therefore encounter the ancestor file if its loader searches those ancestors; that provider-specific step was not executed here.

6. Proposed fix and simple-fix assessment

Define instruction delivery/version semantics per provider conversation, including an unprompted session resumed before its first delivery, changed instruction bundles, forks, compaction, and failed-load fallback. Then deduplicate unchanged instructions while ensuring initial and updated instructions still reach the agent. Merely dropping instructions on every successful load can omit the first delivery or silently ignore updates. Persisted delivery state or a provider-supported replaceable instruction channel would require design beyond the simple-fix allowance.

For personal workspaces, choose an explicit workspace-location/boundary policy and account for existing owned workspace paths and removal behavior. Moving paths or introducing repository boundaries changes user-visible workspace semantics. The combined fix spans provider lifecycle and environment placement. No production patch or pull request was created: the required instruction-lifetime and workspace-placement decisions fail the rule's no-product/architecture-decision condition. No linked open PR was found in issue timeline metadata or the open-PR search.
